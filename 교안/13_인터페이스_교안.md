## 1. 문제 상황: 상속만으로는 부족하다

Day11~12에서 `Student`은 이미 `Person`을 상속받고 있습니다.

```java
public class Student extends Person { ... }
```

그런데 만약 "정보를 출력할 수 있는 모든 것"이라는 공통 기능을, `Student`뿐 아니라 `Person`과 전혀 관계없는 `Course`에게도 강제하고 싶다면 어떻게 해야 할까요? 자바는 **클래스는 오직 하나만 상속받을 수 있습니다(단일 상속)**. `Student`은 이미 `Person`을 상속받고 있어서, 또 다른 클래스를 상속받을 수 없습니다. 그리고 `Course`는 애초에 `Person`과 아무 관계가 없는 클래스입니다.

이럴 때 사용하는 것이 **인터페이스(interface)** 입니다. 인터페이스는 상속과 달리 **여러 개를 동시에 구현할 수 있고**, 서로 관계없는 클래스들에게도 공통된 기능을 강제할 수 있습니다.

---

## 2. 인터페이스란?

인터페이스는 "이 기능을 반드시 구현해야 한다"는 **약속(규칙)만 정의**하고, 실제 구현은 전혀 포함하지 않는 설계도입니다. Day11~12에서 배운 추상 클래스와 비슷해 보이지만 중요한 차이가 있습니다.

| 구분 | 추상 클래스 | 인터페이스 |
|---|---|---|
| 상속/구현 개수 | 하나만 상속 가능(`extends`) | 여러 개 동시에 구현 가능(`implements`) |
| 일반 필드 | 가질 수 있음 | 가질 수 없음 (상수만 가능) |
| 일반 메서드(구현 포함) | 가질 수 있음 | 기본적으로 가질 수 없음(전부 추상 메서드) |
| 목적 | "이것은 ~이다" 관계(is-a) | "이것은 ~할 수 있다" 기능(can-do) |

## 3. 인터페이스 정의와 구현 (interface, implements)

```java
public interface Printable {
    void printInfo(); // 인터페이스의 메서드는 기본적으로 public abstract (구현 내용 없음)
}
```

**설명**: `interface Printable`은 "정보출력가능"이라는 이름의 인터페이스를 정의합니다. 안에 있는 `void printInfo();`은 구현 내용이 전혀 없는 추상 메서드입니다. `abstract` 키워드를 따로 쓰지 않아도, 인터페이스 안의 메서드는 자동으로 추상 메서드로 취급됩니다.

이제 서로 관계없는 두 클래스가 이 인터페이스를 구현(`implements`)합니다.

```java
public class Student extends Person implements Printable {
    private String studentId;

    public Student(String name, String studentId) {
        super(name);
        this.studentId = studentId;
    }

    @Override
    public void printInfo() {
        System.out.println("[학생] 이름: " + getName() + ", 학번: " + studentId);
    }
}
```

```java
public class Course implements Printable { // 사람과 전혀 관계없는 클래스
    private String courseName;
    private int capacity;

    public Course(String courseName, int capacity) {
        this.courseName = courseName;
        this.capacity = capacity;
    }

    @Override
    public void printInfo() {
        System.out.println("[강좌] 강좌명: " + courseName + ", 정원: " + capacity);
    }
}
```

**설명**: `extends Person implements Printable`처럼, 클래스는 상속(`extends`)과 인터페이스 구현(`implements`)을 동시에 할 수 있습니다. 순서는 항상 `extends`가 먼저, `implements`가 나중입니다. `Course`는 `Person`과 전혀 관계가 없지만, 똑같이 `Printable`을 구현했습니다. 인터페이스를 구현한 클래스는 그 안의 추상 메서드를 **반드시 오버라이딩**해야 합니다(추상 클래스의 추상 메서드와 동일한 규칙).

## 4. 인터페이스 참조 변수로 다형성 활용하기

인터페이스도 추상 클래스처럼 참조 변수의 타입으로 사용할 수 있습니다.

```java
public class InterfacePolymorphismExample {
    public static void main(String[] args) {
        Printable[] items = {
            new Student("홍길동", "S001"),
            new Course("자바프로그래밍", 30)
        };

        for (Printable item : items) {
            item.printInfo(); // 실제 객체 타입(학생 또는 강좌)에 맞는 정보출력()이 실행됨
        }
    }
}
```

**출력 결과**
```
[학생] 이름: 홍길동, 학번: S001
[강좌] 강좌명: 자바프로그래밍, 정원: 30
```

**설명**: `Student`과 `Course`는 상속 관계로는 전혀 연결되어 있지 않습니다(하나는 `Person`을 상속받고, 하나는 아무것도 상속받지 않음). 하지만 둘 다 `Printable` 인터페이스를 구현했기 때문에, `Printable[]`이라는 하나의 배열로 함께 관리할 수 있습니다. 이것이 Day11~12에서 배운 다형성을, 상속 관계가 없는 클래스들 사이에서도 가능하게 해주는 인터페이스의 핵심 가치입니다.

## 5. 인터페이스는 여러 개 동시에 구현 가능

클래스가 상속은 하나만 가능한 것과 달리, 인터페이스는 콤마(`,`)로 나열해서 여러 개를 동시에 구현할 수 있습니다.

```java
public interface Savable {
    void save();
}

public class Student extends Person implements Printable, Savable { // 인터페이스 2개 동시 구현
    private String studentId;

    public Student(String name, String studentId) {
        super(name);
        this.studentId = studentId;
    }

    @Override
    public void printInfo() {
        System.out.println("[학생] 이름: " + getName() + ", 학번: " + studentId);
    }

    @Override
    public void save() {
        System.out.println(getName() + " 학생 정보를 저장했습니다.");
    }
}
```

**설명**: `implements Printable, Savable`처럼 콤마로 여러 인터페이스를 나열하면, `Student`은 두 인터페이스의 추상 메서드를 모두 구현해야 합니다. 클래스 상속은 부모를 단 하나만 지정할 수 있는 것과 뚜렷이 대비되는 인터페이스만의 특징입니다.

---

## 자주 하는 실수

1. **extends와 implements 순서를 바꿔 씀**
   ```java
   public class Student implements Printable extends Person { ... } // 컴파일 에러! extends가 항상 먼저
   public class Student extends Person implements Printable { ... } // 올바른 순서
   ```

2. **인터페이스의 메서드를 일부만 구현**
   ```java
   public interface Printable {
       void printInfo();
   }
   public class Course implements Printable {
       // 정보출력()을 구현하지 않으면 컴파일 에러 발생
   }
   ```

3. **인터페이스에 일반 필드를 선언하려고 시도**
   ```java
   public interface Printable {
       String name; // 컴파일 에러! 인터페이스는 일반 필드를 가질 수 없음 (상수만 가능)
   }
   ```

## 핵심 요약

| 항목 | 핵심 내용 |
|---|---|
| 인터페이스 | 구현 내용 없이 "반드시 구현해야 할 기능"만 정의하는 설계도 |
| interface, implements | `interface name { }`으로 정의, `class ... implements 인터페이스 { }`로 구현 |
| extends와 implements | 클래스 상속(extends)은 하나만, 인터페이스 구현(implements)은 여러 개 가능 |
| 인터페이스 다형성 | 상속 관계가 없는 서로 다른 클래스도, 같은 인터페이스로 묶어 다형성 활용 가능 |
| 추상 클래스 vs 인터페이스 | 추상 클래스는 "~이다"(is-a) 관계, 인터페이스는 "~할 수 있다"(can-do) 기능 |
