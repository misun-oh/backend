# 부록 1. 애노테이션 기초 - 실습 답안

---

## 기본

### 문제 1. @Deprecated 사용해보기

```java
// EmpDto.java
public class EmpDto {
    private String empId;

    @Deprecated
    public void info() {
        System.out.println("이 메서드 대신 toString()을 사용하세요.");
    }
}
```

```java
// Practice1.java
public class Practice1 {
    public static void main(String[] args) {
        EmpDto emp = new EmpDto();
        emp.info(); // 정상 실행되지만, 컴파일 시 "deprecated 메서드 사용" 경고가 표시됨
    }
}
```

**설명**: `@Deprecated`는 프로그램의 실행을 막지 않습니다. 다만 컴파일러가 "이 메서드는 더 이상 권장하지 않으니 다른 걸 쓰라"는 경고를 IDE나 컴파일 로그에 표시해줍니다.

**틀리기 쉬운 포인트**: `@Deprecated`를 붙이면 프로그램이 아예 실행이 안 될 거라 생각하기 쉬운데, 그렇지 않습니다. 이건 어디까지나 "권장하지 않는다"는 안내이지 강제 금지가 아닙니다.

### 문제 2. 커스텀 애노테이션 정의만 하기

```java
// 필수입력.java
public @interface 필수입력 {
}
```

**설명**: `@interface` 키워드로 애노테이션 타입을 정의했습니다. 이 자체로는 아직 아무 데도 붙어있지 않고, 다른 곳에서 `@필수입력`으로 사용할 준비만 된 상태입니다.

**틀리기 쉬운 포인트**: `interface 필수입력`(앞의 `@` 없이)이라고 쓰면 이건 애노테이션이 아니라 일반 인터페이스를 정의하는 문법이 되어버립니다. 애노테이션 정의에는 반드시 `@interface`를 사용해야 합니다.

## 응용

### 문제 3. 메타 애노테이션 붙이기

```java
// 필수입력.java
import java.lang.annotation.ElementType;
import java.lang.annotation.Retention;
import java.lang.annotation.RetentionPolicy;
import java.lang.annotation.Target;

@Retention(RetentionPolicy.RUNTIME)
@Target(ElementType.FIELD)
public @interface 필수입력 {
}
```

**설명**: `@Retention(RetentionPolicy.RUNTIME)`은 이 애노테이션이 프로그램 실행 중에도 정보로 남아있도록 지정합니다. `@Target(ElementType.FIELD)`는 이 애노테이션을 필드에만 붙일 수 있도록 제한합니다.

**틀리기 쉬운 포인트**: `import java.lang.annotation.*;` 구문을 빠뜨리면 `Retention`, `Target`, `ElementType`, `RetentionPolicy`를 인식하지 못해 컴파일 에러가 납니다.

### 문제 4. 학과 클래스에 애노테이션 부착

```java
// 학과.java
public class 학과 {
    @필수입력
    private String 학과명;

    private int 정원;

    public 학과(String 학과명, int 정원) {
        this.학과명 = 학과명;
        this.정원 = 정원;
    }

    public String get학과명() {
        return 학과명;
    }

    public int get정원() {
        return 정원;
    }
}
```

```java
// Practice4.java
public class Practice4 {
    public static void main(String[] args) {
        학과 학과1 = new 학과("컴퓨터공학과", 40);
        System.out.println("학과명: " + 학과1.get학과명() + ", 정원: " + 학과1.get정원());
    }
}
```

**설명**: `@필수입력`이 `학과명` 필드에 붙어있지만, 지금 단계에서는 이 표시가 프로그램 동작에 아무 영향도 주지 않습니다. `정원`은 붙지 않았어도 정상적으로 사용됩니다. 애노테이션은 "표시"일 뿐, 이 표시를 읽어서 뭔가 하는 코드는 아직 없기 때문입니다.

**틀리기 쉬운 포인트**: `@필수입력`을 붙이면 자동으로 null 체크가 될 거라 기대하기 쉬운데, 그렇지 않습니다. 이 표시를 실제로 활용하려면 부록2에서 배울 리플렉션 코드가 별도로 필요합니다.

## 도전

### 문제 5. @Target 제약 확인하기

```java
public class 학과 {
    @필수입력
    private String 학과명;

    // @필수입력
    // public void 학과정보출력() { ... }
    // 컴파일 에러 발생: '@필수입력' not applicable to method
    // 이유: @Target(ElementType.FIELD)로 제한되어 있어, 필드가 아닌 메서드에는 사용할 수 없음
}
```

**설명**: `@Target`으로 애노테이션을 붙일 수 있는 위치를 제한해두면, 잘못된 곳에 애노테이션을 붙이려는 실수를 컴파일 시점에 바로 잡아낼 수 있습니다.

**틀리기 쉬운 포인트**: `@Target`을 지정하지 않으면 기본적으로 거의 모든 위치(필드, 메서드, 클래스 등)에 애노테이션을 붙일 수 있게 됩니다. 실무에서는 애노테이션의 용도를 명확히 하기 위해 `@Target`을 구체적으로 지정하는 것이 좋습니다.

### 문제 6. 종합 - 여러 애노테이션을 가진 학생 클래스

```java
// 학생.java
public class 학생 {
    @필수입력
    private String 이름;

    @필수입력
    private String 학번;

    private int 나이;

    public 학생(String 이름, String 학번, int 나이) {
        this.이름 = 이름;
        this.학번 = 학번;
        this.나이 = 나이;
    }

    @Deprecated
    public void 구정보조회() {
        System.out.println("이 메서드 대신 information()을 사용하세요.");
    }

    public String information() {
        return "이름: " + 이름 + ", 학번: " + 학번 + ", 나이: " + 나이;
    }
}
```

```java
// Practice6.java
public class Practice6 {
    public static void main(String[] args) {
        학생 학생1 = new 학생("홍길동", "S001", 20);
        System.out.println(학생1.information());
    }
}
```

**설명**: 이 문제는 지금까지 배운 애노테이션 2가지(`@필수입력`, `@Deprecated`)를 한 클래스 안에서 함께 사용합니다. `이름`과 `학번`은 필수 입력값이라는 의미로 `@필수입력`을 붙였고, `나이`는 상대적으로 덜 중요하다고 판단해 붙이지 않았습니다. 이렇게 "어떤 필드가 중요한지"를 애노테이션으로 표시해두면, 리플렉션과 어노테이션처리에서 이 표시를 읽어 자동으로 검증하는 프로그램을 만들 수 있게 됩니다.

**틀리기 쉬운 포인트**: 이번 챕터까지는 애노테이션이 "의미 있는 표시"이긴 하지만 아직 "실제로 검증하는 기능"은 없습니다. 다음 챕터에서 이 표시를 읽어서 진짜로 활용하는 방법을 배울 것이므로, 지금 단계에서 검증 로직이 없는 것은 정상입니다.
