# Day 15. 제네릭 - 실습 답안

## 기본

### 문제 1. 제네릭 클래스 만들기

```java
// Box.java
public class Box<T> {
    private T content;

    public void setContent(T content) {
        this.content = content;
    }

    public T getContent() {
        return content;
    }
}
```

```java
// Practice1.java
public class Practice1 {
    public static void main(String[] args) {
        Box<String> box1 = new Box<>();
        box1.setContent("자바");

        System.out.println(box1.getContent());
    }
}
```

**설명**: `Box<String>`으로 선언하는 순간, 클래스 정의에 있던 `T`가 전부 `String`으로 바뀐 것처럼 동작합니다. `getContent()`이 `String`을 반환한다는 것을 컴파일러가 알고 있으므로, 캐스팅 없이 바로 `String` 변수에 대입할 수 있습니다.

**틀리기 쉬운 포인트**: `new Box<>()`의 빈 `<>`는 생략이 아니라 "왼쪽의 타입을 그대로 따라간다"는 의미입니다. `new Box()`처럼 `<>` 자체를 아예 안 쓰면 컴파일 경고가 발생합니다(옛날 방식으로 처리되어 타입 안전성이 사라짐).

### 문제 2. 다른 타입으로 같은 제네릭 클래스 재사용

```java
public class Practice2 {
    public static void main(String[] args) {
        Box<Integer> box1 = new Box<>();
        box1.setContent(100);

        System.out.println(box1.getContent());
    }
}
```

**설명**: 똑같은 `Box<T>` 클래스 정의를 코드 한 줄도 고치지 않고, 이번에는 `<Integer>`로 지정해서 정수를 담는 용도로 재사용했습니다. 이것이 제네릭의 핵심 장점입니다 — **타입별로 클래스를 따로 만들 필요 없이, 하나의 클래스 정의로 여러 타입에 재사용**할 수 있습니다.

**틀리기 쉬운 포인트**: `Box<int>`처럼 기본 자료형을 직접 쓰면 컴파일 에러가 납니다. `int`의 객체 버전인 `Integer`를 사용해야 합니다. `box1.setContent(100)`처럼 기본형 값을 그대로 넘겨도 되는 이유는, 자바가 자동으로 `int`를 `Integer`로 변환해주는 오토박싱(autoboxing) 기능이 있기 때문입니다.

## 응용

### 문제 3. 제네릭 없이 만들었을 때의 문제 재현

```java
// Box.java
public class Box {
    private Object content;

    public void setContent(Object content) {
        this.content = content;
    }

    public Object getContent() {
        return content;
    }
}
```

```java
// Practice3.java
public class Practice3 {
    public static void main(String[] args) {
        Box box1 = new Box();
        box1.setContent("문자열입니다");

        String value = (String) box1.getContent();
        System.out.println(value);

        // box1.setContent(123);
        // String value2 = (String) box1.getContent();
        // 실행 시 ClassCastException 발생: Integer를 String으로 캐스팅할 수 없음
        // (컴파일은 정상적으로 되지만, 프로그램을 실행해야만 이 오류를 발견할 수 있다는 것이 문제)
    }
}
```

**설명**: `Object` 기반의 `Box`은 어떤 타입이든 받을 수 있어서, `setContent(123)`처럼 원래 의도(문자열 저장)와 다른 값을 넣어도 컴파일 단계에서는 전혀 문제가 없습니다. 문제는 그 값을 다시 꺼내서 `(String)`으로 캐스팅하려는 순간, 실제로는 `Integer`였다는 것이 드러나며 프로그램이 중단됩니다.

**틀리기 쉬운 포인트**: "컴파일이 잘 됐으니 문제없다"고 안심하기 쉬운데, 이 예제가 보여주는 핵심은 **컴파일이 잘 되는 것과 실행 중 안전한 것은 다른 문제**라는 점입니다. 제네릭은 바로 이 "컴파일은 되지만 실행 중 터지는" 상황을 "아예 컴파일이 안 되게" 앞당겨 잡아주는 도구입니다.

### 문제 4. 제네릭 클래스에 학사관리 도메인 적용

```java
// Pair.java
public class Pair<T> {
    private T first;
    private T second;

    public Pair(T first, T second) {
        this.first = first;
        this.second = second;
    }

    public void printInfo() {
        System.out.println("첫번째: " + first + ", 두번째: " + second);
    }
}
```

```java
// Practice4.java
public class Practice4 {
    public static void main(String[] args) {
        Pair<String> departmentPair = new Pair<>("컴퓨터공학과", "경영학과");
        departmentPair.printInfo();
    }
}
```

**설명**: 생성자에서도 `T` 타입의 매개변수를 그대로 받아 필드에 저장합니다. `Pair<String>`으로 선언했으므로, 생성자에 `String`이 아닌 다른 타입(예: 정수)을 넣으려 하면 컴파일 에러가 발생합니다.

**틀리기 쉬운 포인트**: 제네릭 클래스 안에서 `T` 타입 두 개(`first`, `second`)가 반드시 서로 다른 값을 가질 필요는 없지만, 둘 다 **같은 타입**이어야 합니다. 만약 "이름은 문자열, 나이는 정수"처럼 서로 다른 타입 두 개를 다루고 싶다면 `Pair<K, V>`처럼 타입 파라미터를 두 개(예: 이번 챕터에서 배운 K, V 관례) 선언해야 합니다.

### 문제 5. 제네릭 메서드로 배열 출력하기

```java
public class Practice5 {
    public static <T> void printAll(T[] array) { // 메서드 앞에 <T>를 붙여 이 메서드만의 제네릭 선언
        for (T element : array) {
            System.out.println(element);
        }
    }

    public static void main(String[] args) {
        String[] names = {"홍길동", "김철수", "이영희"};
        Integer[] scores = {90, 85, 78};

        printAll(names);
        printAll(scores);
    }
}
```

**설명**: `public static <T> void printAll(T[] array)`에서 반환형(`void`) 바로 앞에 있는 `<T>`가 "이 메서드는 제네릭 메서드다"라는 선언입니다. 클래스 전체에 `<T>`를 붙이지 않고, 메서드 하나에만 제네릭을 적용할 수 있습니다. `printAll(names)`을 호출하면 `T`가 자동으로 `String`으로, `printAll(scores)`을 호출하면 `T`가 자동으로 `Integer`로 추론됩니다.

**틀리기 쉬운 포인트**: 배열은 `int[]`가 아니라 `Integer[]`로 선언해야 합니다. 제네릭은 기본 자료형을 직접 다룰 수 없다는 규칙이(문제 2에서 배운 것처럼) 배열에도 그대로 적용됩니다.

### 문제 6. 종합 - 제네릭 상자와 인터페이스 함께 사용

```java
// Printable.java (Day13)
public interface Printable {
    void printInfo();
}
```

```java
// Box.java
public class Box<T> implements Printable {
    private T content;

    public Box(T content) {
        this.content = content;
    }

    @Override
    public void printInfo() {
        System.out.println("상자 안에는 " + content + "가 들어있습니다");
    }
}
```

```java
// Practice6.java
public class Practice6 {
    public static void main(String[] args) {
        Printable[] items = {
            new Box<String>("자바"),
            new Box<Integer>(100)
        };

        for (Printable item : items) {
            item.printInfo();
        }
    }
}
```

**설명**: `Box<T>`가 `implements Printable`을 함께 사용한 것처럼, 제네릭과 인터페이스는 서로 배타적인 개념이 아니라 자유롭게 조합할 수 있습니다. `Printable[]` 배열에는 `Box<String>`과 `Box<Integer>`라는, 담긴 타입은 다르지만 인터페이스가 같은 객체들을 함께 넣을 수 있습니다.

**틀리기 쉬운 포인트**: `Printable[] items` 배열 선언에는 제네릭 타입(`<String>`, `<Integer>`)이 드러나지 않습니다. 배열은 `Printable`이라는 인터페이스 타입만 알면 되고, 그 안의 `Box`가 구체적으로 어떤 타입을 담고 있는지는 각 객체 내부의 일이기 때문입니다. 이 문제는 Day13(인터페이스)과 Day15(제네릭)이 실제로 어떻게 함께 쓰이는지 보여주는 종합 예제입니다.
