# Day 20. 미니 프로젝트 — 완료 체크리스트

각 항목을 직접 실행/확인하고 체크하세요. 옆의 (DayN)은 근거 챕터입니다.

## 실행 & 설정

- [ ] `./gradlew build` 성공, 앱 기동 시 오류 없음 (Day2)
- [ ] `application.yml` 에 비밀번호·시크릿이 있으나, 실제 배포용은 환경변수로 뺄 수 있게 `${JWT_SECRET:...}` 형태 (Day19)
- [ ] `logging.level.com.example.hr=DEBUG`, mapper 패키지 DEBUG 로 실행 SQL이 보임 (Day3·9)
- [ ] 정적 리소스(`/css/basic.css`)가 200으로 응답, 화면에 디자인 적용 (Day8)

## 데이터 계층 (Day9·11·12)

- [ ] `EmpMapper` 조회/CRUD/조인 매핑이 각각 테스트로 통과 (`@SpringBootTest @Transactional`)
- [ ] `findPage`/`countPage` 가 검색 조건 조합(없음/키워드/부서/재직/복합)에서 기대 건수
- [ ] 정렬 파라미터가 enum으로만 허용됨 (`?sort=DROP` → 400, `${}` 인젝션 불가)
- [ ] `update`/`delete` 반환 0을 서비스가 "대상 없음"으로 처리
- [ ] 어디에도 `#{}` 대신 `${}` 로 값이 들어가지 않음

## 화면 (Day7·8·12·14)

- [ ] `/emps` : 검색폼(이름·부서·재직토글) + 표(사번·이름·부서명·입사일·상태 badge) + 페이지네이션
- [ ] 페이지 링크에 검색 조건이 실려 2페이지로 가도 검색 유지
- [ ] `/emps/{id}` : 부서명·직급명 표시, 목록/수정/삭제 링크
- [ ] `/emps/new`, `/emps/{id}/edit` : 같은 `form.html`, 수정 시 기존 값 채워짐
- [ ] 폼 검증 실패 시 폼으로 되돌아오고 빨간 메시지 + **입력값 유지**
- [ ] 공통 헤더/푸터가 fragment 로 재사용됨
- [ ] `/` 또는 `/dashboard` : 인원·부서 수·최근 입사자·부서별 인원

## 예외 처리 (Day13·14)

- [ ] 없는 사원(`/emps/999`) → 404 페이지 (Whitelabel 아님)
- [ ] 서버 오류 시 500 페이지 + 콘솔에 스택트레이스 로그 (사용자에겐 일반 문구)
- [ ] 부서 삭제 시 소속 사원 있으면 안내 메시지 (`BusinessException`)
- [ ] 등록 도중 예외가 나면 아무 것도 저장되지 않음 (`@Transactional` 롤백, 테스트로 확인)

## 보안 (Day17·18)

- [ ] 비로그인 상태로 `/emps` → 로그인 페이지로
- [ ] 회원가입 후 `MEMBER.PASSWORD` 가 `$2a$...` (평문 아님)
- [ ] 로그인 후 헤더에 이름 + 로그아웃 버튼, 비로그인 시 로그인 버튼 (`sec:authorize`)
- [ ] `USER` 로 `/depts` 접근 → 403 페이지
- [ ] `USER` 로 `POST /emps/205/delete` (curl 등 직접 호출) → 차단됨 (화면만 숨긴 게 아님)
- [ ] `<form method="post">` 에 CSRF 토큰이 자동 삽입됨(소스 보기로 hidden `_csrf` 확인)

## API (Day15, 선택 Day19)

- [ ] `GET /api/emps` 페이징 JSON, `GET /api/emps/{id}` 200 / 없으면 404 JSON
- [ ] `POST /api/emps` 201 + `Location` 헤더, 잘못된 본문 → 400 + `{code, fieldErrors}`
- [ ] `DELETE /api/emps/{id}` 204
- [ ] MockMvc 테스트(`@WebMvcTest`)로 위 케이스 검증
- [ ] (선택) `POST /api/auth/login` → 토큰, 토큰으로 `/api/emps` 200, 토큰 없으면 401

## 테스트 (Day10)

- [ ] `./gradlew test` 전체 통과
- [ ] Mapper/Service 핵심 시나리오에 단언(assertion)이 있는 테스트 (println 아님)
- [ ] 데이터 변경 테스트는 `@Transactional` 롤백으로 반복 실행 가능

## 코드 품질 (Day5·6)

- [ ] Controller에 업무 로직·SQL 없음, Service에 웹 타입(`HttpServletRequest`) 없음
- [ ] Service·Repository가 인터페이스에 의존
- [ ] 생성자 주입(+`@RequiredArgsConstructor`), 필드 주입 없음
- [ ] `System.out.println` / `printStackTrace()` 없음 (로거 사용)

## 선택 기능

- [ ] (S1) 프로필 사진 업로드 → UUID 저장, 원본명은 DB, 다운로드 시 한글 파일명 유지
- [ ] (S2) 실행 시간 로깅 애스펙트 동작 (`▶ / ◀` 로그)
- [ ] (S3) 프로파일별 로깅(`dev` 콘솔 / `prod` 파일)
- [ ] (S4) `/api/**` JWT stateless 체인 + 화면 세션 체인 병행
