# Day 3. 로깅 설정

| 항목 | 내용 |
|---|---|
| 선수학습 | Day 2(스프링 부트 실행, `application.yml`) |
| 이번 챕터 | `println` 디버깅의 한계 → SLF4J + Logback → 로그 레벨 → `application.yml` 설정 → `@Slf4j` 사용법 → 파일 출력 → 프로파일별 로깅 |
| 권장 진행 | 1일 |
| 결과물 | 콘솔/파일에 레벨별로 로그가 남고, 개발/운영 환경별로 로그 설정이 나뉜 프로젝트 |

## 학습목표

- `System.out.println` 디버깅의 문제 4가지를 말할 수 있다.
- SLF4J(인터페이스)와 Logback(구현체)의 관계를 설명할 수 있다.
- `TRACE < DEBUG < INFO < WARN < ERROR` 레벨을 상황에 맞게 고를 수 있다.
- `application.yml` 로 패키지별 레벨·콘솔 패턴·파일 출력을 설정할 수 있다.
- `@Slf4j` 와 `log.info("id={}", id)` 파라미터 바인딩을 쓸 수 있고, 문자열 `+` 연결을 왜 피하는지 안다.
- `logback-spring.xml` + 프로파일로 개발/운영 로그를 다르게 만들 수 있다.

---

## 1. `System.out.println` 디버깅의 문제

값을 확인하려고 `System.out.println(emp)` 을 여기저기 넣어 본 적이 있을 겁니다. 문제는 이렇습니다.

| 문제 | 설명 |
|---|---|
| **레벨 구분이 없다** | "그냥 궁금해서 찍는 것"과 "심각한 오류"가 똑같이 출력됨 |
| **한꺼번에 끄기 어렵다** | 배포 전에 `println` 을 하나씩 찾아 지워야 함 |
| **정보가 부족하다** | 언제(시각), 어디서(클래스·메서드), 어느 스레드에서 찍혔는지 안 나옴 |
| **운영에서 못 본다** | `System.out` 은 콘솔로만. 서버에서는 파일로 남겨 나중에 봐야 함 |

**로거(logger)** 는 이 4가지를 전부 해결합니다. 레벨을 붙여 찍고, 설정 한 줄로 레벨을 조절하고,
시각·위치·스레드를 자동으로 붙이고, 콘솔·파일·외부 시스템 어디로든 보낼 수 있습니다.

---

## 2. SLF4J + Logback

스프링 부트의 로깅은 두 조각입니다.

- **SLF4J** (Simple Logging Facade for Java): 로깅 **인터페이스**. 우리 코드는 이것만 import 합니다.
  `org.slf4j.Logger`, `org.slf4j.LoggerFactory`
- **Logback**: 실제 출력을 담당하는 **구현체**. 스프링 부트의 기본값. 별도 의존성 추가 불필요
  (`spring-boot-starter-*` 에 이미 포함).

우리 코드가 인터페이스(SLF4J)에만 의존하므로, 나중에 구현체를 Log4j2 등으로 바꿔도 코드는 그대로입니다.
(`Java 3.에노테이션`의 "약속에 의존" 과 같은 원리)

```
[내 코드]  →  SLF4J (인터페이스)  →  Logback (구현체)  →  콘솔 / 파일
```

---

## 3. 로그 레벨

레벨은 5단계이고, **설정한 레벨 이상만** 출력됩니다. (예: 레벨을 `INFO` 로 두면 `DEBUG`·`TRACE` 는 안 나옴)

| 레벨 | 언제 쓰나 | 예 |
|---|---|---|
| `ERROR` | 기능이 실패했고 조치가 필요 | 결제 실패, DB 연결 끊김 |
| `WARN` | 지금은 동작하지만 위험 신호 | 재시도 3회 중 1회 실패, deprecated 설정 사용 |
| `INFO` | 정상 흐름의 큰 이정표 | 애플리케이션 기동, 주문 생성됨(주문번호 …) |
| `DEBUG` | 개발 중 흐름 추적 | "검색 조건 = …", "쿼리 결과 42건" |
| `TRACE` | 아주 상세한 추적 | 반복문 각 스텝, 바이트 단위 |

**운영 기본은 `INFO`**, 개발 중 우리 패키지만 `DEBUG` 로 여는 게 흔한 조합입니다.

## 4. `application.yml` 로 설정

```yaml
logging:
  level:
    root: INFO                       # 전체 기본
    org.springframework.web: INFO
    com.example.hr: DEBUG            # 우리 코드는 자세히
    org.mybatis: DEBUG              # (Day 9 이후) MyBatis 매퍼 로그
  pattern:
    console: "%d{HH:mm:ss.SSS} %-5level [%thread] %logger{36} - %msg%n"
  file:
    name: logs/hr.log               # 이 경로에 파일로도 남김
  logback:
    rollingpolicy:
      max-file-size: 10MB            # 파일이 10MB 넘으면
      max-history: 7                 # 최근 7개만 보관 (hr.log.2026-08-28.0.gz …)
```

- `logging.level.<패키지>` : 패키지(또는 클래스) 단위로 레벨 지정. 더 구체적인 경로가 우선.
- `logging.pattern.console` : 콘솔 출력 형식. `%d` 시각, `%level` 레벨, `%thread` 스레드,
  `%logger` 로거 이름(=보통 클래스명), `%msg` 메시지, `%n` 줄바꿈.
- `logging.file.name` 을 주면 콘솔 + 파일 둘 다 출력. 없으면 콘솔만.

## 5. 코드에서 로거 쓰기 — `@Slf4j`

Lombok의 `@Slf4j` 를 클래스에 붙이면 `log` 라는 로거 필드가 자동 생성됩니다.

```java
import lombok.extern.slf4j.Slf4j;
import org.springframework.web.bind.annotation.*;

@Slf4j
@RestController
public class HelloController {

    @GetMapping("/hello")
    public String hello(@RequestParam(defaultValue = "손님") String name) {
        log.debug("hello 요청: name={}", name);          // 개발 중 흐름
        if (name.isBlank()) {
            log.warn("빈 이름으로 요청됨");
        }
        String result = "안녕하세요, " + name + "님";
        log.info("인사 응답 생성 완료");
        return result;
    }
}
```

Lombok 없이 직접 만들면:
```java
private static final org.slf4j.Logger log =
        org.slf4j.LoggerFactory.getLogger(HelloController.class);
```

### 파라미터 바인딩 `{}` 을 쓰는 이유

```java
log.debug("검색 조건: keyword={}, deptId={}", cond.getKeyword(), cond.getDeptId());   // O
log.debug("검색 조건: keyword=" + cond.getKeyword() + ", deptId=" + cond.getDeptId()); // X
```

- `+` 연결은 **로그 레벨이 꺼져 있어도 문자열을 먼저 만듭니다**(불필요한 비용).
- `{}` 방식은 해당 레벨이 켜져 있을 때만 값을 문자열로 만듭니다.
- `null` 이 섞여도 `NullPointerException` 없이 `null` 로 찍힙니다.
- 예외는 마지막 인자로: `log.error("주문 처리 실패: orderId={}", id, e);` (스택트레이스까지 출력)

## 6. 프로파일별 로깅 — `logback-spring.xml`

`application.yml` 로도 충분하지만, 형식을 정교하게 나누려면 `src/main/resources/logback-spring.xml`
을 씁니다. (`logback.xml` 이 아니라 `logback-spring.xml` 이어야 스프링 프로파일 태그를 쓸 수 있음)

```xml
<?xml version="1.0" encoding="UTF-8"?>
<configuration>
    <include resource="org/springframework/boot/logging/logback/defaults.xml"/>

    <!-- 콘솔 (공통) -->
    <appender name="CONSOLE" class="ch.qos.logback.core.ConsoleAppender">
        <encoder>
            <pattern>%d{HH:mm:ss.SSS} %-5level [%thread] %logger{36} - %msg%n</pattern>
        </encoder>
    </appender>

    <!-- 파일 (운영에서만) -->
    <appender name="FILE" class="ch.qos.logback.core.rolling.RollingFileAppender">
        <file>logs/hr.log</file>
        <rollingPolicy class="ch.qos.logback.core.rolling.SizeAndTimeBasedRollingPolicy">
            <fileNamePattern>logs/hr.%d{yyyy-MM-dd}.%i.log.gz</fileNamePattern>
            <maxFileSize>10MB</maxFileSize>
            <maxHistory>30</maxHistory>
        </rollingPolicy>
        <encoder>
            <pattern>%d{yyyy-MM-dd HH:mm:ss.SSS} %-5level [%thread] %logger - %msg%n</pattern>
        </encoder>
    </appender>

    <!-- 개발: 콘솔만, 우리 패키지 DEBUG -->
    <springProfile name="dev">
        <logger name="com.example.hr" level="DEBUG"/>
        <root level="INFO">
            <appender-ref ref="CONSOLE"/>
        </root>
    </springProfile>

    <!-- 운영: 콘솔 + 파일, WARN 위주 -->
    <springProfile name="prod">
        <logger name="com.example.hr" level="INFO"/>
        <root level="WARN">
            <appender-ref ref="CONSOLE"/>
            <appender-ref ref="FILE"/>
        </root>
    </springProfile>
</configuration>
```

실행 시 프로파일 지정:
```bash
java -jar hr.jar --spring.profiles.active=prod
```
(IntelliJ 에서는 Run Configuration 의 `Active profiles` 칸에 `dev`)

## 자주 하는 실수

- **`log` 를 static import 하거나 다른 클래스의 `@Slf4j` `log` 를 씀** → 로거 이름이 엉뚱한 클래스가 됨.
  각 클래스에 `@Slf4j` 를 따로 붙인다.
- **`+` 문자열 연결로 로그 작성** → 레벨이 꺼져도 문자열 생성 비용 발생. `{}` 파라미터를 쓴다.
- **예외를 `log.error("실패: " + e.getMessage())` 로만 기록** → 스택트레이스가 안 남음.
  `log.error("실패: id={}", id, e)` 처럼 예외 객체를 마지막 인자로.
- **`logback.xml` 로 만들고 `<springProfile>` 사용** → 스프링이 프로파일 태그를 못 읽음.
  파일명을 `logback-spring.xml` 로.
- **운영에서 `com.example.hr` 를 `DEBUG` 로 방치** → 로그 폭증, 디스크·성능 문제. 운영은 `INFO` 이상.
- **민감정보(비밀번호·주민번호·토큰)를 로그에 찍음** → 로그는 여러 사람이 본다. 마스킹하거나 안 찍는다.

## 핵심 요약

| 요소 | 내용 |
|---|---|
| SLF4J / Logback | 인터페이스 / 기본 구현체. 코드는 SLF4J만 import |
| 레벨 | `ERROR > WARN > INFO > DEBUG > TRACE`. 설정 레벨 이상만 출력 |
| `logging.level.<패키지>` | 패키지·클래스별 레벨. 운영 INFO + 우리 패키지 DEBUG가 흔함 |
| `logging.file.name` | 주면 콘솔 + 파일, 없으면 콘솔만 |
| `@Slf4j` | `log` 필드 자동 생성 (Lombok) |
| `log.info("x={}", x)` | 파라미터 바인딩. `+` 연결 금지. 예외는 마지막 인자 |
| `logback-spring.xml` + `<springProfile>` | 개발/운영 로그 분리 |
