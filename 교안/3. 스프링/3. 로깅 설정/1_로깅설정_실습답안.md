## 문제 1. 레벨별 로그 출력

```java
@Slf4j
@RestController
public class HelloController {

    @GetMapping("/hello")
    public String hello(@RequestParam(defaultValue = "손님") String name) {
        log.trace("trace: name={}", name);
        log.debug("debug: name={}", name);
        log.info("info: name={}", name);
        log.warn("warn: name={}", name);
        log.error("error: name={}", name);
        return "안녕하세요, " + name + "님";
    }
}
```

**확인**

- `com.example.hr: INFO` → `info`, `warn`, `error` 세 줄만 출력 (설정 레벨 이상만).
- `com.example.hr: DEBUG` → `debug`, `info`, `warn`, `error` 네 줄. (`trace` 는 여전히 안 나옴)
- `com.example.hr: TRACE` → 다섯 줄 모두.


## 문제 4. 예외 로깅

```java
@GetMapping("/divide")
public String divide(@RequestParam int a, @RequestParam int b) {
    try {
        int result = a / b;
        log.info("나눗셈 성공: {} / {} = {}", a, b, result);
        return String.valueOf(result);
    } catch (ArithmeticException e) {
        log.error("나눗셈 실패: a={}, b={}", a, b, e);   // 마지막 인자 e → 스택트레이스 출력
        return "0으로 나눌 수 없습니다";
    }
}
```

`log.error("...", a, b, e)` 처럼 **예외 객체를 마지막 인자**로 주면, 메시지의 `{}` 는 `a`, `b` 로
채워지고 남은 `e` 는 스택트레이스로 출력됩니다. `e.getMessage()` 만 문자열로 붙이면 스택이 안 남습니다.

## 문제 5. 프로파일별 로깅

`src/main/resources/logback-spring.xml` — (교안 6절 예시와 동일)

```xml
<configuration>
    <include resource="org/springframework/boot/logging/logback/defaults.xml"/>

    <appender name="CONSOLE" class="ch.qos.logback.core.ConsoleAppender">
        <encoder><pattern>%d{HH:mm:ss.SSS} %-5level %logger{36} - %msg%n</pattern></encoder>
    </appender>
    <appender name="FILE" class="ch.qos.logback.core.rolling.RollingFileAppender">
        <file>logs/hr.log</file>
        <rollingPolicy class="ch.qos.logback.core.rolling.SizeAndTimeBasedRollingPolicy">
            <fileNamePattern>logs/hr.%d{yyyy-MM-dd}.%i.log.gz</fileNamePattern>
            <maxFileSize>10MB</maxFileSize>
            <maxHistory>30</maxHistory>
        </rollingPolicy>
        <encoder><pattern>%d %-5level [%thread] %logger - %msg%n</pattern></encoder>
    </appender>

    <springProfile name="dev">
        <logger name="com.example.hr" level="DEBUG"/>
        <root level="INFO"><appender-ref ref="CONSOLE"/></root>
    </springProfile>

    <springProfile name="prod">
        <logger name="com.example.hr" level="INFO"/>
        <root level="WARN">
            <appender-ref ref="CONSOLE"/>
            <appender-ref ref="FILE"/>
        </root>
    </springProfile>
</configuration>
```

**확인** (문제 1의 5줄 로그 기준으로 `GET /hello` 호출 시)

- `dev` : `com.example.hr` 가 DEBUG → `debug/info/warn/error` 4줄, 콘솔만.
- `prod` : `com.example.hr` 가 INFO, root WARN → 컨트롤러 로그는 `info/warn/error` 3줄,
  콘솔 + `logs/hr.log` 둘 다. (스프링 내부 INFO 로그들은 root=WARN 이라 대부분 사라져 콘솔이 조용해짐)

## 문제 6. 어떤 레벨로 찍을까

| 상황 | 레벨 | 근거 |
|---|---|---|
| 1. 사원 정상 등록, 새 empId 발급 | `INFO` | 정상 흐름의 이정표. 나중에 "언제 몇 번 사원이 만들어졌나" 추적에 유용 |
| 2. 결제 API 1차 실패 후 재시도 성공 | `WARN` | 최종적으로는 성공했지만 불안정 신호. 반복되면 조치 필요 |
| 3. 커넥션 풀 고갈 → 요청 타임아웃 | `ERROR` | 기능이 실패했고 즉시 조치가 필요 |
| 4. 검색에 사용된 최종 조건 객체 | `DEBUG` | 개발·디버깅용. 운영 기본(INFO)에서는 안 보여야 정상 |
