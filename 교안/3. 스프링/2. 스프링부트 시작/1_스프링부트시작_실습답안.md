## 문제 3. 인사 컨트롤러

`src/main/java/com/example/hr/controller/HelloController.java`:

```java
package com.example.hr.controller;

import org.springframework.web.bind.annotation.GetMapping;
import org.springframework.web.bind.annotation.RequestParam;
import org.springframework.web.bind.annotation.RestController;

@RestController
public class HelloController {

    @GetMapping("/hello")
    public String hello(@RequestParam(defaultValue = "손님") String name) {
        return "안녕하세요, " + name + "님";
    }
}
```

- `GET /hello` → `안녕하세요, 손님님`
- `GET /hello?name=박지민` → `안녕하세요, 박지민님`

`@RequestParam(defaultValue = "손님")` 덕분에 `name` 이 없어도 오류 없이 기본값이 들어갑니다.
(`defaultValue` 를 빼면 `name` 누락 시 400 Bad Request)

## 문제 4. 앱 이름 설정과 확인

`application.yml`:
```yaml
spring:
  application:
    name: hr-system
```

`HelloController` 에 추가:
```java
import org.springframework.beans.factory.annotation.Value;

@RestController
public class HelloController {

    @Value("${spring.application.name}")
    private String appName;

    // ... hello() ...

    @GetMapping("/appname")
    public String appName() {
        return appName;      // → hr-system
    }
}
```

`@Value("${...}")` 는 `application.yml` 의 값을 필드에 주입합니다. 없는 키를 참조하면 기동 실패하므로,
기본값이 필요하면 `@Value("${some.key:기본값}")` 형태로 씁니다.

## 문제 5. 기동 시 메시지 출력

**방법 A — `@Bean` 으로 `CommandLineRunner` 등록** (`HrApplication` 안):

```java
import org.springframework.boot.CommandLineRunner;
import org.springframework.beans.factory.annotation.Value;
import org.springframework.context.annotation.Bean;

@SpringBootApplication
public class HrApplication {

    public static void main(String[] args) {
        SpringApplication.run(HrApplication.class, args);
    }

    @Bean
    CommandLineRunner startupBanner(@Value("${server.port}") String port) {
        return args -> System.out.println(">>> HR 시스템 준비 완료 (포트: " + port + ")");
    }
}
```

**방법 B — 별도 컴포넌트**:

```java
package com.example.hr.config;

import org.springframework.beans.factory.annotation.Value;
import org.springframework.boot.CommandLineRunner;
import org.springframework.stereotype.Component;

@Component
public class StartupBanner implements CommandLineRunner {

    @Value("${server.port}")
    private String port;

    @Override
    public void run(String... args) {
        System.out.println(">>> HR 시스템 준비 완료 (포트: " + port + ")");
    }
}
```

두 방법 모두 컨테이너가 준비되고 톰캣이 요청을 받기 직전에 한 번 실행됩니다.
콘솔 맨 아래에 `>>> HR 시스템 준비 완료 (포트: 8090)` 이 찍힙니다.

> 실무에서는 `System.out` 대신 로거(`log.info(...)`)를 씁니다 — Day 3.

## 문제 6. 컴포넌트 스캔 범위 확인

`HrApplication.java` 를 `com.example.hr.boot` 로 옮기면:

```java
package com.example.hr.boot;   // 패키지 선언도 변경
// 파일 위치: src/main/java/com/example/hr/boot/HrApplication.java
```

1. **`GET /hello` 가 404 로 실패합니다.** (앱은 뜨지만 `HelloController` 가 등록되지 않음)

2. **이유**: `@SpringBootApplication` 에 포함된 `@ComponentScan` 은 **그 클래스가 속한 패키지와
   하위 패키지**만 스캔합니다. `HrApplication` 이 `com.example.hr.boot` 로 내려가면 스캔 기준도
   `com.example.hr.boot` 아래로 좁아지고, `com.example.hr.controller` 는 그 **바깥**이 되어
   `@RestController` 가 빈으로 등록되지 않습니다. 그래서 `/hello` 매핑 자체가 존재하지 않게 됩니다.
   (`@ComponentScan(basePackages = "com.example.hr")` 를 명시하면 다시 잡히지만, 관례를 따르는 게 낫습니다.)

3. 원위치(`src/main/java/com/example/hr/HrApplication.java`, `package com.example.hr;`)로 되돌리면
   다시 정상 동작합니다.
