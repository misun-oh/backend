# Day 2 준비. 빌드 도구 (Gradle / Maven)

| 항목 | 내용 |
|---|---|
| 선수학습 | Java 컴파일·실행(`javac`/`java`), 라이브러리(jar)를 classpath 에 넣어 본 경험 |
| 이번 문서 | 빌드 도구가 무엇이고 왜 쓰는지 → Maven vs Gradle → `build.gradle` 읽는 법 → 의존성 스코프 → Gradle Wrapper → 자주 쓰는 명령 |
| 위치 | 스프링 부트 프로젝트를 만들기 **전에** 읽는다 |
| 개발 환경 | JDK 17, Gradle 8.14.x(Groovy DSL), Spring Boot 4.0.x |

## 학습목표

- "빌드한다"가 구체적으로 무슨 일들인지 설명할 수 있다.
- Maven 과 Gradle 의 차이를 알고, 이 커리큘럼이 왜 Gradle 을 쓰는지 안다.
- `build.gradle` 의 `plugins` / `repositories` / `dependencies` 블록을 읽을 수 있고, `plugins` 의 `id` / `version` 이 뭘 뜻하는지 안다.
- 빌드 설정을 모를 때 **어느 공식 문서**(Gradle User Manual, Spring Boot Gradle Plugin Reference, Maven Central 등)를 봐야 하는지 안다.
- `implementation` · `runtimeOnly` · `compileOnly` · `annotationProcessor` · `testImplementation` 의 차이를 안다.
- 의존성 좌표(`group:artifact:version`)와 **전이 의존성**·**BOM(버전 관리)** 개념을 안다.
- Gradle Wrapper(`gradlew`)가 왜 필요한지 알고, `./gradlew build` / `bootRun` 을 쓸 수 있다.

## 1. "빌드"란 무엇인가

자바 소스 파일(`.java`) 몇 개짜리 연습은 `javac`, `java` 로 충분합니다. 하지만 실제 프로젝트는:

1. 수십~수백 개의 `.java` 를 **컴파일**하고
2. 필요한 **외부 라이브러리(jar)** 수십 개를 **버전 맞춰 내려받아** classpath 에 걸고
3. **테스트**를 돌리고
4. 리소스 파일까지 묶어 **하나의 실행 가능한 jar** 로 **패키징**하고
5. 필요하면 **실행**까지

합니다. 이 과정을 **빌드(build)** 라 하고, 이걸 **자동화**하는 프로그램이 **빌드 도구**입니다.

### 빌드 도구가 없던 시절

라이브러리 jar 를 웹사이트에서 직접 받아 `lib/` 폴더에 넣고, IDE 에서 classpath 를
일일이 지정했습니다. 문제는:

- 그 라이브러리가 **또 다른 라이브러리**를 필요로 함(전이 의존성) → 그것도 손으로 받아야 함
- A 는 `commons-logging 1.1`, B 는 `commons-logging 1.2` 를 요구 → **버전 충돌**
- 새 팀원이 프로젝트를 받으면 "어떤 jar 가 몇 개 필요한지" 아무도 정확히 모름

빌드 도구는 이걸 **선언**으로 바꿉니다: "나는 `spring-boot-starter-webmvc` 가 필요해" 한 줄이면,
그게 필요로 하는 것까지 전부 자동으로 받아 classpath 를 구성합니다.

## 2. Maven vs Gradle

자바 진영의 양대 빌드 도구입니다.

| | Maven | Gradle |
|---|---|---|
| 설정 파일 | `pom.xml` (**XML**) | `build.gradle` (**Groovy** 또는 Kotlin DSL) |
| 스타일 | 관례 강제, 정해진 틀 | 유연, 스크립트로 뭐든 가능 |
| 빌드 속도 | 보통 | 빠름 (증분 빌드·빌드 캐시·데몬) |
| 학습 곡선 | 낮음(틀이 고정) | 중간(DSL·태스크 개념) |
| 현업 | 여전히 많이 씀(특히 오래된 프로젝트) | 신규·안드로이드·스프링 공식 예제 기본 |

**이 커리큘럼은 Gradle(Groovy DSL)** 을 씁니다. `start.spring.io` 기본값이고, 설정이 짧고,
스프링 공식 가이드가 Gradle 위주라 검색이 쉽습니다. Maven 도 개념은 똑같으니, 회사에서
Maven 을 쓰더라도 `pom.xml` 의 `<dependency>` 로 바꿔 읽으면 됩니다.

> **참고 — 같은 의존성, 두 표기**
> ```groovy
> // Gradle
> implementation 'org.mybatis.spring.boot:mybatis-spring-boot-starter:4.0.1'
> ```
> ```xml
> <!-- Maven -->
> <dependency>
>   <groupId>org.mybatis.spring.boot</groupId>
>   <artifactId>mybatis-spring-boot-starter</artifactId>
>   <version>4.0.1</version>
> </dependency>
> ```

## 3. `build.gradle` 읽는 법

우리 프로젝트의 `build.gradle` 을 블록별로 봅니다.

```groovy
plugins {
    id 'java'                                                   // ① 자바 컴파일·jar
    id 'org.springframework.boot' version '4.0.8'               // ② 부트 플러그인 (bootRun, bootJar, 버전 관리)
    id 'io.spring.dependency-management' version '1.1.7'        // ③ 스타터 버전을 자동으로 맞춰줌(BOM)
}

group = 'com.example'                                           // ④ 조직/패키지 성격의 그룹
version = '0.0.1-SNAPSHOT'                                       //    이 프로젝트의 버전

java {
    toolchain { languageVersion = JavaLanguageVersion.of(17) }  // ⑤ 이 프로젝트가 쓸 JDK 버전
}

repositories { mavenCentral() }                                 // ⑥ 라이브러리를 어디서 받나 (중앙 저장소)

dependencies {                                                  // ⑦ 필요한 라이브러리 목록
    implementation 'org.springframework.boot:spring-boot-starter-webmvc'
    runtimeOnly   'com.mysql:mysql-connector-j'
    compileOnly   'org.projectlombok:lombok'
    annotationProcessor 'org.projectlombok:lombok'
    testImplementation 'org.springframework.boot:spring-boot-starter-test'
}

tasks.named('test') { useJUnitPlatform() }                      // ⑧ 테스트는 JUnit(현재 6) 로
```

| 블록 | 역할 |
|---|---|
| `plugins` | 빌드에 기능을 더함. `java`(기본), `org.springframework.boot`(부트 실행·패키징), `io.spring.dependency-management`(스타터 버전 자동) |
| `group` / `version` | 이 프로젝트를 식별하는 좌표. 배포 시 `com.example:hr:0.0.1-SNAPSHOT` |
| `java.toolchain` | 이 프로젝트를 **어느 JDK 로 빌드**할지. 없으면 Gradle 을 실행한 JDK 를 씀 |
| `repositories` | 의존성을 내려받을 서버. `mavenCentral()` 이 사실상 표준 |
| `dependencies` | **핵심.** 필요한 라이브러리를 스코프와 함께 나열 |
| `tasks` | 특정 작업(태스크)의 동작을 조정 |

### 3.1 `plugins { }` 블록 — 무엇을, `id` 는 무슨 뜻인가

**빌드에 기능(태스크·설정)을 더하는 곳**입니다. 플러그인 하나를 넣으면 그에 딸린
**태스크**(`build`, `bootRun`, `test` …)와 **설정 확장**(`java { }`, `springBoot { }` …)이 생깁니다.

```groovy
plugins {
    id 'java'                                        // ← id 만
    id 'org.springframework.boot' version '4.0.8'    // ← id + version
}
```

- **`id`**: 그 플러그인의 **고유 식별자(이름)**. 점 없는 짧은 이름(`java`, `application`)은
  Gradle 에 **내장된 코어 플러그인**이고, 점이 있는 역도메인식 이름
  (`org.springframework.boot`, `io.spring.dependency-management`)은 **외부(커뮤니티) 플러그인**입니다.
- **`version`**: 외부 플러그인은 버전을 적어야 합니다(**어디서 받나** → 아래). 코어 플러그인은
  Gradle 버전에 묶여 있어 `version` 을 안 씁니다.
- **어디서 받나**: 외부 플러그인은 **Gradle Plugin Portal**([plugins.gradle.org](https://plugins.gradle.org))
  에서 받습니다. `settings.gradle` 에 따로 안 적어도 기본으로 이 저장소를 봅니다.
- **옛날 방식**: 예전 예제의 `apply plugin: 'java'` 는 구식입니다. 지금은 **`plugins { }` 블록**을
  `build.gradle` 맨 위에 씁니다.

**우리 3개 플러그인이 하는 일**

| 플러그인 `id` | 종류 | 넣으면 생기는 것 |
|---|---|---|
| `java` | 코어 | `compileJava`·`test`·`jar` 태스크, `src/main/java` 관례, `implementation` 등 의존성 스코프 |
| `org.springframework.boot` | 외부 | `bootRun`(앱 실행)·`bootJar`(실행 가능 jar) 태스크, `@SpringBootApplication` 메인 클래스 자동 탐지, 스프링 의존성 **버전 세트(BOM) 적용** |
| `io.spring.dependency-management` | 외부 | `dependencies` 에서 **버전을 생략**해도 BOM 이 정한 버전으로 채워줌. (부트 플러그인과 짝) |

> 스프링 부트 플러그인의 정확한 태스크·확장 목록은 그 플러그인의 **레퍼런스 문서**에 있습니다(8절).

### 3.2 의존성 좌표: `group:artifact:version`

```
org.springframework.boot : spring-boot-starter-webmvc : 4.0.8
└─ group(누가) ──────────┘ └─ artifact(무엇) ─────────┘ └ version
```

- **starter**: 스프링 부트가 만든 "묶음". `spring-boot-starter-webmvc` 하나면 톰캣·Spring MVC·Jackson 이 함께 딸려옵니다(검증 `validation` 은 4.0부터 별도 스타터). 필요한 것을 하나하나 안 적어도 됨.
- **버전을 왜 생략하나**: `org.springframework.boot` 플러그인이 **BOM(Bill of Materials)** 으로 스타터들의 궁합 맞는 버전을 이미 정해뒀기 때문입니다. 그래서 스타터엔 버전을 안 씁니다. 반대로 **부트가 관리 안 하는 라이브러리**(예: `mybatis-spring-boot-starter`)는 **버전을 직접** 적어야 합니다.

### 3.3 전이 의존성 (transitive)

```
spring-boot-starter-webmvc
 ├── spring-boot-starter (자동)
 ├── spring-web, spring-webmvc (자동)
 ├── tomcat-embed-core (자동)
 └── jackson-databind (자동, Jackson 3)
```

`starter-webmvc` 한 줄로 위가 전부 따라옵니다. `./gradlew dependencies` 로 트리를 볼 수 있습니다.

## 4. 의존성 스코프(configuration)

"이 라이브러리를 **언제** 쓸 수 있게 할지"를 정합니다. 잘못 고르면 필요 없는 게 배포본에
섞이거나, 컴파일이 안 됩니다.

| 스코프 | 컴파일 시 | 실행 시 | 테스트 시 | 예 |
|---|---|---|---|---|
| `implementation` | O | O | O | 대부분의 라이브러리 (`starter-webmvc`, `starter-thymeleaf`) |
| `runtimeOnly` | ✕ | O | O | 코드에서 직접 import 안 하고 런타임에만 필요. **JDBC 드라이버**(`mysql-connector-j`) |
| `compileOnly` | O | ✕ | ✕ | 컴파일에만 필요, 배포엔 불필요. **Lombok** |
| `annotationProcessor` | (컴파일 중 코드 생성) | ✕ | ✕ | Lombok, MapStruct 등 **애노테이션 처리기** |
| `developmentOnly` | O | 로컬 실행만 | | **DevTools** (배포 jar 에는 안 들어감) |
| `testImplementation` | ✕ | ✕ | O | `starter-test`, `spring-security-test` |

> **Lombok 이 `compileOnly` + `annotationProcessor` 둘 다인 이유**: `@Getter` 같은 애노테이션을
> 컴파일 시점에 읽어(`compileOnly`) 실제 메서드 코드를 생성(`annotationProcessor`)합니다. 생성이
> 끝나면 Lombok 자체는 런타임에 필요 없습니다.

## 5. Gradle Wrapper (`gradlew`)

프로젝트를 받으면 보이는 `gradlew`, `gradlew.bat`, `gradle/wrapper/` — 이게 **래퍼**입니다.

### 왜 필요한가

- 팀원 A 는 Gradle 8.5, B 는 9.0 이 깔려 있으면 **빌드 결과가 달라지거나 깨집니다**.
- 래퍼는 **"이 프로젝트는 Gradle 8.14.3 로 빌드한다"** 를 파일에 박아둡니다.
- `./gradlew build` 를 처음 실행하면 그 버전을 **자동으로 내려받아** 사용합니다. Gradle 을
  따로 설치할 필요조차 없습니다.

### 구성 파일

```
gradle/wrapper/gradle-wrapper.properties   ← 어떤 Gradle 버전인지
gradle/wrapper/gradle-wrapper.jar          ← 래퍼 실행 코드
gradlew                                    ← macOS/Linux 실행 스크립트
gradlew.bat                                ← Windows 실행 스크립트
```

`gradle-wrapper.properties`:
```
distributionUrl=https\://services.gradle.org/distributions/gradle-8.14.3-bin.zip
```

> **이 4개는 반드시 Git 에 커밋**합니다. `.gitignore` 에 `build/`, `.gradle/` 는 넣되
> `gradle/wrapper/` 와 `gradlew*` 는 **제외하지 않습니다.**

### 실행은 항상 래퍼로

| 하지 말 것 | 대신 |
|---|---|
| `gradle build` (로컬에 깔린 Gradle) | `./gradlew build` (Windows: `gradlew build`) |

## 6. 자주 쓰는 Gradle 명령

프로젝트 루트에서:

| 명령 | 하는 일 |
|---|---|
| `./gradlew build` | 컴파일 + 테스트 + jar 패키징 (전체) |
| `./gradlew bootRun` | 스프링 부트 앱 실행 (개발 중) |
| `./gradlew test` | 테스트만 실행 |
| `./gradlew clean` | `build/` 폴더 삭제 (깨끗이 다시 빌드할 때) |
| `./gradlew build -x test` | 테스트를 건너뛰고 빌드 |
| `./gradlew dependencies` | 의존성 트리 출력 (버전 충돌 확인) |
| `./gradlew bootJar` | 실행 가능한 fat jar 생성 → `build/libs/hr-0.0.1-SNAPSHOT.jar` |

만들어진 jar 는 `java -jar build/libs/hr-0.0.1-SNAPSHOT.jar` 로 바로 실행됩니다(내장 톰캣 포함).

## 7. 표준 디렉터리 구조

Maven·Gradle 이 공유하는 관례입니다. 이 위치에 두면 설정 없이 인식됩니다.

```
프로젝트/
├── build.gradle          빌드 설정
├── settings.gradle       프로젝트 이름 (rootProject.name = 'hr')
├── gradlew, gradlew.bat  래퍼 스크립트
├── gradle/wrapper/       래퍼 파일
├── src/
│   ├── main/
│   │   ├── java/         프로덕션 코드
│   │   └── resources/    application.yml, static/, templates/, mapper/*.xml
│   └── test/
│       └── java/         테스트 코드
└── build/                빌드 산출물 (Git 제외, clean 대상)
```

## 8. 어디서 찾아봐야 하나 (공식 문서)

빌드 설정은 외울 게 아니라 **어느 문서를 볼지**를 아는 게 중요합니다.

| 알고 싶은 것 | 참조할 곳 | URL |
|---|---|---|
| Gradle 문법 전반 (`plugins`·`dependencies`·`repositories`·태스크·configuration) | **Gradle User Manual** | docs.gradle.org/current/userguide/userguide.html |
| 의존성 스코프(`implementation` vs `api` vs `runtimeOnly` …) | Gradle - *Java Library Plugin* / *Declaring dependencies* | docs.gradle.org/current/userguide/java_library_plugin.html |
| 외부 **플러그인 검색** (id·최신 버전·적용법) | **Gradle Plugin Portal** | [plugins.gradle.org](https://plugins.gradle.org) |
| `org.springframework.boot` 플러그인이 주는 태스크·확장(`bootRun`·`bootJar`·`springBoot {}`) | **Spring Boot Gradle Plugin Reference** | docs.spring.io/spring-boot/gradle-plugin/ (또는 `/maven-plugin/`) |
| 스프링 부트가 **관리하는 라이브러리 버전 목록**(BOM) | Spring Boot Docs - *Dependency Versions* | docs.spring.io/spring-boot/appendix/dependency-versions/ |
| 스프링 부트가 **지원하는 JDK·Gradle·Maven 버전** | Spring Boot Docs - *System Requirements* | docs.spring.io/spring-boot/system-requirements.html |
| 어떤 스타터가 뭘 담고 있나 | Spring Boot Docs - *Starters* | docs.spring.io/spring-boot/reference/using/build-systems.html#using.build-systems.starters |
| `io.spring.dependency-management` 플러그인 사용법 | 플러그인 GitHub README | github.com/spring-io/dependency-management-plugin |
| **특정 라이브러리의 좌표·버전**(`group:artifact:version`) | **Maven Central** / mvnrepository | [central.sonatype.com](https://central.sonatype.com) · [mvnrepository.com](https://mvnrepository.com) |
| MyBatis 스타터 버전·설정 | MyBatis-Spring-Boot-Starter 문서 | mybatis.org/spring-boot-starter/mybatis-spring-boot-autoconfigure/ |
| Spring Boot ↔ 서드파티(부트 버전별 호환) | 각 라이브러리의 릴리스 노트 / 위 System Requirements | – |

> **찾는 순서 예시** — "MyBatis 를 붙이고 싶다":
> 1. `mybatis-spring-boot-starter` 를 **mvnrepository** 에서 검색 → 최신 좌표·버전 확인
> 2. **Spring Boot System Requirements / 스타터 문서**에서 우리 부트 버전(4.0.x)과 호환되는 라인 확인 (MyBatis 스타터는 `4.0.1`)
> 3. `build.gradle` 의 `dependencies` 에 `implementation 'group:artifact:version'` 추가
> 4. `./gradlew dependencies` 로 실제로 잘 들어왔는지·버전 충돌 없는지 확인

---

## 자주 하는 실수

- **`gradle` 로 실행** → 로컬에 깔린 버전이 프로젝트 지정 버전과 달라 오류. 항상 `./gradlew`.
- **스타터에 버전을 붙임** (`spring-boot-starter-webmvc:4.0.8`) → 부트 BOM 이 관리하므로 **버전 생략**이 정석. 반대로 MyBatis 스타터처럼 부트가 관리 안 하는 건 **버전 필수**.
- **JDBC 드라이버를 `implementation` 으로** → 동작은 하지만, 코드에서 import 하지 않으므로 `runtimeOnly` 가 맞습니다.
- **Lombok 에 `annotationProcessor` 를 빠뜨림** → `@Getter` 등이 코드 생성이 안 돼 "메서드를 찾을 수 없음" 컴파일 오류.
- **`build/`, `.gradle/` 를 Git 에 커밋** → 용량 낭비·충돌. `.gitignore` 에 넣되 `gradlew`·`gradle/wrapper/` 는 **커밋**.
- **의존성 추가 후 IDE 가 인식 못 함** → IDE 의 "Gradle 새로고침/reimport" 를 눌러야 반영됩니다.
- **회사·학원 네트워크에서 의존성 다운로드 실패** → 프록시 설정(`~/.gradle/gradle.properties` 의 `systemProp.http.proxyHost` 등) 또는 사내 Nexus 저장소를 `repositories` 에 추가.

## 핵심 요약

| 항목 | 핵심 |
|---|---|
| 빌드 도구 | 컴파일·의존성·테스트·패키징을 **선언적으로 자동화**. 전이 의존성·버전 충돌을 대신 해결 |
| Maven vs Gradle | `pom.xml`(XML) vs `build.gradle`(Groovy). 커리큘럼은 **Gradle** |
| `plugins` | 빌드에 기능을 더하는 곳. `id`=플러그인 이름(점 없음=코어, 점 있음=외부+`version` 필요, [plugins.gradle.org](https://plugins.gradle.org) 에서). `java`·`org.springframework.boot`·`io.spring.dependency-management` |
| 의존성 좌표 | `group:artifact:version`. 스타터는 **버전 생략**(BOM), 그 외는 **버전 명시**. 좌표 검색은 mvnrepository / Maven Central |
| 문서 | Gradle 문법=Gradle User Manual, 부트 플러그인=Spring Boot Gradle Plugin Reference, 관리 버전=Dependency Versions, 호환 버전=System Requirements (8절 표) |
| 스코프 | `implementation`(기본) / `runtimeOnly`(드라이버) / `compileOnly`+`annotationProcessor`(Lombok) / `developmentOnly`(DevTools) / `testImplementation` |
| Gradle Wrapper | 프로젝트에 Gradle 버전을 박제. **항상 `./gradlew`** 로 실행. `gradlew*`·`gradle/wrapper/` 는 Git 커밋 |
| 자주 쓰는 명령 | `build` / `bootRun` / `test` / `clean` / `dependencies` / `bootJar` / `-x test` |
