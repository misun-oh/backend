# Day 16. 파일 업로드와 다운로드 — 심화 (경험자용)

## 1. 오브젝트 스토리지(S3 등)

로컬 파일시스템은 서버가 여러 대면 공유가 안 됨(A서버에 올린 걸 B서버가 못 봄).

- S3/MinIO/GCS: `software.amazon.awssdk:s3` 또는 `spring-cloud-aws`.
- **Presigned URL**: 업로드/다운로드를 서버를 안 거치고 클라이언트 ↔ 스토리지 직접. 서버는 URL만 발급.
  대용량·트래픽에 유리. 다운로드 권한은 URL 만료 시간으로.
- 메타는 여전히 DB. `PATH` 대신 `BUCKET` + `KEY`.

## 2. 대용량 / 스트리밍 업로드

- `MultipartFile.transferTo()` 는 전체를 다룸. 초대용량은 `InputStream` 을 청크로 읽어 스토리지로 파이프.
- `spring.servlet.multipart.file-size-threshold` : 이 크기 이하는 메모리, 초과는 임시파일.
- 분할 업로드(resumable): 프론트가 청크로 쪼개 보내고 서버가 조립(tus 프로토콜 등). 실무 대용량.

## 3. 이미지 처리

- 썸네일/리사이즈: `imgscalr`, `thumbnailator`, 또는 `ImageIO` + `Graphics2D`.
- EXIF에 위치정보·회전값 → 스트립(개인정보) + orientation 보정.
- 업로드 즉시 처리하면 응답 지연 → 비동기(`@Async` / 메시지 큐)로 원본 저장 후 백그라운드 변환.
- 재인코딩(다시 저장)하면 삽입된 악성 페이로드 대부분 제거됨(폴리글롯 파일 방어).

## 4. 보안 체크리스트

- 저장 파일명은 서버 생성(UUID). 원본명은 표시·다운로드용으로만 DB에.
- 저장 디렉터리에 **실행 권한 제거**, 웹 루트 밖. `X-Content-Type-Options: nosniff`.
- SVG 업로드 허용 시 XSS(스크립트 포함) — 허용 안 하거나 sanitize.
- 다운로드 시 `Content-Type` 을 신뢰하지 말고 화이트리스트 매핑, 미지정은 `octet-stream`.
- ZIP 폭탄·경로 포함 ZIP(zip slip) — 압축 해제 시 엔트리 경로 검증.
- 업로더/소유자 검증(다른 사원의 문서를 attId만 바꿔 다운로드 못 하게).

## 5. 트랜잭션과 파일

파일 저장은 DB 트랜잭션에 참여하지 않는다.
- INSERT 성공 + 파일 저장 실패 → DB엔 메타, 파일 없음(깨진 링크). 순서: **파일 먼저 저장 → DB INSERT**,
  DB 실패 시 방금 저장한 파일 삭제(보상).
- DELETE: DB row 삭제(트랜잭션) **커밋 후** 파일 삭제 — `@TransactionalEventListener(AFTER_COMMIT)`.
  삭제 실패는 로그 + 배치로 고아 파일 청소(스토리지 목록 vs DB 대조).

## 6. 다운로드 성능

- `UrlResource`/`FileSystemResource` 는 스프링이 `sendfile`(제로카피) 활용 가능(톰캣).
- Range 요청(이어받기·비디오 스트리밍): `ResourceRegion` 또는 `ResourceHttpRequestHandler` 가 자동 처리.
- CDN 앞단: `Cache-Control`, `ETag`(파일 해시), `Last-Modified`.

## 7. 테스트

> `@WebMvcTest` 면 `MockMvc` 자동. `@SpringBootTest` 로 `MockMvc` 를 쓸 땐 Boot 4에서
> `@AutoConfigureMockMvc` 를 함께 붙입니다.

```java
@Test
void 사진_업로드() throws Exception {
    MockMultipartFile file = new MockMultipartFile(
        "file", "profile.png", "image/png", "fake-bytes".getBytes());
    mvc.perform(multipart("/emps/205/photo").file(file))
       .andExpect(status().is3xxRedirection());
}

@Test
void 위험한_확장자_거부() throws Exception {
    MockMultipartFile bad = new MockMultipartFile("file", "run.sh", "text/plain", "x".getBytes());
    mvc.perform(multipart("/emps/205/photo").file(bad))
       .andExpect(status().isBadRequest());
}
```
저장 로직은 `@TempDir`(JUnit) 를 baseDir로 주입해 실제 파일시스템 없이 격리.

## 8. `@ConfigurationProperties` 검증

```java
@ConfigurationProperties(prefix = "hr.file")
@Validated
public record FileProps(@NotBlank String baseDir,
                        @Positive long maxImageSize,
                        @NotEmpty List<String> allowedImageExt) {}
```
잘못된 설정으로 뜨는 걸 기동 시점에 실패시킨다.
