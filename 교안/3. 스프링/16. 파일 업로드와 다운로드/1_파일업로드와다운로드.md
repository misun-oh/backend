# Day 16. 파일 업로드와 다운로드

| 항목 | 내용 |
|---|---|
| 선수학습 | `Java 6.파일입출력`(`Files`·스트림·`FileUploadExample`), Day 7~8(폼), Day 14(검증) |
| 이번 챕터 | `multipart/form-data` → `MultipartFile` → 저장 전략(UUID 리네임·경로 분리·DB엔 메타만) → 이미지 표시 → `ResponseEntity<Resource>` 다운로드(한글 파일명) → 확장자·용량 검증 |
| 권장 진행 | 1일 |
| 결과물 | 사원 프로필 사진 업로드/표시, 첨부파일 등록/다운로드. `ATTACHMENT` 테이블 |

## 학습목표

- `enctype="multipart/form-data"` 폼과 `MultipartFile` 파라미터로 파일을 받는다.
- 원본 파일명을 그대로 쓰면 안 되는 이유를 알고 **UUID 리네임 + 경로 분리 + DB엔 메타데이터만** 저장한다.
- `spring.servlet.multipart.*` 로 업로드 크기 상한을 설정한다.
- 업로드된 이미지를 화면에 표시하고, `ResponseEntity<Resource>` 로 다운로드(한글 파일명 인코딩)한다.
- 확장자 화이트리스트·MIME·용량·빈 파일을 검증한다.

## 1. 업로드 기본

폼:
```html
<form th:action="@{/emps/{id}/photo(id=${emp.empId})}" method="post" enctype="multipart/form-data">
  <input type="file" name="file" accept="image/png, image/jpeg">
  <button type="submit">사진 업로드</button>
</form>
```
- **`enctype="multipart/form-data"` 필수.** 없으면 파일이 전송되지 않고 파일명만 텍스트로 옴.

컨트롤러:
```java
@PostMapping("/emps/{id}/photo")
public String uploadPhoto(@PathVariable Long id, @RequestParam("file") MultipartFile file) {
    fileService.saveEmpPhoto(id, file);
    return "redirect:/emps/" + id;
}
```
- 여러 개: `@RequestParam("files") List<MultipartFile> files` 또는 `MultipartFile[]`.
- 폼의 다른 필드와 함께: `@ModelAttribute EmpForm form, @RequestParam MultipartFile file`.
- REST(JSON+파일)는 `@RequestPart`.

설정:
```yaml
spring:
  servlet:
    multipart:
      max-file-size: 5MB          # 파일 하나
      max-request-size: 20MB      # 요청 전체
```
초과 시 `MaxUploadSizeExceededException` → Day 14의 advice에서 사용자 메시지로.

## 2. 저장 전략

원본 파일명(`내 이력서(최종).pdf`, `../../etc/passwd`)을 그대로 저장 경로에 쓰면:
- **경로 조작**(`..` 로 상위 디렉터리 탈출), **중복 덮어쓰기**, **한글·특수문자·길이** 문제.

원칙:

| | 방법 |
|---|---|
| 저장 파일명 | **UUID** + 확장자. `9f8e...c1.png` |
| 저장 위치 | **프로젝트 밖** 디렉터리. `application.yml` 로 경로 주입 |
| DB | 파일 자체가 아니라 **메타데이터**만: `원본명, 저장명, 크기, 콘텐츠타입, 경로, 업로더, 시각` |
| 하위 폴더 | 날짜(`2026/08/28/`)나 해시 앞 2글자로 나눠 한 폴더에 파일이 몰리지 않게 |

```java
// config
@ConfigurationProperties(prefix = "hr.file")
public record FileProps(String baseDir) {}
```
```yaml
hr:
  file:
    base-dir: ${user.home}/hr-uploads
```

```java
@Service
@RequiredArgsConstructor
public class FileStorage {

    private final FileProps props;

    public StoredFile store(MultipartFile file) {
        String ext = extensionOf(file.getOriginalFilename());          // ".png"
        String storedName = UUID.randomUUID() + ext;
        LocalDate today = LocalDate.now();
        Path dir = Path.of(props.baseDir(), String.valueOf(today.getYear()),
                String.format("%02d", today.getMonthValue()));
        Files.createDirectories(dir);
        Path target = dir.resolve(storedName).normalize();
        if (!target.startsWith(Path.of(props.baseDir()))) {            // 경로 탈출 방어
            throw new IllegalArgumentException("잘못된 경로");
        }
        file.transferTo(target);
        return new StoredFile(file.getOriginalFilename(), storedName,
                target.toString(), file.getSize(), file.getContentType());
    }
}
```

`StoredFile`(원본명·저장명·경로·크기·타입)을 `ATTACHMENT` 테이블에 INSERT.

```sql
CREATE TABLE ATTACHMENT (
  ATT_ID       BIGINT AUTO_INCREMENT PRIMARY KEY,
  REF_TYPE     VARCHAR(20)  NOT NULL,     -- 'EMP_PHOTO', 'EMP_DOC'
  REF_ID       BIGINT       NOT NULL,     -- EMP_ID
  ORIGIN_NAME  VARCHAR(255) NOT NULL,
  STORED_NAME  VARCHAR(100) NOT NULL,
  PATH         VARCHAR(500) NOT NULL,
  SIZE_BYTES   BIGINT       NOT NULL,
  CONTENT_TYPE VARCHAR(100),
  CREATED_AT   DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP
);
```

## 3. 검증

```java
private static final Set<String> ALLOWED_IMAGE = Set.of("png", "jpg", "jpeg", "webp");

public void validateImage(MultipartFile file) {
    if (file == null || file.isEmpty())
        throw new BusinessException("FILE_EMPTY", "파일을 선택하세요");
    String ext = extensionOf(file.getOriginalFilename()).replace(".", "").toLowerCase();
    if (!ALLOWED_IMAGE.contains(ext))
        throw new BusinessException("FILE_EXT", "이미지 파일(png/jpg/webp)만 업로드할 수 있습니다");
    String ct = file.getContentType();
    if (ct == null || !ct.startsWith("image/"))
        throw new BusinessException("FILE_TYPE", "이미지 파일이 아닙니다");
    if (file.getSize() > 5 * 1024 * 1024)
        throw new BusinessException("FILE_SIZE", "5MB 이하만 가능합니다");
}
```

- 확장자·`Content-Type` 은 **둘 다** 확인(둘 다 위조 가능하나, 함께 보면 실수는 대부분 걸림).
- 진짜 안전이 필요하면 파일 시그니처(매직 바이트) 검사, 이미지 재인코딩(ImageIO), 별도 스토리지·바이러스 스캔.

## 4. 이미지 표시

### 방법 A — 정적 리소스 핸들러로 매핑
```java
@Configuration
public class WebConfig implements WebMvcConfigurer {
    private final FileProps props;
    public void addResourceHandlers(ResourceHandlerRegistry r) {
        r.addResourceHandler("/uploads/**")
         .addResourceLocations("file:" + props.baseDir() + "/");
    }
}
```
`<img th:src="@{/uploads/2026/08/{name}(name=${att.storedName})}">`

### 방법 B — 컨트롤러에서 스트리밍 (권한 체크 가능)
```java
@GetMapping("/files/{attId}/view")
public ResponseEntity<Resource> view(@PathVariable Long attId) {
    Attachment att = attachmentService.get(attId);
    Resource res = new FileSystemResource(att.getPath());
    return ResponseEntity.ok()
            .contentType(MediaType.parseMediaType(att.getContentType()))
            .body(res);
}
```
"로그인한 담당자만 볼 수 있는 문서"라면 B(중간에 권한 검사).

## 5. 다운로드 — `ResponseEntity<Resource>` + 한글 파일명

```java
@GetMapping("/files/{attId}/download")
public ResponseEntity<Resource> download(@PathVariable Long attId) throws IOException {
    Attachment att = attachmentService.get(attId);
    Path path = Path.of(att.getPath());
    Resource resource = new UrlResource(path.toUri());
    if (!resource.exists() || !resource.isReadable())
        throw new NoSuchElementException("파일 없음");

    String encoded = URLEncoder.encode(att.getOriginName(), StandardCharsets.UTF_8)
            .replaceAll("\\+", "%20");     // 공백 처리

    return ResponseEntity.ok()
            .contentType(MediaType.APPLICATION_OCTET_STREAM)
            .header(HttpHeaders.CONTENT_DISPOSITION,
                    "attachment; filename=\"" + encoded + "\"; filename*=UTF-8''" + encoded)
            .contentLength(att.getSizeBytes())
            .body(resource);
}
```

- `Content-Disposition: attachment` → 브라우저가 "저장"하도록.
- 한글 파일명은 `filename*=UTF-8''<percent-encoded>` (RFC 5987). `filename="..."` 는 구형 대비용.
- `application/octet-stream` 이면 무조건 다운로드. 이미지 미리보기는 4-B처럼 원본 타입.

## 자주 하는 실수

- **`enctype` 누락** → 파일이 안 옴. `multipart/form-data`.
- **원본 파일명으로 저장** → 경로 조작·덮어쓰기·인코딩 문제. UUID + `normalize()` + baseDir 검사.
- **파일을 DB(BLOB)에 통째 저장** → DB 비대·백업·성능. 파일은 파일시스템/오브젝트스토리지, DB엔 메타.
- **업로드 경로가 `src/main/resources` / 프로젝트 내부** → 재배포 시 사라지고 빌드에 포함됨. 프로젝트 밖.
- **`max-file-size` 만 키우고 리버스 프록시 한계 그대로** → Nginx `client_max_body_size` 등도 조정.
- **다운로드 한글 파일명 깨짐** → `filename*=UTF-8''` 인코딩.
- **`transferTo` 후 임시파일 안 지움** → 톰캣이 관리하지만, 커스텀 임시 저장은 직접 정리.
- **삭제 시 DB row만 지우고 파일은 방치** → 고아 파일. 트랜잭션 커밋 후 파일 삭제(실패 시 배치로 청소).
