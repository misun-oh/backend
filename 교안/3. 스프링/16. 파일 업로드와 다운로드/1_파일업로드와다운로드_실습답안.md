## 문제 2. 저장 서비스

```java
@Service
@RequiredArgsConstructor
public class FileStorage {

    private final FileProps props;

    public StoredFile store(MultipartFile file) {
        try {
            String origin = file.getOriginalFilename();
            String ext = extensionOf(origin);                       // ".png"
            String storedName = UUID.randomUUID() + ext;

            LocalDate d = LocalDate.now();
            Path dir = Path.of(props.baseDir(),
                    String.valueOf(d.getYear()),
                    String.format("%02d", d.getMonthValue()));
            Files.createDirectories(dir);

            Path base = Path.of(props.baseDir()).toAbsolutePath().normalize();
            Path target = dir.resolve(storedName).toAbsolutePath().normalize();
            if (!target.startsWith(base)) {
                throw new IllegalArgumentException("잘못된 저장 경로");
            }

            file.transferTo(target);
            return new StoredFile(origin, storedName, target.toString(),
                    file.getSize(), file.getContentType());
        } catch (IOException e) {
            throw new RuntimeException("파일 저장 실패", e);
        }
    }

    private String extensionOf(String name) {
        if (name == null) return "";
        int i = name.lastIndexOf('.');
        return (i >= 0) ? name.substring(i).toLowerCase() : "";
    }
}

public record StoredFile(String originName, String storedName, String path,
                         long size, String contentType) {}
```

## 문제 3. 사원 사진 업로드

```java
@PostMapping("/emps/{id}/photo")
public String uploadPhoto(@PathVariable Long id, @RequestParam("file") MultipartFile file,
                          RedirectAttributes ra) {
    if (file.isEmpty())
        throw new BusinessException("FILE_EMPTY", "파일을 선택하세요");
    String ext = ext(file.getOriginalFilename());
    if (!Set.of("png","jpg","jpeg","webp").contains(ext))
        throw new BusinessException("FILE_EXT", "이미지 파일만 업로드할 수 있습니다");
    if (file.getSize() > 5L * 1024 * 1024)
        throw new BusinessException("FILE_SIZE", "5MB 이하만 가능합니다");

    StoredFile sf = fileStorage.store(file);
    attachmentService.save("EMP_PHOTO", id, sf);
    ra.addFlashAttribute("message", "사진이 등록되었습니다");
    return "redirect:/emps/" + id;
}
```

## 문제 4. 첨부 다운로드

```java
@GetMapping("/files/{attId}/download")
public ResponseEntity<Resource> download(@PathVariable Long attId) throws IOException {
    Attachment att = attachmentService.get(attId);     // 없으면 NoSuchElementException → 404 (advice)
    Path path = Path.of(att.getPath());
    Resource resource = new UrlResource(path.toUri());
    if (!resource.exists() || !resource.isReadable())
        throw new NoSuchElementException("파일 없음");

    String enc = URLEncoder.encode(att.getOriginName(), StandardCharsets.UTF_8)
            .replaceAll("\\+", "%20");

    return ResponseEntity.ok()
            .contentType(MediaType.APPLICATION_OCTET_STREAM)
            .header(HttpHeaders.CONTENT_DISPOSITION,
                    "attachment; filename=\"" + enc + "\"; filename*=UTF-8''" + enc)
            .contentLength(att.getSizeBytes())
            .body(resource);
}
```

`한글 이름.png` 업로드 → 저장 파일명은 `3f...c2.png`(UUID)지만, 다운로드 시
`Content-Disposition` 의 `filename*` 덕분에 브라우저가 **`한글 이름.png`** 로 저장한다.

## 문제 6. 이 저장 코드의 위험

```java
Path target = Path.of(baseDir, file.getOriginalFilename());
file.transferTo(target);
```

1. `../../../home/app/.ssh/authorized_keys` → `Path.of(baseDir, "../../...")` 가
   **baseDir 밖으로 탈출**해 시스템 파일을 덮어쓸 수 있다(경로 조작, 원격 코드 실행급 취약점).
2. `report.pdf` → 같은 이름이 이미 있으면 **말없이 덮어쓴다**(다른 사용자 파일 손실).
3. 아주 긴 한글/공백/괄호 이름 → 파일시스템 길이 제한 초과, 인코딩·셸 처리 문제, URL에서 깨짐.

**고침**
- 저장 파일명 = `UUID + 확장자` (서버 생성). 원본명은 DB `ORIGIN_NAME` 에만.
- `target.normalize()` 후 `target.startsWith(baseDir)` 검사.
- baseDir은 프로젝트/웹루트 밖, 실행 권한 없는 디렉터리.
- 확장자는 화이트리스트로 제한.
→ 문제 2의 `FileStorage.store()` 형태.
