## 학습목표

- `@Controller`가 **뷰 이름**을 돌려주면 화면(HTML)이 렌더링된다는 것을 안다.
- Thymeleaf 자동 구성 덕분에 **설정 파일 한 줄 없이** 뷰 이름 `"greeting"` → `templates/greeting.html` 로 찾아간다는 것을 안다.
- 컨트롤러를 작성하는 절차(클래스 애노테이션 → 메서드 매핑 → 파라미터 바인딩 → 반환값)를 설명하고,
  지금까지 배운 애노테이션(`@Controller`/`@GetMapping`/`@PostMapping`/`@RequestParam`/`@PathVariable`/`@ModelAttribute`/`@RequestBody`)을
  표로 구분해 쓸 수 있다.
- `@RequestParam` 의 `required`/`defaultValue` 로 필수 여부를 다루고, 문자열·숫자·날짜(`LocalDate`
  + `@DateTimeFormat`)를 각각 알맞은 타입으로 받을 수 있다. 값이 여러 개면 쿼리스트링·폼은
  `@ModelAttribute`, JSON 요청 본문은 `@RequestBody` 로 객체 하나에 한 번에 받을 수 있다.
- `@PathVariable` 로 URL 경로 값을 이름 매칭·여러 개로 받을 수 있다.
- `@RestController` + `@GetMapping`으로 첫 요청(문자열·JSON)을 처리할 수 있고, `@Controller`와
  무엇이 다른지 설명할 수 있다.
- `@Value("${키}")`로 `application.yml`/`.properties`에 적어 둔 설정값을 필드에 주입받을 수 있고,
  기본값 문법(`${키:기본값}`)과 기본값 없이 없는 키를 참조하면 **기동 자체가 실패**하는 이유를
  설명할 수 있다.

## 1. 화면(HTML)을 돌려주는 컨트롤러 — `@Controller`

컨트롤러(Controller)는 브라우저의 요청을 받아 처리하고 응답을 돌려주는 역할을 합니다. 가장 먼저
익힐 형태는 **화면(HTML)을 그려주는 컨트롤러**입니다 — 우리가 웹이라 하면 흔히 떠올리는 모습이죠.

클래스에 `@Controller` 를 붙이면, 그 안의 메서드가 **반환하는 문자열을 "뷰 이름"으로 해석**합니다.
스프링이 그 이름으로 `src/main/resources/templates/` 아래 HTML 을 찾아 렌더링해서 응답합니다.

```java
package com.example.hr.controller;

import org.springframework.stereotype.Controller;
import org.springframework.web.bind.annotation.GetMapping;

@Controller                                       // 반환 문자열을 "뷰 이름"으로 해석
public class HomeController {

    // "/greeting" → templates/greeting.html 을 찾아 렌더링
    @GetMapping("/greeting")
    public String greeting() {
        return "greeting";
    }
}
```

> 이 컨트롤러에 Day 1 설계 화면 주소(`/`, `/emps`, `/emps/{id}`, `/depts` …)를 실제로 채우는 것은
> hr 프로토타입을 붙이는 **2. 프로토타입/1. 프로토타입.md** 에서 이어집니다.

`src/main/resources/templates/greeting.html` (Thymeleaf 엔진이 읽지만, 지금은 순수 HTML 로 충분):

```html
<!DOCTYPE html>
<html lang="ko">
<head><meta charset="UTF-8"><title>인사</title></head>
<body>
  <h1>HR 시스템</h1>
  <p><a href="/hr/index.html">사원 목록으로</a></p>
</body>
</html>
```

- `http://localhost:8080/greeting` → 위 HTML 화면.
- 값을 화면에 꽂아 넣는 `Model` 과 `th:text`·`th:each` 같은 Thymeleaf 문법은 **Day 6~10**.
  오늘은 "**`@Controller` 는 뷰 이름을 돌려준다**" 만 확실히 잡습니다.

### 1.1 `"greeting"` 이 어떻게 `templates/greeting.html` 이 되나 — 자동 구성

`application.yml` 에 뷰 관련 설정을 **한 줄도 안 썼는데** 뷰 이름이 알아서 파일을 찾아갑니다.
`build.gradle` 에 `spring-boot-starter-thymeleaf` 가 있으면, `1_스프링부트시작.md` 4절에서 본
**자동 구성(`@EnableAutoConfiguration`)** 이 클래스패스에서 Thymeleaf 를 발견하고
`ThymeleafViewResolver`(뷰 이름 → 실제 파일을 찾는 담당)를 **기본값으로 등록**해 주기 때문입니다.

| 기본값 (프로퍼티) | 값 | 의미 |
|---|---|---|
| `spring.thymeleaf.prefix` | `classpath:/templates/` | 뷰 이름 앞에 붙는 경로 |
| `spring.thymeleaf.suffix` | `.html` | 뷰 이름 뒤에 붙는 확장자 |
| `spring.thymeleaf.cache` | `false` (개발), `true` (운영) | 템플릿 캐시 |
| `spring.thymeleaf.encoding` | `UTF-8` | 인코딩 |

그래서 `return "greeting"` 은 **`classpath:/templates/` + `greeting` + `.html`** =
`src/main/resources/templates/greeting.html` 로 조립됩니다. `return "hr/index"` 면
`templates/hr/index.html`. **디렉터리도 뷰 이름에 슬래시로 그대로 씁니다.**

- 정적 파일(`static/`)과 헷갈리지 마세요. `static/` 은 브라우저가 주소로 **직접** 받는 파일이고,
  `templates/` 는 `@Controller` 가 뷰 이름으로 **지목해야만** 렌더링됩니다.
- 기본값을 바꾸고 싶을 때만 `application.yml` 에 `spring.thymeleaf.*` 를 적습니다
  (예: 운영에서 캐시 강제 `spring.thymeleaf.cache: true`). 안 적으면 위 표가 그대로 적용됩니다.

> `templates/` 렌더링에는 `spring-boot-starter-thymeleaf` 가 필요합니다(1_스프링부트시작.md 2절에서
> 이미 추가). 클래스에 `@Controller` 가 정확히 붙어 있는지, 오타는 없는지 확인하세요 — 화면 대신
> `greeting` 이라는 **문자열이 그대로 응답**된다면 원인은 이 문서 **맨 뒤**에서 마저 다룹니다.

## 2. 컨트롤러 작성 방법·어노테이션 정리

1절에서 컨트롤러 하나를 만들어 봤으니, 여기서 "컨트롤러는 어떻게 작성하는가"를 절차와 표로
한 번 정리하고 넘어갑니다.

### 2.1 작성 절차 4단계

| 단계 | 하는 일 | 예시 |
|---|---|---|
| ① 클래스에 역할 표시 | `@Controller` 부착 — "이 클래스는 화면을 그린다"는 표시 | `@Controller public class HomeController` |
| ② 메서드에 주소·방식 매핑 | `@GetMapping`/`@PostMapping` 등에 URL 문자열 | `@GetMapping("/greeting")` |
| ③ 파라미터 바인딩 | 요청 값을 메서드 매개변수로 받을 애노테이션 부착 | `@RequestParam`, `@PathVariable` |
| ④ 반환값 = 뷰 이름 | 메서드가 반환한 문자열이 `templates/*.html` 로 연결됨 | `return "greeting";` |

이 네 단계는 앞으로 만들 모든 컨트롤러(`EmpController`, `DeptController` …)에 그대로 반복됩니다.
**"클래스 표시 하나 + 메서드마다 매핑 하나"** 가 컨트롤러의 기본 골격입니다.

### 2.2 애노테이션 정리

| 애노테이션 | 붙는 위치 | 역할 |
|---|---|---|
| `@Controller` | 클래스 | 메서드 반환 문자열을 **뷰 이름**으로 해석해 화면(HTML)을 렌더링 |
| `@GetMapping("/경로")` | 메서드 | GET 요청 중 이 경로를 이 메서드가 처리 |
| `@PostMapping("/경로")` | 메서드 | POST 요청 중 이 경로를 이 메서드가 처리(폼 전송 등) |
| `@RequestParam` | 매개변수 | 쿼리스트링(`?name=값`)·폼 값을 매개변수로 바인딩. `required`/`defaultValue`, 타입별 변환은 **2.3 문자·숫자·날짜 수집하기** |
| `@PathVariable` | 매개변수 | URL 경로 안의 `{id}` 같은 자리 값을 매개변수로 바인딩. 이름 매칭·여러 개 받기는 **2.3 경로로 수집하기** |
| `@ModelAttribute` | 매개변수 **또는** 메서드 | 매개변수에 붙이면 여러 **쿼리스트링·폼** 값을 DTO 객체 하나로 한꺼번에 바인딩(사실 생략해도 자동 적용되지만, 명시적으로 쓰길 권장 — **2.3 객체로 수집하기**). 메서드에 붙이면 그 메서드가 **요청마다 먼저 실행**되어 반환값을 `Model` 에 자동으로 담아 둠(여러 화면이 공통으로 쓰는 값에 사용 — `Model` 을 본격적으로 다루는 **Day 6**) |
| `@RequestBody` | 매개변수 | **요청 본문**(대개 JSON)을 객체 하나로 역직렬화. URL 쿼리스트링이 아니라 REST API 의 요청 본문을 받을 때 사용(**2.3 객체로 수집하기**, 본격적으로는 **Day 15**) |

> **헷갈리기 쉬운 것**: `@RequestParam` 은 `?key=value` 처럼 **주소 뒤에 붙는 값**, `@PathVariable`
> 은 `/emps/{id}` 처럼 **주소 자체에 박힌 값**입니다. `/emps/200` 이면 `id` 는 `@PathVariable`,
> `/emps?name=김` 이면 `name` 은 `@RequestParam`.

### 2.3 파라미터 자동수집

컨트롤러 메서드가 요청에서 값을 받는 방법은 지금까지 크게 세 가지가 나왔습니다 — **문자·숫자·날짜**를
하나씩 받는 방법(`@RequestParam`), 값이 많을 때 **객체로** 한꺼번에 받는 방법(`@ModelAttribute`),
그리고 URL **경로**에서 받는 방법(`@PathVariable`). 여기서 하나씩 자세히 정리합니다.

#### 문자·숫자·날짜 수집하기 — `@RequestParam`

지금까지는 `@RequestParam(defaultValue = "손님")` 하나만 봤습니다. 실제로는 검색 조건마다
"있어도 되고 없어도 되는 값", "숫자·날짜로 받아야 하는 값"이 계속 나오므로, 여기서 한 번에
정리합니다.

##### 필수 여부 — `required` / `defaultValue`

| 옵션 | 기본값 | 값이 없을 때 |
|---|---|---|
| (아무것도 안 씀) | `required = true` | **400 Bad Request** — `MissingServletRequestParameterException` |
| `required = false` | — | 매개변수에 `null` (기본 타입 `int`·`long` 등은 **쓰면 안 됨** — 아래 참고) |
| `defaultValue = "값"` | `required` 를 **자동으로 false**로 취급 | 지정한 기본값이 들어감(문자열로 쓰지만 타입에 맞게 변환됨) |

```java
@GetMapping("/emps")
public String empList(
        @RequestParam(required = false) String name,          // 없으면 null
        @RequestParam(defaultValue = "1") int page,            // 없으면 1 (문자열 "1"→int 로 자동 변환)
        @RequestParam(required = false, defaultValue = "10") int size  // defaultValue 가 있으면 required는 의미 없음
) {
    ...
}
```

> **자주 하는 실수**: `@RequestParam(required = false) int page` 처럼 **기본 타입(int, long, double …)에
> required=false 만 쓰고 defaultValue 를 안 주면**, 값이 없을 때 `null` 을 `int` 에 넣으려다
> `500 Internal Server Error`(변환 실패)가 납니다. 기본 타입은 꼭 `defaultValue` 를 같이 쓰거나,
> `Integer`(래퍼 타입)로 받아서 `null` 을 직접 처리하세요.

##### 타입별 자동 변환 — 스프링이 문자열을 알아서 변환

쿼리스트링은 원래 전부 **문자열**입니다. `@RequestParam` 은 매개변수의 선언 타입을 보고
그 타입에 맞게 **자동 변환**해 줍니다.

| 받고 싶은 값 | 매개변수 선언 | `?키=값` 예시 | 비고 |
|---|---|---|---|
| 문자열 | `String name` | `?name=김철수` | 변환 없음 |
| 정수 | `int page`, `Integer page` | `?page=2` | 숫자가 아니면 400 |
| 실수 | `double price` | `?price=15000.5` | |
| 참/거짓 | `boolean active` | `?active=true` | `true`/`false` 문자열만 인식 |
| 날짜 | `LocalDate from` | `?from=2026-09-01` | **기본 포맷이 `yyyy-MM-dd`(ISO)** — 다른 포맷은 아래 참고 |
| 날짜시간 | `LocalDateTime updatedAt` | `?updatedAt=2026-09-01T10:00:00` | 기본 포맷 `yyyy-MM-dd'T'HH:mm:ss` |

```java
import java.time.LocalDate;
import org.springframework.format.annotation.DateTimeFormat;

@GetMapping("/emps/search")
public String search(
        @RequestParam(required = false) String keyword,
        @RequestParam(defaultValue = "1") int page,
        @RequestParam(required = false)
        @DateTimeFormat(pattern = "yyyy-MM-dd") LocalDate hireFrom,   // 포맷을 직접 지정
        @RequestParam(required = false)
        @DateTimeFormat(pattern = "yyyy-MM-dd") LocalDate hireTo
) {
    ...
}
// GET /emps/search?keyword=김&hireFrom=2020-01-01&hireTo=2025-12-31
```

- `LocalDate`/`LocalDateTime` 은 기본으로 **ISO 형식**(`yyyy-MM-dd`, `...T...`)만 그냥 인식합니다.
  `2026/09/01`, `20260901` 같은 다른 형식은 `@DateTimeFormat(pattern = "...")` 로 직접 지정해야
  400 없이 받아집니다.
- 타입이 안 맞으면(`?page=abc`) 컨트롤러 메서드가 **아예 호출되지 않고** 400 이 응답됩니다 — 메서드
  안에서 형변환·검증을 따로 할 필요가 없습니다.

#### 객체로 수집하기 — 커맨드 객체(`@ModelAttribute`)

검색 조건이 서너 개를 넘어가면 `@RequestParam` 을 매개변수마다 나열하는 대신, **필드 이름이
쿼리스트링 키와 같은 클래스**를 만들어 매개변수 하나로 받을 수 있습니다. 이때는 매개변수에
`@ModelAttribute` 를 붙입니다.

> **참고 — 사실 생략해도 동작은 합니다.** 매개변수 타입이 `int`/`String` 같은 "단순 타입"이
> 아니면, 애노테이션이 전혀 없어도 스프링이 자동으로 `@ModelAttribute` 로 취급합니다(공식 문서:
> *"use of `@ModelAttribute` is optional"*). 그래도 이 교안은 **명시적으로 붙이길 권장**합니다 —
> 코드만 보고 값의 출처를 알 수 있고, `@ModelAttribute("이름")` 으로 `Model` 이름을 지정할 수
> 있고, GraalVM 네이티브 이미지 빌드에는 명시적 애노테이션이 필요하기 때문입니다.

```java
// dto/EmpSearchCond.java — getter/setter 필요(Lombok @Getter @Setter)
package com.example.hr.dto;

import java.time.LocalDate;
import lombok.Getter;
import lombok.Setter;
import org.springframework.format.annotation.DateTimeFormat;

@Getter @Setter
public class EmpSearchCond {
    private String keyword;
    private int page = 1;                                   // 필드 기본값 = 기본값 역할

    @DateTimeFormat(pattern = "yyyy-MM-dd")
    private LocalDate hireFrom;

    @DateTimeFormat(pattern = "yyyy-MM-dd")
    private LocalDate hireTo;
}
```

```java
import org.springframework.web.bind.annotation.ModelAttribute;

@GetMapping("/emps/search")
public String search(@ModelAttribute EmpSearchCond cond) {
    // cond.getKeyword(), cond.getPage(), cond.getHireFrom() ...
    ...
}
// GET /emps/search?keyword=김&page=2&hireFrom=2020-01-01
// → EmpSearchCond{keyword="김", page=2, hireFrom=2020-01-01, hireTo=null}
```

- 동작 원리: 스프링이 쿼리스트링의 `키=값` 마다 `cond.set키(값)` 를 **리플렉션으로 호출**합니다
  (그래서 **getter/setter 가 필수**입니다). 일치하는 키가 없으면 그 필드는 필드 기본값(선언 시
  초깃값)으로 남고, 애초에 setter 자체가 없으면 값이 채워지지 않습니다.
- 날짜·숫자 변환 규칙은 위 "문자·숫자·날짜 수집하기" 표와 동일하게 적용됩니다(`@DateTimeFormat`
  도 필드에 그대로 붙임).
- 이 방식은 검색 조건 DTO 뿐 아니라 화면 등록 폼(`EmpForm`)을 받을 때도 그대로 씁니다 —
  `@RequestParam` 여러 개 vs `@ModelAttribute` 객체 하나는 "필드가 몇 개냐"로 고르면 됩니다
  (2~3개는 `@RequestParam`, 그 이상은 객체).

##### `@ModelAttribute`, 메서드에 붙이면 다른 뜻

지금까지 본 `@ModelAttribute` 는 **매개변수**에 붙여 요청 값을 객체로 받는 용도였습니다. 같은
애노테이션을 **메서드**에 붙이면 완전히 다른 일을 합니다 — 그 메서드가 **이 컨트롤러의 모든
요청 처리 메서드보다 먼저 실행**되어, 반환값을 자동으로 `Model` 에 담아 둡니다.

```java
@Controller
public class EmpController {

    @ModelAttribute("depts")             // 이 컨트롤러의 어떤 요청이 와도 먼저 실행됨
    public List<String> depts() {
        return List.of("개발팀", "인사팀", "영업팀");   // Model 에 "depts" 이름으로 자동 저장
    }

    @GetMapping("/emps/new")
    public String newForm() {
        return "hr/emp-form";   // 뷰에서 th:each="d : ${depts}" 로 바로 씀 — 여기서 담을 필요 없음
    }
}
```

여러 화면에서 공통으로 쓰는 값(부서 목록, 로그인 사용자 정보 등)을 매 메서드마다 반복해서
`Model` 에 담지 않아도 되게 해 줍니다. `Model` 자체는 **Day 6**에서 본격적으로 다룹니다 — 지금은
"`@ModelAttribute` 는 붙는 위치(매개변수 vs 메서드)에 따라 역할이 다르다"는 것만 기억해 두세요.

##### 참고 — 요청 본문(body)을 객체로 받을 땐 `@RequestBody`

`@ModelAttribute` 는 **쿼리스트링과 폼 본문**(`Content-Type: application/x-www-form-urlencoded`,
`key=value&key2=value2`)을 읽습니다 — 서블릿이 이 둘을 똑같이 "파라미터"로 취급하기 때문입니다.
반면 REST API 는 값을 **JSON 요청 본문**에 실어 보내는 경우가 대부분이고, 이건 `@ModelAttribute`
가 못 읽습니다. 이때 쓰는 게 `@RequestBody` 입니다 — 요청 본문 전체를 통째로 읽어서
`Content-Type` 에 맞는 컨버터(대개 Jackson)로 객체 하나로 변환합니다.

| | `@RequestParam` / `@ModelAttribute` | `@RequestBody` |
|---|---|---|
| 읽는 곳 | URL 쿼리스트링 + 폼 본문(둘 다 "서블릿 파라미터") | 요청 본문(body) 전체, 한 번에 |
| 채우는 방법 | 키마다 값 하나씩(또는 `set필드명(값)`) | `Content-Type` 에 맞는 컨버터가 본문 전체를 객체로 변환 |
| 주로 쓰는 곳 | 화면 검색·등록 폼, URL 파라미터 | REST API 의 JSON 본문(`POST`/`PUT`) |

```java
@PostMapping("/api/emps")
public EmpCreateResponse create(@RequestBody EmpCreateRequest req) {   // JSON 본문 → 객체
    ...
}
// POST /api/emps  Content-Type: application/json
// { "name": "김철수", "deptId": 10 }
```

- **`@RequestBody` 는 `@ModelAttribute` 와 달리 생략할 수 없습니다.** 앞서 본 묵시적 인식은
  쿼리스트링·폼에만 적용되고, 요청 본문을 읽는 경로는 `@RequestBody` 하나뿐입니다. 안 붙이면
  JSON 값을 못 읽어 필드가 텅 빈 객체가 되거나 오류로 보이는 증상이 납니다.
- `@RequestBody` 는 GET/POST 같은 **HTTP 메서드와 무관하게 "본문이 있으면 읽는다"**가 전부입니다.
  다만 GET 은 원래 "본문 없이 조회"가 관례(브라우저 주소창은 body 를 보낼 수도 없음)라서, 실무
  에서는 거의 항상 `POST`/`PUT`/`PATCH` 와 짝지어 씁니다.
- REST API 를 본격적으로 만드는 **Day 15**에서 `EmpCreateRequest`/`EmpCreateResponse` 로
  실습합니다.

#### 경로로 수집하기 — `@PathVariable`

`@PathVariable` 도 `@RequestParam` 처럼 문자열을 자동으로 타입 변환해 주지만, **값이 "주소 자체에
박혀 있다"**는 점이 다릅니다. 매핑 경로에 `{중괄호}` 로 자리를 만들어 두고, 그 이름과 같은 이름의
매개변수로 받습니다.

##### 이름이 같으면 자동 매칭, 다르면 명시

```java
@GetMapping("/emps/{id}")
public String empDetail(@PathVariable String id) {   // 경로의 {id} 와 매개변수 이름 id 가 같음 → 자동 매칭
    ...
}
```

경로의 자리 이름과 매개변수 이름이 다르면, `@PathVariable("경로이름")` 으로 직접 연결해야 합니다.

```java
@GetMapping("/emps/{empId}")
public String empDetail(@PathVariable("empId") String id) {   // 경로는 empId, 매개변수는 id
    ...
}
```

##### 여러 개 받기

경로에 `{}` 가 여러 개면 매개변수도 그만큼 받을 수 있습니다.

```java
@GetMapping("/depts/{deptId}/emps/{empId}")
public String deptEmpDetail(@PathVariable Long deptId, @PathVariable Long empId) {
    ...
}
// GET /depts/10/emps/200 → deptId=10, empId=200
```

##### 타입 변환 — `@RequestParam` 과 같은 규칙

`int`/`Long`/`LocalDate` 등으로 선언하면 위 "문자·숫자·날짜 수집하기"의 표와 똑같이 자동
변환됩니다. 다만 값이 아예 없을 수는 없습니다 — **`{id}` 자리 자체가 URL 의 일부**라서, 값이
없으면 그 URL 자체가 매핑되지 않습니다(`@RequestParam` 처럼 `required`/`defaultValue` 를 쓸
일이 거의 없는 이유입니다).

```java
@GetMapping("/emps/{id}")
public String empDetail(@PathVariable Long id) {   // "abc" 처럼 숫자가 아니면 400
    ...
}
```

> `/emps/abc` 처럼 타입이 안 맞는 값이 오면, `Long id` 로 변환하다 실패해서 **400 Bad Request** 가
> 응답됩니다(주소 자체는 `/emps/{id}` 패턴에 걸리므로 404 가 아닙니다).

## 3. 응답 본문을 그대로 돌려주는 컨트롤러 — `@RestController`

1~2절에서 화면을 그리는 컨트롤러(`@Controller`)를 충분히 살펴봤습니다. 그런데 화면이 아니라
문자열이나 JSON 같은 **데이터를 그대로** 돌려주고 싶을 때도 많습니다 — 모바일 앱이나 프런트엔드
자바스크립트가 호출하는 API가 그렇습니다. 이때는 `@RestController` 를 씁니다.

`com.example.hr` 아래에 `controller` 패키지를 만들고 `HelloController` 를 추가합니다.

```java
package com.example.hr.controller;

import org.springframework.web.bind.annotation.GetMapping;
import org.springframework.web.bind.annotation.RequestParam;
import org.springframework.web.bind.annotation.RestController;

@RestController                                   // 이 클래스의 메서드 반환값을 그대로 응답 본문으로
public class HelloController {

    @GetMapping("/hello")                         // GET /hello 요청을 이 메서드가 처리
    public String hello(@RequestParam(defaultValue = "손님") String name) {
        return "안녕하세요, " + name + "님";
    }
}
```

저장하고(DevTools가 재시작), 브라우저에서:

- `http://localhost:8080/hello` → `안녕하세요, 손님님`
- `http://localhost:8080/hello?name=박지민` → `안녕하세요, 박지민님`

동작 원리(간단히):

1. 요청이 내장 톰캣 → `DispatcherServlet`(자동 구성으로 등록됨)에 도착
2. `DispatcherServlet` 이 주소(`/hello`)와 방식(GET)에 맞는 메서드를 찾음 → `HelloController.hello`
3. `@RequestParam` 이 쿼리스트링 `name` 값을 파라미터에 바인딩
4. 반환한 문자열을 `@RestController` 규칙에 따라 응답 본문으로 씀

> `@RequestParam`·`@PathVariable`·`@ModelAttribute` 는 1~2절에서 배운 그대로 `@RestController`
> 에서도 똑같이 씁니다 — **파라미터를 받는 방법은 클래스 애노테이션과 무관합니다.** 달라지는 건
> 오직 "반환값을 어떻게 해석하느냐" 뿐입니다.

객체를 반환하면 자동으로 JSON이 됩니다(자동 구성된 Jackson):

```java
@GetMapping("/ping")
public Map<String, Object> ping() {
    return Map.of("status", "ok", "time", java.time.LocalTime.now().toString());
}
// → {"status":"ok","time":"14:32:10.123"}
```

### 3.1 설정값 읽어오기 — `@Value`

지금까지 컨트롤러 코드 안의 값(포트, 인사말 등)은 전부 **코드에 직접 적혀** 있었습니다. 그런데
"로컬에서는 이 이름, 운영 서버에서는 저 이름"처럼 **환경마다 달라져야 하는 값**을 코드에 박아두면,
값 하나 바꾸려고 코드를 고치고 다시 빌드해야 합니다. 이런 값은 `application.yml` 에 적어 두고,
컨트롤러는 그 값을 **읽어오기만** 하는 게 맞습니다 — `1_스프링부트시작.md` 6절에서 만든
`application.yml` 을 코드에서 실제로 쓰는 첫 사례입니다.

`@Value("${키}")` 를 필드에 붙이면, 스프링이 그 키를 `application.yml`(또는 `.properties`)에서
찾아 필드에 주입합니다.

`HelloController` 에 필드와 메서드를 하나씩 추가합니다(`import org.springframework.beans.factory.annotation.Value;`):

```java
@Value("${spring.application.name:hr}")   // application.yml 의 spring.application.name 값 주입
private String appName;

@GetMapping("/appname")
public String appName() {
    return appName;   // → "hr-system" (application.yml 에 적어 둔 값)
}
```

```yaml
spring:
  application:
    name: hr-system
```

- `${스프링.점.표기}` 는 YAML 의 들여쓰기를 점(`.`)으로 이어 쓴 키입니다 — YAML 의
  `spring: application: name:` 세 줄이 `spring.application.name` 한 키가 됩니다.
- **기본값**: `${키:기본값}` 처럼 콜론 뒤에 적으면, 그 키가 설정 파일에 없어도 기본값이 들어가고
  기동은 정상적으로 됩니다(위 예시에서 `hr`).
- **기본값이 없는데 키도 없으면 컨트롤러가 아니라 애플리케이션 자체가 뜨지 않습니다** — 자리를
  채울 값을 못 찾았다는 예외(`PlaceholderResolutionException` 계열)를 던지고 기동이 실패합니다.
  `@RequestParam`/`@PathVariable` 처럼 요청이 와야 드러나는 오류가 아니라, **서버를 켜는 순간**
  바로 드러납니다.
- 필드뿐 아니라 생성자 파라미터에도 붙일 수 있습니다(생성자 주입의 원리는 **Day 4 IoC와 DI**):
  `HelloController(@Value("${server.port}") String port) { ... }`.

> 값이 한둘이 아니라 여러 개로 늘어나면 `@Value` 를 필드마다 반복하는 대신 타입 안전한 객체
> 하나로 묶어 받는 `@ConfigurationProperties` 가 있습니다 — **Day 4 IoC와 DI 심화**
> (`1_IoC와DI_심화.md`) 참고.

### 3.2 `@Controller` vs `@RestController` 한눈에

| | `@Controller` | `@RestController` |
|---|---|---|
| 반환 문자열의 의미 | **뷰 이름** → `templates/<이름>.html` | 응답 본문 텍스트 |
| 주 용도 | 화면(HTML) | REST API (JSON) |
| 데이터 전달 | `Model` 에 담아 뷰에서 사용 (**Day 6**) | 반환 객체가 곧 JSON |
| 본문을 그대로 쓰려면 | 메서드에 `@ResponseBody` 를 따로 붙일 때만 | 기본 동작 |

`@ResponseBody` 는 "`@Controller` 안에서 이 메서드 하나만 예외적으로 `@RestController`처럼
동작시키는" 애노테이션입니다 — 화면 컨트롤러 안에 API 메서드를 하나만 살짝 끼워 넣고 싶을 때 씁니다.

## 자주 하는 실수

- **`@Controller` 인데 화면 대신 뷰 이름 문자열이 그대로 응답됨** → 클래스/메서드에 `@RestController` 나 `@ResponseBody` 가 붙어 있는 것. 화면을 그리려면 `@Controller` + 뷰 이름이어야 함.
- **`@RequestParam` 과 `@PathVariable` 을 헷갈림** → `?key=value`(쿼리스트링)는 `@RequestParam`, `/emps/{id}`(경로 자체)는 `@PathVariable`. 2.2 표 참고.
- **`@RequestParam(required = false) int page` 인데 값이 없으면 500** → 기본 타입(`int`/`long`/`double`)에 `null` 을 못 넣어서 나는 오류. `defaultValue` 를 같이 쓰거나 `Integer` 같은 래퍼 타입으로 받을 것. 2.3(문자·숫자·날짜 수집하기) 참고.
- **`LocalDate` 파라미터에 `2026/09/01`, `20260901` 을 넣으면 400** → 기본은 ISO(`yyyy-MM-dd`)만 인식. 다른 포맷은 `@DateTimeFormat(pattern = "...")` 로 지정해야 함. 2.3(문자·숫자·날짜 수집하기) 참고.
- **JSON 으로 보냈는데 객체 필드가 텅 빔** → `@ModelAttribute`(또는 애노테이션 생략)는 **쿼리스트링·폼만** 읽습니다. JSON 요청 본문은 반드시 `@RequestBody` 로 받아야 함. 2.3(객체로 수집하기) 참고.
- **커맨드 객체(`EmpSearchCond` 등)의 필드가 안 채워짐** → `@ModelAttribute` 는 붙였는데 클래스에 **getter/setter 가 없거나**, 쿼리스트링 키와 **필드 이름이 다른** 경우. 스프링은 이름이 일치하는 필드에만 `set필드명(값)` 을 호출합니다.
- **`@PathVariable` 이름이 안 맞아서 500** → 경로의 `{경로이름}` 과 매개변수 이름이 다른데 `@PathVariable("경로이름")` 을 안 붙인 경우. 2.3(경로로 수집하기) 참고.
- **`@PathVariable Long id` 인데 문자를 넣으면 400** → `/emps/abc` 처럼 타입이 안 맞는 값. 라우팅 자체는 되므로 404 가 아니라 400 입니다. 2.3(경로로 수집하기) 참고.
- **`@Value("${없는.키}")` 를 썼는데 앱 자체가 안 뜸** → 기본값(`${키:기본값}`) 없이 설정 파일에 없는 키를 참조한 것. 요청이 와야 아는 오류가 아니라 **기동 시점에 바로 실패**합니다. 키 오타를 확인하거나 기본값을 추가하세요. 3.1 참고.

> hr 프로토타입·DevTools 관련 실수(CSS 안 먹음, `/emps` 404, DevTools 미반영)는
> **2. 프로토타입/1. 프로토타입.md** 의 "자주 하는 실수"에 모아 뒀습니다.

| Thymeleaf 자동 구성 | `starter-thymeleaf` 만 있으면 뷰 리졸버가 기본값(`classpath:/templates/` + `.html`)으로 등록 | `application.yml` 설정 불필요. 바꿀 때만 `spring.thymeleaf.*` (1.1) |
| 컨트롤러 작성 4단계 | 클래스 표시 → 메서드 매핑 → 파라미터 바인딩 → 반환값 | 2.1 표. 모든 컨트롤러가 이 골격을 따름 |
| `@RequestParam` / `@PathVariable` | 쿼리스트링 값 / URL 경로 값 바인딩 | `?name=` 은 전자, `/emps/{id}` 는 후자 |
| `@RequestParam` 의 `required`/`defaultValue` | 필수 여부·기본값 지정 | 기본 타입은 `defaultValue` 없이 `required=false` 만 쓰면 500 (2.3 문자·숫자·날짜 수집하기) |
| 타입별 자동 변환 | 문자열·숫자·`boolean`·`LocalDate`/`LocalDateTime` | 날짜는 기본 ISO 포맷, 다르면 `@DateTimeFormat` (2.3 문자·숫자·날짜 수집하기) |
| 커맨드 객체 바인딩 | 쿼리스트링/폼 값을 DTO 필드에 한꺼번에 매핑 | `@ModelAttribute` 는 사실 생략 가능(묵시적 적용)하지만 명시 권장, getter/setter 필요 (2.3 객체로 수집하기) |
| `@RequestBody` | 요청 본문(대개 JSON)을 객체 하나로 역직렬화 | URL 쿼리스트링·폼은 `@RequestParam`/`@ModelAttribute`, 요청 본문은 `@RequestBody` (2.3 객체로 수집하기, 본격적으로는 Day 15) |
| `@PathVariable` 이름 매칭·여러 개 | 경로 이름과 매개변수 이름이 다르면 `@PathVariable("이름")` | 값이 없으면 애초에 그 URL 이 매핑 안 됨 (2.3 경로로 수집하기) |
| `@RestController` + `@GetMapping` | 요청을 메서드로 매핑, 반환값을 **응답 본문**으로 | 문자열·JSON. REST API. 파라미터 바인딩 방법은 `@Controller` 와 동일 |
| `@Value("${키}")` | `application.yml`/`.properties` 의 설정값을 필드(또는 생성자 파라미터)에 주입 | 기본값은 `${키:기본값}`. 기본값 없이 없는 키 → **기동 실패** (3.1) |
