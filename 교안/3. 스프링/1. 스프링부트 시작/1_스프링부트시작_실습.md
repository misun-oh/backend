앞으로 모든 챕터가 이 프로젝트 위에서 이어집니다. 천천히 정확히 만드세요.

## 문제 1. 프로젝트 생성과 실행

`start.spring.io` 에서 아래 조건으로 프로젝트를 만들고 IntelliJ에서 실행하세요.

- Gradle-Groovy / Java 17 / Spring Boot 4.0.x / Jar
- Group `com.example`, Artifact `hr`, Package `com.example.hr`
- Dependencies: Spring Web, Thymeleaf, Lombok, Spring Boot DevTools
  (생성된 `build.gradle` 의 웹 스타터가 `spring-boot-starter-webmvc` 인지 확인)

**확인할 것**: 콘솔에서 `Started HrApplication in ...` 과 `Tomcat started on port 8080` 두 줄을 찾고,
`http://localhost:8080` 접속 시 뜨는 화면 이름을 적으세요.

## 문제 2. 포트 변경

`application.properties` 를 `application.yml` 로 바꾸고, 서버 포트를 **8090** 으로 변경하세요.
재실행 후 `http://localhost:8090` 으로 접속되는지 확인하세요.

**확인할 것**: 콘솔의 포트 관련 로그 한 줄을 붙여넣으세요.

## 문제 3. 인사 컨트롤러

`com.example.hr.controller` 패키지에 `HelloController` 를 만들어 다음을 만족시키세요.

- `GET /hello` → `안녕하세요, 손님님`
- `GET /hello?name=박지민` → `안녕하세요, 박지민님`

## 문제 4. 앱 이름 설정과 확인

`application.yml` 에 `spring.application.name` 을 `hr-system` 으로 설정하세요.
그리고 `GET /appname` 요청 시 이 값을 그대로 응답하는 메서드를 `HelloController` 에 추가하세요.

**힌트**: 설정값을 코드에서 읽을 때는 `@Value("${spring.application.name}")` 를 필드에 붙입니다.

## 문제 5. 기동 시 메시지 출력

앱이 완전히 뜬 직후 콘솔에 `>>> HR 시스템 준비 완료 (포트: 8090)` 를 한 번 출력하도록 만드세요.

**힌트**: `CommandLineRunner` 타입 빈을 `@Bean` 으로 등록하거나, 별도 클래스에 `@Component` +
`implements CommandLineRunner`. 포트 값은 `@Value("${server.port}")` 로 주입.

## 문제 7. hr 프로토타입 화면 붙이기

`3. 스프링/2. 프로토타입/` 의 파일을 프로젝트 리소스 폴더로 나눠 담고, 설계 URL 로 사원관리
화면이 뜨게 하세요.

1. `static/css/*`(4개: `basic` `component` `app-shell` `hr`), `static/js/component.js` →
   `src/main/resources/static/css/`, `.../static/js/` (**`app-shell.js` 는 복사 안 함**)
2. `templates/hr/*.html`(5개) → `src/main/resources/templates/hr/`
3. `com.example.hr.controller.EmpController` (`@Controller`) 를 만들어 Day 1 설계 URL 표에
   뷰 이름을 반환하세요(`redirect:` 안 씀 — 파일이 이미 `templates/` 안에 있으므로):

   | URL | 반환하는 뷰 이름 |
   |---|---|
   | `GET /` | `"hr/dashboard"` |
   | `GET /emps` | `"hr/index"` |
   | `GET /emps/new` | `"hr/emp-form"` |
   | `GET /emps/{id}` | `"hr/emp-detail"` |
   | `GET /emps/{id}/edit` | `"hr/emp-form"` |
   | `GET /depts` | `"hr/depts"` |

4. **화면 안의 메뉴·상세·수정 링크를 눌러 보세요.** 십중팔구 404 가 납니다 — 프로토타입 HTML
   안의 이동 링크가 `href="depts.html"` 처럼 **같은 폴더 옆 파일**을 가리키는 상대경로라서,
   지금 주소(`/emps` 등)를 기준으로 계산하면 실제 매핑 주소(`/depts`)와 어긋나기 때문입니다.
   `templates/hr/*.html` 안의 `<a href="...">` 를 **실제 매핑 주소**(`/`, `/emps`, `/depts`,
   `/emps/{실제id}` 등)로 직접 고쳐서, 메뉴·상세·수정 링크가 전부 정상적으로 이동하게 만드세요.

**확인할 것**:
1. `http://localhost:8080/` 이 대시보드 화면으로, `/emps` 가 사원 목록으로 뜨는가? (CSS 적용 상태)
2. (수정 전) 상단 "부서" 메뉴를 눌렀을 때 어떤 주소로 이동하며, 왜 404 가 나는지 한두 문장으로
   설명하세요.
3. (수정 후) 메뉴·목록의 "상세"·"수정" 링크를 눌러서 전부 올바른 화면으로 이동하는지 확인하세요.
4. `@GetMapping` 의 주소 문자열과 `templates/` 안 파일의 실제 위치는 어떤 관계인지 한 문장으로
   설명하세요.
5. (개념) `app-shell.js` 를 안 옮겼는데 헤더가 정상으로 뜨는 이유는?
