## 문제 3. 인사 컨트롤러

`src/main/java/com/example/hr/controller/HelloController.java`:

```java
package com.example.hr.controller;

import org.springframework.web.bind.annotation.GetMapping;
import org.springframework.web.bind.annotation.RequestParam;
import org.springframework.web.bind.annotation.RestController;

@RestController
public class HelloController {

    @GetMapping("/hello")
    public String hello(@RequestParam(defaultValue = "손님") String name) {
        return "안녕하세요, " + name + "님";
    }
}
```

- `GET /hello` → `안녕하세요, 손님님`
- `GET /hello?name=박지민` → `안녕하세요, 박지민님`

`@RequestParam(defaultValue = "손님")` 덕분에 `name` 이 없어도 오류 없이 기본값이 들어갑니다.
(`defaultValue` 를 빼면 `name` 누락 시 400 Bad Request)

## 문제 4. 앱 이름 설정과 확인

`application.yml`:
```yaml
spring:
  application:
    name: hr-system
```

`HelloController` 에 추가:
```java
import org.springframework.beans.factory.annotation.Value;

@RestController
public class HelloController {

    @Value("${spring.application.name}")
    private String appName;

    // ... hello() ...

    @GetMapping("/appname")
    public String appName() {
        return appName;      // → hr-system
    }
}
```

`@Value("${...}")` 는 `application.yml` 의 값을 필드에 주입합니다. 없는 키를 참조하면 기동 실패하므로,
기본값이 필요하면 `@Value("${some.key:기본값}")` 형태로 씁니다.

## 문제 5. 기동 시 메시지 출력

**방법 A — `@Bean` 으로 `CommandLineRunner` 등록** (`HrApplication` 안):

```java
import org.springframework.boot.CommandLineRunner;
import org.springframework.beans.factory.annotation.Value;
import org.springframework.context.annotation.Bean;

@SpringBootApplication
public class HrApplication {

    public static void main(String[] args) {
        SpringApplication.run(HrApplication.class, args);
    }

    @Bean
    CommandLineRunner startupBanner(@Value("${server.port}") String port) {
        return args -> System.out.println(">>> HR 시스템 준비 완료 (포트: " + port + ")");
    }
}
```

**방법 B — 별도 컴포넌트**:

```java
package com.example.hr.config;

import org.springframework.beans.factory.annotation.Value;
import org.springframework.boot.CommandLineRunner;
import org.springframework.stereotype.Component;

@Component
public class StartupBanner implements CommandLineRunner {

    @Value("${server.port}")
    private String port;

    @Override
    public void run(String... args) {
        System.out.println(">>> HR 시스템 준비 완료 (포트: " + port + ")");
    }
}
```

두 방법 모두 컨테이너가 준비되고 톰캣이 요청을 받기 직전에 한 번 실행됩니다.
콘솔 맨 아래에 `>>> HR 시스템 준비 완료 (포트: 8090)` 이 찍힙니다.

> 실무에서는 `System.out` 대신 로거(`log.info(...)`)를 씁니다 — Day 3.

## 문제 6. 컴포넌트 스캔 범위 확인

`HrApplication.java` 를 `com.example.hr.boot` 로 옮기면:

```java
package com.example.hr.boot;   // 패키지 선언도 변경
// 파일 위치: src/main/java/com/example/hr/boot/HrApplication.java
```

1. **`GET /hello` 가 404 로 실패합니다.** (앱은 뜨지만 `HelloController` 가 등록되지 않음)

2. **이유**: `@SpringBootApplication` 에 포함된 `@ComponentScan` 은 **그 클래스가 속한 패키지와
   하위 패키지**만 스캔합니다. `HrApplication` 이 `com.example.hr.boot` 로 내려가면 스캔 기준도
   `com.example.hr.boot` 아래로 좁아지고, `com.example.hr.controller` 는 그 **바깥**이 되어
   `@RestController` 가 빈으로 등록되지 않습니다. 그래서 `/hello` 매핑 자체가 존재하지 않게 됩니다.
   (`@ComponentScan(basePackages = "com.example.hr")` 를 명시하면 다시 잡히지만, 관례를 따르는 게 낫습니다.)

3. 원위치(`src/main/java/com/example/hr/HrApplication.java`, `package com.example.hr;`)로 되돌리면
   다시 정상 동작합니다.

## 문제 7. hr 프로토타입 화면 붙이기

복사 후 구조 (`app-shell.js` 는 옮기지 않음):

```
src/main/resources/
├── static/
│   ├── css/  basic.css  component.css  app-shell.css  hr.css
│   └── js/   component.js
└── templates/
    └── hr/   index.html  depts.html  dashboard.html  emp-detail.html  emp-form.html
```

`src/main/java/com/example/hr/controller/EmpController.java`:

```java
package com.example.hr.controller;

import org.springframework.stereotype.Controller;
import org.springframework.web.bind.annotation.GetMapping;
import org.springframework.web.bind.annotation.PathVariable;
import org.springframework.web.bind.annotation.PostMapping;

@Controller
public class EmpController {

    @GetMapping("/")               public String dashboard()   { return "hr/dashboard"; }

    @GetMapping("/emps")           public String empList()      { return "hr/index"; }
    @GetMapping("/emps/new")       public String empNewForm()   { return "hr/emp-form"; }
    @GetMapping("/emps/{id}")      public String empDetail(@PathVariable String id)   { return "hr/emp-detail"; }
    @GetMapping("/emps/{id}/edit") public String empEditForm(@PathVariable String id) { return "hr/emp-form"; }

    @GetMapping("/depts")          public String deptList()     { return "hr/depts"; }

    @PostMapping("/login")         public String login()        { return "hr/dashboard"; }
}
```

**확인**:

1. `http://localhost:8080/` → 대시보드, `/emps` → 사원 목록. 둘 다 CSS 적용됨(정적 파일은
   `static/`, HTML 은 `templates/` 로 나눠 담았으므로).
2. **수정 전**: `/emps` 화면에서 "부서" 메뉴(`href="depts.html"`)를 누르면 브라우저는 현재 주소
   `/emps` 를 기준으로 `depts.html` 을 계산해 **`/depts.html`** 로 이동합니다. 하지만 실제 매핑은
   `.html` 없는 `/depts` 라서 문자열이 안 맞아 **404** 가 납니다(브라우저는 서버의 폴더 구조를
   모르고, 지금 URL 을 기준으로만 상대경로를 계산하기 때문입니다).
3. **수정**: `templates/hr/*.html` 안의 상대경로 링크를 실제 매핑 주소로 바꿉니다. 예를 들어
   `index.html`(상단 메뉴 부분)에서:

   ```html
   <!-- 수정 전 -->
   <a href="index.html">사원 목록</a>
   <a href="depts.html">부서</a>
   <a href="dashboard.html">대시보드</a>

   <!-- 수정 후 -->
   <a href="/emps">사원 목록</a>
   <a href="/depts">부서</a>
   <a href="/">대시보드</a>
   ```

   상세·수정 링크도 같은 방식으로 바꿉니다(`emp-detail.html` → `/emps/1`, `emp-form.html` →
   `/emps/new` 또는 `/emps/1/edit` — 오늘은 `id` 를 실제로 안 쓰므로 아무 값이나 넣어도 됩니다).
   5개 파일(`index`·`depts`·`dashboard`·`emp-detail`·`emp-form`) 전부 같은 요령으로 고치면,
   메뉴·상세·수정 링크가 전부 정상적으로 이동합니다.
4. **관계 없음.** `@GetMapping` 의 주소 문자열은 "이 URL 요청을 이 메서드가 처리한다"는 라우팅
   정보일 뿐이고, 메서드가 반환하는 뷰 이름(`"hr/depts"`)이 `templates/hr/depts.html` 을 찾는
   것은 완전히 별개의 과정입니다. `@GetMapping` 주소를 자유롭게 바꿔도 `templates/` 안 파일 위치와는
   아무 상관이 없습니다.
5. 헤더 마크업이 **각 HTML 파일에 그대로 들어 있기** 때문입니다. 예전엔 `app-shell.js` 가
   `data-shell-*` 를 읽어 헤더를 그렸지만, 지금은 `_menu.html`(메뉴 폼)의 `<header>` 를 각 페이지에
   인라인해 뒀습니다. 다크 모드 토글 등 동작은 `component.js` 가 자동 초기화합니다.

> CSS 가 안 먹으면: 파일이 `static/css/` 밑에 있는지, `http://localhost:8080/css/basic.css` 가
> 200 으로 열리는지 확인.

## 문제 8. `@Controller` 로 뷰 돌려주기

`src/main/resources/templates/greeting.html`:

```html
<!DOCTYPE html>
<html lang="ko">
<head><meta charset="UTF-8"><title>인사</title></head>
<body>
  <h1>HR 시스템</h1>
  <p><a href="/emps">사원 목록으로</a></p>
</body>
</html>
```

`EmpController` 에 추가:

```java
@GetMapping("/greeting")
public String greeting() {
    return "greeting";        // templates/greeting.html
}
```

**확인**:

1. `http://localhost:8080/greeting` → 위 HTML 이 렌더링된 화면.
2. `@RestController`(또는 메서드에 `@ResponseBody`) 였다면 `greeting` 이라는 **글자 그대로**가
   응답 본문으로 나갑니다(화면 렌더링 없음). `@Controller` 라서 반환 문자열이 "뷰 이름"으로
   해석되어 해당 HTML 을 찾아 응답합니다.
