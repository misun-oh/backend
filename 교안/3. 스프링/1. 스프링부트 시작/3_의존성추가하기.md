# Day 2 보충. 프로젝트 생성 후 의존성 추가하기 — Lombok

| 항목 | 내용 |

| 이번 문서 | `start.spring.io`에서 못 고른 의존성을 나중에 추가하는 법 → Lombok 추가 + IDE 설정 → 동작 확인 (실습: MyBatis 추가하기) |

| 권장 진행 | 30분 |

## 학습목표

- `start.spring.io`에서 놓친 의존성을, 프로젝트를 다시 만들지 않고 `build.gradle`에 직접 추가할 수 있다.
- Lombok이 `compileOnly` **와** `annotationProcessor` 두 줄을 **함께** 요구하는 이유를 설명할 수 있다.
- IDE(IntelliJ/VS Code)에서 Lombok이 생성한 코드를 인식하도록 설정할 수 있다.
- 의존성을 고친 뒤 **Gradle을 다시 읽게 하는 절차**를 안다.
- 같은 방법으로 다른 의존성(MyBatis 등)도 추가할 수 있다.

---

## 1. 왜 프로젝트를 다시 만들지 않아도 되는가

`start.spring.io`가 하는 일은 딱 하나입니다 — 우리가 고른 의존성 목록으로 **`build.gradle` 파일을
생성**해 주는 것. `0_빌드도구.md`에서 봤듯, `build.gradle`의 `dependencies { }` 블록이 곧 "이
프로젝트가 쓰는 라이브러리 목록"입니다. 그러니 Initializr 화면에서 뭔가를 빠뜨렸어도, **그 파일에
줄 두 개를 직접 추가**하면 결과는 똑같습니다 — 프로젝트를 지우고 새로 받을 필요가 없습니다.

> 의존성 좌표(`group:artifact:version`)는 어디서 찾을까요? `0_빌드도구.md` 7절에서 본 대로
> [mvnrepository.com](https://mvnrepository.com) 또는 Maven Central 에서 이름으로 검색하면 됩니다.

---

## 2. Lombok 추가하기

`build.gradle`의 `dependencies { }` 블록에 두 줄을 추가합니다.

```groovy
dependencies {
    implementation 'org.springframework.boot:spring-boot-starter-webmvc'
    implementation 'org.springframework.boot:spring-boot-starter-thymeleaf'

    compileOnly 'org.projectlombok:lombok'            // ← 추가
    annotationProcessor 'org.projectlombok:lombok'     // ← 추가

    testImplementation 'org.springframework.boot:spring-boot-starter-test'
    testRuntimeOnly 'org.junit.platform:junit-platform-launcher'
}
```

### 왜 두 줄인가 — `compileOnly` + `annotationProcessor`

Lombok은 `@Getter`·`@Setter`·`@Slf4j` 같은 애노테이션을 보고, **컴파일 시점에 진짜 코드(getter,
setter, `log` 필드 …)를 만들어 끼워 넣는** 도구입니다. 실행 중에 뭔가를 하는 라이브러리가 아니라,
**컴파일할 때만 필요한 도구**라서 스코프가 둘로 나뉩니다.

| 스코프 | 역할 | 없으면 |
|---|---|---|
| `compileOnly` | Lombok 애노테이션(`@Getter` 등)을 **코드에서 참조**할 수 있게 함. 실행 시(jar)엔 안 들어감 | `@Getter` 를 못 찾아 컴파일 오류 |
| `annotationProcessor` | 컴파일 단계에서 **실제로 코드를 생성**하는 처리기를 동작시킴 | 애노테이션은 인식되지만 getter/setter가 **생성되지 않아** "메서드가 없다"는 컴파일 오류 |

`0_빌드도구.md`의 스코프 표에서 "compileOnly + annotationProcessor (Lombok)" 라고 짝지어 둔
바로 그 이유입니다 — **하나만 넣으면 반쪽짜리 설정**이 됩니다.

## 3. IDE에서 Lombok 인식시키기

`build.gradle`만 고쳐서는 IDE가 아직 모릅니다. 아래 둘을 확인하세요.

### IntelliJ IDEA

1. **Gradle 다시 읽기** — 오른쪽 **Gradle 탭 → 새로고침(🔄) 아이콘**, 또는 `build.gradle` 우클릭 →
   *Reload Gradle Project*. (자동 새로고침이 켜져 있으면 저장만 해도 반영됩니다.)
2. **Lombok 플러그인 설치** — `Settings → Plugins → Marketplace` 에서 "Lombok" 검색 후 설치
   (최신 IntelliJ는 기본 내장인 경우도 많습니다 — Plugins 목록에 이미 있으면 활성화만 확인).
3. **애노테이션 처리 활성화** — `Settings → Build, Execution, Deployment → Compiler →
   Annotation Processors` 에서 **Enable annotation processing** 체크(Gradle 프로젝트는 보통
   기본 켜져 있습니다).

### VS Code

Extension Pack for Java(00_VSCode_개발환경_세팅.pdf 참고)에 포함된 언어 서버가 Gradle의
`annotationProcessor` 설정을 읽어 Lombok을 자동으로 인식합니다. 추가한 직후 인식이 안 되면:

- `Ctrl+Shift+P` → **Java: Clean Java Language Server Workspace** → *Restart and delete*
  (`1_스프링부트시작.md` 2.2절에서 이미 한 번 써 본 그 명령입니다).

## 4. 동작 확인

임시로 아무 클래스에나 붙여서 확인해 봅니다. `HelloController.java` 맨 위에 필드 하나를 추가:

```java
import lombok.Getter;
import lombok.Setter;

// ... @RestController 클래스 안 ...
@Getter @Setter
private String memo = "lombok 동작 확인용";
```

저장 후:

- **빨간 밑줄 없이** `getMemo()`/`setMemo(...)` 를 다른 코드에서 호출할 수 있으면 정상입니다
  (직접 작성한 적 없는 메서드인데 자동완성에 뜨는지 확인).
- 확인이 끝나면 이 필드는 지웁니다 — 실제 코드가 아니라 **점검용**입니다.

## 실습 — MyBatis 의존성 추가하기

같은 방법으로 이번엔 **MyBatis**를 추가해 보세요. (실제 DB 연결·매퍼 작성은 **Day 10**에서 하고,
오늘은 "의존성 추가" 절차만 연습합니다.)

1. mvnrepository에서 `mybatis-spring-boot-starter` 를 검색해 **Boot 4.0 대응 버전(4.0.1)** 좌표를
   찾으세요.
2. `build.gradle`의 `dependencies { }` 에 `implementation` 스코프로 추가하세요.
3. Gradle을 다시 읽고(IntelliJ Reload / VS Code 언어 서버 재시작), 아무 클래스에나
   `import org.apache.ibatis.annotations.Mapper;` 를 써서 빨간 밑줄 없이 임포트되는지 확인하세요
   (확인 후 지워도 됩니다 — 실제 `@Mapper` 사용은 Day 10).

**확인할 것**:
1. `build.gradle`에 추가한 한 줄을 그대로 적으세요.
2. `org.apache.ibatis.annotations.Mapper` 가 빨간 밑줄 없이 임포트되나요?
3. Lombok 때와 달리 MyBatis는 `annotationProcessor` 줄이 필요 없습니다 — 이유를 한 문장으로
   설명하세요(힌트: MyBatis는 컴파일 시점에 코드를 만들어 내는 도구가 아닙니다. 2절의 표와
   비교해 보세요).

> `mysql-connector-j` 는 `1_스프링부트시작.md`의 예시 `build.gradle`에 처음부터 들어 있었습니다
> (Day 10 대비로 미리 넣어 둔 것) — 오늘 추가로 넣을 필요는 없습니다.

## 자주 하는 실수

- **`compileOnly` 만 넣고 `annotationProcessor` 를 빠뜨림** → `@Getter`는 빨간 줄 없이 써지는데,
  실제로 `getX()` 를 호출하면 "메서드가 없다"는 컴파일 오류. 2절 표 참고 — 둘 다 있어야 합니다.
- **`build.gradle`을 고치고 Gradle을 다시 안 읽음** → IDE가 옛날 상태 그대로. 저장만으로 안 되면
  Reload를 직접 눌러야 합니다.
- **`plugins { }` 블록에 넣음** → Lombok·MyBatis는 **라이브러리**지 **빌드 플러그인**이 아닙니다.
  반드시 `dependencies { }` 안에.
- **IntelliJ에서 Lombok 플러그인 미설치** → 코드는 정상 컴파일되는데 **IDE에서만** 빨간 줄(오탐).
  빌드는 되는데 화면만 빨갛다면 이걸 의심하세요.

## 핵심 요약

| 요소 | 내용 |
|---|---|
| 의존성 나중에 추가 | `build.gradle`의 `dependencies { }` 에 좌표를 추가하면 끝 — 프로젝트 재생성 불필요 |
| Lombok = 두 줄 | `compileOnly`(참조) + `annotationProcessor`(코드 생성). 하나만 넣으면 반쪽 |
| IDE 반영 | IntelliJ는 Gradle Reload + Lombok 플러그인, VS Code는 언어 서버 재시작 |
| MyBatis는 한 줄 | `implementation` 만 있으면 됨 — 코드 생성 도구가 아니라서 `annotationProcessor` 불필요 |

> Lombok을 처음부터 넣고 프로젝트를 만들었다면 이 문서는 그냥 건너뛰고 **[2_컨트롤러.md](2_컨트롤러.md)**로.
