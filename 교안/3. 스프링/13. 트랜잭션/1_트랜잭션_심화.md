# Day 13. 트랜잭션 — 심화 (경험자용)

## 1. 전파 7종 정리

| 전파 | 기존 트랜잭션 있음 | 없음 |
|---|---|---|
| `REQUIRED`(기본) | 참여 | 새로 시작 |
| `REQUIRES_NEW` | 기존 보류(suspend), 새로 시작 | 새로 시작 |
| `NESTED` | 세이브포인트 생성(부분 롤백 가능) | 새로 시작 |
| `SUPPORTS` | 참여 | 트랜잭션 없이 실행 |
| `NOT_SUPPORTED` | 보류, 트랜잭션 없이 실행 | 트랜잭션 없이 |
| `MANDATORY` | 참여 | 예외 |
| `NEVER` | 예외 | 트랜잭션 없이 |

- `REQUIRES_NEW`: 별도 커넥션. 바깥이 롤백돼도 안쪽은 커밋됨(감사 로그). 데드락·풀 고갈 주의.
- `NESTED`: JDBC 세이브포인트. 드라이버 지원 필요. "이 하위 단계만 롤백" — 벌크 처리에서 실패 건 스킵.
- 바깥이 롤백되면 `REQUIRED` 로 참여한 안쪽도 함께 롤백. 안쪽에서 예외를 잡아도
  트랜잭션은 `rollback-only` 로 마킹되어 커밋 시 `UnexpectedRollbackException`.

## 2. 격리 수준(isolation)

`@Transactional(isolation = Isolation.REPEATABLE_READ)` — 보통 **DB 기본값**(MySInnoDB = REPEATABLE READ)을
그대로 둔다. 바꾸는 건 특수한 팬텀/논리 충돌 이슈가 명확할 때만. 애플리케이션 레벨 동시성은
낙관적 잠금(Day 11 심화) / `SELECT ... FOR UPDATE`(비관적)로 다루는 편이 명시적.

## 3. `timeout`, 롤백 마킹

```java
@Transactional(timeout = 3)   // 초. 넘으면 롤백
```
런타임에 롤백만 결정: `TransactionAspectSupport.currentTransactionStatus().setRollbackOnly();`
(예외를 삼켜야 하지만 롤백은 원할 때).

## 4. 커밋 이후 훅

트랜잭션이 **커밋된 뒤** 메일 발송·이벤트 발행:
```java
@TransactionalEventListener(phase = TransactionPhase.AFTER_COMMIT)
public void on(EmpRegistered e) { mailService.welcome(e.empId()); }
```
- 커밋 전에 메일 보냈다가 롤백되면 "가입 안 됐는데 환영 메일" 사고. AFTER_COMMIT 으로 방지.
- 이벤트는 `ApplicationEventPublisher.publishEvent(new EmpRegistered(id))` 로 서비스에서 발행.
- 저수준: `TransactionSynchronizationManager.registerSynchronization(...)`.

## 5. 트랜잭션과 스레드

- 트랜잭션 = 커넥션이 **스레드 로컬**에 바인딩. `@Async` 메서드나 새 스레드는 **별도 트랜잭션 없음**.
- 병렬 처리 시 각 작업이 자기 트랜잭션을 열게 설계.

## 6. 읽기 전용 라우팅

`AbstractRoutingDataSource` + `TransactionSynchronizationManager.isCurrentTransactionReadOnly()` 로
`readOnly=true` 면 읽기 복제본(replica)으로. 다만 커밋 직후 조회 시 복제 지연(replica lag) 주의 —
"쓰고 바로 읽기"는 primary 강제.

## 7. MyBatis + 스프링 트랜잭션 동작

- `SqlSessionTemplate` 이 스프링 트랜잭션에 참여(같은 커넥션 공유). 그래서 별도 설정 없이
  `@Transactional` 안의 여러 매퍼 호출이 한 트랜잭션.
- `logging.level.org.mybatis.spring: DEBUG` 로 세션/커밋 로그 확인.
- 1차 캐시(로컬 세션 캐시)는 트랜잭션(세션) 범위. 같은 트랜잭션에서 같은 쿼리 두 번이면 캐시될 수 있음
  (`localCacheScope=STATEMENT` 로 끄기 가능).

## 8. 테스트에서 롤백 뉘앙스

- `@SpringBootTest @Transactional` : 각 테스트 자동 롤백. **서비스 트랜잭션 검증엔 부적합**
  (테스트 트랜잭션이 바깥을 감싸 서비스의 커밋/롤백이 테스트 롤백에 흡수됨).
- 진짜 커밋/롤백을 보려면: 테스트에 `@Transactional` 안 붙이고 `@Sql` 또는 `@AfterEach` 정리,
  또는 `TestTransaction.flagForCommit()` / `end()`, 또는 Testcontainers로 격리.
- `@Commit`, `@Rollback(false)` 로 개별 제어.
