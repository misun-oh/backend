## 문제 1. Emp 계층 동작 확인

- `POST /api/emps` → `{"empId": 201}` (seq 가 200에서 시작해 +1)
- `GET /api/emps` → `[{"empId":201,"empName":"신입","hireDate":"2026-09-01","active":true,"deptName":null}]`
  (`deptName` 은 DEPT 조인 전이라 `null` — Day 11에서 채워짐)
- `GET /api/emps/201` 은 방금 만든 사원이 있으므로 정상. **없는 id(예: 999)** 로 호출하면
  `500` + `NoSuchElementException: 사원 없음: 999`.
  이유: `EmpServiceImpl.get()` 이 `findById(id).orElseThrow(...)` 로 없는 경우 예외를 던진다.
  (이 예외를 404로 예쁘게 바꾸는 건 Day 14 `@ControllerAdvice`.)

## 문제 2. Dept 계층

```java
// domain/Dept.java
@Getter @Builder @AllArgsConstructor @NoArgsConstructor
public class Dept {
    private Long deptId;
    private String deptName;
    private String location;
}

// dto/DeptForm.java
@Getter @Setter
public class DeptForm {
    private String deptName;
    private String location;
}

// repository/DeptRepository.java
public interface DeptRepository {
    List<Dept> findAll();
    Optional<Dept> findById(Long id);
    Dept save(Dept dept);
    void deleteById(Long id);
}

// repository/DeptMemoryRepository.java
@Repository
public class DeptMemoryRepository implements DeptRepository {
    private final Map<Long, Dept> store = new ConcurrentHashMap<>();
    private final AtomicLong seq = new AtomicLong(10);

    public List<Dept> findAll() { return new ArrayList<>(store.values()); }
    public Optional<Dept> findById(Long id) { return Optional.ofNullable(store.get(id)); }
    public Dept save(Dept d) {
        Long id = d.getDeptId() != null ? d.getDeptId() : seq.incrementAndGet();
        Dept toStore = Dept.builder().deptId(id).deptName(d.getDeptName()).location(d.getLocation()).build();
        store.put(id, toStore);
        return toStore;
    }
    public void deleteById(Long id) { store.remove(id); }
}

// service/DeptService.java
public interface DeptService {
    List<Dept> findAll();
    Long register(DeptForm form);
    void remove(Long id);
}

// service/DeptServiceImpl.java
@Service
@RequiredArgsConstructor
public class DeptServiceImpl implements DeptService {
    private final DeptRepository deptRepository;

    public List<Dept> findAll() { return deptRepository.findAll(); }

    public Long register(DeptForm form) {
        Dept saved = deptRepository.save(Dept.builder()
                .deptName(form.getDeptName()).location(form.getLocation()).build());
        return saved.getDeptId();
    }

    public void remove(Long id) {
        deptRepository.findById(id)
                .orElseThrow(() -> new NoSuchElementException("부서 없음: " + id));
        deptRepository.deleteById(id);
    }
}

// controller/DeptController.java
@RestController
@RequestMapping("/api/depts")
@RequiredArgsConstructor
public class DeptController {
    private final DeptService deptService;

    @GetMapping                 public List<Dept> list() { return deptService.findAll(); }
    @PostMapping                public Map<String, Long> create(@RequestBody DeptForm f) {
        return Map.of("deptId", deptService.register(f));
    }
    @DeleteMapping("/{id}")     public void delete(@PathVariable Long id) { deptService.remove(id); }
}
```

## 문제 3. 계층 규칙 위반

**위반 1**: Controller가 `EmpRepository` 를 **직접 주입·호출**(Service 건너뜀).
**위반 2**: `filter(e -> e.getSalary() >= 3_000_000)` — **업무 규칙이 Controller에 있음**.

고친 버전:

```java
// service 쪽에 추가
public interface EmpService {
    // ...
    List<Emp> findHighPaid(int threshold);
}

@Override
public List<Emp> findHighPaid(int threshold) {
    return empRepository.findAll().stream()
            .filter(e -> e.getSalary() >= threshold)
            .toList();
}

// controller
@RestController
@RequiredArgsConstructor
public class EmpQueryController {
    private final EmpService empService;

    @GetMapping("/api/emps/high-paid")
    public List<Emp> highPaid() {
        return empService.findHighPaid(3_000_000);
    }
}
```

## 문제 4. 구현 교체 실험

```java
@Primary
@Repository
public class EmpFakeRepository implements EmpRepository {
    public List<Emp> findAll() {
        return List.of(
            Emp.builder().empId(1L).empName("가짜1").hireDate(LocalDate.now()).active(true).build(),
            Emp.builder().empId(2L).empName("가짜2").hireDate(LocalDate.now()).active(true).build());
    }
    public Optional<Emp> findById(Long id) { return Optional.empty(); }
    public Emp save(Emp e) { return e; }
    public void deleteById(Long id) {}
}
```

`GET /api/emps` → 가짜1, 가짜2 두 명이 나온다.

**질문 답**: `EmpServiceImpl`·`EmpController` 는 **한 줄도 안 고쳤다.** 둘 다 `EmpRepository`
**인터페이스**에만 의존하고, 어떤 구현이 주입될지는 스프링이 `@Primary` 를 보고 결정하기 때문이다.
Day 9에서 `EmpMapper`(MyBatis)로 바꿀 때도 같은 이유로 상위 계층은 그대로 둔다.

## 문제 5. 순환 참조

두 서비스가 서로를 생성자 주입하면 기동 시:

```
The dependencies of some of the beans in the application context form a cycle:
  empServiceImpl → deptServiceImpl → empServiceImpl
```

**설계로 푸는 방법 (예)**

- "부서의 소속 사원 수"가 필요해서 `DeptService` 가 `EmpService` 를 불렀다면 →
  `EmpRepository` 에 `long countByDeptId(Long deptId)` 를 두고 `DeptServiceImpl` 이 그것을 직접 쓴다.
  (서비스→서비스 호출을 서비스→리포지토리 호출로 낮춤)
- 또는 목록 화면용 통계는 Day 11에서 `DeptMapper.selectAllWithStats()` 처럼 SQL 조인 한 번으로 해결.
- 그래도 상호 호출이 불가피하면, 한 방향을 이벤트(`ApplicationEventPublisher`)로 바꾼다.
