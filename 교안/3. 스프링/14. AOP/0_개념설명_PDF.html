AOP

Aspect-Oriented Programming — 흩어진 코드를 한곳에, 프록시로 끼워 넣기

Day 13에서 @Transactional 하나만 붙였는데 커밋·롤백이 자동으로 됐던 것, 기억하시나요? 그 마법의 정체가 오늘 배울 AOP입니다 — 메서드에 코드를 한 줄도 안 더했는데 어떻게 트랜잭션이 걸렸는지, 원리를 직접 만들어 보며 풉니다.

4 한계 — 같은 클래스 내부 호출

  ctl["Controller"] -->|"프록시 통과 → @Timed 동작"| a["a() 호출"]

해결책

  • 대상 메서드를 다른 빈으로 분리(가장 깔끔)
  • ObjectProvider로 자기 자신을 프록시로 주입

스프링 AOP 한계 정리

  • 같은 클래스 내부 호출(self-invocation)엔 안 걸림
  • private 메서드엔 안 걸림(프록시 기반이라 public만)

그래서 — @Transactional도 AOP다

  • @Transactional → 프록시가 앞에서 트랜잭션 시작, 정상 반환 시 커밋, 예외 시 롤백
  • @Cacheable → 캐시에 있으면 진짜 메서드 호출 없이 반환
  • @PreAuthorize(부록 3) → 권한 없으면 진짜 메서드 호출 전에 차단
  • 셋 다 "메서드 호출을 가로채는 프록시" 라는 같은 원리 — Day 13에서 이미 써 봤던 그 동작의 정체입니다.
