## 학습목표

- **프로토타입**이 무엇이고, `2. 프로토타입/` 폴더가 왜 스프링 부트의 `static/`·`templates/`
  구조 그대로 만들어져 있는지 설명할 수 있다.
- 프로토타입의 `css`/`js`는 `src/main/resources/static/`, `html`은 `templates/`에 나눠 담고,
  `@Controller`로 Day 1 설계 URL(`/emps`, `/depts` …)에 뷰 이름을 연결할 수 있다.
- 프로토타입 안의 상대경로 링크(`href="depts.html"`)가 실제 매핑 주소와 왜 어긋나는지 설명하고,
  실제 주소에 맞게 고칠 수 있다.
- DevTools로 코드 수정을 바로 반영할 수 있다.

## 1. hr 프로토타입 화면 붙이기

Day 1 설계 때 만든 **hr 프로토타입**(`2. 프로토타입/`)을 이 프로젝트에 얹어, `main()` 을 실행하면
바로 사원관리 화면이 뜨게 만듭니다. 오늘은 **정적 파일 그대로** 서빙합니다(데이터는 프로토타입에
박혀 있는 고정 HTML). 실제 DB 데이터로 채우는 서버 렌더링은 **Day 6~10**.

### 1.1 프로토타입이란? — `2. 프로토타입/` 폴더 살펴보기

**프로토타입(prototype)**은 실제 서버 로직·DB 없이, 화면 디자인과 **화면 간 이동 흐름**만 먼저
만들어 보는 것입니다. "이 버튼을 누르면 이 화면으로 간다"를 컨트롤러·서비스·DB 코드를 짜기
전에 HTML 만으로 미리 확인해 보는 게 목적입니다. Day 1 설계 때 만든 `2. 프로토타입/` 의 `hr/`
화면 5개(대시보드·목록·상세·등록/수정 폼·부서)가 그 결과물입니다.

폴더를 열어보면:

```
2. 프로토타입/
├── static/
│   ├── css/   basic.css  component.css  app-shell.css  hr.css  ...
│   └── js/    component.js  app-shell.js
└── templates/
    └── hr/    index.html  depts.html  dashboard.html  emp-detail.html  emp-form.html  _menu.html
```

**이미 스프링 부트 구조 그대로입니다.** `src/main/resources/` 아래의 `static/`·`templates/`
와 폴더 이름이 똑같습니다 — "그대로 복사해서 스프링 프로젝트에 넣을 수 있게" 처음부터 이렇게
나눠 둔 것입니다.

그런데 `templates/hr/*.html` 안을 보면, 화면끼리 이동하는 링크가 서버 주소(`/emps` 같은 것)가
아니라 **그냥 옆 파일 이름**입니다.

```html
<a href="index.html">사원 목록</a>
<a href="depts.html">부서</a>
<a href="emp-detail.html">상세</a>
```

그래서 스프링도, 컨트롤러도, DB 도 하나 없어도 이 HTML 파일들만 있으면 **화면에서 화면으로
클릭해서 넘어가는 게 그대로 동작**합니다 — 진짜 프로토타입답게 "화면 흐름"만큼은 이미 완성돼
있는 것입니다. (다만 CSS·JS 는 `/css/...` 처럼 스프링식 절대경로라서, 파일을 그냥 더블클릭해서
열면 스타일 없이 날것으로 보입니다 — 오늘처럼 스프링 프로젝트 안에서 실행해야 CSS 까지 완전하게
보입니다.)

실무에서는 이렇게 **디자이너가 화면 디자인을 미리 만들어서 개발자에게 넘겨주는 경우**가 많습니다
— HTML·CSS·JS 로 된, 클릭하면 화면이 넘어가는 "진짜처럼 동작하는" 결과물이죠. 개발자가 할 일은
이걸 그대로 베끼는 게 아니라, **스프링 프로젝트의 리소스 폴더 구조(`static/`·`templates/`)에
맞게 나눠 담고**, 서버가 실제로 처리할 주소(라우팅)에 연결하는 것입니다. 오늘 우리가 할 일이
정확히 이겁니다 — 디자이너의 프로토타입을 리소스 폴더로 옮겨 담아 봅니다.

### 1.2 파일 복사

프로토타입 폴더의 파일을 프로젝트 `src/main/resources/` 아래로 **폴더 구조 그대로** 나눠 담습니다
— `static/`은 `static/`으로, `templates/`은 `templates/`으로.

| 프로토타입(리소스 경로) | 복사 위치 |
|---|---|
| `2. 프로토타입/static/css/` (`basic.css` `component.css` `app-shell.css` `hr.css`) | `src/main/resources/static/css/` |
| `2. 프로토타입/static/js/` (`component.js`) | `src/main/resources/static/js/` |
| `2. 프로토타입/templates/hr/*.html` (5개 화면) | `src/main/resources/templates/hr/` |

```
src/main/resources/
├── static/
│   ├── css/  basic.css  component.css  app-shell.css  hr.css
│   └── js/   component.js
└── templates/
    ├── greeting.html          ← 2_컨트롤러.md 1절에서 만든 것
    └── hr/   index.html  depts.html  dashboard.html  emp-detail.html  emp-form.html
```

> **`app-shell.js` 는 복사하지 않습니다.** 예전엔 이 스크립트가 헤더/푸터를 JS로 그려 넣었지만,
> 지금 프로토타입은 각 페이지에 헤더/푸터 마크업이 **그대로 들어 있습니다**(공통 원본은
> `2. 프로토타입/templates/hr/_menu.html` — "메뉴 폼"). 다크 모드 토글·모달 같은 동작은
> `component.js` 가 알아서 초기화합니다. (Day 10에서 이 메뉴 폼을 Thymeleaf fragment 로 바꿔
> 페이지마다 한 줄로 재사용합니다.)

> **`css`/`js` 는 `static/`, `html` 은 `templates/` 인 이유**: CSS·JS 는 브라우저가 주소로 **직접**
> 요청하는 정적 리소스라서 `static/`(`<link href="/css/basic.css">` 그대로 동작). HTML 화면은
> `@Controller` 가 **뷰 이름으로 지목해서 렌더링**할 것이므로 `templates/` — 2_컨트롤러.md 1절에서
> 배운 `return "greeting";` 과 똑같은 원리를, `hr` 화면 5개에 그대로 적용하는 것입니다.

### 1.3 설계 URL 연결 — `EmpController`

파일만 복사해서는 아직 아무 URL 도 안 뜹니다 — `templates/` 는 컨트롤러가 뷰 이름으로 지목해야만
렌더링되기 때문입니다. **Day 1 설계에서 정한 주소**(`/`, `/emps`, `/depts` …)에 각각 뷰 이름을
반환하는 메서드를 만들어 연결합니다.

| 설계 화면 | URL (설계) | 반환하는 뷰 이름 | Day 6 |
|---|---|---|---|
| 대시보드 | `GET /` | `"hr/dashboard"` | `Model` + 같은 뷰 |
| 사원 목록·검색 | `GET /emps` | `"hr/index"` | 뷰 `hr/index` + 사원 리스트 |
| 사원 상세 | `GET /emps/{id}` | `"hr/emp-detail"` | `@PathVariable id` 로 조회 |
| 사원 등록 폼 | `GET /emps/new` | `"hr/emp-form"` | 빈 폼 객체 |
| 사원 수정 폼 | `GET /emps/{id}/edit` | `"hr/emp-form"` | id 로 조회한 값 채운 폼 |
| 부서 목록 | `GET /depts` | `"hr/depts"` | 뷰 `hr/depts` + 부서 리스트 |
| 로그인 | `POST /login` | `"hr/dashboard"` (자리만) | Spring Security (**Day 17**) |

```java
package com.example.hr.controller;

import org.springframework.stereotype.Controller;
import org.springframework.web.bind.annotation.GetMapping;
import org.springframework.web.bind.annotation.PathVariable;
import org.springframework.web.bind.annotation.PostMapping;

@Controller
public class EmpController {

    @GetMapping("/")                 public String dashboard()   { return "hr/dashboard"; }

    @GetMapping("/emps")             public String empList()      { return "hr/index"; }
    @GetMapping("/emps/new")         public String empNewForm()   { return "hr/emp-form"; }   // {id} 보다 먼저 매칭
    @GetMapping("/emps/{id}")        public String empDetail(@PathVariable String id)   { return "hr/emp-detail"; }
    @GetMapping("/emps/{id}/edit")   public String empEditForm(@PathVariable String id) { return "hr/emp-form"; }

    @GetMapping("/depts")            public String deptList()     { return "hr/depts"; }

    @PostMapping("/login")           public String login()        { return "hr/dashboard"; }   // 실제 인증은 Day 17
}
```

- `redirect:` 를 쓰지 않았습니다 — 파일이 이미 `templates/` 안에 있으니, 뷰 이름을 **그대로**
  반환하면 됩니다(2_컨트롤러.md 1절과 동일한 방식). 주소창도 안 바뀌고, 응답 상태코드도 200입니다.
- **`{id}` 는 오늘은 안 씁니다** — `/emps/200` 이든 `/emps/999` 든 같은 상세 화면으로 갑니다.
  URL 에서 값을 꺼내는 `@PathVariable` 은 **Day 6**에서 실제로 사용합니다.
- `/emps/new` 를 `/emps/{id}` 보다 **위에** 두면 스프링이 구체적 경로를 먼저 잡습니다(순서 무관하게
  스프링이 "더 구체적인 것" 우선이지만, 읽는 사람을 위해 위에 둡니다).

### 1.4 실행 확인 — 그리고 발견하는 문제

`main()` 실행 → `http://localhost:8080/` 접속:

- 헤더(👔 사원관리) + 대시보드 통계 카드가 있는 **완성된 화면**이 뜹니다.
- `http://localhost:8080/emps`, `/depts` 로 직접 주소를 쳐서 들어가면 그 화면도 잘 뜹니다.

그런데 **화면 안의 메뉴("사원 목록"·"부서"·"대시보드")나 "상세"·"수정" 링크를 클릭하면 404 가
납니다.** 왜 그럴까요?

프로토타입 HTML 안의 이동 링크는 원래 `<a href="depts.html">` 처럼 **같은 폴더의 옆 파일**을
가리키던 상대경로입니다. 프로토타입 폴더 안에서는(모든 화면이 `hr/` 한 폴더 안에 나란히 있으니)
이 상대경로가 정확히 맞았습니다. 하지만 지금은 `/emps` 라는 주소에서 렌더링되고 있고, 브라우저는
**서버의 폴더 구조를 전혀 모른 채 지금 주소창의 URL 기준으로** 상대경로를 계산합니다 — `/emps`
에서 `depts.html` 은 `/depts.html` 로 계산되는데, 우리가 매핑해 둔 진짜 주소는 `.html` 이 없는
`/depts` 라서 어긋납니다.

```
/emps 에서 <a href="depts.html"> 클릭
  → 브라우저 계산: /depts.html
  → 실제 매핑: /depts        ← 문자열이 달라서 404
```

> **디자이너가 준 프로토타입의 링크를, 실제 서버 주소에 맞게 고치는 것** — 이게 오늘 여러분이
> 직접 할 일입니다(실습 참고). `@GetMapping` 의 주소 문자열과 `templates/` 안 파일의 위치는
> 서로 무관하다는 걸 앞에서 봤죠? 그러니 "파일을 어디 두느냐"가 아니라 "HTML 안의 `href` 를 실제
> 매핑 주소(`/depts`, `/emps` 등)에 맞게 고치는" 방향으로 해결합니다.

> **참고**: 테이블의 사원들은 프로토타입에 박아 둔 **고정 HTML** 입니다. Day 6 에서
> `@Controller` 가 `Model` 에 진짜 사원 리스트를 담고, `th:each`·`th:href` 같은 Thymeleaf 문법으로
> 이 링크 문제까지 자연스럽게 해결합니다 — 오늘은 "왜 이런 문제가 생기는지"만 이해하면 충분합니다.

## 2. DevTools — 저장하면 바로 반영

`spring-boot-devtools` 가 있으면:

- **자동 재시작**: `src/main` 의 클래스를 저장하면 앱이 빠르게 재기동(전체 재시작보다 훨씬 빠름).
- **정적 리소스 즉시 반영**: `templates/`, `static/` 변경은 재시작 없이 반영.
- **캐시 비활성화**: 개발 중 Thymeleaf 템플릿 캐시 등을 자동으로 끔.

IntelliJ에서 자동 재시작이 안 되면 두 가지를 켭니다.

1. `Settings > Build, Execution, Deployment > Compiler` → **Build project automatically** 체크
2. `Settings > Advanced Settings` → **Allow auto-make to start ... even if the developed application is currently running** 체크

그래도 안 되면 코드 저장 후 `Ctrl+F9`(Build Project)를 눌러 수동 트리거합니다.

## 자주 하는 실수

- **프로토타입은 떴는데 CSS 가 안 먹고 날것으로 보임** → CSS·JS 가 `src/main/resources/static/` 아래에 있는지 확인(`/css/basic.css` 로 접속돼야 함). `templates/` 안에 둔 CSS·JS 는 서빙되지 않음 — 정적 리소스는 반드시 `static/`.
- **`http://localhost:8080/` 나 `/emps` 가 404** → 설계 URL 을 처리하는 매핑이 없어서. `EmpController` 가 각 주소에 뷰 이름을 반환하는지 확인 (1.3).
- **화면 안 메뉴·상세·수정 링크를 누르면 404** → 프로토타입 HTML 의 상대경로 링크(`href="depts.html"`)가 실제 매핑 주소(`/depts`)와 문자열이 달라서 그렇습니다. **버그가 아니라 오늘의 실습 과제**입니다 (1.4 참고) — 링크를 실제 매핑 주소에 맞게 고치세요.
- **`@GetMapping` 주소를 바꿨는데도 안 된다** → `@GetMapping` 의 주소 문자열과 `templates/` 안 파일 위치는 서로 무관합니다. 뷰 이름(`return "hr/depts";`)이 `templates/hr/depts.html` 을 찾는 것이지, `@GetMapping` 주소와는 관계없습니다 (1.3 참고).
- **코드를 저장했는데 반영 안 됨** → DevTools 재시작이 안 걸린 것. 2절의 IntelliJ 설정 확인, 또는 앱 재시작.

## 핵심 요약

| 요소 | 역할 | 비고 |
|---|---|---|
| `src/main/resources/static/` | 정적 리소스(css·js)를 주소 `/` 에 그대로 공개 | 무수정 동작(1.2) |
| `src/main/resources/templates/` | `@Controller` 가 뷰 이름으로 지목해야 렌더링 | hr 화면 5개는 여기(1.2), `redirect:` 불필요(1.3) |
| `@GetMapping` 주소 vs 뷰 이름 | 서로 완전히 독립적 | 주소는 라우팅용, 뷰 이름은 `templates/` 파일 탐색용(1.3) |
| 상대경로 링크가 깨지는 이유 | 브라우저는 서버 폴더 구조를 모르고 **현재 URL 기준**으로만 상대경로 계산 | `/emps` 에서 `depts.html` → `/depts.html`(매핑 안 됨) (1.4) |
| DevTools | 저장 시 자동 재시작 | `developmentOnly` 의존성 |
