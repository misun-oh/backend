# Day 12. 로그인과 권한 — 실습

## 문제 1. `MEMBER` 시드 데이터 + 로그인

`MEMBER` 테이블에 `admin`/`1234`(`ROLE='ADMIN'`), `user`/`1234`(`ROLE='USER'`) 두 계정을
`BCryptPasswordEncoder`로 해시해서 넣으세요(짧은 `main` 메서드나 테스트로 해시값을 한 번
출력해서 `INSERT` 문에 붙여넣어도 됩니다). `/login` 폼으로 두 계정 모두 로그인되는지 확인하세요.

## 문제 2. 로그인 실패 메시지

존재하지 않는 아이디, 틀린 비밀번호 두 경우 모두 `login.html`에 "아이디 또는 비밀번호가
올바르지 않습니다"가 뜨는지 확인하세요. 아이디는 맞고 비밀번호만 틀렸을 때 "아이디가
존재하지 않습니다"처럼 **아이디 존재 여부를 알려주는 메시지로 바꾸면 안 되는 이유**를 한 줄로 적으세요.

## 문제 3. `LoginCheckInterceptor` 적용

인터셉터를 등록하고, 로그인하지 않은 상태로 `/emps`에 접속하면 `/login`으로 리다이렉트되는지
확인하세요. `/login`, `/css/**`를 `excludePathPatterns`에서 빼먹으면 어떤 현상이 나는지
직접 재현하고 설명하세요.

## 문제 4. 헤더에 로그인 사용자 표시

공통 레이아웃(`fragments/menu.html` 등)에 `th:if="${loginMember != null}"` 로그인 상태
표시를 붙이고, 로그아웃 버튼(`POST /logout`)을 추가하세요.

## 문제 5. (개념) 세션과 쿠키

`session.invalidate()`를 호출해도 브라우저에 `JSESSIONID` 쿠키 자체는 남아있을 수 있습니다.
그런데도 로그아웃이 되는 이유를 한 문단으로 설명하세요.

## 문제 6. `AdminOnlyInterceptor` 적용

`/depts/**`에 `AdminOnlyInterceptor`를 등록하세요. `user`로 로그인한 상태에서 `/depts`에
접속하면 403이 나고, `admin`으로 로그인하면 정상 접근되는지 확인하세요. 두 인터셉터
(`LoginCheckInterceptor`, `AdminOnlyInterceptor`)의 등록 순서를 바꿔서 실행해 보고,
비로그인 상태로 `/depts`에 접속했을 때 결과가 어떻게 달라지는지(또는 안 달라지는지) 적으세요.
