## 문제 1. `cond` 확장 + 정렬 enum

`1_동적SQL과검색.md` 실습에서 만든 `EmpSearchCond` 에 `sort`(`EmpSort`), `page`(기본 1),
`size`(기본 10), `getOffset()` 을 추가하세요. `dto/EmpSort` enum(`EMP_ID`/`HIRE_DATE`/`SALARY`/
`NAME`, column·direction) 도 만드세요.

## 문제 2. `LIMIT` + `COUNT`

`EmpMapper.selectByCond` 에 `ORDER BY ${sort.column} ${sort.direction}` 와
`LIMIT #{size} OFFSET #{offset}` 을 추가하고, `EmpMapper.countByCond(EmpSearchCond)` 를
새로 만드세요. 두 SQL 모두 `searchWhere` 를 `<include>` 로 공유해야 합니다.

테스트:
- `size=10, page=1` → `selectByCond` 결과 10건, `countByCond` 결과 21
- `page=3` → `selectByCond` 결과 1건, `countByCond` 결과는 여전히 21 (조건은 그대로이므로)

## 문제 3. `PageDto` 로 페이지 네비게이션

`EmpService.selectByCond(cond, model)` 이 `countByCond` 결과로 `new PageDto(cond.getPage(),
totalCnt)` 를 만들어 모델에 담도록 구현하세요.

테스트:
- `page=1` 요청 → `pageDto.getSPageNo()==1`, `pageDto.isPrev()==false`
- 마지막 페이지 요청 → `pageDto.isNext()==false`

## 문제 4. 정렬 화이트리스트

`?sort=SALARY` 로 요청 시 급여 내림차순 첫 행이 곽상혁(8,000,000)인지 확인하세요.
컨트롤러 파라미터를 `?sort=DROP TABLE` 로 호출하면 무슨 일이 일어나는지 확인하고, 왜 그런
결과가 나오는지 설명해보세요. (enum 변환 실패)

## 문제 5. 화면 페이지네이션
