# Day 11-2. 페이징 — 심화 (경험자용)

## 1. OFFSET 페이징의 한계와 키셋(cursor) 페이징

`LIMIT n OFFSET m` 은 m이 커질수록 앞의 m행을 읽고 버려서 느려진다(딥 페이징).
정렬 키가 유일하면 **키셋 페이징**:

```sql
-- 다음 페이지: 마지막으로 본 행의 (hire_date, emp_id) 이후
WHERE (e.hire_date, e.emp_id) < (#{lastHireDate}, #{lastEmpId})
ORDER BY e.hire_date DESC, e.emp_id DESC
LIMIT #{size}
```
- 장점: 항상 인덱스로 시작점 점프 → 일정한 속도. 무한 스크롤에 적합.
- 단점: "5페이지로 바로 가기" 불가, 정렬 바꾸면 커서 무효. `PageDto` 처럼 페이지 번호가 필요한
  관리자 목록은 OFFSET(`2_페이징.md` 방식)을 유지.

## 2. COUNT 최적화

- 조인이 결과 수에 영향 없으면 COUNT는 `FROM 기준테이블` 만 (`2_페이징.md`의 `countByCond` 참고).
- `WHERE` 가 인덱스를 타게. `LEFT JOIN ... IS NULL` 같은 건 COUNT에서 서브쿼리로.
- 전체 건수가 꼭 필요 없으면(무한 스크롤) COUNT 생략. "다음 있음?"만: `LIMIT size+1` 로 한 건 더 읽어 판단.
- 매우 큰 테이블은 근사치(`information_schema` 통계, 별도 집계 테이블).

## 3. `PageDto`의 고정 페이지 크기 풀어주기

본문(`2_페이징.md`)의 `PageDto`는 페이지당 건수가 `private int size = 10;` 으로 고정되어 있어,
`cond.size`를 바꾸면 실제 조회 건수와 페이지 네비게이션이 어긋난다(본문 3절 주의 참고). "페이지당
20개씩 보기" 같은 기능이 필요하면 `PageDto`에 `size`를 받는 생성자를 추가해야 한다.

```java
public PageDto(int page, int totalCnt, int size) {
    this.page = page;
    this.totalCnt = totalCnt;
    this.size = size;   // 하드코딩된 10 대신 파라미터로 받음
    // 이하 eNo/sNo/ePageNo/sPageNo/isPrev/isNext 계산은 기존 (page, totalCnt) 생성자와 동일
}

// 기존 호출부(new PageDto(page, totalCnt))를 깨지 않도록, 기본값 10을 넘기는 오버로드로 남겨둔다
public PageDto(int page, int totalCnt) {
    this(page, totalCnt, 10);
}
```

> 이렇게 3-인자 생성자를 새로 만들고, 기존 2-인자 생성자는 `size=10`을 채워 3-인자 생성자를
> 호출하도록 바꾸면(`this(...)` 위임), 지금까지의 `new PageDto(cond.getPage(), totalCnt)` 호출
> 코드는 그대로 두면서 `new PageDto(cond.getPage(), totalCnt, cond.getSize())` 도 쓸 수 있다.

## 4. 스프링 데이터 `Pageable` / PageHelper

- `Pageable`(`spring-data-commons`)을 컨트롤러 파라미터로 받으면 `?page=0&size=10&sort=salary,desc` 자동 바인딩.
  MyBatis에는 기본 연동이 없어 `pageable.getPageNumber()/getPageSize()/getSort()` 를 직접 꺼내 씀.
  hr 프로젝트의 `EmpSearchCond`+`PageDto` 조합은 이걸 학습용으로 직접 구현해본 것이라고 볼 수 있다.
- **PageHelper**(`pagehelper-spring-boot-starter`): `PageHelper.startPage(page, size)` 한 줄로 다음
  쿼리에 자동 LIMIT + COUNT. 편하지만 ThreadLocal 기반이라 "startPage 후 반드시 바로 그 쿼리 하나"
  규칙을 어기면 엉뚱한 쿼리에 페이징이 붙는 함정. 팀 합의하에. (Boot 4 지원 버전인지 릴리스 노트 확인)
