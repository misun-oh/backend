# Day 18. 인증 심화

| 항목 | 내용 |
|---|---|
| 선수학습 | Day 17(폼 로그인·`UserDetailsService`·권한), Day 8(Thymeleaf) |
| 이번 챕터 | 커스텀 `UserDetails` → `@AuthenticationPrincipal` 로 로그인 사용자 사용 → Thymeleaf `sec:*` 로 권한별 메뉴 → CSRF 심화 → 세션 관리(동시 세션·만료) → 접근 거부(403) 처리 |
| 권장 진행 | 1일 |

## 학습목표

- `Member` 를 감싼 커스텀 `UserDetails` 로 도메인 정보(이름·부서)를 인증 객체에 담는다.
- 컨트롤러·서비스에서 `@AuthenticationPrincipal` 로 현재 로그인 사용자를 안전하게 얻는다.
- Thymeleaf `sec:authorize`, `sec:authentication` 으로 권한별로 메뉴·버튼을 보이거나 숨긴다.
- CSRF가 언제 필요하고 `fetch` 요청에서 토큰을 어떻게 보내는지 안다.
- 동시 세션 제한·세션 만료·로그아웃 후 처리를 설정한다.
- 미인증(401)과 권한 없음(403)을 구분해 처리한다.

## 1. 커스텀 `UserDetails`

Day 17은 표준 `User` 를 반환했습니다. 화면에서 "홍길동님" 처럼 **이름**을 쓰려면 도메인 정보를 담습니다.

```java
@Getter
public class MemberPrincipal implements UserDetails {

    private final Member member;                 // 도메인 객체 통째로
    private final List<GrantedAuthority> authorities;

    public MemberPrincipal(Member member, List<String> roles) {
        this.member = member;
        this.authorities = roles.stream()
                .map(r -> new SimpleGrantedAuthority("ROLE_" + r))
                .collect(Collectors.toList());
    }

    @Override public Collection<? extends GrantedAuthority> getAuthorities() { return authorities; }
    @Override public String getPassword() { return member.getPassword(); }
    @Override public String getUsername() { return member.getUsername(); }
    @Override public boolean isEnabled() { return member.isEnabled(); }
    @Override public boolean isAccountNonExpired() { return true; }
    @Override public boolean isAccountNonLocked() { return true; }
    @Override public boolean isCredentialsNonExpired() { return true; }

    public String getDisplayName() { return member.getName(); }   // 편의 메서드
}
```

```java
@Override
public UserDetails loadUserByUsername(String username) {
    Member m = memberMapper.findByUsername(username);
    if (m == null) throw new UsernameNotFoundException(username);
    return new MemberPrincipal(m, memberMapper.findRoles(m.getMemberId()));
}
```

## 2. `@AuthenticationPrincipal`

컨트롤러에서 현재 로그인 사용자:

```java
@GetMapping("/my")
public String my(@AuthenticationPrincipal MemberPrincipal me, Model model) {
    model.addAttribute("name", me.getDisplayName());
    model.addAttribute("memberId", me.getMember().getMemberId());
    return "member/my";
}
```

- 로그인 안 했으면 `me` 는 `null`(경로가 `permitAll` 인 경우). 인증 필요 경로면 여기 오기 전에 이미 차단됨.
- 필드만 필요하면 SpEL: `@AuthenticationPrincipal(expression = "member.name") String name`.
- 어디서나: `SecurityContextHolder.getContext().getAuthentication().getPrincipal()` (테스트·비컨트롤러).

> 로그인한 사원이 **자기 정보만** 수정하게 하려면: 서비스에서
> `if (!me.getMember().getMemberId().equals(targetOwnerId)) throw new AccessDeniedException(...)`.

## 3. Thymeleaf 권한별 화면

`org.thymeleaf.extras:thymeleaf-extras-springsecurity6` 를 추가하면 `sec:` 방언이 자동 구성됩니다
(`spring-boot-starter-thymeleaf` 가 자동으로 끌고 오지 않으므로 직접 추가). 버전은 부트 BOM 이 관리 —
직접 적지 마세요. 네임스페이스:

```html
<html xmlns:th="http://www.thymeleaf.org"
      xmlns:sec="http://www.thymeleaf.org/extras/spring-security">
```

```html
<!-- 로그인 상태에 따라 헤더 우측 -->
<div sec:authorize="isAnonymous()">
  <a class="btn btn--primary btn--sm" th:href="@{/login}">로그인</a>
</div>
<div sec:authorize="isAuthenticated()">
  <span class="user-chip">
    <span class="avatar avatar--sm" sec:authentication="principal.displayName">홍</span>
    <span sec:authentication="principal.displayName">홍길동</span>
  </span>
  <form th:action="@{/logout}" method="post" style="display:inline">
    <button class="btn btn--secondary btn--sm">로그아웃</button>
  </form>
</div>

<!-- ADMIN 에게만 부서 메뉴 -->
<a sec:authorize="hasRole('ADMIN')" th:href="@{/depts}">부서 관리</a>

<!-- 삭제 버튼은 ADMIN 만 -->
<button sec:authorize="hasRole('ADMIN')" class="btn btn--danger" type="submit">삭제</button>
```

- `sec:authorize="표현식"` : 표현식이 참일 때만 그 요소를 렌더링(아니면 DOM에서 제거).
- `sec:authentication="principal.xxx"` : 인증 객체의 값 출력.
- **주의**: 화면에서 버튼을 숨겨도 **서버 인가는 별도로** 걸어야 함(URL 직접 호출 방어).
  `authorizeHttpRequests` 또는 `@PreAuthorize`.

이제 프로토타입 `app-shell.js` 가 하던 "로그인/로그아웃 헤더 토글"이 **서버 렌더링**으로 대체됩니다.

## 4. CSRF 심화

- **필요한 경우**: 세션 쿠키 기반 인증 + 상태 변경 요청(POST/PUT/DELETE). 브라우저가 쿠키를
  자동 첨부하므로, 다른 사이트가 우리 세션으로 위조 요청 가능 → 토큰으로 "우리 폼에서 온 요청"임을 증명.
- **불필요**: `Authorization: Bearer` 헤더 기반(JWT, Day 19) — 브라우저가 자동으로 안 붙이므로.
- Thymeleaf `<form>` 은 hidden `_csrf` 자동 삽입. `fetch` 는 직접:

```html
<meta name="_csrf" th:content="${_csrf.token}">
<meta name="_csrf_header" th:content="${_csrf.headerName}">
```
```js
const token  = document.querySelector('meta[name=_csrf]').content;
const header = document.querySelector('meta[name=_csrf_header]').content;
fetch('/emps/205/photo', { method: 'POST', headers: { [header]: token }, body: fd });
```

- SPA + 쿠키 인증이면 `CookieCsrfTokenRepository.withHttpOnlyFalse()` 로 JS가 읽는 `XSRF-TOKEN` 쿠키.

## 5. 세션 관리

```java
http.sessionManagement(s -> s
    .sessionFixation(sf -> sf.changeSessionId())      // 로그인 시 세션ID 교체(고정공격 방지, 기본값)
    .maximumSessions(1)                               // 한 계정 동시 접속 1개
    .maxSessionsPreventsLogin(false)                  // 새 로그인 시 → 기존 세션 만료
    .expiredUrl("/login?expired"));
```
```yaml
server:
  servlet:
    session:
      timeout: 30m       # 무활동 30분 후 만료
```
- `maxSessionsPreventsLogin(true)` 면 "이미 로그인 중입니다" 로 새 로그인 거부.
- 만료된 세션으로 요청 시 `expiredUrl` 로. AJAX는 401을 받도록 별도 처리.
- 로그아웃: `invalidateHttpSession(true)`, `deleteCookies("JSESSIONID")` (Day 17 설정).

## 6. 접근 거부(403) 처리

```java
http.exceptionHandling(e -> e
    .accessDeniedPage("/error/403")                  // 인증됐지만 권한 없음
    // 미인증(401)은 formLogin 이 로그인 페이지로 보냄
);
```

`error/403.html` 을 layout fragment 로. API 경로는 JSON 403이 나가도록 `@RestControllerAdvice` 에
`AccessDeniedException` 핸들러 또는 `AccessDeniedHandler` 빈.

`@PreAuthorize` 실패(메서드 보안)도 `AccessDeniedException` → 같은 경로로 처리.

## 자주 하는 실수

- **화면에서 버튼만 숨기고 서버 인가 안 함** → URL·API 직접 호출로 우회. `authorizeHttpRequests`/`@PreAuthorize` 필수.
- **`@AuthenticationPrincipal` 타입이 실제 principal과 다름** → `null`. `UserDetailsService` 가 반환하는 타입과 일치.
- **`sec:` 네임스페이스 미선언 / extras 의존성 없음** → `sec:authorize` 가 무시되어 다 보임.
- **CSRF 끄고 폼 유지** → CSRF 공격 노출. 폼은 켜고 JWT/API만 제외.
- **`fetch` POST에서 CSRF 토큰 누락** → 403 Forbidden. 메타 태그로 헤더 전송.
- **동시 세션 제한을 켰는데 `HttpSessionEventPublisher` 빈이 없음(비부트)** → 세션 카운트가 안 됨(부트는 자동).
- **로그아웃을 GET으로** → CSRF 활성 시 `logout` 은 POST. `<form method="post">`.
