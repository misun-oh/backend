## 문제 1. 커스텀 `UserDetails`

`MemberPrincipal implements UserDetails` (Member + roles, `getDisplayName()`) 를 만들고
`DbUserDetailsService` 가 이걸 반환하도록 바꾸세요. 로그인이 여전히 되는지 확인.

## 문제 2. `@AuthenticationPrincipal`

`GET /my` 컨트롤러에서 `@AuthenticationPrincipal MemberPrincipal me` 로 로그인 사용자의
이름·아이디·권한을 화면에 표시하세요. (`me` 가 null이면 어떤 경우인지도 생각)

## 문제 3. 권한별 화면

`fragments/layout.html` 헤더를:
- 비로그인: "로그인" 버튼 (`sec:authorize="isAnonymous()"`)
- 로그인: 사용자 이름 + "로그아웃" 폼 (`sec:authorize="isAuthenticated()"`, `sec:authentication="principal.displayName"`)
- "부서 관리" 링크는 `sec:authorize="hasRole('ADMIN')"`

`emp/detail.html` 의 삭제 버튼도 `sec:authorize="hasRole('ADMIN')"` 로.
**추가로**: `POST /emps/{id}/delete` 를 서버에서도 `hasRole('ADMIN')` 으로 막으세요(화면만 숨기면 안 됨).

## 문제 4. CSRF + fetch

`emp/detail.html` 의 사진 업로드를 `fetch` 로 바꾸고, `<meta name="_csrf">` 토큰을 헤더로 실어
보내세요. 토큰 없이 보내면 어떤 상태 코드가 오는지 확인.

## 문제 5. 세션 관리

- `sessionManagement` 으로 동시 세션 1개, 새 로그인 시 기존 만료(`maxSessionsPreventsLogin(false)`),
  `expiredUrl("/login?expired")`.
- 같은 계정으로 브라우저 2개(또는 시크릿 창)에서 로그인 → 먼저 로그인한 창을 새로고침하면?
- `server.servlet.session.timeout: 1m` 로 낮추고 1분 대기 후 요청 → 결과?

## 문제 6. 403 페이지

- `accessDeniedPage("/error/403")` + `error/403.html`(layout fragment).
- `USER` 계정으로 `/depts` 직접 접근 → 403 페이지가 뜨는지 확인.
- API(`/api/depts`)로 `USER` 접근 시엔 JSON 403이 나가도록 처리(핸들러 또는 별도 필터 체인).
