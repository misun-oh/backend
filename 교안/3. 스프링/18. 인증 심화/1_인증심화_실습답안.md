## 문제 2. `@AuthenticationPrincipal`

```java
@GetMapping("/my")
public String my(@AuthenticationPrincipal MemberPrincipal me, Model model) {
    model.addAttribute("name", me.getDisplayName());
    model.addAttribute("username", me.getUsername());
    model.addAttribute("roles", me.getAuthorities());
    return "member/my";
}
```

`me` 가 `null` 인 경우: 그 경로가 `permitAll` 이고 **로그인하지 않은** 상태로 접근했을 때.
(인증 필요 경로면 시큐리티가 먼저 로그인 페이지로 보내므로 컨트롤러에 `null` 로 들어오지 않는다.)
익명 사용자면 principal 이 문자열 `"anonymousUser"` 라서 타입이 안 맞아 `null` 이 될 수도 있으니,
`permitAll` 경로에서 쓸 땐 null 체크.

## 문제 3. 권한별 화면 + 서버 인가

```html
<div sec:authorize="isAnonymous()">
  <a class="btn btn--primary btn--sm" th:href="@{/login}">로그인</a>
</div>
<div sec:authorize="isAuthenticated()">
  <span class="user-chip">
    <span class="avatar avatar--sm" sec:authentication="principal.displayName">홍</span>
    <span sec:authentication="principal.displayName">홍길동</span>
  </span>
  <form th:action="@{/logout}" method="post" style="display:inline">
    <button class="btn btn--secondary btn--sm">로그아웃</button>
  </form>
</div>

<a sec:authorize="hasRole('ADMIN')" th:href="@{/depts}">부서 관리</a>
```
```html
<!-- emp/detail.html -->
<form sec:authorize="hasRole('ADMIN')" th:action="@{/emps/{id}/delete(id=${emp.empId})}" method="post">
  <button class="btn btn--danger" type="submit">삭제</button>
</form>
```

**서버 인가** (SecurityConfig 또는 메서드 보안):
```java
.requestMatchers(HttpMethod.POST, "/emps/*/delete").hasRole("ADMIN")
// 또는
@PreAuthorize("hasRole('ADMIN')")
public String delete(@PathVariable Long id) { ... }   // + @EnableMethodSecurity
```
`sec:authorize` 로 버튼을 숨겨도 `USER` 가 `POST /emps/205/delete` 를 curl로 보내면 통과되므로,
반드시 서버에서도 막아야 한다.

## 문제 4. CSRF + fetch

```html
<meta name="_csrf" th:content="${_csrf.token}">
<meta name="_csrf_header" th:content="${_csrf.headerName}">
```
```js
const csrf  = document.querySelector('meta[name=_csrf]').content;
const cHead = document.querySelector('meta[name=_csrf_header]').content;

form.addEventListener('submit', async (e) => {
  e.preventDefault();
  const fd = new FormData();
  fd.append('file', fileInput.files[0]);
  const res = await fetch(`/emps/${empId}/photo`, {
    method: 'POST',
    headers: { [cHead]: csrf },        // ← CSRF 토큰
    body: fd
  });
  if (res.redirected) location.href = res.url;
});
```

토큰 없이 보내면 → **403 Forbidden** (`CsrfException`). 시큐리티가 컨트롤러 도달 전에 차단.

## 문제 5. 세션 관리

```java
http.sessionManagement(s -> s
    .maximumSessions(1)
    .maxSessionsPreventsLogin(false)
    .expiredUrl("/login?expired"));
```
```yaml
server.servlet.session.timeout: 1m
```

- 같은 계정으로 두 번째 창에서 로그인 → 첫 번째 창의 세션이 **만료 표시**됨. 첫 창을 새로고침하면
  `/login?expired` 로 이동("세션이 만료되었습니다" 메시지).
- `timeout: 1m` + 1분 무활동 후 요청 → 세션 만료 → 로그인 페이지로. (AJAX면 401을 받도록 별도 처리 필요.)

## 문제 6. 403 페이지

```java
http.exceptionHandling(e -> e.accessDeniedPage("/error/403"));
```
`templates/error/403.html` (layout fragment + "접근 권한이 없습니다" + 목록 링크).

- `USER` 로 `/depts` → `AuthorizationFilter` 가 차단 → `accessDeniedPage` → `error/403.html` (상태 403).
- API JSON 403: `/api/**` 를 별도 `SecurityFilterChain`(`@Order(1)`, `securityMatcher("/api/**")`)으로
  분리하고 `exceptionHandling.accessDeniedHandler((req,res,ex) -> res.sendError(403))`,
  또는 `@RestControllerAdvice` 에:
  ```java
  @ExceptionHandler(AccessDeniedException.class)
  @ResponseStatus(HttpStatus.FORBIDDEN)
  public ApiError denied(AccessDeniedException e) { return ApiError.of("FORBIDDEN", "권한이 없습니다"); }
  ```
  (단, 필터 단계의 `AccessDeniedException` 은 `@ControllerAdvice` 로 안 잡히므로 `AccessDeniedHandler`
  빈이 더 확실.)
