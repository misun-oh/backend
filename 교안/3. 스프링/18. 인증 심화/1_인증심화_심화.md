# Day 18. 인증 심화 — 더 깊이 (경험자용)

## 1. 인가 아키텍처 (Spring Security 6)

- `AuthorizationFilter` → `AuthorizationManager` 체인.
- `authorizeHttpRequests` 의 각 규칙 = `AuthorizationManager<RequestAuthorizationContext>`.
- 커스텀: `access(new WebExpressionAuthorizationManager("hasRole('ADMIN') and @deptGuard.check(request)"))`
  또는 `AuthorizationManager` 구현 빈.
- 메서드 보안도 `AuthorizationManager<MethodInvocation>` 로 통일(`@EnableMethodSecurity`).

## 2. 도메인 객체 권한 (ACL / 소유자 검사)

"본인 것만" 규칙은 표현식보다 서비스에서 명시적으로:
```java
public void update(Long empId, EmpForm form, MemberPrincipal me) {
    Emp emp = empMapper.findById(empId);
    if (!me.getAuthorities().contains(new SimpleGrantedAuthority("ROLE_ADMIN"))
            && !emp.getManagerId().equals(me.getMember().getMemberId())) {
        throw new AccessDeniedException("수정 권한이 없습니다");
    }
    ...
}
```
행 단위 권한이 복잡하면 Spring Security ACL 모듈(무겁다) 또는 쿼리에 소유자 조건을 항상 포함.

## 3. `RememberMe`

```java
http.rememberMe(rm -> rm
    .key("hr-remember")
    .tokenValiditySeconds(60 * 60 * 24 * 14)
    .userDetailsService(userDetailsService));
```
- 브라우저를 닫아도 로그인 유지(쿠키). 해시 기반 또는 `PersistentTokenRepository`(DB, 토큰 회전 — 안전).
- 민감 작업(비번 변경·결제)은 `RememberMe` 로는 못 하게: `fullyAuthenticated` 요구.

## 4. 계정 잠금 / 시도 제한

- 로그인 실패 이벤트(`AuthenticationFailureBadCredentialsEvent`) 수신 → 실패 카운트 증가,
  N회 초과 시 `MEMBER.LOCKED='Y'` → `isAccountNonLocked()` false.
- 성공 이벤트에서 카운트 리셋. 시간 경과 자동 해제.
- IP 기반 레이트 리밋(Bucket4j) 병행. 크리덴셜 스터핑 방어.

## 5. 이벤트 & 감사 로그

```java
@Component
@RequiredArgsConstructor
public class AuthEventListener {
    @EventListener
    public void onSuccess(AuthenticationSuccessEvent e) {
        log.info("로그인 성공: {}", e.getAuthentication().getName());
    }
    @EventListener
    public void onFailure(AbstractAuthenticationFailureEvent e) {
        log.warn("로그인 실패: {} ({})", e.getAuthentication().getName(), e.getException().getMessage());
    }
}
```
`SecurityContextHolderStrategy` / `AuditorAware`(작성자 자동 세팅) 연계.

## 6. 다중 `SecurityFilterChain`

경로마다 다른 정책:
```java
@Bean @Order(1)
SecurityFilterChain api(HttpSecurity http) throws Exception {
    http.securityMatcher("/api/**")
        .authorizeHttpRequests(a -> a.anyRequest().authenticated())
        .csrf(csrf -> csrf.disable())
        .sessionManagement(s -> s.sessionCreationPolicy(STATELESS))
        .oauth2ResourceServer(o -> o.jwt(withDefaults()));   // Day 19
    return http.build();
}

@Bean @Order(2)
SecurityFilterChain web(HttpSecurity http) throws Exception {
    http.authorizeHttpRequests(...).formLogin(...);
    return http.build();
}
```
`/api/**` 는 JWT stateless, 나머지는 폼 세션.

## 7. 세션 외부화

- `spring-session-jdbc` 또는 `spring-session-data-redis` → 세션을 DB/Redis에.
- 서버 여러 대에서 스티키 세션 없이 공유, 무중단 배포 시 세션 유지.
- `@EnableJdbcHttpSession` / 자동 구성. `SPRING_SESSION` 테이블.
