# Day 14. 검증과 예외 처리 — 심화 (경험자용)

## 1. 검증 그룹 (groups)

등록과 수정에서 규칙이 다를 때:

```java
public interface OnCreate {}
public interface OnUpdate {}

public class EmpForm {
    @Null(groups = OnCreate.class)     // 등록 시 id는 없어야
    @NotNull(groups = OnUpdate.class)  // 수정 시 id 필수
    private Long empId;

    @NotBlank(groups = {OnCreate.class, OnUpdate.class})
    private String empName;
}
```
```java
public String create(@Validated(OnCreate.class) @ModelAttribute EmpForm form, BindingResult br) {}
```
`@Valid`(표준) 대신 `@Validated`(스프링, 그룹 지원)를 쓴다.

## 2. `@Validated` 클래스 레벨 — 메서드 파라미터 검증

```java
@Service
@Validated
public class EmpService {
    public Emp get(@Min(1) Long id) { ... }   // 서비스 파라미터도 검증 (AOP)
}
```
실패 시 `ConstraintViolationException`(Bean Validation) — advice에서 별도 처리.

## 3. 중첩 객체 / 컬렉션 검증

public class OrderForm {

## 4. 표준 에러 응답 — Problem Details (RFC 7807)

Spring 6 / Boot 3 는 `ProblemDetail` 내장:
```java
@ExceptionHandler(NoSuchElementException.class)
ProblemDetail handle(NoSuchElementException e) {
    ProblemDetail pd = ProblemDetail.forStatusAndDetail(HttpStatus.NOT_FOUND, e.getMessage());
    pd.setTitle("리소스 없음");
    pd.setProperty("timestamp", Instant.now());
    return pd;
}
```
```yaml
spring:
  mvc:
    problemdetails:
      enabled: true    # 스프링 표준 예외를 자동으로 ProblemDetail 로
```
`application/problem+json` 으로 `{type,title,status,detail,instance,...}`.

## 5. `ResponseEntityExceptionHandler` 상속

Spring MVC 표준 예외(`MethodArgumentNotValidException`, `HttpMessageNotReadableException`,
`NoResourceFoundException` …)를 한 번에 오버라이드하려면 `@RestControllerAdvice` 가
`ResponseEntityExceptionHandler` 를 상속하고 `handleMethodArgumentNotValid` 등을 override.

## 6. `@ResponseStatus` vs `ResponseStatusException`

- 예외 클래스에 `@ResponseStatus(HttpStatus.NOT_FOUND)` — 고정 상태.
- 던지는 시점에 결정: `throw new ResponseStatusException(HttpStatus.NOT_FOUND, "사원 " + id)`.
  advice 없이도 상태코드 + 메시지. 단, 도메인 예외 타입이 사라지므로 큰 프로젝트는 커스텀 예외 + advice 권장.

## 7. 메시지 국제화 & 코드 규약

- `messages.properties` 에 `NotBlank.empForm.empName=이름은 필수입니다` 형태로 두면 애노테이션 `message` 없이도 매핑
  (`{제약}.{객체}.{필드}` → `{제약}.{필드}` → `{제약}` 순 fallback).
- `BindingResult.getAllErrors()` 의 `getCodes()` 로 어떤 키를 찾는지 확인.
- 프론트가 필드별 에러를 파싱하도록 `{field, code, message}` 구조로 응답 통일.

## 8. 보안·안정성

- **에러 메시지에 내부 정보 노출 금지**: SQL, 스택트레이스, 파일 경로 → 사용자에겐 일반 문구, 로그엔 상세.
- `server.error.include-stacktrace=never`, `include-message=never`(운영).
- 대량 요청/봇: 검증 실패도 비용. 레이트 리밋(Bucket4j, 게이트웨이).
- 파일/문자열 길이 상한을 검증으로 강제(메모리 보호).

@WebMvcTest(EmpViewController.class)
class EmpFormValidationTest {
