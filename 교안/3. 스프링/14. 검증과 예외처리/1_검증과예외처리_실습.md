# Day 14. 검증과 예외 처리 — 실습

준비: `build.gradle` 에 `spring-boot-starter-validation` 추가.

## 문제 1. EmpForm 검증 규칙

`EmpForm` 에 다음을 붙이세요.
- `empName` : `@NotBlank`(메시지 "이름은 필수"), `@Size(max=20)`
- `email` : `@NotBlank`, `@Email`
- `deptId` : `@NotNull`("부서를 선택하세요")
- `salary` : `@NotNull`, `@PositiveOrZero`
- `hireDate` : `@NotNull`, `@PastOrPresent`

## 문제 2. 컨트롤러 검증 처리

`POST /emps`(등록), `POST /emps/{id}`(수정)에서 `@Valid EmpForm form, BindingResult br` 로 받아
`br.hasErrors()` 면 `depts` 를 다시 담고 `emp/form` 반환. 통과하면 저장 후 redirect.

`GET /emps/new` 에서 `model.addAttribute("form", new EmpForm())` 도 잊지 마세요.

## 문제 3. Thymeleaf 에러 표시

`emp/form.html` 을 프로토타입(`emp-form.html`)의 `field--error` / `form-hint` 를 활용해:
- 에러 있는 `.field` 에 `field--error` 클래스 (`th:errorclass` 또는 `th:classappend`)
- `form-hint` 에 `th:errors="*{필드}"`

브라우저에서 이름을 비우고 이메일에 `abc` 를 넣어 저장 → 빨간 테두리 + 메시지, **입력값은 유지**되는지 확인.

## 문제 4. 이메일 중복 (DB 검증)

`EmpService.existsByEmail(String email)` 을 만들고, 컨트롤러에서
`br.rejectValue("email", "duplicate", "이미 사용 중인 이메일입니다")` 로 에러 추가.
기존 사원의 이메일로 등록 시도 → 화면에 중복 메시지가 나오는지 확인.

## 문제 5. 전역 예외 처리

`GlobalExceptionHandler`(`@ControllerAdvice`)를 만들어:
- `NoSuchElementException` → `error/404` (404 상태)
- `Exception` → `error/500` (500 상태) + `log.error`

`templates/error/404.html`, `error/500.html` 을 layout fragment 로 만들고,
존재하지 않는 사원(`/emps/999`) 접속 시 404 페이지가 뜨는지 확인.

## 문제 6. (개념) 왜 검증이 안 될까 / 왜 400일까

1. `@NotBlank` 를 붙였는데 빈 값도 통과한다. 원인 2가지.
2. `create(@Valid EmpForm form, Model model, BindingResult br)` — 빈 이름으로 POST 하면 폼이 아니라
   400 에러 페이지가 뜬다. 왜인가?
