### 문제 1. 날짜 형식 변환

```sql
SELECT EMP_NAME, DATE_FORMAT(HIRE_DATE, '%Y년 %m월 %d일') AS 입사일
FROM EMP
WHERE DEPT_ID = 'D9'
ORDER BY HIRE_DATE ASC;
```

**출력 결과**
```
곽상혁 2013년 03월 02일
권진우 2013년 09월 15일
김민혜 2014년 02월 10일
```

**설명**: `DATE_FORMAT(날짜, 형식)`은 `DATE`/`DATETIME` 값을 원하는 모양의 문자열로 바꿔줍니다.
`%Y`는 4자리 연도, `%m`은 2자리 월, `%d`는 2자리 일을 의미하며, 월/일이 한 자리 수여도
`03`, `02`처럼 0이 채워집니다.

### 문제 2. 문자 길이 함수

```sql
SELECT EMP_NAME, CHAR_LENGTH(EMP_NAME), LENGTH(EMP_NAME)
FROM EMP
WHERE DEPT_ID = 'D2';
```

**출력 결과**
```
박홍주 3 9
심재호 3 9
엄용민 3 9
```

**설명**: `CHAR_LENGTH`는 "글자 수"를, `LENGTH`는 "바이트 수"를 반환합니다. `utf8mb4` 환경에서
한글 한 글자는 3바이트를 차지하므로, 3글자 이름은 항상 `CHAR_LENGTH = 3`, `LENGTH = 9`로
나옵니다. 영문/숫자가 섞이면 두 값의 차이가 더 잘 드러납니다(예: 이메일 아이디는 모두 아스키
문자라 `CHAR_LENGTH`와 `LENGTH`가 항상 같습니다).

### 문제 8. LPAD 활용

```sql
SELECT EMP_NAME, LPAD(EMP_ID, 5, '0') AS 사번
FROM EMP
WHERE DEPT_ID = 'D8'
ORDER BY EMP_ID;
```

**출력 결과**
```
이광렬 00210
이금빈 00211
오미자 00212
```

**설명**: `LPAD(문자열, 길이, 채울문자)`는 문자열이 지정한 길이보다 짧을 때 왼쪽을
채울문자로 채웁니다. `EMP_ID`는 3자리 문자열이므로 5자리를 맞추기 위해 왼쪽에 `'0'`
2개가 채워집니다.

### 문제 9. EXTRACT 활용

```sql
SELECT EMP_NAME, EXTRACT(YEAR FROM HIRE_DATE) AS 입사연도
FROM EMP
WHERE DEPT_ID = 'D2'
ORDER BY HIRE_DATE ASC;
```

**출력 결과**
```
박홍주 2015
심재호 2016
엄용민 2017
```

**설명**: `EXTRACT(YEAR FROM 날짜)`는 날짜에서 연도만 뽑아냅니다. 회계관리부(D2) 세
사원은 입사 연도가 모두 달라서(2015/2016/2017) 정렬 결과가 명확하게 구분됩니다.

### 문제 3. IFNULL + 산술 연산

```sql
SELECT EMP_NAME, SALARY, (SALARY + SALARY * IFNULL(BONUS, 0)) * 12 AS 연봉
FROM EMP
WHERE DEPT_ID = 'D5'
ORDER BY 연봉 DESC;
```

**출력 결과**
```
박지민 3500000 48300000
윤정주 3760000 45120000
유제영 2500000 30000000
염성원 2200000 29040000
최주호 1800000 21600000
```

**설명**: `BONUS`가 `NULL`인 사원(유제영, 윤정주, 최주호)은 `SALARY * NULL`이 `NULL`이 되어
전체 연산 결과가 `NULL`로 오염됩니다. `IFNULL(BONUS, 0)`으로 먼저 `NULL`을 0으로 바꿔줘야
"보너스가 없으면 급여 12개월치만 받는다"는 의도대로 계산됩니다. 급여가 더 높아도 보너스가
없으면(윤정주 376만) 급여가 낮아도 보너스가 있는 사람(박지민 350만, 15%)에게 연봉이 역전당할
수 있다는 점도 확인할 수 있습니다.

### 문제 4. CASE + GROUP BY

```sql
SELECT
    CASE
        WHEN SALARY >= 5000000 THEN '고액'
        WHEN SALARY >= 2500000 THEN '중액'
        ELSE '소액'
    END AS 등급,
    COUNT(*) AS 인원수
FROM EMP
GROUP BY 등급;
```

**출력 결과**
```
고액 2
중액 11
소액 8
```
(등급이 나오는 순서는 보장되지 않으므로, 특정 순서가 필요하면 `ORDER BY`를 추가로 붙여야
합니다)

**설명**: `GROUP BY`에는 컬럼뿐 아니라 `CASE` 표현식(또는 그 별칭)도 그룹 기준으로 쓸 수
있습니다. MySQL은 `SELECT`에 쓴 별칭(`등급`)을 `GROUP BY`에서 그대로 재사용할 수 있어
`CASE` 식을 두 번 쓰지 않아도 됩니다. 고액 2명(곽상혁 800만, 권진우 600만), 소액 8명
(염성원·최주호·이광렬·오미자·한재헌·심재호·엄용민·조정원), 나머지 11명이 중액입니다.

### 문제 5. GROUP BY + HAVING

```sql
SELECT DEPT_ID, ROUND(AVG(SALARY)) AS 평균급여
FROM EMP
GROUP BY DEPT_ID
HAVING AVG(SALARY) >= 3000000;
```

**출력 결과**
```
D9 5900000
D6 3650000
```

**설명**: `WHERE`는 그룹으로 묶기 **전** 개별 행을 거르고, `HAVING`은 `GROUP BY`로 집계된
**그룹 결과**를 거릅니다. 부서별 평균은 총무부(D9) 590만, 해외영업2부(D6) 365만이 300만을
넘고, 나머지 부서(D5 275.2만, D1 260.7만, 부서 미배정 260.5만, D8 232.9만, D2 228만)는
모두 300만 미만이라 결과에서 빠집니다. `HAVING`에는 `AVG(SALARY)`처럼 집계 함수를 직접 써야
하며, `SELECT`의 별칭(`평균급여`)을 `HAVING`에 쓰면 반올림된 값 기준으로 비교되어 결과가
달라질 수 있으므로 원본 집계식을 쓰는 것이 안전합니다.

### 문제 10. SUBSTRING + INSTR

```sql
SELECT EMP_NAME, SUBSTRING(EMAIL, 1, INSTR(EMAIL, '@') - 1) AS 이메일아이디
FROM EMP
WHERE DEPT_ID = 'D9'
ORDER BY EMP_ID;
```

**출력 결과**
```
곽상혁 kwak_sh
권진우 kwon_jw
김민혜 kim_mh
```

**설명**: `INSTR(EMAIL, '@')`로 `'@'`이 몇 번째 글자인지 찾은 뒤, 그 위치 바로 앞
글자까지(`- 1`)를 `SUBSTRING`으로 잘라내면 아이디 부분만 남습니다. 예를 들어
`'kwak_sh@company.com'`에서 `'@'`은 8번째 글자이므로 `SUBSTRING(EMAIL, 1, 7)`이 되어
`'kwak_sh'`이 나옵니다.

### 문제 11. COALESCE 활용

```sql
SELECT EMP_NAME, COALESCE(MANAGER_ID, '없음') AS 매니저사번
FROM EMP
WHERE DEPT_ID IN ('D2', 'D8')
ORDER BY EMP_ID;
```

**출력 결과**
```
이광렬 200
이금빈 210
오미자 210
박홍주 없음
심재호 없음
엄용민 없음
```

**설명**: `COALESCE(값1, 값2, ...)`는 여러 값 중 `NULL`이 아닌 첫 번째 값을 반환합니다.
기술지원부(D8) 세 명은 모두 관리자가 있어 `MANAGER_ID`가 그대로 나오지만, 회계관리부(D2)
세 명은 `MANAGER_ID`가 모두 `NULL`이라 `COALESCE`가 두 번째 인자인 `'없음'`을 대신
반환합니다.

### 문제 12. CASE + GROUP BY 종합

```sql
SELECT
    CASE
        WHEN JOB_CODE IN ('J1','J2','J3') THEN '고위직'
        WHEN JOB_CODE IN ('J4','J5') THEN '중간관리직'
        ELSE '실무직'
    END AS 직급분류,
    COUNT(*) AS 인원수,
    ROUND(AVG(SALARY)) AS 평균급여
FROM EMP
GROUP BY 직급분류;
```

**출력 결과**
```
고위직 6 4750000
중간관리직 6 2550000
실무직 9 2424027
```

**설명**: 고위직(J1~J3) 6명의 급여 합은 28,500,000원(평균 4,750,000원), 중간관리직
(J4~J5) 6명의 급여 합은 15,300,000원(평균 2,550,000원), 실무직(J6~J7) 9명의 급여 합은
21,816,240원(평균 2,424,026.67 → 반올림 2,424,027원)입니다. 세 그룹의 급여 합을
더하면 `1_함수.md`에서 확인한 전체 급여 합계 65,616,240원과 정확히 일치하고, 인원수를
더하면 전체 21명과 일치해서 분류가 빠짐없이 이뤄졌음을 검산할 수 있습니다.

### 문제 6. 종합 - CASE로 성별 구분 후 집계

```sql
SELECT
    CASE
        WHEN SUBSTRING(EMP_NO, 8, 1) IN ('1', '3') THEN '남'
        WHEN SUBSTRING(EMP_NO, 8, 1) IN ('2', '4') THEN '여'
    END AS 성별,
    COUNT(*) AS 인원수,
    ROUND(AVG(SALARY)) AS 평균급여
FROM EMP
GROUP BY 성별;
```

**출력 결과**
```
남 14 3106429
여 7  3160891
```

**설명**: 주민등록번호 뒷자리 첫 글자(`EMP_NO`의 8번째 문자)는 `1`(남, 1900년대),
`2`(여, 1900년대), `3`(남, 2000년대), `4`(여, 2000년대)로 출생연도와 성별을 함께
나타냅니다. `SUBSTRING(EMP_NO, 8, 1)`로 이 한 글자를 뽑아 `IN`으로 묶으면 연도와
무관하게 성별만 분리할 수 있습니다. 남 14명의 급여 합은 43,490,000원, 여 7명의 급여
합은 22,126,240원이며 두 값을 더하면 `1_함수.md`에서 확인한 전체 급여 합계
65,616,240원과 정확히 일치합니다.

### 문제 7. 종합 - TIMESTAMPDIFF + WHERE

```sql
SELECT EMP_NAME, HIRE_DATE,
       TIMESTAMPDIFF(MONTH, HIRE_DATE, '2026-08-19') AS 재직개월
FROM EMP
WHERE ENT_YN = 'N'
  AND TIMESTAMPDIFF(MONTH, HIRE_DATE, '2026-08-19') >= 120
ORDER BY 재직개월 DESC;
```

**출력 결과**
```
곽상혁 2013-03-02 161
권진우 2013-09-15 155
김민혜 2014-02-10 150
김은민 2014-07-01 145
김태일 2014-11-11 141
박지민 2015-05-20 134
박홍주 2015-11-09 129
```

**설명**: `TIMESTAMPDIFF(MONTH, 시작일, 종료일)`은 두 날짜 사이의 **완전히 채워진** 개월
수를 계산합니다(예: `2020-01-15`~`2020-02-14`는 아직 1개월이 안 채워져 0을 반환하고,
`2020-02-15`부터 1이 됩니다). `ENT_YN = 'N'` 조건이 없으면 퇴사자인 오미자(212, 입사일
2021-11-28)도 오늘까지 계속 재직 중인 것처럼 계산되어 버리므로, 실제로 존재하지 않는
재직 기간이 나옵니다. 날짜 함수로 "현재까지의 기간"을 구할 때는 항상 재직 여부처럼
그 계산이 의미를 가지는 대상인지부터 `WHERE`로 걸러야 합니다.

### 문제 13. 종합 - CASE로 출생연대 구분 후 집계

```sql
SELECT
    CASE
        WHEN CONCAT(IF(SUBSTRING(EMP_NO, 8, 1) IN ('1','2'), '19', '20'),
                    SUBSTRING(EMP_NO, 1, 2)) BETWEEN '1980' AND '1989' THEN '1980년대'
        WHEN CONCAT(IF(SUBSTRING(EMP_NO, 8, 1) IN ('1','2'), '19', '20'),
                    SUBSTRING(EMP_NO, 1, 2)) BETWEEN '1990' AND '1999' THEN '1990년대'
        ELSE '2000년대'
    END AS 출생연대,
    COUNT(*) AS 인원수
FROM EMP
GROUP BY 출생연대;
```

**출력 결과**
```
1980년대 8
1990년대 10
2000년대 3
```

**설명**: `EMP_NO`의 8번째 글자가 `'1'`/`'2'`면 1900년대생, `'3'`/`'4'`면 2000년대생이므로
`IF()`로 `'19'`/`'20'`을 고른 뒤 앞 2글자(`SUBSTRING(EMP_NO, 1, 2)`, 실제 태어난 해의
뒤 두 자리)와 `CONCAT`해서 4자리 출생연도 문자열을 만듭니다. 예를 들어 오미자
(`001215-4...`)는 8번째 글자가 `'4'`이므로 `'20' + '00'` = `'2000'`으로 계산되어
2000년대생으로 분류됩니다. 세 그룹의 인원수를 더하면 전체 21명과 일치합니다.

### 문제 14. 종합 - TIMESTAMPDIFF + CASE로 근속연수 구간별 집계

```sql
SELECT
    CASE
        WHEN TIMESTAMPDIFF(YEAR, HIRE_DATE, '2026-08-19') < 5 THEN '5년미만'
        WHEN TIMESTAMPDIFF(YEAR, HIRE_DATE, '2026-08-19') < 10 THEN '5~9년'
        ELSE '10년이상'
    END AS 근속구간,
    COUNT(*) AS 인원수,
    ROUND(AVG(SALARY)) AS 평균급여
FROM EMP
WHERE ENT_YN = 'N'
GROUP BY 근속구간;
```

**출력 결과**
```
5년미만 4 2097500
5~9년 9 2610000
10년이상 7 4471429
```

**설명**: `TIMESTAMPDIFF(YEAR, ...)`는 `MONTH`와 마찬가지로 완전히 채워진 연 단위만
셉니다. 퇴사자 오미자(`ENT_YN = 'Y'`)를 제외한 재직자 20명을 기준으로, 근속 5년 미만은
4명(평균 2,097,500원), 5~9년은 9명(평균 2,610,000원), 10년 이상은 7명(평균 4,471,429원)
입니다. 세 그룹의 급여 합(8,390,000 + 23,490,000 + 31,300,000 = 63,180,000원)은 전체
급여 합계 65,616,240원에서 퇴사자 오미자의 급여(2,436,240원)를 뺀 값과 정확히
일치합니다.
