- 날짜 간 간격을 계산하고, 날짜에 기간을 더하거나 특정 요소를 추출할 수 있다

- `CASE`로 조건에 따라 다른 값을 반환하는 표현식을 만들 수 있고, 두 갈래(참/거짓)
  조건은 `IF()` 함수로 더 간단히 쓸 수 있다
- `SUM`/`AVG`/`MIN`/`MAX`/`COUNT` 그룹 함수와 `GROUP BY`/`HAVING`으로 집계 결과를 조회할 수 있다

## 0. 단일 행 함수 vs 그룹 함수

| 구분 | 설명 | 예시 |
|---|---|---|
| 단일 행 함수 | 행마다 각각 적용되어, 입력한 행 개수만큼 결과를 반환 | `UPPER(EMP_NAME)` |
| 그룹 함수 | 여러 행을 하나의 그룹으로 묶어 계산해서, 그룹당 결과 1개를 반환 | `SUM(SALARY)` |

**설명**: 이번 챕터는 1~6절(단일 행 함수)과 7~8절(그룹 함수)로 나뉩니다. 단일 행 함수와
그룹 함수는 SELECT절에 함께 쓸 수 없는 경우가 많으므로(결과 행 개수가 다르기 때문), 뒤에서
`GROUP BY`와 함께 사용하는 규칙을 별도로 배웁니다.

## 1. 문자 함수

| 함수 | 역할 |
|---|---|
| `CHAR_LENGTH(문자열)` | 문자 개수 반환 |
| `LENGTH(문자열)` | 바이트 크기 반환 |
| `INSTR(문자열, 찾을문자)` | 특정 문자가 처음 등장하는 위치 반환 |
| `LPAD`/`RPAD(문자열, 길이, 채울문자)` | 왼쪽/오른쪽을 지정한 문자로 채워 길이를 맞춤 |
| `TRIM(... FROM 문자열)` | 앞/뒤/양쪽의 지정한 문자를 제거 |
| `SUBSTRING(문자열, 시작위치, 길이)` | 지정한 위치부터 지정한 길이만큼 잘라냄 |
| `LOWER`/`UPPER(문자열)` | 소문자/대문자로 변환 |
| `CONCAT(문자열, 문자열, ...)` | 여러 문자열을 이어붙임 (2개 이상 가능) |
| `REPLACE(문자열, 찾을문자, 바꿀문자)` | 특정 문자를 다른 문자로 치환 |

### CHAR_LENGTH / LENGTH
```sql
SELECT EMP_NAME, CHAR_LENGTH(EMP_NAME), LENGTH(EMP_NAME)
FROM EMP
WHERE EMP_ID = '200';
```
**출력 결과**: `곽상혁, 3, 9`

**설명**: `CHAR_LENGTH`는 글자 수, `LENGTH`는 바이트 수를 반환합니다. MySQL의 기본 문자셋(`utf8mb4`)에서
한글 한 글자는 3바이트이므로, 3글자인 `'곽상혁'`은 `CHAR_LENGTH`가 3, `LENGTH`가 9입니다. 영문/숫자는
1글자당 1바이트이므로 영문 이메일은 두 함수의 결과가 같습니다.

### INSTR
```sql
SELECT EMAIL, INSTR(EMAIL, '@') AS 위치
FROM EMP
WHERE EMP_ID = '200';
```
**출력 결과**: `kwak_sh@company.com, 8`

**설명**: `INSTR(문자열, 찾을문자)`는 찾을 문자가 처음 등장하는 위치(1부터 시작)를 반환합니다.
`'kwak_sh@company.com'`에서 `@`는 8번째 글자이므로 8을 반환합니다.

### LPAD / RPAD
```sql
SELECT LPAD(EMAIL, 25, '*') AS 왼쪽채움,
       RPAD(EMAIL, 25, '*') AS 오른쪽채움
FROM EMP
WHERE EMP_ID = '200';
```
**출력 결과**
```
왼쪽채움: ******kwak_sh@company.com
오른쪽채움: kwak_sh@company.com******
```

**설명**: `EMAIL`(19글자)을 25글자로 맞추기 위해 부족한 6글자를 `'*'`로 채웁니다. `LPAD`는 왼쪽에,
`RPAD`는 오른쪽에 채웁니다. 두 번째 인자(길이)는 반드시 **정수**여야 하며, `25.5`처럼
소수를 넣으면 자동으로 정수로 반올림되어 처리됩니다.

### TRIM / LTRIM / RTRIM

`TRIM`은 어느 쪽을 제거할지 옵션으로 지정할 수 있습니다. 옵션을 생략하면 `BOTH`(양쪽)가
기본값입니다.

| 옵션 | 의미 |
|---|---|
| `LEADING 문자 FROM 문자열` | 문자열 **앞쪽**에서만 지정한 문자를 제거 |
| `TRAILING 문자 FROM 문자열` | 문자열 **뒤쪽**에서만 지정한 문자를 제거 |
| `BOTH 문자 FROM 문자열` (생략 시 기본값) | 문자열 **양쪽**에서 지정한 문자를 제거 |

```sql
SELECT TRIM('   Hello   ') AS 양쪽공백제거,                 -- 'Hello'
       TRIM(LEADING '0' FROM '000123') AS 앞쪽0제거,        -- '123'
       TRIM(TRAILING '0' FROM '123000') AS 뒤쪽0제거,       -- '123'
       TRIM(BOTH 'z' FROM 'zzHELLOzz') AS 양쪽문자제거,     -- 'HELLO'
       LTRIM('   SQL') AS 왼쪽공백만,                       -- 'SQL' (공백만 제거 가능)
       RTRIM('SQL   ') AS 오른쪽공백만;                     -- 'SQL'
```

> **왜 `FROM`이 없나요?** 테이블 컬럼이 아니라 직접 적어준 문자열(`'   Hello   '` 등)만
> 계산하는 경우, MySQL은 `FROM`절 없이 `SELECT 식;`만으로도 실행됩니다. 어떤 테이블의
> 어떤 행을 조회하는 것이 아니라 "이 함수가 어떤 값을 반환하는지"만 즉석에서 확인하고
> 싶을 때 자주 쓰는 방식입니다. 반대로 `EMP` 같은 테이블의 컬럼을 다룰 때는 반드시
> `FROM EMP`를 써야 합니다(아래 예제들처럼).

**설명**: MySQL의 `LTRIM`/`RTRIM`은 **공백만** 제거할 수 있습니다(Oracle과 달리 지정 문자를
받는 두 번째 인자가 없습니다). 공백이 아닌 특정 문자를 제거하려면 반드시
`TRIM(LEADING|TRAILING|BOTH 문자 FROM 문자열)` 형태를 써야 합니다. `LEADING`/`TRAILING`은
"어느 한쪽만 지정한 문자를 벗겨낸다"는 뜻으로, 예를 들어 `000123`처럼 앞자리에 붙은 `0`만
지우고 싶을 때(`LEADING`), 반대로 `123000`처럼 뒷자리에 붙은 `0`만 지우고 싶을 때
(`TRAILING`) 구분해서 씁니다.

### SUBSTRING
```sql
-- EMP_NO(주민등록번호 형식)에서 성별을 나타내는 8번째 글자만 추출
SELECT EMP_NAME, EMP_NO, SUBSTRING(EMP_NO, 8, 1) AS 성별코드
FROM EMP
WHERE EMP_ID = '200';
```
**출력 결과**: `곽상혁, 800514-1234567, 1`

**설명**: `SUBSTRING(문자열, 시작위치, 길이)`는 지정한 위치부터 지정한 개수만큼 문자를 잘라냅니다.
**시작위치와 길이는 반드시 정수**여야 합니다(음수 시작위치는 "뒤에서부터"를 뜻하는
별도 규칙이며, 소수를 넣으면 오류가 아니라 자동으로 정수로 반올림됩니다). `EMP_NO`의
8번째 글자는 성별 코드로, 1990년대생까지는 남자 `1`/여자 `2`, 2000년대생부터는 남자
`3`/여자 `4`로 표기하는 것이 관례입니다(우리 실습 데이터도 이 규칙을 따릅니다).

### LOWER / UPPER / CONCAT / REPLACE
```sql
SELECT UPPER('company.com') AS 대문자,                          -- COMPANY.COM
       CONCAT(EMP_NAME, '(', EMP_ID, ')') AS 이름사번,           -- 곽상혁(200)
       REPLACE(EMAIL, 'company.com', 'work.co.kr') AS 새이메일   -- kwak_sh@work.co.kr
FROM EMP
WHERE EMP_ID = '200';
```

**설명**: MySQL의 `CONCAT`은 인자를 **2개 이상 자유롭게** 받을 수 있습니다(Oracle의 `CONCAT`은
정확히 2개만 가능해서 3개 이상을 이어붙이려면 `CONCAT`을 중첩해야 했지만, MySQL은 그럴 필요가
없습니다).

## 2. 숫자 함수

| 함수 | 역할 |
|---|---|
| `ABS(숫자)` | 절댓값 |
| `MOD(숫자, 나눌수)` | 나머지 (`%` 연산자와 동일) |
| `ROUND(숫자, 자리수)` | 반올림 |
| `CEIL(숫자)` | 올림 (소수점 이하를 무조건 올림) |
| `FLOOR(숫자)` | 버림 (소수점 이하를 무조건 버림, 음수는 더 작은 쪽으로) |
| `TRUNCATE(숫자, 자리수)` | 반올림 없이 지정한 자리에서 잘라냄 |

```sql
SELECT ABS(-15.5),          -- 15.5
       MOD(10, 3),          -- 1
       ROUND(123.456, 1),   -- 123.5
       ROUND(123.456, -1),  -- 120   (10의 자리에서 반올림)
       CEIL(123.1),         -- 124
       FLOOR(123.9),        -- 123
       FLOOR(-123.1),       -- -124  (음수는 더 작은 정수 쪽으로)
       TRUNCATE(123.456, 1),  -- 123.4 (반올림 없이 자름)
       TRUNCATE(123.456, -1); -- 120
```

**설명**: `자리수`가 양수면 소수점 아래 자릿수, 음수면 소수점 위(10의 자리, 100의 자리...)를
기준으로 합니다. **`자리수`는 반드시 정수**여야 합니다(소수를 넣으면 오류). `ROUND`는
반올림하지만 `TRUNCATE`는 그 자리 아래를 그냥 잘라버린다는 차이를 꼭 구분하세요.
`FLOOR(-123.1)`이 `-123`이 아니라 `-124`인 이유는 "버림"이 0 방향이 아니라
**항상 더 작은 정수 쪽**으로 가기 때문입니다.

## 3. 날짜 함수

| 함수 | 역할 |
|---|---|
| `NOW()` | 현재 날짜와 시각 |
| `CURDATE()` | 현재 날짜만 |
| `DATE_ADD(날짜, INTERVAL n 단위)` | 날짜에 기간을 더함 |
| `DATE_SUB(날짜, INTERVAL n 단위)` | 날짜에서 기간을 뺌 (`DATE_ADD`의 반대) |
| `TIMESTAMPDIFF(단위, 날짜1, 날짜2)` | 두 날짜 사이의 완전한 간격(개월/년 등)을 계산 |
| `LAST_DAY(날짜)` | 그 날짜가 속한 달의 마지막 날짜 |
| `EXTRACT(단위 FROM 날짜)` | 날짜에서 연/월/일 등 특정 요소만 추출 |

### 날짜 단위 정리

`DATE_ADD`/`DATE_SUB`의 `INTERVAL n 단위`, `EXTRACT(단위 FROM 날짜)`,
`TIMESTAMPDIFF(단위, ...)` 세 함수는 모두 **같은 단위 키워드**를 공유합니다. 아래
표를 한 번 익혀두면 세 함수 모두에 그대로 재사용할 수 있습니다.

| 단위 | 의미 | 사용 예 |
|---|---|---|
| `YEAR` | 연 | `INTERVAL 1 YEAR` |
| `QUARTER` | 분기(3개월) | `INTERVAL 1 QUARTER` |
| `MONTH` | 월 | `INTERVAL 6 MONTH` |
| `WEEK` | 주(7일) | `INTERVAL 2 WEEK` |
| `DAY` | 일 | `INTERVAL 7 DAY` |
| `HOUR` | 시 | `INTERVAL 3 HOUR` |
| `MINUTE` | 분 | `INTERVAL 30 MINUTE` |
| `SECOND` | 초 | `INTERVAL 10 SECOND` |

> `EXTRACT`는 이 외에도 `YEAR_MONTH`, `DAY_HOUR`처럼 두 단위를 합친 복합 단위도
> 지원하지만, 실무에서는 표의 8가지 기본 단위만으로 대부분의 요구를 해결할 수
> 있습니다.

```sql
-- 입사일에 6개월을 더한 날짜 (수습 기간 종료일 계산 등에 활용)
SELECT HIRE_DATE, DATE_ADD(HIRE_DATE, INTERVAL 6 MONTH) AS 수습종료일
FROM EMP
WHERE EMP_ID = '200';
```
**출력 결과**: `2013-03-02, 2013-09-02`

```sql
-- DATE_SUB: 날짜에서 기간을 뺌 (DATE_ADD의 반대)
SELECT CURDATE(), DATE_SUB(CURDATE(), INTERVAL 7 DAY) AS 일주일전;
```

**설명**: `DATE_SUB(날짜, INTERVAL n 단위)`는 `DATE_ADD(날짜, INTERVAL -n 단위)`와 완전히
같은 결과를 냅니다. "며칠 전/몇 개월 전"처럼 과거 날짜를 구할 때는 부호를 헷갈리기보다
`DATE_SUB`를 쓰는 것이 더 읽기 쉽습니다.

```sql
-- 두 고정된 날짜 사이의 개월 수 (완전히 채워진 달만 셈)
SELECT TIMESTAMPDIFF(MONTH, '2020-01-15', '2024-03-20');
```
**출력 결과**: `50`

**설명**: 2020-01-15에서 2024-01-15까지 정확히 48개월, 거기서 2024-03-15까지 2개월 더해서
50개월이 됩니다. 남은 5일(15일→20일)은 온전한 한 달이 되지 않으므로 세지 않습니다.

```sql
-- 재직 기간(개월)을 구할 때는 두 번째 인자에 오늘 날짜(CURDATE())를 사용
SELECT EMP_NAME, TIMESTAMPDIFF(MONTH, HIRE_DATE, CURDATE()) AS 재직개월
FROM EMP;
```
**설명**: 이 쿼리는 `CURDATE()`(오늘 날짜)를 기준으로 계산하므로, **실행하는 날짜에 따라 결과
숫자가 달라집니다.** 지금 당장 정확한 숫자를 외울 필요는 없고, "오늘 기준으로 몇 개월 근무했는지"를
구하는 패턴 자체를 기억해두세요.

```sql
-- LAST_DAY: 그 달의 마지막 날짜
SELECT LAST_DAY('2026-02-15');
```
**출력 결과**: `2026-02-28` (2026년은 4로 나누어떨어지지 않는 평년이라 2월이 28일까지입니다)

```sql
-- EXTRACT: 입사 연/월/일 각각 추출
SELECT EMP_NAME,
       EXTRACT(YEAR FROM HIRE_DATE) AS 입사년,
       EXTRACT(MONTH FROM HIRE_DATE) AS 입사월,
       EXTRACT(DAY FROM HIRE_DATE) AS 입사일
FROM EMP
WHERE EMP_ID = '200';
```
**출력 결과**: `곽상혁, 2013, 3, 2`

## 4. 형변환 함수

| 함수 | 역할 |
|---|---|
| `CAST(값 AS 타입)` | 명시적으로 자료형을 변환 |
| `DATE_FORMAT(날짜, 포맷)` | 날짜를 원하는 형식의 문자열로 변환 |
| `STR_TO_DATE(문자열, 포맷)` | 문자열을 날짜로 변환 |

```sql
-- 날짜 -> 문자열 (원하는 형식으로 출력)
SELECT EMP_NAME, DATE_FORMAT(HIRE_DATE, '%Y년 %m월 %d일') AS 입사일
FROM EMP
WHERE EMP_ID = '200';
```
**출력 결과**: `곽상혁, 2013년 03월 02일`

| 포맷 기호 | 의미 |
|---|---|
| `%Y` | 4자리 연도 |
| `%m` | 2자리 월(01~12) |
| `%d` | 2자리 일(01~31) |
| `%H:%i:%s` | 시:분:초 |

```sql
-- 문자열 -> 날짜
SELECT STR_TO_DATE('2026-08-19', '%Y-%m-%d');

-- 숫자 <-> 문자열 형변환
SELECT CAST(SALARY AS CHAR) AS 문자로,
       CAST('12345' AS SIGNED) AS 숫자로
FROM EMP
WHERE EMP_ID = '200';
```

**`CAST(값 AS 타입)`에 쓸 수 있는 타입은 정해져 있습니다.** `CREATE TABLE`에서 쓰던
타입명을 아무거나 쓸 수 있는 게 아니라, 아래 표에 있는 키워드만 허용됩니다.

| 변환 대상 타입 | 의미 |
|---|---|
| `CHAR[(n)]` | 문자열로 변환 |
| `SIGNED [INTEGER]` | 부호 있는 정수로 변환 |
| `UNSIGNED [INTEGER]` | 부호 없는(0 이상) 정수로 변환 |
| `DECIMAL[(m,d)]` | 정확한 소수로 변환 |
| `DATE` | 날짜로 변환 |
| `DATETIME` | 날짜+시각으로 변환 |
| `TIME` | 시각으로 변환 |
| `BINARY[(n)]` | 이진 문자열로 변환 |
| `JSON` | JSON으로 변환 |

> **주의**: `CREATE TABLE`에서는 `VARCHAR`, `INT`를 자연스럽게 썼지만, `CAST`에는 이
> 이름을 쓸 수 없습니다. 문자로 바꿀 때는 `VARCHAR`가 아니라 `CHAR`, 정수로 바꿀
> 때는 `INT`가 아니라 `SIGNED`(또는 `UNSIGNED`)를 써야 합니다.
> ```sql
> SELECT CAST(SALARY AS VARCHAR(10));  -- 에러! CAST에는 VARCHAR를 쓸 수 없음
> SELECT CAST(SALARY AS CHAR(10));     -- 올바른 표현
>
> SELECT CAST('123' AS INT);           -- 에러! CAST에는 INT를 쓸 수 없음
> SELECT CAST('123' AS SIGNED);        -- 올바른 표현
> ```

**설명**: `CAST(값 AS 타입)`의 대표적인 타입은 `CHAR`(문자), `SIGNED`/`DECIMAL`(숫자), `DATE`(날짜)입니다.
MySQL은 `'123' + 1`처럼 문자와 숫자를 섞어도 자동으로 형변환해주는 경우가 많지만, 의도를
명확히 하려면 `CAST`를 명시적으로 쓰는 것이 안전합니다.

### 형변환이 잘 되었는지 확인하는 방법

`CAST` 결과가 화면에 값은 잘 나와도, "진짜 원하는 타입으로 바뀐 것인지"는 눈으로만
봐서는 확신하기 어렵습니다. 문자 `'8000000'`과 숫자 `8000000`은 조회 결과 화면에
똑같이 보이기 때문입니다. 가장 확실한 방법은 `DDL` 챕터에서 배운 `CREATE TABLE ...
AS SELECT`(CTAS)로 결과를 임시 테이블에 담아 `DESC`로 실제 컬럼 타입을 눈으로
확인하는 것입니다.

```sql
CREATE TABLE TEMP_CAST_CHECK AS
SELECT SALARY,
       CAST(SALARY AS CHAR)   AS 문자로,
       CAST('12345' AS SIGNED) AS 숫자로,
       CAST(HIRE_DATE AS CHAR) AS 날짜를문자로
FROM EMP
WHERE EMP_ID = '200';

DESC TEMP_CAST_CHECK;
```

**출력 결과(일부)**
```
Field        Type
SALARY       int
문자로        varchar(11)
숫자로        bigint
날짜를문자로  varchar(10)
```

**설명**: CTAS는 조회 결과의 값뿐 아니라 **각 컬럼(계산식 포함)의 실제 데이터 타입까지
그대로 옮겨 담습니다.** `DESC`로 확인해보면 `문자로`는 진짜 `varchar`로, `숫자로`는
진짜 `bigint`(정수)로 바뀌어 있는 것을 눈으로 직접 확인할 수 있습니다. 확인이
끝나면 임시 테이블은 지웁니다.

```sql
DROP TABLE TEMP_CAST_CHECK;
```

> **참고**: 화면에 값이 똑같아 보여도 타입이 다르면 동작이 달라집니다. 예를 들어
> 숫자로 제대로 바뀐 값은 `ORDER BY` 시 `1, 2, 10` 순으로 정렬되지만, 문자로 남아
> 있다면 `'1', '10', '2'` 순(사전식)으로 정렬됩니다. 정렬 결과가 예상과 다르게
> 나온다면 형변환이 의도대로 되지 않았다는 신호일 수 있습니다.

## 5. NULL 처리 함수

| 함수 | 역할 |
|---|---|
| `IFNULL(값, 대체값)` | 값이 NULL이면 대체값을, 아니면 값을 그대로 반환 |
| `COALESCE(값1, 값2, ...)` | 여러 값 중 NULL이 아닌 첫 번째 값을 반환 |
| `NULLIF(값1, 값2)` | 두 값이 같으면 NULL, 다르면 값1을 반환 |

```sql
-- 보너스를 받지 않는 사원은 0으로 취급해서 보너스 포함 연봉 계산
SELECT EMP_NAME, BONUS,
       IFNULL(BONUS, 0) AS 보너스율,
       (SALARY + (SALARY * IFNULL(BONUS, 0))) * 12 AS 연봉
FROM EMP
WHERE EMP_ID IN ('200', '201');
```
**출력 결과**
```
곽상혁 0.30 0.30 124800000
권진우 (null) 0.00 72000000
```

**설명**: `IFNULL(BONUS, 0)`은 인자를 정확히 2개만 받습니다. `COALESCE(BONUS, 0)`은 같은 결과를
내지만 인자를 3개 이상도 받을 수 있어("첫 번째로 NULL이 아닌 값") 더 범용적입니다. `NULLIF(10, 10)`은
`NULL`을, `NULLIF(10, 20)`은 `10`을 반환합니다 — 두 값이 같을 때 일부러 `NULL`로 만들고 싶을 때
사용합니다.

## 6. CASE / IF — 조건에 따른 값 선택

```sql
-- 급여를 3단계 등급으로 분류
SELECT EMP_NAME, SALARY,
       CASE WHEN SALARY >= 5000000 THEN '고액'
            WHEN SALARY >= 2500000 THEN '중액'
            ELSE '소액'
       END AS 등급
FROM EMP
WHERE EMP_ID IN ('200', '205', '210');
```
**출력 결과**
```
곽상혁 8000000 고액
박지민 3500000 중액
이광렬 2000000 소액
```

**설명**: `CASE`는 위에서부터 순서대로 조건을 검사하다가, 처음으로 참이 되는 `WHEN`의 결과를
반환하고 나머지는 검사하지 않습니다. 어떤 조건에도 해당하지 않으면 `ELSE`의 값을 반환하고,
`ELSE`가 없으면 `NULL`을 반환합니다. (MySQL에는 Oracle의 `DECODE` 함수가 없으므로, "값이
같은지"만 비교하는 간단한 경우에도 `CASE`를 사용합니다.)

> **`CASE WHEN`은 프로그래밍 언어의 `if / else if / else`와 똑같이 동작합니다.**
> 위 예제를 자바/파이썬 식으로 옮기면 `if (SALARY >= 5000000) 고액; else if (SALARY
> >= 2500000) 중액; else 소액;`과 정확히 같은 흐름입니다. `WHEN`을 하나만 쓰고
> `ELSE`만 붙이면 `if / else` 두 갈래로도 쓸 수 있습니다(바로 다음의 `IF()` 함수와
> 비교해보세요).

```sql
-- EMP_NO 8번째 글자로 성별 표시
SELECT EMP_NAME,
       CASE SUBSTRING(EMP_NO, 8, 1)
            WHEN '1' THEN '남'
            WHEN '2' THEN '여'
            WHEN '3' THEN '남'
            WHEN '4' THEN '여'
       END AS 성별
FROM EMP
WHERE EMP_ID = '200';
```
**출력 결과**: `곽상혁, 남`

**설명**: `CASE 표현식 WHEN 값 THEN 결과 ...` 형태로 쓰면, "표현식이 이 값과 같을 때"를 하나씩
비교합니다. 방금 위에서 쓴 `CASE WHEN 조건 THEN ...` 형태와는 살짝 다른 문법이니 구분해두세요.

### IF() 함수 — 두 갈래(참/거짓)만 필요할 때

조건이 **참/거짓 두 갈래뿐**이라면, `CASE WHEN ... THEN ... ELSE ... END`를 다 쓰지
않고 `IF(조건, 참일때값, 거짓일때값)` 함수 하나로 줄일 수 있습니다.

```sql
SELECT EMP_NAME, SALARY,
       IF(SALARY >= 3000000, '고액', '일반') AS 급여구분
FROM EMP
WHERE EMP_ID IN ('200', '210');
```
**출력 결과**
```
곽상혁 8000000 고액
이광렬 2000000 일반
```

**설명**: `IF(SALARY >= 3000000, '고액', '일반')`은 `CASE WHEN SALARY >= 3000000 THEN
'고액' ELSE '일반' END`와 완전히 같은 결과를 냅니다. 아래 표처럼 상황에 맞게 골라
씁니다.

| 상황 | 선택 |
|---|---|
| 조건이 딱 2갈래(참/거짓)뿐 | `IF(조건, 참, 거짓)` — 더 짧고 간결 |
| 조건이 3갈래 이상(등급 분류 등) | `CASE WHEN ... WHEN ... ELSE ... END` |
| 특정 컬럼 값이 여러 값 중 무엇과 같은지 비교 | `CASE 표현식 WHEN 값 THEN ... END` |

> **주의**: `IF()` **함수**(값 하나를 반환, `SELECT`절에서 사용)와, 스토어드
> 프로시저 안에서만 쓰는 `IF ... THEN ... END IF;` **제어문**(값을 반환하지 않고
> 실행 흐름을 분기)은 이름은 같지만 완전히 다른 문법입니다. 이 교재에서 다루는 것은
> 항상 값을 반환하는 **`IF()` 함수** 쪽입니다.

## 7. 그룹 함수

| 함수 | 역할 |
|---|---|
| `SUM(컬럼)` | 합계 |
| `AVG(컬럼)` | 평균 |
| `MIN(컬럼)` / `MAX(컬럼)` | 최솟값 / 최댓값 |
| `COUNT(*)` | 조건에 맞는 전체 행 개수 |
| `COUNT(컬럼)` | 그 컬럼 값이 NULL이 아닌 행 개수 |
| `COUNT(DISTINCT 컬럼)` | 그 컬럼의 중복을 제거한 값 개수 |

**모든 그룹 함수는 NULL을 자동으로 제외하고 계산합니다.** 그래서 `AVG`를 쓸 때는
`AVG(IFNULL(BONUS, 0))`처럼 NULL을 원하는 값으로 미리 바꿔줄지 고민해야 합니다(NULL을 그냥
두면 "보너스가 있는 사람들만의 평균"이 되고, 0으로 바꾸면 "전체 인원 기준 평균"이 됩니다).

```sql
SELECT SUM(SALARY),              -- 65616240
       ROUND(AVG(SALARY)),       -- 3124583
       MAX(SALARY),              -- 8000000
       MIN(SALARY),              -- 1380000
       COUNT(*),                 -- 21  (전체 사원 수)
       COUNT(BONUS),             -- 9   (보너스를 받는 사원 수)
       COUNT(DISTINCT DEPT_ID),  -- 6   (사원이 배치된 부서 종류 수)
       COUNT(DISTINCT JOB_CODE)  -- 7   (등장하는 직급 종류 수)
FROM EMP;
```

**설명**: `COUNT(*)`은 조건에 맞는 모든 행을 세지만, `COUNT(BONUS)`는 `BONUS`가 `NULL`이 아닌
행만 셉니다(보너스를 받지 않는 12명은 세지 않으므로 21이 아니라 9입니다). `COUNT(DISTINCT
DEPT_ID)`는 부서가 배정되지 않은 2명(`NULL`)을 자동으로 제외하고, 실제 사용된 부서 코드
6종류(D1, D2, D5, D6, D8, D9)만 셉니다.

## 8. GROUP BY / HAVING

그룹 함수는 기본적으로 "테이블 전체"를 하나의 그룹으로 계산합니다. 부서별·직급별처럼 **여러
그룹으로 나눠서** 각각 계산하고 싶다면 `GROUP BY`가 반드시 필요합니다.

```sql
-- 부서별 급여 합계, 인원수
SELECT DEPT_ID, SUM(SALARY) AS 급여합계, COUNT(*) AS 인원수
FROM EMP
GROUP BY DEPT_ID
ORDER BY DEPT_ID;
```
**출력 결과**
```
(null)  5210000  2
D1      7820000  3
D2      6840000  3
D5     13760000  5
D6      7300000  2
D8      6986240  3
D9     17700000  3
```

**설명**: `GROUP BY DEPT_ID`는 `DEPT_ID` 값이 같은 행끼리 하나의 그룹으로 묶습니다. `DEPT_ID`가
`NULL`인 2명(조정원, 한규원)도 "`NULL`끼리" 하나의 그룹으로 묶여서 별도로 집계됩니다.

**HAVING**: 그룹 함수로 계산한 결과에 조건을 걸고 싶을 때는 `WHERE`가 아니라 `HAVING`을
써야 합니다. `WHERE`는 그룹으로 묶이기 **전** 개별 행에 대한 조건이고, `HAVING`은 그룹으로
묶인 **후** 집계 결과에 대한 조건이기 때문입니다.

```sql
-- 부서별 급여 합계가 1000만원 이상인 부서만 조회
SELECT DEPT_ID, SUM(SALARY) AS 급여합계
FROM EMP
GROUP BY DEPT_ID
HAVING SUM(SALARY) >= 10000000
ORDER BY DEPT_ID;
```
**출력 결과**
```
D5  13760000
D9  17700000
```

**실행 순서**: `FROM` → `WHERE` → `GROUP BY` → `HAVING` → `SELECT` → `ORDER BY`. `WHERE`절에는
그룹 함수를 쓸 수 없다는 점(아직 그룹이 만들어지기 전이므로), `HAVING`절에는 그룹으로 묶인
컬럼이나 그룹 함수만 쓸 수 있다는 점을 기억하세요.

---

## 자주 하는 실수

1. **Oracle 함수 이름을 그대로 씀**
   ```sql
   SELECT NVL(BONUS, 0) FROM EMP;   -- 에러! MySQL에는 NVL이 없음
   SELECT IFNULL(BONUS, 0) FROM EMP; -- 올바른 표현
   ```

2. **`LTRIM`/`RTRIM`에 지정 문자를 넘기려는 시도**
   ```sql
   SELECT LTRIM('000123', '0');           -- 에러! MySQL의 LTRIM은 인자 1개만 받음
   SELECT TRIM(LEADING '0' FROM '000123'); -- 올바른 표현 -> '123'
   ```

3. **`CAST`에 `CREATE TABLE`에서 쓰던 타입명(`VARCHAR`, `INT` 등)을 그대로 사용**
   ```sql
   SELECT CAST(SALARY AS VARCHAR(10)); -- 에러! CAST에는 VARCHAR를 쓸 수 없음
   SELECT CAST(SALARY AS CHAR(10));    -- 올바른 표현
   ```
   `CAST`에 쓸 수 있는 타입은 `CHAR`/`SIGNED`/`UNSIGNED`/`DECIMAL`/`DATE` 등으로
   정해져 있습니다(4절 표 참고).

4. **그룹 함수와 일반 컬럼을 `GROUP BY` 없이 함께 SELECT**
   ```sql
   SELECT DEPT_ID, EMP_NAME, SUM(SALARY) FROM EMP; -- 의도와 다르게 동작하거나 에러
   ```
   `EMP_NAME`처럼 그룹화 기준이 아닌 컬럼을 그룹 함수와 함께 쓰려면, `GROUP BY`에 그 컬럼도
   포함시키거나 애초에 그런 조합을 피해야 합니다.

5. **집계 조건을 `WHERE`에 씀**
   ```sql
   SELECT DEPT_ID, SUM(SALARY)
   FROM EMP
   WHERE SUM(SALARY) >= 10000000  -- 에러! WHERE절에는 그룹 함수 사용 불가
   GROUP BY DEPT_ID;
   ```
   그룹 함수에 대한 조건은 반드시 `HAVING`에 써야 합니다.

## 핵심 요약

| 항목 | 핵심 내용 |
|---|---|
| 문자 함수 | `CHAR_LENGTH`(글자 수)/`LENGTH`(바이트), `INSTR`, `LPAD`/`RPAD`, `SUBSTRING`, `CONCAT`(2개 이상 가능) |
| 숫자 함수 | `ROUND`(반올림) vs `TRUNCATE`(그냥 자름), `CEIL`/`FLOOR` |
| 날짜 함수 | `DATE_ADD`/`DATE_SUB`, `TIMESTAMPDIFF`, `LAST_DAY`, `EXTRACT` (단위: YEAR~SECOND 공유) |
| 형변환 | `CAST`(대상 타입은 `CHAR`/`SIGNED`/`UNSIGNED`/`DECIMAL`/`DATE` 등으로 한정, `VARCHAR`/`INT` 불가), `DATE_FORMAT`(날짜→문자열), `STR_TO_DATE`(문자열→날짜) |
| NULL 처리 | `IFNULL`/`COALESCE`(대체), `NULLIF`(같으면 NULL로) |
| CASE / IF | `CASE`는 if/else if/else와 동일(3갈래 이상), `IF(조건,참,거짓)`는 2갈래 조건에 사용 (MySQL엔 `DECODE` 없음) |
| 그룹 함수 | `SUM`/`AVG`/`MIN`/`MAX`/`COUNT`, NULL은 자동 제외 |
| GROUP BY / HAVING | `WHERE`(그룹화 전 조건) vs `HAVING`(그룹화 후 집계 조건) |
