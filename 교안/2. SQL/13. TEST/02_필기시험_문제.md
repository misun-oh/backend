# I. 선다형 (40문항 × 1점)

**1.** SQL 명령어 분류에서 `SELECT` 가 속하는 것은?
① DDL  ② DML(DQL)  ③ DCL  ④ TCL

**2.** 다음 중 DDL(데이터 정의어)이 **아닌** 것은?
① `CREATE`  ② `ALTER`  ③ `DROP`  ④ `UPDATE`

**3.** `WHERE` 절과 `HAVING` 절의 차이로 옳은 것은?
① 둘은 완전히 같다
② `HAVING` 은 `GROUP BY` 로 묶은 **그룹**에 대한 조건에 쓴다
③ `WHERE` 절에는 집계함수를 제한 없이 쓸 수 있다
④ `HAVING` 은 결과 정렬을 담당한다

**4.** 급여(`SAL`)가 입력되지 않은(NULL) 행을 조회하는 조건으로 옳은 것은?
① `WHERE SAL = NULL`  ② `WHERE SAL != NULL`  ③ `WHERE SAL IS NULL`  ④ `WHERE SAL == NULL`

**5.** `WHERE A = 1 OR A = 2 AND B = 3` 의 해석으로 옳은 것은?
① `(A=1 OR A=2) AND B=3`
② `A=1 OR (A=2 AND B=3)`
③ `A=1 AND A=2 AND B=3`
④ 문법 오류

**6.** `LIKE '_국%'` 이 찾는 문자열은?
① '국' 으로 시작하는 문자열
② **두 번째** 글자가 '국' 인 문자열
③ '국' 으로 끝나는 문자열
④ '국' 을 포함하지 않는 문자열

**7.** SELECT 문의 **논리적 실행 순서**로 옳은 것은?
① `SELECT → FROM → WHERE → GROUP BY → HAVING → ORDER BY`
② `FROM → WHERE → GROUP BY → HAVING → SELECT → ORDER BY`
③ `FROM → SELECT → WHERE → ORDER BY → GROUP BY`
④ `WHERE → FROM → GROUP BY → SELECT → HAVING`

**8.** MySQL 에서 문자열 두 개를 이어붙이는 방법은?
① `A || B`  ② `A + B`  ③ `CONCAT(A, B)`  ④ `A & B`

**9.** `IFNULL(BONUS, 0)` 의 결과는?
① `BONUS` 가 0 이면 NULL
② `BONUS` 가 NULL 이면 0
③ 항상 0
④ 항상 `BONUS`

**10.** `CASE` 표현식이 돌려주는 값은?
① 마지막 `WHEN` 의 값
② 처음으로 조건이 참인 `WHEN` 의 `THEN` 값
③ 모든 `THEN` 값의 합
④ 항상 `ELSE` 값

**11.** 집계함수 `AVG(SAL)` 은 `SAL` 이 NULL 인 행을 어떻게 처리하나?
① 0 으로 보고 계산  ② NULL 인 행을 제외하고 평균  ③ 결과가 무조건 NULL  ④ 오류

**12.** `COUNT(*)` 와 `COUNT(COMM)` 의 차이로 옳은 것은?
① 항상 같다
② `COUNT(COMM)` 은 `COMM` 이 NULL 인 행을 세지 않는다
③ `COUNT(*)` 가 NULL 을 세지 않는다
④ 둘 다 NULL 을 제외한다

**13.** `ROUND(3.14159, 2)` 의 결과는?
① 3.1  ② 3.14  ③ 3.142  ④ 3

**14.** MySQL 에서 `SUBSTRING('DATABASE', 5)` 의 결과는?
① 'DATA'  ② 'BASE'  ③ 'ABASE'  ④ 'TABASE'

**15.** 오늘 날짜에서 **연도만** 숫자로 얻는 함수는?
① `YEAR(NOW())`  ② `DATE(NOW())`  ③ `DAY(NOW())`  ④ `TIME(NOW())`

**16.** 두 날짜 사이의 **만(滿) 연수**를 구하는 함수는?
① `DATEDIFF(d1, d2)`
② `TIMESTAMPDIFF(YEAR, d1, d2)`
③ `ADDDATE(d1, d2)`
④ `LAST_DAY(d1)`

**17.** MySQL 에서 `DATE_FORMAT('2026-03-02', '%Y/%m/%d')` 의 결과는?
① `2026/03/02`  ② `2026-03-02`  ③ `26/03/02`  ④ `2026/3/2`

**18.** `NULL + 100` 의 결과는?
① 100  ② 0  ③ NULL  ④ 오류

**19.** `GROUP BY DEPT_ID` 로 묶은 결과에서 `SELECT` 절에 그대로 쓸 수 있는 것은? (기본 `ONLY_FULL_GROUP_BY` 기준)
① 모든 컬럼  ② `DEPT_ID` 와 집계함수  ③ 집계함수만  ④ 아무 컬럼이나

**20.** 부서별 인원이 **5명 이상**인 부서만 남기려면?
① `WHERE COUNT(*) >= 5`
② `HAVING COUNT(*) >= 5`
③ `GROUP BY COUNT(*) >= 5`
④ `ORDER BY COUNT(*) >= 5`

**21.** `INNER JOIN` 의 결과는?
① 왼쪽 테이블 전체
② 양쪽에서 조인 조건이 일치하는 행만
③ 양쪽 테이블 전체
④ 오른쪽 테이블 전체

**22.** `A LEFT JOIN B` 에서 B에 짝이 없는 A의 행은?
① 결과에서 제외된다
② B쪽 컬럼이 NULL 로 채워져 나온다
③ 오류가 난다
④ A쪽 컬럼이 NULL 이 된다

**23.** 같은 테이블을 두 번 참조해 계층 관계(예: 과목–선수과목)를 조회하는 조인은?
① CROSS JOIN  ② SELF JOIN  ③ NATURAL JOIN  ④ FULL JOIN

**24.** `SELECT` 절에 쓰여 **값 하나**를 돌려주는 서브쿼리는?
① 다중행 서브쿼리  ② 스칼라 서브쿼리  ③ 인라인 뷰  ④ 상관 서브쿼리

**25.** 상관(correlated) 서브쿼리의 특징은?
① 전체 쿼리에서 한 번만 실행된다
② 외부 쿼리의 각 행마다 실행된다
③ `FROM` 절에만 쓸 수 있다
④ 항상 스칼라 값을 반환한다

**26.** `EXISTS (서브쿼리)` 의 의미는?
① 서브쿼리 결과의 행 수를 반환
② 서브쿼리 결과가 한 행이라도 있으면 참
③ 서브쿼리의 첫 번째 값을 반환
④ 항상 참

**27.** `COL NOT IN (서브쿼리)` 에서 서브쿼리 결과에 NULL 이 섞이면?
① 정상 동작한다
② 조건에 맞아도 결과가 한 건도 안 나올 수 있다
③ NULL 을 0 으로 본다
④ 오류가 난다

**28.** 외래키(FK)가 참조할 수 있는 **부모 컬럼**의 조건은?
① 아무 컬럼이나
② 부모 테이블의 PRIMARY KEY 또는 UNIQUE 컬럼
③ NULL 이 들어 있는 컬럼
④ 인덱스가 없는 컬럼

**29.** `CREATE TABLE T AS SELECT ...` (CTAS) 로 새 테이블을 만들 때 원본에서 **복사되지 않는** 것은?
① 컬럼 이름  ② 데이터  ③ 데이터 타입  ④ PRIMARY KEY·FK 같은 제약조건

**30.** PRIMARY KEY 제약의 성질로 옳은 것은?
① NULL 허용 + 중복 허용
② NOT NULL + UNIQUE
③ NULL 허용 + UNIQUE
④ 중복만 금지

**31.** (30번과 같은 개념) 어떤 컬럼을 FK 로 참조하려면 그 컬럼에는 어떤 제약이 있어야 하나?
① CHECK  ② PRIMARY KEY 또는 UNIQUE  ③ DEFAULT  ④ 제약 불필요

**32.** `DELETE FROM T` 를 `WHERE` 없이 실행하면?
① 오류가 난다  ② 아무 일도 없다  ③ 테이블의 모든 행이 삭제된다  ④ 테이블 자체가 삭제된다

**33.** `DELETE` 와 `TRUNCATE` 의 차이로 옳은 것은?
① 둘 다 `ROLLBACK` 으로 되돌릴 수 있다
② `TRUNCATE` 는 `WHERE` 로 일부만 지울 수 있다
③ `TRUNCATE` 는 DDL 성이라 자동 커밋되고 되돌릴 수 없다
④ `DELETE` 가 항상 더 빠르다

**34.** MySQL 의 `autocommit` 기본값은?
① 0 (꺼짐)  ② 1 (켜짐)  ③ NULL  ④ 접속마다 무작위

**35.** 트랜잭션 도중 `CREATE TABLE` 같은 DDL 을 실행하면?
① 무시된다
② **암묵적 커밋**이 일어나 그전의 변경까지 확정된다
③ 오류가 난다
④ 자동으로 롤백된다

**36.** `SAVEPOINT` 의 용도는?
① 전체 트랜잭션을 커밋한다
② 트랜잭션 안에 되돌아갈 지점을 만들어 **부분 롤백**을 가능하게 한다
③ 자동 저장 기능이다
④ 백업 파일을 만든다

**37.** `ROW_NUMBER()` 와 `RANK()` 의 차이는?
① 완전히 같다
② `RANK()` 는 동점이면 같은 순위를 주고 그다음 순위를 **건너뛴다**
③ `ROW_NUMBER()` 는 동점을 같은 번호로 준다
④ `RANK()` 는 정렬이 필요 없다

**38.** 인덱스에 대한 설명으로 옳은 것은?
① 조회·쓰기 모두 빨라지고 공간도 줄어든다
② 조회는 빨라지지만 `INSERT`/`UPDATE`/`DELETE` 는 느려지고 저장 공간을 더 쓴다
③ 인덱스는 데이터를 물리적으로 복제한 별도 테이블이다
④ 모든 컬럼에 인덱스를 걸수록 항상 좋다

**39.** 뷰(VIEW)에 대한 설명으로 옳은 것은?
① 조회 결과를 물리적으로 복사해 별도 공간에 저장한다
② 저장된 `SELECT` 문이며, 뷰를 조회할 때마다 그 `SELECT` 가 다시 실행된다
③ 뷰를 만들면 원본 테이블은 삭제된다
④ 뷰에는 `WHERE` 조건을 넣을 수 없다

**40.** 사용자정의 함수(`CREATE FUNCTION`)와 프로시저(`CREATE PROCEDURE`)에 대한 설명으로 옳은 것은?
① 함수는 `RETURNS` 로 반환 타입을 반드시 지정하고, `SELECT` 절에서 호출할 수 있다
② 프로시저는 `RETURN` 으로 값 하나를 돌려준다
③ 함수는 `CALL` 로 호출한다
④ 함수 안에서 `COMMIT` / `ROLLBACK` 을 자유롭게 쓸 수 있다
