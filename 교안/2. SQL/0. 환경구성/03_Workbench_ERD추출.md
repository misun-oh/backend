# 3. Workbench에서 ERD 추출하기

| 항목 | 내용 |
|---|---|
| 이번 자료 | MySQL Workbench의 Reverse Engineer 기능으로 기존 데이터베이스에서 ERD를 자동 생성하는 방법 |
| 권장 시점 | `02_ERD읽는법.md`(표기법 이해) 이후, DQL 챕터 시작 전 또는 DDL 챕터 학습 후 |
| 선수 학습 | `01_실습데이터.md`로 `hr` 데이터베이스 생성 완료 |

## 학습목표
- Workbench의 **Reverse Engineer** 마법사로 기존 데이터베이스에서 EER 다이어그램을
  자동으로 생성할 수 있다.
- 자동 생성된 다이어그램의 레이아웃을 정리하고, 관계선이 `02_ERD읽는법.md`에서 배운
  표기법과 어떻게 대응되는지 읽을 수 있다.
- 완성한 ERD를 PNG/PDF 파일로 내보낼 수 있다.
- 왜 우리 실습 데이터베이스에서는 관계선이 자동으로 그려지지 않는지 이해한다
  (제약조건과의 연관성).

---

## 1. 왜 ERD를 "추출"하는가

`02_ERD읽는법.md`에서는 이미 그려진 ERD를 **읽는 법**을 배웠습니다. 하지만 실무에서는
반대 상황이 더 흔합니다 — 신규 프로젝트에 투입되어 **이미 존재하는 데이터베이스**를
넘겨받았는데, 정작 그 구조를 설명해주는 ERD 문서는 없는 경우입니다.

이럴 때 테이블을 하나하나 `DESC`로 열어보며 손으로 관계도를 그리는 대신, MySQL
Workbench는 실제 데이터베이스에 접속해서 테이블·컬럼·제약조건을 스스로 읽어들여
**ERD를 자동으로 그려주는 기능**을 제공합니다. 이를 **리버스 엔지니어링(Reverse
Engineering)**이라고 부릅니다("정방향"이 모델 설계 → DDL 생성이라면, 이건 그 반대
방향입니다).

---

## 2. Reverse Engineer 마법사 실행

`hr` 데이터베이스(또는 실습용으로 만든 다른 데이터베이스)에 접속된 상태에서 시작합니다.

1. 상단 메뉴 **Database → Reverse Engineer...** 클릭 (단축키 `Ctrl+R`)
2. **1단계 (Connection Options)**: 현재 접속 정보(호스트, 계정)를 확인하고 `Next`
3. **2단계 (Connect to DBMS)**: Workbench가 실제로 서버에 접속을 시도합니다. 초록색
   체크가 뜨면 `Next`
4. **3단계 (Select Schemas)**: 추출할 스키마 목록이 체크박스로 표시됩니다. 우리가 만든
   `hr`(또는 실습에 사용 중인 데이터베이스)를 체크하고 `Next`

   > **자주 하는 실수**: 이 단계에서 스키마를 체크하지 않고 그냥 `Next`를 누르면, 이후
   > 단계가 전부 빈 채로 진행되어 아무 테이블도 없는 빈 다이어그램이 만들어집니다.

5. **4단계 (Reverse Engineer Progress)**: Workbench가 스키마 정보를 읽어오는 진행
   상황이 표시됩니다. `Execute` → `Next`
6. **5단계 (Select Objects)**: 가져올 테이블 목록이 나타납니다(기본적으로 전체 선택).
   `EMP`, `DEPT`, `JOB`, `LOCATION`, `NATIONAL`, `SAL_GRADE` 6개가 모두 보이는지
   확인하고 `Next`
7. 마지막 안내 화면에서 `Finish`를 누르면 **EER Diagram** 캔버스가 열리고, 테이블
   박스들이 화면에 자동으로 배치됩니다.

---

## 3. 결과 다이어그램 정리하기

방금 만들어진 다이어그램은 테이블 박스가 서로 겹치거나 순서가 뒤죽박죽인 경우가
많습니다. 정리 방법은 다음과 같습니다.

- 캔버스 빈 곳에서 우클릭 → **Arrange → Auto Layout**을 선택하면 Workbench가
  테이블 박스를 자동으로 재배치합니다.
- 자동 배치 후에도 관계선이 서로 겹쳐 읽기 어렵다면, 테이블 박스를 마우스로 직접
  드래그해서 손으로 정리하는 것을 권장합니다.
- 관계선 위에 마우스를 올리면 카디널리티 표기가 강조되어 보이는데, 이것이
  `02_ERD읽는법.md`에서 배운 까마귀발(crow's foot) 표기와 동일합니다.

---

## 4. 관계선이 하나도 안 보인다면 (FK 제약조건 이슈)

`01_실습데이터.md`의 `hr` 스키마로 Reverse Engineer를 실행하면, **테이블 박스만
나타나고 테이블 사이를 잇는 관계선이 하나도 보이지 않습니다.** 이것은 Workbench가
고장난 것이 아니라 당연한 결과입니다.

`6. DDL/1_DDL.md`에서 배운 것처럼, 우리 실습 데이터베이스는 강의 편의상 `PRIMARY
KEY`/`FOREIGN KEY` 같은 제약조건 없이 컬럼 타입만으로 만들어졌습니다(`01_실습데이터.md`
3절의 `CREATE TABLE`을 다시 보면 제약조건이 전혀 없습니다). **Reverse Engineer는
데이터가 아니라 실제 `FOREIGN KEY` 제약조건을 근거로 관계선을 그리기 때문에**, FK가
없는 테이블은 서로 연관되어 보여도 관계선이 그려지지 않습니다.

관계선이 있는 ERD를 직접 보고 싶다면 다음 중 하나를 시도해보세요.

- `6. DDL/1_DDL_실습답안.md`에서 `PRIMARY KEY`/`FOREIGN KEY`를 추가한
  `EMP_COPY`/`DEPT_COPY`로 Reverse Engineer를 다시 실행해봅니다.
- 다이어그램 위에서 좌측 도구모음의 **관계 도구(예: "Place a Foreign Key Relationship
  Using an Existing Column")**를 선택해 테이블 사이를 직접 손으로 이어봅니다. 이 과정
  자체가 `02_ERD읽는법.md`에서 배운 관계를 다시 한번 확인하는 좋은 복습이 됩니다.

---

## 5. 이미지/PDF로 내보내기

다이어그램 정리가 끝나면 문서나 발표 자료에 붙여넣을 수 있도록 파일로 저장합니다.

1. 상단 메뉴 **File → Export → Export as PNG...**(또는 `SVG`, `PDF`, `Single Page
   PDF...`)를 선택합니다.
2. 저장할 파일명과 위치를 지정하고 저장합니다.

> **참고**: `Export as Single Page PDF...`를 선택하면 다이어그램이 아무리 커도 여러
> 장으로 잘리지 않고 한 페이지짜리 PDF로 저장됩니다. 팀 문서 공유용으로는 이 옵션이
> 편리합니다.

---

## 6. (선택) Synchronize Model — 다이어그램과 DB 다시 맞추기

시간이 지나 실제 데이터베이스에 테이블이 추가되거나 컬럼이 바뀌면, 이전에 추출해둔
다이어그램은 낡은 정보가 됩니다. 이때 처음부터 다시 Reverse Engineer를 실행하는 대신,
**Database → Synchronize Model...** 메뉴로 다이어그램과 실제 DB의 차이점만 비교해서
원하는 방향으로 반영할 수 있습니다(DB → 모델, 또는 모델 → DB 양쪽 다 가능).

---

## 자주 하는 실수

- **3단계(Select Schemas)에서 스키마를 체크하지 않고 진행** → 빈 다이어그램이 만들어
  집니다. 원하는 스키마가 체크되었는지 항상 확인하세요.
- **FK가 없는 테이블을 추출하고 "관계선이 안 그려진다"며 기능 오류로 오해** → 4절에서
  설명한 대로, Reverse Engineer는 실제 `FOREIGN KEY` 제약조건이 있어야만 관계선을
  그립니다. 데이터나 컬럼명이 비슷하다고 자동으로 관계를 추론하지 않습니다.
- **레이아웃 정리 없이 곧바로 내보내기** → 테이블 박스가 겹친 채로 저장되어 알아보기
  어려운 이미지가 됩니다. `Auto Layout` 또는 수동 정리를 먼저 거치세요.
- **작업한 모델(.mwb) 파일을 저장하지 않고 Workbench를 종료** → 다이어그램 정리
  작업이 전부 사라집니다. `Ctrl+S`로 모델 파일을 별도로 저장해두는 습관을 들이세요.

---

## 핵심 요약

| 단계 | 내용 |
|---|---|
| 실행 | `Database → Reverse Engineer...` (`Ctrl+R`) |
| 마법사 순서 | 접속 확인 → DBMS 연결 → 스키마 선택 → 진행/Execute → 객체 선택 → Finish |
| 정리 | 우클릭 `Arrange → Auto Layout` + 수동 드래그 |
| 관계선이 안 보이는 이유 | 우리 실습 DB는 FK 제약조건이 없어서(6. DDL 챕터 참고) |
| 내보내기 | `File → Export → Export as PNG/PDF/Single Page PDF...` |
| 최신 상태 유지 | `Database → Synchronize Model...` |
