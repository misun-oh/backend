# Day 15. INDEX & EXPLAIN - 실습

> 아래 문제는 `1_인덱스.md`의 `BIG_EMP`(63,000행) 테이블과 원본 `EMP` 테이블로
> 풀 수 있습니다. 숫자 정답이 아니라 SQL 작성과 EXPLAIN 결과 해석이 핵심입니다.

---

## 기본

### 문제 1. 인덱스 생성
`BIG_EMP`의 `DEPT_ID` 컬럼에 `IDX_BIGEMP_DEPT`라는 이름의 인덱스를 생성하는 SQL을
작성하세요.

---

### 문제 2. EXPLAIN 전후 비교
문제 1의 인덱스를 만들기 **전**과 **후**에 각각
`EXPLAIN SELECT * FROM BIG_EMP WHERE DEPT_ID = 'D9';`를 실행하고, `type`/`key`/`rows`
컬럼이 각각 어떻게 달라지는지, 왜 그렇게 되는지 서술하세요.

---

## 응용

### 문제 3. 복합 인덱스와 컬럼 순서
`BIG_EMP`에 `(DEPT_ID, SALARY)` 순서의 복합 인덱스 `IDX_BIGEMP_DEPT_SALARY`를
생성하세요. 그리고 아래 두 쿼리 중 이 인덱스를 거의 활용하지 못하는 쪽은
무엇이고 이유는 무엇인지 서술하세요.

```sql
SELECT * FROM BIG_EMP WHERE DEPT_ID = 'D5' AND SALARY >= 3000000;
SELECT * FROM BIG_EMP WHERE SALARY >= 3000000;
```

---

### 문제 4. 함수를 씌운 조건 다시 쓰기
`BIG_EMP.HIRE_DATE`에 인덱스가 걸려 있다고 가정할 때,
`WHERE YEAR(HIRE_DATE) = 2013`는 이 인덱스를 타지 못합니다. 같은 조건(2013년에
입사한 행)을 인덱스를 탈 수 있는 형태로 다시 작성하세요.

## 도전

### 문제 5. 타입 불일치 찾기
`EMP.EMP_ID`는 `VARCHAR(3)`입니다. 아래 두 쿼리 중 `EMP_ID`에 인덱스가 있어도 그
인덱스를 타지 못하는 쪽은 무엇이고, 그 이유를 설명하세요.

```sql
SELECT * FROM EMP WHERE EMP_ID = 200;
SELECT * FROM EMP WHERE EMP_ID = '200';
```
