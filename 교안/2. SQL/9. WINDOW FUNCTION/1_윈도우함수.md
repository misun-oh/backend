## 학습목표
- `GROUP BY`(그룹당 1행으로 축약)와 윈도우 함수(원본 행을 유지한 채 계산값을 붙임)의
  차이를 설명할 수 있다.
- `ROW_NUMBER()`/`RANK()`/`DENSE_RANK()`의 차이를 동점(tie) 상황에서 구분해서 쓸 수 있다.
- `PARTITION BY`로 그룹별 윈도우를 나눠 부서별 순위/집계를 구할 수 있다.
- `LAG()`/`LEAD()`로 정렬된 결과에서 이전/다음 행의 값을 같은 행에서 참조할 수 있다.
- `SUM() OVER (ORDER BY ...)`로 누적 합계를 구할 수 있다.
- 윈도우 함수 + 인라인 뷰로 "부서별 Top-N"을 서브쿼리 없이 풀 수 있다.

## 1. 윈도우 함수란 - GROUP BY와 무엇이 다른가

`GROUP BY`는 여러 행을 **하나의 그룹으로 압축**해서 그룹당 1행만 남깁니다. 반면
**윈도우 함수**는 `OVER()`로 지정한 범위("윈도우")를 기준으로 계산하되, **원본 행 개수를
그대로 유지**하면서 각 행에 계산 결과를 붙입니다.

```sql
SELECT EMP_NAME, DEPT_ID, SALARY,
       AVG(SALARY) OVER (PARTITION BY DEPT_ID) AS 부서평균
FROM EMP
WHERE DEPT_ID = 'D5'
ORDER BY EMP_ID;
```

**출력 결과**
```
박지민 D5 3500000 2752000
염성원 D5 2200000 2752000
유제영 D5 2500000 2752000
윤정주 D5 3760000 2752000
최주호 D5 1800000 2752000
```

**설명**: `GROUP BY DEPT_ID`로 같은 쿼리를 짰다면 `D5, 2752000` 딱 1행만 나왔을
것입니다. `AVG(SALARY) OVER (PARTITION BY DEPT_ID)`는 "D5 부서 전체의 평균을 구하되,
5명 각각의 행은 그대로 유지하고 그 옆에 평균값만 나란히 붙여라"는 뜻입니다.
`PARTITION BY`는 `GROUP BY`와 비슷하게 "어떤 기준으로 창을 나눌지"를 지정하지만,
행을 압축하지 않는다는 점이 다릅니다.

## 2. ROW_NUMBER / RANK / DENSE_RANK

세 함수 모두 `OVER (ORDER BY ...)`로 순위를 매기지만, **동점(같은 값)을 처리하는 방식**이
다릅니다.

```sql
SELECT EMP_NAME, EXTRACT(YEAR FROM HIRE_DATE) AS 입사연도,
       ROW_NUMBER() OVER (ORDER BY EXTRACT(YEAR FROM HIRE_DATE) ASC) AS 순번,
       RANK()       OVER (ORDER BY EXTRACT(YEAR FROM HIRE_DATE) ASC) AS 순위,
       DENSE_RANK() OVER (ORDER BY EXTRACT(YEAR FROM HIRE_DATE) ASC) AS 밀집순위
FROM EMP
WHERE DEPT_ID = 'D9';
```

**출력 결과**
```
곽상혁 2013 1 1 1
권진우 2013 2 1 1
김민혜 2014 3 3 2
```

**설명**: 곽상혁·권진우는 둘 다 2013년 입사로 **동점**입니다.
- `ROW_NUMBER()`는 동점이어도 무조건 서로 다른 순번(1, 2)을 매깁니다.
- `RANK()`는 동점에게 같은 순위(1, 1)를 주고, 그다음 순위는 **동점 인원수만큼
  건너뜁니다**(2가 아니라 3).
- `DENSE_RANK()`는 동점에게 같은 순위(1, 1)를 주지만, 그다음 순위는 **건너뛰지 않고**
  바로 다음 번호(2)를 씁니다.

| 함수 | 동점 처리 | 다음 순위 |
|---|---|---|
| `ROW_NUMBER()` | 동점 없음(무조건 유일한 번호) | 항상 +1 |
| `RANK()` | 동점 허용, 같은 순위 부여 | 동점 인원수만큼 건너뜀 |
| `DENSE_RANK()` | 동점 허용, 같은 순위 부여 | 건너뛰지 않고 +1 |

## 3. PARTITION BY - 그룹별로 윈도우 나누기

`PARTITION BY`를 `ORDER BY`와 함께 쓰면 "그룹 안에서의 순위"를 구할 수 있습니다.

```sql
SELECT EMP_NAME, DEPT_ID, SALARY,
       RANK() OVER (PARTITION BY DEPT_ID ORDER BY SALARY DESC) AS 부서내순위
FROM EMP
WHERE DEPT_ID IN ('D5', 'D8')
ORDER BY DEPT_ID, 부서내순위;
```

**출력 결과**
```
윤정주 D5 3760000 1
박지민 D5 3500000 2
유제영 D5 2500000 3
염성원 D5 2200000 4
최주호 D5 1800000 5
이금빈 D8 2550000 1
오미자 D8 2436240 2
이광렬 D8 2000000 3
```

**설명**: `PARTITION BY DEPT_ID`가 D5, D8 각각을 별도의 윈도우로 나누고, 그 안에서만
`RANK()`가 다시 1부터 매겨집니다. `GROUP BY`와 달리 부서 내 개별 사원 행이 모두 살아있는
채로 "이 사람이 자기 부서에서 몇 등인지"를 알 수 있습니다.

## 4. LAG / LEAD - 이전/다음 행 값 참조

`LAG(컬럼)`은 정렬 기준으로 **바로 앞** 행의 값을, `LEAD(컬럼)`은 **바로 다음** 행의
값을 같은 행에서 참조합니다.

```sql
SELECT EMP_NAME, SALARY,
       LAG(SALARY)  OVER (ORDER BY SALARY DESC) AS 윗사람급여,
       LEAD(SALARY) OVER (ORDER BY SALARY DESC) AS 아랫사람급여
FROM EMP
WHERE DEPT_ID = 'D5'
ORDER BY SALARY DESC;
```

**출력 결과**
```
윤정주 3760000 (null)   3500000
박지민 3500000 3760000  2500000
유제영 2500000 3500000  2200000
염성원 2200000 2500000  1800000
최주호 1800000 2200000  (null)
```

**설명**: 1등(윤정주)은 위에 아무도 없으므로 `LAG(SALARY)`가 `NULL`, 꼴찌(최주호)는
아래에 아무도 없으므로 `LEAD(SALARY)`가 `NULL`입니다. `LAG`/`LEAD`는 "직전 달 대비
증감", "다음 순위와의 격차"처럼 인접한 행끼리 비교할 때 유용하며, SUBQUERY로 이런
계산을 하려면 자기 자신을 조인하는 SELF JOIN이 필요했던 것을 한 줄로 대체합니다.

## 5. 누적 합계 - SUM() OVER

```sql
SELECT EMP_NAME, SALARY,
       SUM(SALARY) OVER (ORDER BY SALARY DESC) AS 누적합계
FROM EMP
WHERE DEPT_ID = 'D9'
ORDER BY SALARY DESC;
```

**출력 결과**
```
곽상혁 8000000 8000000
권진우 6000000 14000000
김민혜 3700000 17700000
```

**설명**: `SUM(컬럼) OVER (ORDER BY ...)`처럼 `ORDER BY`가 있으면, 기본적으로 "정렬
순서상 지금 이 행까지의 합"(누적 합계)을 계산합니다. `ORDER BY` 없이
`SUM(SALARY) OVER (PARTITION BY DEPT_ID)`만 쓰면(1절 예제처럼) 정렬과 무관하게 그
파티션 전체의 합이 모든 행에 똑같이 반복됩니다 - `ORDER BY`의 유무가 "누적"이냐
"전체"냐를 가릅니다.

## 6. 그룹별 Top-N (윈도우 함수로 SUBQUERY 대체)

MySQL은 `WHERE`절에서 윈도우 함수 결과(별칭)를 바로 쓸 수 없습니다(`WHERE`가
`SELECT`보다 먼저 처리되기 때문). 그래서 윈도우 함수로 순위를 매긴 결과를
**인라인 뷰**로 감싼 뒤, 바깥에서 `WHERE`로 걸러야 합니다.

```sql
SELECT *
FROM (
    SELECT EMP_NAME, DEPT_ID, SALARY,
           RANK() OVER (PARTITION BY DEPT_ID ORDER BY SALARY DESC) AS 부서내순위
    FROM EMP
    WHERE DEPT_ID IS NOT NULL
) T
WHERE T.부서내순위 <= 2
ORDER BY DEPT_ID, 부서내순위;
```

**출력 결과**
```
전태성 D1 3660000 1
이다현 D1 2780000 2
박홍주 D2 2800000 1
엄용민 D2 2490000 2
윤정주 D5 3760000 1
박지민 D5 3500000 2
김태일 D6 3900000 1
김은민 D6 3400000 2
이금빈 D8 2550000 1
오미자 D8 2436240 2
곽상혁 D9 8000000 1
권진우 D9 6000000 2
```

**설명**: SUBQUERY 챕터에서 "부서별 평균 급여 1위 부서"를 `ORDER BY ... LIMIT 1`로
구했다면(전체를 한 줄로 세운 뒤 상위 1개만 자름), 이번엔 **부서마다 각각** 상위 2명을
뽑아야 하므로 `LIMIT`만으로는 불가능합니다. `PARTITION BY`로 부서별 순위를 먼저
매기고, 그 결과를 인라인 뷰로 감싸 `부서내순위 <= 2`로 걸러야 합니다.

## 자주 하는 실수

- **윈도우 함수 별칭을 `WHERE`에서 바로 사용하려는 시도** → `Unknown column` 오류.
  `SELECT`절의 결과는 `WHERE` 처리 시점에 아직 존재하지 않으므로, 인라인 뷰로 감싸서
  바깥 쿼리의 `WHERE`에서 걸러야 합니다(6절).
- **`RANK()`와 `DENSE_RANK()`를 반대로 기억** → `RANK()`는 동점 다음 순위를 건너뛰고,
  `DENSE_RANK()`는 건너뛰지 않습니다(2절 표 참고).
- **`GROUP BY`와 윈도우 함수를 같은 것으로 착각** → `GROUP BY`는 행 수를 줄이고,
  윈도우 함수는 행 수를 그대로 유지합니다.
- **`PARTITION BY` 없이 써놓고 "부서별로 나뉘길" 기대** → `PARTITION BY`가 없으면
  테이블 전체가 하나의 윈도우가 됩니다.
- **`SUM() OVER`에서 `ORDER BY` 유무를 안 따짐** → `ORDER BY`가 있으면 누적 합계,
  없으면(파티션) 전체 합이 나옵니다(5절).

## 핵심 요약

| 함수/구문 | 역할 | 비고 |
|---|---|---|
| `ROW_NUMBER() OVER (...)` | 동점 없이 유일한 순번 | |
| `RANK() OVER (...)` | 동점 시 같은 순위, 다음 순위는 건너뜀 | |
| `DENSE_RANK() OVER (...)` | 동점 시 같은 순위, 다음 순위는 안 건너뜀 | |
| `PARTITION BY 컬럼` | 그룹별로 윈도우를 나눔 | `GROUP BY`와 달리 행을 압축하지 않음 |
| `LAG(컬럼)` / `LEAD(컬럼)` | 이전/다음 행의 값을 같은 행에서 참조 | SELF JOIN 대체 |
| `SUM()/AVG() OVER (ORDER BY ...)` | 누적 합계/평균 | `ORDER BY` 없으면 파티션 전체 값 |
| 그룹별 Top-N | `PARTITION BY` 순위 + 인라인 뷰 + `WHERE` | `WHERE`에 윈도우 함수 별칭 직접 사용 불가 |
