## 1. 애노테이션이란?

**애노테이션(annotation)** 은 클래스, 필드, 메서드 등에 **추가 정보(메타데이터)** 를 붙이는 표시입니다. 애노테이션 자체는 코드의 동작을 직접 바꾸지 않습니다. 대신 "이 요소에는 이런 의미가 있다"는 표시만 남기고, 그 표시를 **누군가(컴파일러 또는 다른 프로그램)가 읽어서 처리**하는 방식으로 동작합니다.

이미 Day11에서 사용해본 `@Override`가 애노테이션의 대표적인 예입니다.

```java
public class Student extends Person {
    @Override // 애노테이션: "이 메서드는 부모의 메서드를 재정의한 것이다"라는 표시
    public void printInfo() {
        System.out.println("저는 학생입니다.");
    }
}
```

**설명**: `@Override`를 붙이면, 컴파일러가 "정말로 부모 클래스에 이름·매개변수가 똑같은 메서드가 있는지" 확인합니다. 만약 실수로 메서드 이름을 다르게 썼다면, `@Override`가 붙어있는 덕분에 컴파일 에러로 바로 알 수 있습니다. 이것이 애노테이션의 핵심 역할입니다 — **표시를 남기고, 그 표시를 누군가가 검사하거나 활용한다.**

## 2. 자주 쓰는 내장 애노테이션

자바가 기본으로 제공하는 애노테이션들입니다.

| 애노테이션 | 설명 | 예시 |
|---|---|---|
| `@Override` | 부모 메서드를 재정의했음을 표시, 컴파일러가 검증 | `@Override public void printInfo() {...}` |
| `@Deprecated` | 더 이상 사용을 권장하지 않는 요소임을 표시 | `@Deprecated public void oldMethod() {...}` |
| `@SuppressWarnings` | 특정 컴파일 경고를 무시하도록 지시 | `@SuppressWarnings("unchecked")` |

```java
public class Department {
    private int capacity;

    @Deprecated // 이 메서드는 더 이상 사용하지 말라는 표시
    public int getOldCapacity() {
        System.out.println("이 메서드 대신 getCapacity()를 사용하세요.");
        return capacity;
    }

    public int getCapacity() {
        return capacity;
    }
}
```

```java
public class AnnotationExample {
    public static void main(String[] args) {
        Department department1 = new Department();
        department1.getOldCapacity(); // 컴파일은 되지만, 경고(warning)가 표시됨: "deprecated 메서드입니다"
    }
}
```

**설명**: `@Deprecated`가 붙은 메서드를 호출하면, 프로그램은 정상적으로 실행되지만 컴파일 시 "이 메서드는 더 이상 쓰지 않는 게 좋습니다"라는 경고가 뜹니다. 실무에서는 API가 업데이트되어 예전 메서드를 당장 지우기는 어렵지만, 새 방식으로 유도하고 싶을 때 이렇게 표시해둡니다.

## 3. 커스텀 애노테이션 정의하기

내장 애노테이션 외에, 직접 애노테이션을 만들 수도 있습니다. `@interface` 키워드를 사용합니다.

```java
public @interface Required {
}
```

**설명**: `@interface Required`는 "`Required`라는 이름의 새로운 애노테이션을 만든다"는 뜻입니다. 이렇게 정의하면 `@Required`라는 표시를 다른 클래스의 필드나 메서드에 붙일 수 있게 됩니다.

```java
public class Department {
    @Required // 커스텀 애노테이션을 필드에 부착
    private String departmentName;

    private int capacity; // 이 필드는 Required 표시가 없음
}
```

**중요**: 이 상태에서 `@Required`는 아직 아무 동작도 하지 않습니다. 단지 "departmentName은 필수 입력값이어야 한다"는 **표시만** 붙었을 뿐, 그 표시를 읽어서 실제로 검증하는 코드는 없기 때문입니다. 이 표시를 **읽어서 활용**하는 방법은 부록2(리플렉션)에서 다룹니다.

## 4. 메타 애노테이션 (@Retention, @Target)

커스텀 애노테이션을 만들 때, 애노테이션 자체에 몇 가지 규칙을 지정할 수 있습니다. 애노테이션에 붙이는 애노테이션이라서 **메타 애노테이션**이라고 부릅니다.

| 메타 애노테이션 | 설명 |
|---|---|
| `@Retention(정책)` | 이 애노테이션이 언제까지 유지되는지 지정 (아래 표 참고) |
| `@Target(위치)` | 이 애노테이션을 어디에 붙일 수 있는지 제한 (필드만? 메서드만? 클래스만?) |

**@Retention의 정책 종류**

| 정책 | 의미 |
|---|---|
| `RetentionPolicy.SOURCE` | 소스코드에만 남고, 컴파일하면 사라짐 |
| `RetentionPolicy.CLASS` | `.class` 파일까지는 남지만, 실행 중(런타임)에는 사라짐 (기본값) |
| `RetentionPolicy.RUNTIME` | 프로그램이 실행되는 동안에도 계속 유지됨 |

**부록2에서 리플렉션으로 애노테이션을 읽으려면, 반드시 `RUNTIME`으로 지정해야 합니다.** 그렇지 않으면 프로그램이 실행될 때는 이미 애노테이션 정보가 사라진 상태이기 때문입니다.

**@Target의 위치 종류**

| 위치 | 의미 |
|---|---|
| `ElementType.FIELD` | 필드에만 붙일 수 있음 |
| `ElementType.METHOD` | 메서드에만 붙일 수 있음 |
| `ElementType.TYPE` | 클래스/인터페이스에 붙일 수 있음 |

```java
import java.lang.annotation.ElementType;
import java.lang.annotation.Retention;
import java.lang.annotation.RetentionPolicy;
import java.lang.annotation.Target;

@Retention(RetentionPolicy.RUNTIME) // 실행 중에도 이 표시를 읽을 수 있어야 함
@Target(ElementType.FIELD)          // 필드에만 붙일 수 있도록 제한
public @interface Required {
}
```

**설명**: `@Retention(RetentionPolicy.RUNTIME)`을 붙이지 않으면, 부록2에서 만들 "리플렉션으로 애노테이션을 읽는 코드"가 아무것도 찾지 못합니다. `@Target(ElementType.FIELD)`을 붙이면, 실수로 `@Required`를 메서드나 클래스에 붙이려고 할 때 컴파일러가 미리 막아줍니다.

```java
public class Department {
    @Required
    private String departmentName; // OK: 필드이므로 허용됨

    // @Required
    // public void printInfo() { ... } // 컴파일 에러! @Target이 FIELD인데 메서드에 붙이려 함
}
```

---

## 자주 하는 실수

1. **RetentionPolicy를 RUNTIME으로 하지 않아 나중에 리플렉션에서 못 읽음**
   ```java
   @Retention(RetentionPolicy.CLASS) // 기본값 그대로 두면
   public @interface Required { }
   // 실행 중에는 이 애노테이션 정보가 사라져서, 부록2의 리플렉션 코드가 찾을 수 없음
   ```

2. **애노테이션을 붙이기만 하고 아무 동작도 없을 거라 기대**
   ```java
   @Required
   private String departmentName = null; // 애노테이션을 붙였다고 자동으로 null 체크가 되는 게 아님
   // 검증 로직은 직접 만들어야 함 (부록2에서 구현)
   ```

3. **@Target 범위를 벗어난 곳에 애노테이션 사용**
   ```java
   @Target(ElementType.FIELD)
   public @interface Required { }

   @Required
   public class Department { } // 컴파일 에러! FIELD 전용인데 클래스에 붙임
   ```

## 핵심 요약

| 항목 | 핵심 내용 |
|---|---|
| 애노테이션 | 코드에 추가 정보(메타데이터)를 붙이는 표시, 그 자체로는 동작하지 않음 |
| @Override | 부모 메서드 재정의를 컴파일러가 검증하도록 표시 |
| @Deprecated | 더 이상 권장하지 않는 요소임을 표시, 경고 발생 |
| @interface | 커스텀 애노테이션을 정의하는 키워드 |
| @Retention | 애노테이션이 언제까지 유지되는지 지정, 리플렉션으로 읽으려면 RUNTIME 필수 |
| @Target | 애노테이션을 붙일 수 있는 위치 제한 (FIELD, METHOD, TYPE 등) |

다음 챕터(부록2)에서는 지금 만든 `@Required` 표시를 실제로 "읽어서" 검증 로직에 활용하는 방법(리플렉션)을 배웁니다.
