## 기본

### 문제 1. == 결과 예측하고 확인하기

```java
public class Practice1 {
    public static void main(String[] args) {
        String s1 = new String("java");
        String s2 = new String("java");

        System.out.println("== 결과: " + (s1 == s2));
        System.out.println("equals 결과: " + s1.equals(s2));
    }
}
```

**설명**: `new String(...)`으로 만든 두 객체는 내용이 같아도 힙 메모리에서 서로 다른 위치를 차지하므로 `==` 비교는 `false`입니다. `.equals()`는 내용을 비교하므로 `true`가 됩니다.

**틀리기 쉬운 포인트**: `new`를 쓰지 않고 `String s1 = "java";`처럼 리터럴로 선언하면 자바가 같은 객체를 재사용해서 `==`도 `true`가 나올 수 있습니다. 하지만 이 동작을 신뢰하고 코드를 작성하면 안 되며, 항상 `.equals()`를 쓰는 것이 안전합니다.

### 문제 2. null 확인하기

```java
public class Practice2 {
    public static void main(String[] args) {
        String 값 = null;
        System.out.println(값);

        if (값 == null) {
            System.out.println("값이 없습니다");
        }
    }
}
```

**설명**: `System.out.println(값)`은 `값`이 `null`이어도 에러 없이 문자열 `"null"`을 출력합니다(예외적으로 println은 null을 안전하게 처리). 반면 `값.length()`처럼 메서드를 호출하면 NullPointerException이 발생합니다.

**틀리기 쉬운 포인트**: "null을 출력하는 것"과 "null에 메서드를 호출하는 것"은 다릅니다. 전자는 안전하지만 후자는 위험합니다.

## 응용

### 문제 3. 안전한 문자열 비교

```java
import java.util.Scanner;

public class Practice3 {
    public static void main(String[] args) {
        Scanner sc = new Scanner(System.in);
        String 입력값 = sc.nextLine();

        if (입력값 != null && 입력값.equals("hello")) {
            System.out.println("인사 감지");
        } else {
            System.out.println("다른 입력");
        }
    }
}
```

**설명**: `&&`는 왼쪽부터 순서대로 검사하고, 왼쪽이 `false`이면 오른쪽은 검사하지 않는 단락 평가 특성이 있습니다(Day2 복습). 따라서 `입력값 != null`이 먼저 `false`로 나오면 `입력값.equals("hello")`는 아예 실행되지 않아 NullPointerException을 방지할 수 있습니다.

**틀리기 쉬운 포인트**: 순서를 바꿔서 `입력값.equals("hello") && 입력값 != null`처럼 쓰면, `입력값`이 `null`일 때 `equals()`가 먼저 호출되어 NullPointerException이 발생합니다. null 체크는 반드시 먼저 와야 합니다.

### 문제 4. NullPointerException 재현하고 방어하기

```java
public class Practice4 {
    public static void main(String[] args) {
        String 문자열 = null;

        // 문자열.length()를 그대로 호출하면 아래 에러가 발생합니다:
        // Exception in thread "main" java.lang.NullPointerException
        // null인 참조 변수에는 메서드를 호출할 수 없기 때문입니다.

        if (문자열 != null) {
            System.out.println("길이: " + 문자열.length());
        } else {
            System.out.println("문자열이 null이라 길이를 확인할 수 없습니다.");
        }
    }
}
```

**설명**: 참조형 변수를 사용하기 전에 `null` 여부를 먼저 확인하는 방어적 코딩 습관을 들이면 NullPointerException을 예방할 수 있습니다.

**틀리기 쉬운 포인트**: 주석으로만 설명하고 실제 `.length()` 호출 코드를 남겨두면 프로그램이 그 줄에서 즉시 중단됩니다. 실제 실행 코드에서는 반드시 null 체크 분기 안에서만 메서드를 호출해야 합니다.

## 도전

### 문제 5. 리터럴을 앞에 두는 안전한 equals 패턴

```java
import java.util.Scanner;

public class Practice5 {
    public static void main(String[] args) {
        Scanner sc = new Scanner(System.in);
        String 입력값 = sc.nextLine();

        if ("관리자".equals(입력값)) {
            System.out.println("관리자입니다");
        } else {
            System.out.println("일반 사용자입니다");
        }
    }
}
```

**설명**: `"관리자".equals(입력값)`처럼 리터럴을 앞에 두면, `입력값`이 설령 `null`이어도 `equals()` 내부에서 안전하게 `false`를 반환하도록 처리되어 있어 NullPointerException이 발생하지 않습니다. 반대로 `입력값.equals("관리자")`처럼 쓰면 `입력값`이 `null`일 때 바로 에러가 납니다.

**틀리기 쉬운 포인트**: 이 패턴은 "입력값이 null일 수도 있다"는 상황을 미리 대비하는 실무 관례입니다. 항상 리터럴.equals(변수) 순서로 쓰는 습관을 들이면 null 체크 코드를 따로 안 써도 안전합니다.

### 문제 6. 종합 - 회원 등급 확인 프로그램

```java
import java.util.Scanner;

public class Practice6 {
    public static void main(String[] args) {
        Scanner sc = new Scanner(System.in);
        String 이름 = sc.nextLine();

        String 결과 = "".equals(이름) ? "이름을 입력해주세요" : "환영합니다, " + 이름 + "님";
        System.out.println(결과);
    }
}
```

**설명**: 빈 문자열(`""`)은 `null`과는 다른 개념입니다. `null`은 "객체 자체가 없음"이고, `""`은 "글자 수가 0개인 문자열 객체는 존재함"입니다. 그래서 `"".equals(이름)`으로 "이름이 빈 문자열인지"를 확인합니다.

**틀리기 쉬운 포인트**: `null`과 `""`(빈 문자열)을 같은 것으로 착각하기 쉽습니다. `이름 == null`은 이름 변수 자체가 아무 객체도 안 가리키는 상태이고, `이름.equals("")`은 이름이 빈 문자열 객체를 가리키고 있는 상태로, 서로 다른 상황입니다. 실무에서는 두 경우를 모두 체크하는 경우도 많습니다(`이름 == null || 이름.equals("")`).
