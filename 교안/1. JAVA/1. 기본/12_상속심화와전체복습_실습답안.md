### 문제 1. protected로 자식 클래스에서 필드 접근하기

```java
// 동물.java
public class 동물 {
    protected String 이름;

    public 동물(String 이름) {
        this.이름 = 이름;
    }

    public void 소리내기() {
        System.out.println("동물이 소리를 냅니다");
    }
}
```

```java
// 고양이.java
public class 고양이 extends 동물 {
    public 고양이(String 이름) {
        super(이름);
    }

    public void 이름출력() {
        System.out.println(이름); // protected라서 자식 클래스에서 필드에 직접 접근 가능
    }
}
```

```java
// Practice1.java
public class Practice1 {
    public static void main(String[] args) {
        고양이 고양이1 = new 고양이("초코");
        고양이1.이름출력();
    }
}
```

**설명**: `이름` 필드가 `protected`이기 때문에, 자식 클래스인 `고양이`의 `이름출력()` 메서드 안에서 `get이름()` 같은 별도의 메서드 없이도 `이름`이라는 필드명으로 직접 접근할 수 있습니다.

**틀리기 쉬운 포인트**: 만약 `이름`이 `private`였다면, `고양이` 클래스에서 `이름`을 직접 쓰는 순간 컴파일 에러가 나고 반드시 `get이름()` 같은 메서드를 통해야만 합니다. `protected`는 상속 관계에서만 이 제약을 풀어준다는 점이 `private`와의 차이입니다.

### 문제 2. 다형성 - 배열로 여러 자식 다루기

```java
// 고양이.java
public class 고양이 extends 동물 {
    public 고양이(String 이름) {
        super(이름);
    }

    @Override
    public void 소리내기() {
        System.out.println("야옹");
    }
}
```

```java
// 강아지.java
public class 강아지 extends 동물 {
    public 강아지(String 이름) {
        super(이름);
    }

    @Override
    public void 소리내기() {
        System.out.println("멍멍");
    }
}
```

```java
// Practice2.java
public class Practice2 {
    public static void main(String[] args) {
        동물[] 동물들 = {
            new 고양이("나비"),
            new 강아지("초코")
        };

        for (동물 동물 : 동물들) {
            동물.소리내기(); // 실제 객체 타입(고양이/강아지)에 맞는 소리내기가 실행됨
        }
    }
}
```

**설명**: `동물들` 배열은 선언 타입이 `동물`이지만, 실제로는 `고양이`와 `강아지` 객체가 들어 있습니다. `동물.소리내기()`를 호출하면 자바는 실제 객체의 타입을 확인해서 그에 맞는 오버라이딩된 메서드를 실행합니다. 이것이 다형성의 핵심입니다.

**틀리기 쉬운 포인트**: 배열 선언 타입을 `동물`이 아니라 `고양이[]`처럼 하나로 고정하면, 강아지 객체를 같이 담을 수 없습니다. 공통 부모 타입(`동물`)으로 배열을 선언해야 서로 다른 자식 클래스들을 함께 관리할 수 있습니다.

### 문제 3. 추상 클래스 만들기

```java
// 도형.java
public abstract class 도형 {
    public abstract double 넓이구하기();
}
```

```java
// 사각형.java
public class 사각형 extends 도형 {
    private double 가로;
    private double 세로;

    public 사각형(double 가로, double 세로) {
        this.가로 = 가로;
        this.세로 = 세로;
    }

    @Override
    public double 넓이구하기() {
        return 가로 * 세로;
    }
}
```

```java
// 원.java
public class 원 extends 도형 {
    private double 반지름;
    static final double PI = 3.14159;

    public 원(double 반지름) {
        this.반지름 = 반지름;
    }

    @Override
    public double 넓이구하기() {
        return 반지름 * 반지름 * PI;
    }
}
```

```java
// Practice3.java
public class Practice3 {
    public static void main(String[] args) {
        도형 사각형1 = new 사각형(6, 4);
        도형 원1 = new 원(5);

        System.out.printf("사각형 넓이: %.2f%n", 사각형1.넓이구하기());
        System.out.printf("원 넓이: %.2f%n", 원1.넓이구하기());
    }
}
```

**설명**: `도형`은 추상 클래스라서 `new 도형()`으로 직접 객체를 만들 수 없습니다. 대신 `사각형`, `원`처럼 이를 상속받는 구체적인 클래스들이 각자의 방식으로 `넓이구하기()`를 구현합니다. Day10에서 배운 `static final` 상수(`PI`)도 함께 활용했습니다.

**틀리기 쉬운 포인트**: `사각형`이나 `원` 중 하나라도 `넓이구하기()`를 구현하지 않으면 컴파일 에러가 발생합니다. 추상 메서드는 상속받은 자식 클래스가 반드시 구현해야 하는 "의무"입니다.

### 문제 4. 다운캐스팅 활용

```java
// 강아지.java
public class 강아지 extends 동물 {
    public 강아지(String 이름) {
        super(이름);
    }

    public void 꼬리흔들기() {
        System.out.println("꼬리를 흔듭니다");
    }
}
```

```java
// Practice4.java
public class Practice4 {
    public static void main(String[] args) {
        동물 동물1 = new 강아지("초코"); // 업캐스팅: 강아지 객체를 동물 타입 변수에 담음

        // 동물1.꼬리흔들기(); // 컴파일 에러! 동물 타입에는 꼬리흔들기()가 없음

        강아지 강아지1 = (강아지) 동물1; // 다운캐스팅: 동물 타입을 다시 강아지 타입으로
        강아지1.꼬리흔들기();
    }
}
```

**설명**: `동물1` 변수는 선언 타입이 `동물`이므로, `동물` 클래스에 정의된 메서드만 바로 호출할 수 있습니다. `강아지`만의 메서드(`꼬리흔들기()`)를 사용하려면 `(강아지) 동물1`처럼 명시적으로 다운캐스팅해서 원래 타입(`강아지`)으로 되돌려야 합니다.

**틀리기 쉬운 포인트**: 다운캐스팅은 실제 객체가 해당 타입일 때만 안전합니다. 만약 `동물1`이 실제로는 `고양이` 객체인데 `(강아지) 동물1`로 캐스팅을 시도하면 `ClassCastException`이라는 실행 오류가 발생합니다.

### 문제 5. 학사관리 종합 - 학생 성적 처리 시스템

```java
// 사람.java
public abstract class 사람 {
    protected String 이름;

    public 사람(String 이름) {
        this.이름 = 이름;
    }

    public String get이름() {
        return 이름;
    }

    public abstract void 소개하기();
}
```

```java
// 학생.java
public class 학생 extends 사람 {
    private int[] 점수들;

    public 학생(String 이름, int[] 점수들) {
        super(이름);
        this.점수들 = 점수들;
    }

    public double 평균구하기() {
        int 합계 = 0;
        for (int 점수 : 점수들) {
            합계 += 점수;
        }
        return (double) 합계 / 점수들.length;
    }

    @Override
    public void 소개하기() {
        System.out.printf("저는 %s이고 평균 점수는 %.2f점입니다.%n", get이름(), 평균구하기());
    }
}
```

```java
// Practice5.java
public class Practice5 {
    public static void main(String[] args) {
        사람[] 학생들 = {
            new 학생("홍길동", new int[]{90, 85, 88}),
            new 학생("김철수", new int[]{70, 75, 80}),
            new 학생("이영희", new int[]{95, 92, 98})
        };

        학생 최고학생 = (학생) 학생들[0]; // 다운캐스팅해서 평균구하기() 사용 준비

        for (사람 사람 : 학생들) {
            사람.소개하기();

            학생 현재학생 = (학생) 사람; // 다운캐스팅
            if (현재학생.평균구하기() > 최고학생.평균구하기()) {
                최고학생 = 현재학생;
            }
        }

        System.out.println("최고 평균 학생: " + 최고학생.get이름());
    }
}
```

**설명**: `사람`을 추상 클래스로 만들어 `소개하기()`를 자식(`학생`)이 반드시 구현하도록 강제했습니다(Day12 추상 클래스). `평균구하기()`는 Day6~7에서 배운 배열 순회와 메서드 반환값 패턴을 그대로 사용합니다. 최고 평균 학생을 찾을 때는 `사람` 타입 배열에서 `학생`만의 메서드(`평균구하기()`)를 쓰기 위해 다운캐스팅이 필요합니다.

**틀리기 쉬운 포인트**: `사람[] 학생들` 배열의 원소는 선언 타입이 `사람`이므로, `평균구하기()`처럼 `학생`에만 있는 메서드는 다운캐스팅 없이는 호출할 수 없습니다. `소개하기()`는 `사람`에도 추상 메서드로 선언되어 있어 다운캐스팅 없이 호출 가능하지만, `평균구하기()`는 `학생`에만 있으므로 반드시 `(학생)`으로 캐스팅해야 합니다.

### 문제 6. 종합 - 학과별 학생 관리

```java
// 학과.java
public class 학과 {
    private String 학과명;

    public 학과(String 학과명) {
        this.학과명 = 학과명;
    }

    public String get학과명() {
        return 학과명;
    }
}
```

```java
// 사람.java
public class 사람 {
    protected String 이름;

    public 사람(String 이름) {
        this.이름 = 이름;
    }

    public String get이름() {
        return 이름;
    }
}
```

```java
// 학생.java
public class 학생 extends 사람 {
    private 학과 소속학과;
    private int 점수;

    public 학생(String 이름, 학과 소속학과, int 점수) {
        super(이름);
        this.소속학과 = 소속학과;
        this.점수 = 점수;
    }

    public 학과 get소속학과() {
        return 소속학과;
    }

    public int get점수() {
        return 점수;
    }
}
```

```java
// Practice6.java
public class Practice6 {
    public static void main(String[] args) {
        학과 컴공 = new 학과("컴퓨터공학과");
        학과 경영 = new 학과("경영학과");

        학생[] 학생들 = {
            new 학생("홍길동", 컴공, 90),
            new 학생("김철수", 경영, 82),
            new 학생("이영희", 컴공, 88),
            new 학생("박민수", 경영, 79)
        };

        System.out.println("[컴퓨터공학과 소속 학생]");
        int 합계 = 0;
        int 인원수 = 0;

        for (학생 학생 : 학생들) {
            if (학생.get소속학과().get학과명().equals("컴퓨터공학과")) { // Day4~5 equals 복습
                System.out.println(학생.get이름() + " - " + 학생.get점수() + "점");
                합계 += 학생.get점수();
                인원수++;
            }
        }

        double 평균 = (double) 합계 / 인원수;
        System.out.printf("평균: %.2f%n", 평균);
    }
}
```

**설명**: 이 종합 문제는 12일간 배운 개념을 대부분 결합합니다: 클래스와 객체(Day9), 캡슐화·getter(Day10), 상속(Day11), 객체를 필드로 가지는 구조(`학생`이 `학과` 객체를 필드로 참조), 배열 순회와 조건 필터링(Day3, Day5~6), 문자열 비교(Day4~5의 `.equals()`), 형변환을 통한 평균 계산(Day1~2). 학생 한 명이 다른 객체(`학과`)를 필드로 가지는 것은, 다음 단계에서 배울 "객체 간 관계"의 기본 형태이기도 합니다.

**틀리기 쉬운 포인트**: 학과명을 비교할 때 `학과.get학과명() == "컴퓨터공학과"`처럼 `==`을 쓰면 안 됩니다(Day4 복습). 문자열 내용 비교는 항상 `.equals()`를 사용해야 하며, 이 원칙은 상속·캡슐화 같은 복잡한 구조 안에서도 변하지 않습니다.
