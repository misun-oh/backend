|---|---|

## 학습목표

## 1. 문제 상황: 제네릭 없이 여러 타입을 담으려면?

어떤 값이든 하나 담아두는 `Box` 클래스를 만든다고 해봅시다. "어떤 타입이든" 담으려면, 모든 자바 객체의 조상인 `Object` 타입을 쓰면 됩니다.

```java
public class Box {
    private Object content;

    public void setContent(Object content) {
        this.content = content;
    }

    public Object getContent() {
        return content;
    }
}
```

```java
public class GenericLessExample {
    public static void main(String[] args) {
        Box box1 = new Box();
        box1.setContent("문자열입니다");

        String value = (String) box1.getContent(); // Object로 저장했으므로 꺼낼 때 매번 캐스팅 필요
        System.out.println(value);

        box1.setContent(123); // 실수로 다른 타입을 넣어도 컴파일러가 막지 못함

        try {
            String value2 = (String) box1.getContent(); // Integer를 String으로 캐스팅 시도
            System.out.println(value2);
        } catch (ClassCastException e) {
            System.out.println("캐스팅 실패: " + e.getMessage()); // 실행은 계속되지만, 이 시점에야 문제를 알게 됨
        }
    }
}
```

**출력 결과**
```
문자열입니다
캐스팅 실패: class java.lang.Integer cannot be cast to class java.lang.String
```

**설명**: `Object` 타입으로 만든 `Box`은 어떤 타입이든 담을 수 있어서 편해 보이지만, 두 가지 문제가 있습니다. 첫째, 꺼낼 때마다 `(String)`처럼 매번 캐스팅해야 합니다(Day12 다운캐스팅 복습). 둘째, 애초에 `box1.setContent(123)`처럼 의도치 않은 타입을 넣는 실수를 **컴파일러가 전혀 막아주지 못합니다** — 프로그램을 실제로 실행해봐야 `ClassCastException`으로 뒤늦게 발견됩니다.

## 2. 제네릭 클래스로 해결하기

제네릭은 "이 클래스는 어떤 타입을 다룰지 나중에 지정한다"는 것을 `<T>`처럼 표시하는 문법입니다.

```java
public class Box<T> { // T는 "아직 정해지지 않은 타입"을 나타내는 자리표시자
    private T content;

    public void setContent(T content) {
        this.content = content;
    }

    public T getContent() {
        return content;
    }
}
```

```java
public class GenericExample {
    public static void main(String[] args) {
        Box<String> box1 = new Box<>(); // <String>: 이 보관함은 String 전용

        box1.setContent("문자열입니다");
        String value = box1.getContent(); // 캐스팅 불필요! 이미 String이라는 것을 컴파일러가 알고 있음
        System.out.println(value);

        // box1.setContent(123); // 컴파일 에러! String 전용 box에 int를 넣으려 함
    }
}
```

**설명**: `Box<T>`에서 `T`는 "Type"의 약자로, 실제 사용할 때 어떤 타입이든 대입할 수 있는 자리표시자입니다. `new Box<String>()`처럼 객체를 만들 때 `<String>`으로 실제 타입을 지정하면, 그 순간부터 이 `box1`은 "String 전용" 보관함이 됩니다. 이렇게 하면 (1) 꺼낼 때 캐스팅이 필요 없고, (2) 잘못된 타입을 넣으려는 실수를 **컴파일 시점에** 바로 잡아낼 수 있습니다.

**`new Box<>()`의 빈 `<>`(다이아몬드 연산자)**: 오른쪽의 `<>`는 비워둬도, 왼쪽 `Box<String>`을 보고 자바가 자동으로 타입을 추론해줍니다. `new Box<String>()`이라고 다시 쓸 필요가 없습니다.

---

## 3. 제네릭 타입 이름 관례

`T` 외에도 관례적으로 자주 쓰는 이름들이 있습니다.

| 이름 | 의미 |
|---|---|
| `T` | Type (일반적인 타입) |
| `E` | Element (컬렉션의 요소, Day16의 List에서 사용) |
| `K` | Key (예: Map의 키) |
| `V` | Value (예: Map의 값) |

이건 강제 규칙이 아니라 관례이지만, 자바 표준 라이브러리(`List<E>` 등)도 이 관례를 따르고 있어서 익혀두면 나중에 문서를 읽을 때 도움이 됩니다.

## 4. 제네릭과 다음 챕터(List) 미리보기

사실 지금까지 배운 것으로, 우리는 이미 다음 챕터에서 배울 `List`를 읽을 준비가 되었습니다.

```java
List<String> names = new ArrayList<>();
```

**설명**: `List`는 Day13에서 배운 **인터페이스**이고, `ArrayList`는 그것을 구현한 클래스입니다(Day13의 `Printable`과 `Student`의 관계와 똑같습니다). `<String>`은 이번 챕터에서 배운 **제네릭**으로, "이 List는 String만 담을 수 있다"는 뜻입니다. 즉 `List<String>`이라는 코드 한 줄 안에 Day13과 이번 챕터(Day15)에서 배운 개념이 정확히 하나씩 들어있는 것입니다.

## 자주 하는 실수

1. **제네릭 타입과 다른 타입을 섞어서 넣으려 시도**
   ```java
   Box<String> box1 = new Box<>();
   box1.setContent(123); // 컴파일 에러! String 전용인데 int(정확히는 Integer)를 넣으려 함
   ```

2. **다이아몬드 연산자 안에 타입을 또 적는 실수(문제는 아니지만 불필요)**
   ```java
   Box<String> box1 = new Box<String>(); // 동작은 하지만 중복. new 보관함<>()으로 충분
   ```

3. **제네릭 타입에 기본 자료형을 직접 사용하려 시도**
   ```java
   Box<int> box1 = new Box<>(); // 컴파일 에러! 제네릭에는 int, double 같은 기본형을 쓸 수 없음
   Box<Integer> box1 = new Box<>(); // 올바른 표현: 기본형 대신 래퍼 클래스(Integer) 사용
   ```
   **참고**: `int`의 객체 버전인 `Integer`, `double`의 객체 버전인 `Double`처럼, 기본 자료형마다 대응하는 클래스(래퍼 클래스)가 있습니다. 제네릭은 객체만 다룰 수 있어서, 기본형을 쓰고 싶을 땐 이 래퍼 클래스를 사용해야 합니다.

## 핵심 요약

| 항목 | 핵심 내용 |
|---|---|
| 제네릭이 필요한 이유 | Object로 다루면 캐스팅이 매번 필요하고, 잘못된 타입 실수를 컴파일러가 못 잡음 |
| 제네릭 클래스 | `class name<T> { ... }`, `T`는 실제 사용 시점에 타입이 결정되는 자리표시자 |
| 제네릭 객체 생성 | `클래스<타입> 변수 = new 클래스<>();` (오른쪽 `<>`는 비워도 자동 추론) |
| 자주 쓰는 이름 관례 | T(일반 타입), E(요소), K(키), V(값) |
| 기본형 제한 | 제네릭엔 `int` 대신 `Integer` 같은 래퍼 클래스를 사용 |
| List와의 연결 | `List<String>` = 인터페이스(Day13) + 제네릭(Day15)의 조합 |

다음 챕터(Day16)에서는 배열의 불편함을 직접 확인해보고, `List`/`ArrayList`로 그 문제를 해결하는 법을 배웁니다.
