# 자바로 DB 연결해서 사원 목록 읽어오기 (실무형 HR 스키마)

**학습 대상**: 자바 기본 문법(변수, 클래스, 메서드)을 배운 초급자
**학습 목표**: 외부 라이브러리(JDBC 드라이버)를 추가하고, MySQL의 실무형 HR 스키마에 연결해서 사원 목록을 조회할 수 있다
**예상 소요 시간**: 90~120분

---

## 2. HR 스키마 구조 이해하기

이번 실습은 단일 테이블이 아니라, 회사 조직도를 표현하는 **6개 테이블**로 구성됩니다. 사원 목록만 조회할 거라면 `EMPLOYEE` 테이블 하나만 알아도 되지만, 전체 구조를 이해하면 나중에 부서명·직급명까지 함께 조회하는 JOIN 실습으로 자연스럽게 이어집니다.

```
NATIONAL(국가) ─┬─< LOCATION(지역) ─┬─< DEPARTMENT(부서) ─┬─< EMPLOYEE(사원)
                                                          │
                                          JOB(직급) ──────┘
                                     SAL_GRADE(급여등급) ─ (참조 관계 없음, 급여 구간표)
```

| 테이블 | 역할 | 사원 목록 조회에 필요? |
|---|---|---|
| `EMPLOYEE` | 사원 정보 (이번 실습의 핵심) | ✅ 필수 |
| `DEPARTMENT` | 부서 코드 ↔ 부서명 매핑 | 심화(JOIN)에서 사용 |
| `JOB` | 직급 코드 ↔ 직급명 매핑 | 심화(JOIN)에서 사용 |
| `LOCATION` / `NATIONAL` | 부서의 위치 정보 | 이번 실습 범위 밖 |
| `SAL_GRADE` | 급여 구간별 등급표 | 이번 실습 범위 밖 |

**`EMPLOYEE` 테이블 주요 컬럼**:

| 컬럼명 | 의미 | NULL 가능? |
|---|---|---|
| `EMP_ID` | 사원번호 (PK) | ❌ |
| `EMP_NAME` | 이름 | ❌ |
| `EMP_NO` | 주민등록번호 | ❌ |
| `EMAIL`, `PHONE` | 연락처 | ⭕ (일부 사원은 전화번호 없음) |
| `DEPT_CODE` | 소속 부서 코드 | ⭕ (아직 부서 미배정 사원 존재) |
| `JOB_CODE` | 직급 코드 | ❌ |
| `SALARY` | 급여 | ⭕ |
| `BONUS` | 보너스율 | ⭕ (대부분 NULL) |
| `MANAGER_ID` | 직속 상사 사번 | ⭕ (대표는 상사가 없음) |
| `HIRE_DATE` | 입사일 | ❌ |
| `ENT_DATE` | 퇴사일 | ⭕ (재직 중이면 NULL) |
| `ENT_YN` | 퇴직 여부(Y/N) | ❌ |

> ⚠️ **왜 이 부분을 강조하나요?** 학습용 예제 데이터는 보통 NULL이 없게 깔끔하지만, 이번 데이터는 실무처럼 NULL이 섞여 있습니다. 이걸 자바 코드에서 제대로 처리하지 않으면 `NullPointerException`을 만나거나, 급여 0원과 급여 정보 없음을 헷갈리는 버그가 생깁니다. (8단계에서 자세히 다룹니다)

## 3. 실습용 DB/테이블 만들기

첨부된 `00_setup.sql` 파일을 MySQL 클라이언트(또는 Workbench 등)에서 그대로 실행합니다.

```bash
mysql -u root -p < 00_setup.sql
```

또는 MySQL 접속 후:
```sql
SOURCE /경로/00_setup.sql;
```

실행이 끝나면 마지막에 `SELECT * FROM EMPLOYEE;` 결과로 23명의 사원이 조회됩니다.

> ✅ **체크포인트**: 아래 쿼리로 데이터가 잘 들어갔는지 확인하세요.
> ```sql
> USE HR;
> SELECT COUNT(*) FROM EMPLOYEE;   -- 23 이 나와야 정상
> ```

## 4. 자바 프로젝트에 JDBC 라이브러리 추가하기

**Maven (`pom.xml`)**
```xml
<dependencies>
    <dependency>
        <groupId>com.mysql</groupId>
        <artifactId>mysql-connector-j</artifactId>
        <version>8.4.0</version>
    </dependency>
</dependencies>
```

**Maven 없이 jar 직접 추가**
1. [MySQL 공식 다운로드 페이지](https://dev.mysql.com/downloads/connector/j/)에서 `mysql-connector-j-8.4.0.jar` 다운로드
2. 프로젝트의 `lib` 폴더에 저장 후 IDE에서 Build Path에 추가
3. 커맨드라인 실행 시:
   ```bash
   javac -cp .:lib/mysql-connector-j-8.4.0.jar *.java
   java  -cp .:lib/mysql-connector-j-8.4.0.jar Main
   ```
   (윈도우는 `:` 대신 `;`)

## 7. 사원 목록 조회 코드 작성

### 7-1. `Employee.java` (VO)
`EMPLOYEE` 테이블의 한 행을 자바 객체로 표현합니다. NULL이 가능한 컬럼(`deptCode`, `salary`, `bonus`, `managerId`, `entDate`)은 기본 타입(`int`, `double`) 대신 **래퍼 타입**(`Integer`, `BigDecimal`)으로 선언했습니다.

### 7-2. `EmployeeDao.java` (DAO)
- `findAll()`: 전체 사원 조회
- `findActiveEmployees()`: 퇴직하지 않은(`ENT_YN = 'N'`) 사원만 조회 (심화 예시)
- `mapRowToEmployee()`: `ResultSet` 한 행을 `Employee` 객체로 변환하는 부분을 별도 메서드로 분리 → 코드 중복 방지

### 7-3. `Main.java`
`EmployeeDao`를 호출해 결과를 콘솔에 출력합니다.

**실행 순서**:
1. `DBUtil.java`의 접속 정보 확인
2. `Employee.java`, `EmployeeDao.java`, `Main.java`, `DBUtil.java`를 같은 폴더(패키지)에 위치
3. `Main.java` 실행

**기대 출력 예시 (일부)**:
```
사원 목록 조회 결과 (총 23명)
--------------------------------------------------------------------------------
사번:200  이름:선동일  부서:D9  직급:J1  급여:8000000    보너스:0.30   입사일:1990-02-06 퇴직여부:N
사번:201  이름:송종기  부서:D9  직급:J2  급여:6000000    보너스:-      입사일:2001-09-01 퇴직여부:N
...
사번:213  이름:하동운  부서:-   직급:J6  급여:2320000    보너스:0.10   입사일:1999-12-31 퇴직여부:N
```
→ 213번 하동운 사원은 `DEPT_CODE`가 NULL이라 부서 칸에 `-`로 표시됩니다. (`Employee.toString()`에서 NULL을 `-`로 바꿔주는 처리를 해뒀기 때문)

## 8. NULL이 있는 실무 데이터 다루는 법

초급자가 가장 많이 실수하는 부분입니다. 아래 표로 정리합니다.

| 상황 | 잘못된 방법 | 올바른 방법 |
|---|---|---|
| SALARY 컬럼이 NULL일 수 있음 | `int salary = rs.getInt("SALARY");` → NULL이면 조용히 `0`이 됨 | `Integer salary = (Integer) rs.getObject("SALARY");` → NULL이면 진짜 `null` |
| ENT_DATE(퇴사일)가 NULL일 수 있음 | `rs.getDate("ENT_DATE").toLocalDate()` → NULL이면 `NullPointerException` 발생! | `Date d = rs.getDate("ENT_DATE"); LocalDate result = (d == null) ? null : d.toLocalDate();` |
| 화면에 NULL을 그냥 출력 | `System.out.println(salary);` → `null`이라는 글자가 그대로 찍혀 어색함 | `salary == null ? "-" : salary` 처럼 대체 문자열 지정 |

`EmployeeDao.mapRowToEmployee()`와 `Employee.toString()`에 이 패턴이 이미 적용되어 있으니, 코드를 직접 열어서 확인해보세요.

> 💡 **실습 과제**: `rs.getDate("ENT_DATE").toLocalDate()`처럼 NULL 체크 없이 짜면 어떤 사원 데이터에서 에러가 나는지 직접 확인해보세요. (힌트: `ENT_YN = 'N'`인 사원, 즉 아직 퇴사하지 않은 사원 대부분이 `ENT_DATE`가 NULL입니다)

## 9. 자주 만나는 에러와 해결법

| 에러 메시지 | 원인 | 해결법 |
|---|---|---|
| `ClassNotFoundException: com.mysql.cj.jdbc.Driver` | 라이브러리가 클래스패스에 없음 | 4단계 재확인 |
| `Communications link failure` | DB 서버 접속 불가 | MySQL 서버 실행 여부, 포트(3306) 확인 |
| `Access denied for user` | 아이디/비밀번호 오류 | `DBUtil`의 `USER`, `PASSWORD` 확인 |
| `Unknown database 'HR'` | 3단계 SQL 미실행 | `00_setup.sql` 다시 실행 |
| `NullPointerException` (조회 중) | NULL 컬럼을 기본 타입으로 받음 | 8단계 표 참고 |
| `Cannot add or update a child row: a foreign key constraint fails` | 참조 무결성 위반 (예: 존재하지 않는 DEPT_CODE로 INSERT) | 부모 테이블(DEPARTMENT 등)에 해당 코드가 있는지 먼저 확인 |

**다음에 도전해볼 것 (심화 학습 순서 추천)**:
1. `EMPLOYEE`와 `DEPARTMENT`, `JOB`을 JOIN해서 부서명·직급명까지 함께 조회하기
   ```sql
   SELECT e.EMP_ID, e.EMP_NAME, d.DEPT_TITLE, j.JOB_NAME
   FROM EMPLOYEE e
   LEFT JOIN DEPARTMENT d ON e.DEPT_CODE = d.DEPT_ID
   JOIN JOB j ON e.JOB_CODE = j.JOB_CODE;
   ```
   (부서가 NULL인 사원도 빠지지 않도록 `LEFT JOIN` 사용에 주목)
2. 사원 등록(`INSERT`), 수정(`UPDATE`), 삭제(`DELETE`) 기능 추가해서 CRUD 완성하기
3. 부서별 평균 급여 등 `GROUP BY` 집계 기능 추가하기
4. 매번 새 연결을 맺는 대신 **커넥션 풀(HikariCP)** 도입해보기
