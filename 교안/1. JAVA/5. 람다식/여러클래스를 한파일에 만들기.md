# 부록 6. 하나의 파일에 여러 클래스/인터페이스 작성하기

| 항목 | 내용 |
|---|---|
| 선수 학습 | 클래스와 객체 (Day 9), 인터페이스 (Day 13), 람다식 (부록 4) |
| 이번 챕터 | 자바 파일-클래스 규칙, `public`의 제약, 파일을 나눌지 합칠지 판단하는 기준 |

## 학습목표
- 하나의 `.java` 파일에 `public` 타입은 최대 1개만 가능하다는 규칙을 설명할 수 있다
- `public` 타입의 이름이 파일명과 반드시 같아야 하는 이유를 이해할 수 있다
- `public`이 없는 보조 클래스/인터페이스를 같은 파일에 함께 정의할 수 있다
- 타입을 별도 파일로 분리할지, 한 파일에 모아둘지 판단할 수 있다

---

## 1. 문제 상황: 보조 타입마다 파일을 따로 만들기

람다식을 연습하면서 `Greeter`, `StudentFilter`처럼 딱 한 곳에서만 쓰는 작은 함수형 인터페이스도 매번 별도 파일(`Greeter.java`, `StudentFilter.java`)로 만들어왔습니다. 실행 클래스 하나 때문에 이런 보조 인터페이스까지 전부 파일을 나누다 보면 프로젝트에 자잘한 파일이 많아집니다.

```java
// Logger.java (파일 1)
public interface Logger {
    void log(String message);
}
```
```java
// LoggerExample.java (파일 2)
public class LoggerExample {
    public static void main(String[] args) {
        Logger logger = message -> System.out.println("[LOG] " + message);
        logger.log("메시지 출력");
    }
}
```

**설명**: `Logger`가 `LoggerExample`에서만 쓰이는 보조 인터페이스라면, 굳이 파일을 나누지 않고 한 파일에 같이 넣을 수 있습니다. 이번 챕터는 그 방법과, 왜 아무렇게나는 안 되고 규칙이 있는지를 다룹니다.

---

## 2. 핵심 규칙: `public`은 파일당 1개, 파일명과 이름이 같아야 함

자바 컴파일러는 소스 파일과 타입 사이에 다음 규칙을 강제합니다.

| 규칙 | 내용 |
|---|---|
| `public` 타입 개수 | 파일 하나에 **최대 1개**만 허용 |
| `public` 타입의 이름 | **파일명과 정확히 일치**해야 함 (`Greeter` → `Greeter.java`) |
| `public`이 없는 타입 | 같은 파일에 **여러 개** 작성 가능 (이름은 파일명과 무관) |

```java
// LoggerExample.java
public class LoggerExample {        // public → 파일명(LoggerExample.java)과 반드시 일치
    public static void main(String[] args) {
        Logger logger = message -> System.out.println("[LOG] " + message);
        logger.log("메시지 출력");
    }
}

interface Logger {                   // public 없음 → 이름이 파일명과 달라도 됨, 같은 파일에 여러 개 가능
    void log(String message);
}

class Helper {                       // 이것도 가능 (필요하다면)
}
```

**설명**: `public class LoggerExample`은 파일명이 `LoggerExample.java`이어야만 컴파일됩니다. 반면 `interface Logger`와 `class Helper`는 `public`이 없으므로 이름이 파일명과 달라도 되고, 한 파일 안에 여러 개를 함께 둘 수 있습니다. 컴파일하면 `javac`는 파일 하나에서 타입 개수만큼 `.class` 파일을 각각 만듭니다(`LoggerExample.class`, `Logger.class`, `Helper.class`).

---

## 3. 규칙을 어기면 나는 에러

```java
// Logger.java 라는 파일 안인데...
public class LoggerExample {  // 컴파일 에러!
    // ...
}
```
```
error: class LoggerExample is public, should be declared in a file named LoggerExample.java
```

```java
// 한 파일 안에 public이 두 개
public class LoggerExample { }
public interface Logger { }   // 컴파일 에러! public은 파일당 1개까지만
```
```
error: class Logger is public, should be declared in a file named Logger.java
```

**설명**: 두 에러 모두 "이 파일에서 `public`으로 선언될 자격이 있는 타입은 파일명과 같은 이름의 타입 하나뿐"이라는 규칙을 어겼을 때 나옵니다.

---

## 4. `public`이 없는 타입은 어디서 접근 가능한가?

`public`이 없는(package-private) 클래스/인터페이스는 **같은 패키지 안에서만** 접근할 수 있습니다. 다른 패키지에서는 import해서 쓸 수 없습니다.

```java
package ex08.lambda;

public class LoggerExample {
    public static void main(String[] args) {
        Logger logger = message -> System.out.println("[LOG] " + message);
        logger.log("메시지 출력");
    }
}

interface Logger { // ex08.lambda 패키지 안에서만 보임
    void log(String message);
}
```

**설명**: `Logger`를 다른 패키지(`ex09` 등)에서도 재사용해야 한다면 `public`을 붙여 별도 파일(`Logger.java`)로 분리해야 합니다. 반대로 `LoggerExample`에서만 쓰고 끝날 보조 타입이라면, `public`을 빼고 이렇게 한 파일에 묶어두는 편이 파일 개수를 줄여줍니다.

## 5. 파일을 나눌지, 합칠지 판단하는 기준

| 상황 | 선택 |
|---|---|
| 다른 클래스/패키지에서도 재사용해야 함 | `public`으로 **별도 파일**로 분리 |
| 지금 이 실행 클래스에서만 쓰고 끝남 | `public` 없이 **같은 파일**에 함께 작성 |
| 특정 클래스에 강하게 종속된 보조 클래스(빌더 등) | **중첩 정적 클래스**(`static class`)로 그 클래스 내부에 작성 |

**설명**: 세 번째 항목은 부록 3(빌더 패턴)에서 만든 `EmpDto`의 `Builder`처럼, 아예 특정 클래스 내부에 `static class`로 넣어 캡슐화하는 방식입니다. 이는 "한 파일에 별개의 top-level 타입 여러 개를 늘어놓는 것"과는 다른 접근입니다. `EmpDto.Builder`는 `EmpDto` 없이는 의미가 없는 보조 타입이라 중첩 클래스가 자연스럽고, `Logger`처럼 "여러 클래스가 같이 써도 이상하지 않은" 독립적인 개념이라면 top-level로 나란히 두는 쪽이 자연스럽습니다.

## 자주 하는 실수

1. **`public` 타입 이름과 파일명을 다르게 작성**
   ```java
   // Greeter.java 파일인데
   public interface StudentFilter { ... } // 컴파일 에러! 파일명과 타입명이 달라야 함
   ```

2. **한 파일에 `public` 타입을 2개 이상 선언**
   ```java
   public class A { }
   public class B { } // 컴파일 에러! public은 파일당 1개까지만
   ```

3. **`public`을 빼먹고 다른 패키지에서 쓰려는 시도**
   ```java
   // ex08.lambda 패키지의 Logger (public 없음)
   ex08.lambda.Logger logger = ...; // ex09 패키지에서 컴파일 에러! package-private이라 접근 불가
   ```

## 핵심 요약

| 항목 | 핵심 내용 |
|---|---|
| `public` 타입 개수 제한 | 파일 하나당 `public` 클래스/인터페이스는 최대 1개 |
| 파일명 일치 규칙 | `public` 타입의 이름은 파일명과 정확히 같아야 함 |
| package-private 타입 | `public` 없는 타입은 같은 파일에 여러 개 작성 가능, 같은 패키지에서만 접근 가능 |
| 판단 기준 | 재사용 여부에 따라 별도 파일(`public`) vs 같은 파일(package-private) vs 중첩 정적 클래스 중 선택 |
