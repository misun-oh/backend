## 기본

### 문제 1. 부모 클래스 상속받기

```java
// 동물.java
public class 동물 {
    private String 이름;

    public 동물(String 이름) {
        this.이름 = 이름;
    }

    public String get이름() {
        return 이름;
    }

    public void 소리내기() {
        System.out.println("동물이 소리를 냅니다");
    }
}
```

```java
// 강아지.java
public class 강아지 extends 동물 {
    public 강아지(String 이름) {
        super(이름); // 부모(동물)의 생성자 호출
    }
}
```

```java
// Practice1.java
public class Practice1 {
    public static void main(String[] args) {
        강아지 강아지1 = new 강아지("초코");

        System.out.println("이름: " + 강아지1.get이름());
        강아지1.소리내기();
    }
}
```

**설명**: `강아지`는 자신만의 생성자만 정의했을 뿐, `get이름()`이나 `소리내기()`는 전혀 작성하지 않았는데도 부모 클래스 `동물`로부터 물려받아 그대로 사용할 수 있습니다.

**틀리기 쉬운 포인트**: `강아지` 클래스에 `이름` 필드를 다시 선언하면 안 됩니다. 이미 부모 클래스에 `이름` 필드가 있고, 자식은 이를 상속받아 사용하므로 중복 선언은 불필요합니다(오히려 부모의 private 필드에 직접 접근이 안 되어 혼란만 생깁니다).

### 문제 2. super()로 부모 생성자 호출

```java
// 강아지.java
public class 강아지 extends 동물 {
    private String 품종;

    public 강아지(String 이름, String 품종) {
        super(이름);
        this.품종 = 품종;
    }

    public String get품종() {
        return 품종;
    }
}
```

```java
// Practice2.java
public class Practice2 {
    public static void main(String[] args) {
        강아지 강아지1 = new 강아지("초코", "푸들");
        System.out.println("이름: " + 강아지1.get이름() + ", 품종: " + 강아지1.get품종());
    }
}
```

**설명**: `강아지` 생성자의 첫 줄에서 `super(이름)`을 호출해 부모의 `이름` 필드를 초기화하고, 이어서 자신만의 필드인 `품종`을 초기화합니다. 부모의 `이름`은 `private`이라 자식이 직접 대입할 수 없으므로, 반드시 부모 생성자를 통해서만 초기화할 수 있습니다.

**틀리기 쉬운 포인트**: `super(이름);`을 생성자의 첫 줄이 아닌 곳에 쓰면 컴파일 에러가 발생합니다. 항상 자식 생성자의 맨 첫 줄에 위치해야 합니다.

### 문제 3. 메소드 오버라이딩

```java
// 강아지.java
public class 강아지 extends 동물 {
    private String 품종;

    public 강아지(String 이름, String 품종) {
        super(이름);
        this.품종 = 품종;
    }

    @Override
    public void 소리내기() {
        System.out.println("멍멍!");
    }
}
```

```java
// Practice3.java
public class Practice3 {
    public static void main(String[] args) {
        강아지 강아지1 = new 강아지("초코", "푸들");
        강아지1.소리내기(); // 부모의 소리내기가 아니라 자식이 재정의한 버전이 실행됨
    }
}
```

**설명**: `강아지`에서 부모(`동물`)와 똑같은 이름, 매개변수, 반환형으로 `소리내기()`를 다시 작성했습니다. 이렇게 하면 `강아지1.소리내기()`를 호출했을 때 부모의 "동물이 소리를 냅니다" 대신, 자식이 재정의한 "멍멍!"이 출력됩니다.

**틀리기 쉬운 포인트**: `@Override`를 붙이지 않아도 오버라이딩 자체는 동작하지만, 만약 메서드 이름을 실수로 다르게 쓰면(`소리내다()` 등) 오버라이딩이 아니라 새로운 메서드가 되어버립니다. `@Override`를 붙여두면 이런 실수를 컴파일 시점에 바로 알 수 있습니다.

### 문제 4. 학사관리 도메인 - 사람과 교수

```java
// 사람.java
public class 사람 {
    private String 이름;

    public 사람(String 이름) {
        this.이름 = 이름;
    }

    public String get이름() {
        return 이름;
    }

    public void 소개하기() {
        System.out.println("저는 " + 이름 + "입니다.");
    }
}
```

```java
// 교수.java
public class 교수 extends 사람 {
    private String 교수번호;

    public 교수(String 이름, String 교수번호) {
        super(이름);
        this.교수번호 = 교수번호;
    }

    public String get교수번호() {
        return 교수번호;
    }

    @Override
    public void 소개하기() {
        System.out.println("저는 교수번호 " + 교수번호 + "인 " + get이름() + "입니다.");
    }
}
```

```java
// Practice4.java
public class Practice4 {
    public static void main(String[] args) {
        교수 교수1 = new 교수("김교수", "P001");
        교수1.소개하기();
    }
}
```

**설명**: `교수`는 `사람`의 `이름` 필드에 직접 접근할 수 없으므로(private), 오버라이딩한 `소개하기()` 안에서 부모가 제공하는 `get이름()`을 호출해서 이름 값을 가져옵니다.

**틀리기 쉬운 포인트**: `소개하기()` 안에서 `이름`이라는 필드를 직접 쓰려고 하면 컴파일 에러가 납니다(부모의 private 필드는 자식도 직접 접근 불가). 반드시 부모가 공개한 `get이름()` 메서드를 통해 값을 가져와야 합니다.

### 문제 5. 여러 자식 클래스가 하나의 부모를 상속

```java
// 학생.java
public class 학생 extends 사람 {
    private String 학번;

    public 학생(String 이름, String 학번) {
        super(이름);
        this.학번 = 학번;
    }

    @Override
    public void 소개하기() {
        System.out.println("저는 학번 " + 학번 + "인 " + get이름() + "입니다.");
    }
}
```

```java
// Practice5.java
public class Practice5 {
    public static void main(String[] args) {
        사람[] 사람들 = new 사람[2];
        사람들[0] = new 학생("홍길동", "S001");
        사람들[1] = new 교수("김교수", "P001");

        for (사람 사람 : 사람들) {
            사람.소개하기(); // 실제 객체가 학생이면 학생의 소개하기, 교수면 교수의 소개하기가 실행됨
        }
    }
}
```

**설명**: `사람[] 사람들` 배열에는 `학생`과 `교수` 객체가 함께 담겨 있지만, 둘 다 `사람`을 상속받았기 때문에 하나의 배열로 관리할 수 있습니다. 반복문에서 `사람.소개하기()`를 호출하면, 배열 변수의 선언 타입(`사람`)과 상관없이 **실제 객체의 타입**(학생 또는 교수)에 맞는 오버라이딩된 메서드가 실행됩니다.

**틀리기 쉬운 포인트**: `사람들[0]`의 선언 타입은 `사람`이지만, 실제로 그 안에 들어있는 것은 `학생` 객체입니다. `소개하기()`를 호출하면 선언 타입(`사람`)이 아니라 실제 객체 타입(`학생`)의 오버라이딩된 메서드가 실행된다는 점이 상속·오버라이딩의 중요한 특징입니다.

### 문제 6. 종합 - 오버라이딩 활용한 성적 처리

```java
// 학생.java
public class 학생 extends 사람 {
    private int 점수;

    public 학생(String 이름, int 점수) {
        super(이름);
        this.점수 = 점수;
    }

    public int get점수() {
        return 점수;
    }

    @Override
    public void 소개하기() {
        System.out.println("저는 " + get이름() + "이고 점수는 " + 점수 + "점입니다.");
    }
}
```

```java
// Practice6.java
public class Practice6 {
    public static void main(String[] args) {
        학생[] 학생들 = {
            new 학생("홍길동", 90),
            new 학생("김철수", 85),
            new 학생("이영희", 78)
        };

        int 합계 = 0;
        for (학생 학생 : 학생들) {
            학생.소개하기();
            합계 += 학생.get점수();
        }

        double 평균 = (double) 합계 / 학생들.length;
        System.out.printf("평균 점수: %.2f%n", 평균);
    }
}
```

**설명**: 이 문제는 Day6(배열 순회, 평균 계산)와 Day11(상속, 오버라이딩)을 결합합니다. `학생[]` 배열을 향상된 for문으로 순회하며 각자의 `소개하기()`를 호출하고, 동시에 `get점수()`로 값을 꺼내 합계를 누적한 뒤 평균을 계산합니다.

**틀리기 쉬운 포인트**: 합계를 구할 때 `(double)` 캐스팅을 빠뜨리면 정수 나눗셈이 되어 소수점이 사라집니다(Day1~2에서 여러 번 반복한 실수 패턴입니다). 새로운 개념(상속)을 배우더라도 이전 챕터의 기본기(형변환)는 계속 함께 적용해야 한다는 점을 기억해두세요.
