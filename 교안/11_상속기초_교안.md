## 1. 상속이란?

여러 클래스가 공통된 필드와 메서드를 가질 때, 그 공통 부분을 하나의 클래스로 만들어두고 다른 클래스가 이를 **물려받아** 사용하는 것을 상속이라고 합니다.

예를 들어 학사관리 도메인에서 `학생`과 `교수`는 둘 다 "이름", "소속 학과"라는 공통 정보를 가집니다. 이런 공통점을 매번 각 클래스에 중복해서 작성하는 대신, `사람`이라는 공통 클래스를 만들고 `학생`과 `교수`가 이를 상속받으면 코드 중복을 줄일 수 있습니다.

| 용어 | 설명 |
|---|---|
| 부모 클래스(Super class) | 물려주는 클래스 (예: `사람`) |
| 자식 클래스(Sub class) | 물려받는 클래스 (예: `학생`, `교수`) |
| `extends` | "자식 클래스가 부모 클래스를 상속받는다"는 것을 나타내는 키워드 |

## 2. 클래스 상속 (extends)

```java
// 부모 클래스
public class 사람 {
    private String 이름;

    public 사람(String 이름) {
        this.이름 = 이름;
    }

    public String get이름() {
        return 이름;
    }

    public void 소개하기() {
        System.out.println("저는 " + 이름 + "입니다.");
    }
}
```

```java
// 자식 클래스: extends로 부모 클래스를 상속
public class 학생 extends 사람 {
    private String 학번;

    public 학생(String 이름, String 학번) {
        super(이름); // 부모 클래스의 생성자 호출 (아래 3번에서 자세히)
        this.학번 = 학번;
    }

    public String get학번() {
        return 학번;
    }
}
```

```java
public class 상속예제 {
    public static void main(String[] args) {
        학생 학생1 = new 학생("홍길동", "S001");

        System.out.println(학생1.get이름());   // 사람 클래스의 메서드를 그대로 사용 가능
        System.out.println(학생1.get학번());   // 학생 클래스 자신의 메서드
        학생1.소개하기();                        // 사람 클래스의 메서드도 사용 가능: "저는 홍길동입니다."
    }
}
```

**설명**: `학생 extends 사람`은 "학생은 사람이다"라는 관계를 의미합니다. `학생` 클래스는 `이름` 필드나 `get이름()`, `소개하기()` 메서드를 다시 작성하지 않아도, 부모 클래스인 `사람`으로부터 그대로 물려받아 사용할 수 있습니다. `학생`은 여기에 자신만의 필드(`학번`)와 메서드(`get학번()`)를 추가로 가집니다.

## 3. 부모 생성자 호출 (super)

자식 클래스의 생성자에서는 부모 클래스의 필드를 초기화하기 위해 `super(...)`로 부모의 생성자를 호출해야 합니다.

```java
public class 학생 extends 사람 {
    private String 학번;

    public 학생(String 이름, String 학번) {
        super(이름); // 반드시 자식 생성자의 "첫 줄"에 위치해야 함
        this.학번 = 학번;
    }
}
```

**설명**: `사람` 클래스의 `이름` 필드는 `private`이므로 `학생` 클래스에서 직접 접근해 초기화할 수 없습니다. 대신 `super(이름)`으로 부모 클래스의 생성자를 호출해서, 부모 쪽 초기화는 부모 생성자에게 맡깁니다. `super(...)`는 반드시 자식 생성자의 **첫 줄**에 와야 합니다.

**주의**: 만약 자식 클래스 생성자에서 `super(...)`를 명시적으로 호출하지 않으면, 자바는 자동으로 부모의 **매개변수 없는 생성자**를 호출합니다. 부모 클래스에 매개변수 없는 생성자가 없다면 컴파일 에러가 발생합니다.

```java
public class 학생 extends 사람 {
    public 학생(String 이름, String 학번) {
        // super(이름); 을 생략하면 자바가 자동으로 super()를 호출하려 시도함
        // 하지만 사람 클래스에는 매개변수 없는 생성자가 없으므로 컴파일 에러 발생!
        this.학번 = 학번;
    }
}
```

## 4. 메소드 재정의 (오버라이딩, Overriding)

자식 클래스가 부모 클래스로부터 물려받은 메서드를 **자신에게 맞게 다시 구현**하는 것을 오버라이딩이라고 합니다.

```java
public class 학생 extends 사람 {
    private String 학번;

    public 학생(String 이름, String 학번) {
        super(이름);
        this.학번 = 학번;
    }

    @Override // 오버라이딩임을 명시하는 표시(어노테이션). 필수는 아니지만 실수 방지를 위해 권장
    public void 소개하기() {
        System.out.println("저는 학번 " + 학번 + "인 " + get이름() + "입니다.");
    }
}
```

```java
public class 오버라이딩예제 {
    public static void main(String[] args) {
        학생 학생1 = new 학생("홍길동", "S001");
        학생1.소개하기(); // "저는 학번 S001인 홍길동입니다." (부모의 소개하기가 아니라 자식의 것이 실행됨)
    }
}
```

**설명**: 부모 클래스의 `소개하기()`는 이름만 소개하지만, `학생` 클래스는 학번까지 포함해서 소개하고 싶으므로 같은 이름·같은 매개변수로 메서드를 **다시 정의**했습니다. 이렇게 하면 `학생1.소개하기()`를 호출했을 때 부모의 버전이 아니라 자식(`학생`)에서 재정의한 버전이 실행됩니다.

**오버라이딩 규칙**: 메서드 이름, 매개변수, 반환형이 부모 클래스의 메서드와 정확히 같아야 합니다. `@Override` 어노테이션을 붙이면, 혹시 이름을 잘못 쓰거나 매개변수가 달라 오버라이딩이 실패했을 때 컴파일러가 에러로 알려주므로 실수를 방지할 수 있습니다.

## 자주 하는 실수

1. **super()를 생성자 첫 줄이 아닌 곳에 작성**
   ```java
   public 학생(String 이름, String 학번) {
       this.학번 = 학번;
       super(이름); // 컴파일 에러! super()는 반드시 첫 줄에 있어야 함
   }
   ```

2. **부모 클래스에 매개변수 없는 생성자가 없는데 super()를 생략**
   ```java
   public class 사람 {
       public 사람(String 이름) { ... } // 매개변수 있는 생성자만 존재
   }
   public class 학생 extends 사람 {
       public 학생(String 학번) {
           // super()를 안 쓰면 자바가 자동으로 super()(매개변수 없는 버전)를 호출하려다 실패
       }
   }
   ```

3. **오버라이딩 시 매개변수를 다르게 작성해 오버로딩이 되어버림**
   ```java
   // 부모: public void 소개하기()
   public void 소개하기(String 추가정보) { ... } // 매개변수가 다르므로 오버라이딩이 아니라 오버로딩(새 메서드)이 됨
   ```

## 핵심 요약

| 항목 | 핵심 내용 |
|---|---|
| 상속 | 공통된 필드/메서드를 부모 클래스로 묶고, 자식 클래스가 `extends`로 물려받음 |
| extends | `자식클래스 extends 부모클래스` |
| super(...) | 부모 클래스의 생성자 호출, 자식 생성자의 반드시 첫 줄에 위치 |
| 오버라이딩 | 자식 클래스가 부모의 메서드를 이름·매개변수·반환형 그대로 재정의 |
| @Override | 오버라이딩임을 명시, 실수 방지를 위해 권장 |
