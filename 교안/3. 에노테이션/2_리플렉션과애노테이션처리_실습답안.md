# 부록 2. 리플렉션과 애노테이션 처리 - 실습 답안

---

## 기본

### 문제 1. 클래스의 필드 목록 출력하기

```java
// 학생.java
public class 학생 {
    private String 이름;
    private String 학번;
    private int 나이;

    public 학생(String 이름, String 학번, int 나이) {
        this.이름 = 이름;
        this.학번 = 학번;
        this.나이 = 나이;
    }
}
```

```java
// Practice1.java
import java.lang.reflect.Field;

public class Practice1 {
    public static void main(String[] args) {
        Field[] fields = 학생.class.getDeclaredFields();

        for (Field field : fields) {
            System.out.println("필드 이름: " + field.getName() + ", 타입: " + field.getType());
        }
    }
}
```

**설명**: `학생.class`는 객체를 만들지 않고도 클래스 자체의 `Class` 정보에 바로 접근하는 방법입니다(`학생1.getClass()`와 같은 정보를 얻지만, 객체 없이도 가능). `getDeclaredFields()`는 `private` 필드까지 포함한 모든 필드를 배열로 반환합니다.

**틀리기 쉬운 포인트**: `getFields()`를 쓰면 `public` 필드만 반환되는데, 이 예제의 필드들은 전부 `private`이므로 빈 배열이 나옵니다. 반드시 `getDeclaredFields()`를 사용해야 합니다.

### 문제 2. 리플렉션으로 필드 값 읽기

```java
import java.lang.reflect.Field;

public class Practice2 {
    public static void main(String[] args) throws Exception {
        학생 학생1 = new 학생("홍길동", "S001", 20);

        Field field = 학생1.getClass().getDeclaredField("이름");
        field.setAccessible(true); // private 필드 접근 허용

        Object value = field.get(학생1);
        System.out.println("이름 필드 값: " + value);
    }
}
```

**설명**: `getDeclaredField("이름")`은 이름이 정확히 "이름"인 필드 하나를 찾습니다(복수형 `getDeclaredFields()`와 달리 단수형은 필드 하나만 반환). `setAccessible(true)`를 호출하지 않으면 `private` 필드이므로 `field.get(...)` 호출 시 예외가 발생합니다.

**틀리기 쉬운 포인트**: `getDeclaredField`는 존재하지 않는 필드 이름을 넣으면 예외를 던지므로, `main`에 `throws Exception`을 붙여야 컴파일됩니다.

## 응용

### 문제 3. 리플렉션으로 필드 값 변경하기

```java
import java.lang.reflect.Field;

public class Practice3 {
    public static void main(String[] args) throws Exception {
        학생 학생1 = new 학생("홍길동", "S001", 20);

        Field field = 학생1.getClass().getDeclaredField("나이");
        field.setAccessible(true);

        System.out.println("변경 전 나이: " + field.get(학생1));

        field.set(학생1, 25); // 리플렉션으로 값 변경

        System.out.println("변경 후 나이: " + field.get(학생1));
    }
}
```

**설명**: `field.set(학생1, 25)`는 `학생1` 객체의 `나이` 필드에 `25`를 대입합니다. 이는 `학생1.나이 = 25;`와 동일한 효과지만, `나이`가 `private`이라 평소라면 클래스 밖에서 직접 쓸 수 없는 코드를, 리플렉션을 통해 우회해서 실행한 것입니다.

**틀리기 쉬운 포인트**: `field.set(...)`의 두 번째 인자 자료형은 필드의 실제 타입과 호환되어야 합니다. `int` 필드에 문자열을 넣으려 하면 `IllegalArgumentException`이 발생합니다.

### 문제 4. @필수입력이 붙은 필드만 찾기

```java
// 학생.java
public class 학생 {
    @필수입력
    private String 이름;

    @필수입력
    private String 학번;

    private int 나이;

    public 학생(String 이름, String 학번, int 나이) {
        this.이름 = 이름;
        this.학번 = 학번;
        this.나이 = 나이;
    }
}
```

```java
// Practice4.java
import java.lang.reflect.Field;

public class Practice4 {
    public static void main(String[] args) {
        Field[] fields = 학생.class.getDeclaredFields();

        for (Field field : fields) {
            if (field.isAnnotationPresent(필수입력.class)) {
                System.out.println("필수 입력 필드: " + field.getName());
            }
        }
    }
}
```

**설명**: `isAnnotationPresent(필수입력.class)`는 `for`문으로 순회하는 각 필드마다 "`@필수입력`이 붙어있는가?"를 확인해서 `true`/`false`를 반환합니다. `나이` 필드는 애노테이션이 없으므로 조건에서 걸러져 출력되지 않습니다.

**틀리기 쉬운 포인트**: `필수입력.class`처럼 애노테이션 타입 뒤에 `.class`를 붙이는 문법을 놓치기 쉽습니다. `isAnnotationPresent`의 매개변수는 애노테이션 "타입 정보"를 요구하기 때문에, 그냥 `필수입력`이 아니라 `필수입력.class`로 전달해야 합니다.

## 도전

### 문제 5. 검증기 만들기 (Null 체크)

```java
// 검증기.java
import java.lang.reflect.Field;

public class 검증기 {
    public static void 검증(Object obj) throws Exception {
        Class<?> clazz = obj.getClass();

        for (Field field : clazz.getDeclaredFields()) {
            if (field.isAnnotationPresent(필수입력.class)) {
                field.setAccessible(true);
                Object value = field.get(obj);

                if (value == null) {
                    System.out.println(field.getName() + "은(는) 필수 입력값입니다.");
                }
            }
        }
    }
}
```

```java
// Practice5.java
public class Practice5 {
    public static void main(String[] args) throws Exception {
        학생 학생1 = new 학생(null, "S001", 20); // 이름을 일부러 비워둠

        검증기.검증(학생1);
    }
}
```

**설명**: `검증()` 메서드는 `학생1`이 어떤 클래스인지(`obj.getClass()`)를 실행 중에 알아내고, 그 클래스가 가진 필드를 순회하면서 `@필수입력`이 붙은 필드 중 `null`인 것을 찾아 경고를 출력합니다.

**틀리기 쉬운 포인트**: `검증()` 메서드의 매개변수 타입이 `Object`라는 점이 중요합니다. 만약 매개변수를 `학생`으로 고정했다면, 이 검증기는 `학생` 클래스에만 쓸 수 있고 다른 클래스(`학과` 등)에는 재사용할 수 없습니다. `Object`로 받으면 어떤 클래스의 객체든 전달할 수 있습니다.

### 문제 6. 종합 - 여러 객체를 한 검증기로 처리하기

```java
// 학과.java
public class 학과 {
    @필수입력
    private String 학과명;

    public 학과(String 학과명) {
        this.학과명 = 학과명;
    }
}
```

```java
// 학생.java (문제 4와 동일)
public class 학생 {
    @필수입력
    private String 이름;

    @필수입력
    private String 학번;

    private int 나이;

    public 학생(String 이름, String 학번, int 나이) {
        this.이름 = 이름;
        this.학번 = 학번;
        this.나이 = 나이;
    }
}
```

```java
// Practice6.java
public class Practice6 {
    public static void main(String[] args) throws Exception {
        학과 학과1 = new 학과(null);
        학생 학생1 = new 학생(null, "S001", 20);

        검증기.검증(학과1); // "학과명은(는) 필수 입력값입니다." 출력
        검증기.검증(학생1); // "이름은(는) 필수 입력값입니다." 출력
    }
}
```

**설명**: 문제 5에서 만든 `검증기.검증()` 메서드를 코드 수정 없이 그대로 `학과`와 `학생` 두 클래스 모두에 사용했습니다. 검증기 코드 안에는 `학과`나 `학생`이라는 이름이 전혀 등장하지 않는데도, 애노테이션(`@필수입력`)이라는 표시만으로 두 클래스 모두를 검증할 수 있었습니다.

**틀리기 쉬운 포인트**: 만약 애노테이션과 리플렉션 없이 이런 검증 기능을 만들려면, `학과`용 검증 메서드와 `학생`용 검증 메서드를 각각 따로 작성해야 했을 것입니다. 클래스가 10개, 20개로 늘어나면 그만큼 중복 코드가 늘어나는데, 리플렉션 기반 검증기는 클래스 개수와 상관없이 코드 한 벌로 재사용됩니다. 이것이 실무에서 Bean Validation(`@NotNull` 등)이나 스프링 프레임워크가 리플렉션을 광범위하게 사용하는 이유입니다.
