# Day 1~2. DQL(SELECT) - 실습

> (교안에서 다룬 SELECT 기본 문법, 별칭, WHERE, 비교 연산자, BETWEEN, LIKE, IN, IS NULL,
> 논리 연산자, ORDER BY만 사용 / MySQL 문법 기준)

---

## 기본

### 문제 1. 급여 내림차순 전체 조회
전 사원의 사번, 이름, 급여를 조회하되 급여가 높은 사람부터 나오도록 정렬하세요.

**확인할 것**: 21행이 조회되고, 첫 번째 행이 곽상혁(급여 8,000,000)인지 확인합니다.

---

### 문제 2. 특정 부서 조회
부서코드가 `'D5'`(해외영업1부)인 사원의 이름과 급여를 조회하세요.

**Output**
```
박지민 3500000
염성원 2200000
유제영 2500000
윤정주 3760000
최주호 1800000
```
(순서는 무관합니다)

---

## 응용

### 문제 3. 범위 조건 + 정렬
급여가 200만원 이상 300만원 이하인 사원의 이름, 급여, 부서코드를 급여가 낮은 사람부터
정렬해서 조회하세요.

**확인할 것**: 10행이 조회되고, 첫 행이 이광렬(급여 2,000,000)인지 확인합니다.

---

### 문제 4. 문자 패턴 + NULL 조건
이름이 `'이'`로 시작하지 **않으면서** 보너스를 받는 사원의 이름, 보너스를 조회하세요.

**확인할 것**: 7행이 조회됩니다. (보너스를 받는 사원은 총 9명인데, 그중 성이 '이'씨인
2명은 제외됩니다)

---

### 문제 5. IN + AND 조합
부서가 `'D1'`, `'D5'`, `'D8'` 중 하나이면서 직급이 대리(`'J6'`)인 사원의 사번, 이름,
부서코드, 직급코드를 조회하세요.

**Output**
```
210 이광렬 D8 J6
211 이금빈 D8 J6
213 이다현 D1 J6
214 전태성 D1 J6
```
(순서는 무관합니다)

---

## 도전

### 문제 6. LIKE + ESCAPE
이메일 아이디(`@` 앞부분)의 첫 3글자 뒤에 곧바로 밑줄(`_`)이 오는 사원의 사번, 이름,
이메일을 사번 오름차순으로 조회하세요.

예) `kim_mh@company.com`은 `kim` 다음이 `_`이므로 해당하지만, `park_jm@company.com`은
`park`(4글자) 다음이 `_`이므로 해당하지 않습니다.

**확인할 것**: 11행이 조회되고, 첫 행이 사번 202(김민혜)인지 확인합니다.

---

### 문제 7. 종합 - NULL 조건 여러 개 결합
부서가 배정되지 않았거나, 관리자가 지정되지 않은 사원의 사번, 이름, 부서코드, 관리자사번을
사번 오름차순으로 조회하세요.

**확인할 것**: 6행이 조회되고, 첫 행이 사번 200(곽상혁, 대표라서 관리자가 없음)인지
확인합니다.
