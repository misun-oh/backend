### 문제 1. 날짜 형식 변환

```sql
SELECT EMP_NAME, DATE_FORMAT(HIRE_DATE, '%Y년 %m월 %d일') AS 입사일
FROM EMP
WHERE DEPT_ID = 'D9'
ORDER BY HIRE_DATE ASC;
```

**출력 결과**
```
곽상혁 2013년 03월 02일
권진우 2013년 09월 15일
김민혜 2014년 02월 10일
```

**설명**: `DATE_FORMAT(날짜, 형식)`은 `DATE`/`DATETIME` 값을 원하는 모양의 문자열로 바꿔줍니다.
`%Y`는 4자리 연도, `%m`은 2자리 월, `%d`는 2자리 일을 의미하며, 월/일이 한 자리 수여도
`03`, `02`처럼 0이 채워집니다.

### 문제 2. 문자 길이 함수

```sql
SELECT EMP_NAME, CHAR_LENGTH(EMP_NAME), LENGTH(EMP_NAME)
FROM EMP
WHERE DEPT_ID = 'D2';
```

**출력 결과**
```
박홍주 3 9
심재호 3 9
엄용민 3 9
```

**설명**: `CHAR_LENGTH`는 "글자 수"를, `LENGTH`는 "바이트 수"를 반환합니다. `utf8mb4` 환경에서
한글 한 글자는 3바이트를 차지하므로, 3글자 이름은 항상 `CHAR_LENGTH = 3`, `LENGTH = 9`로
나옵니다. 영문/숫자가 섞이면 두 값의 차이가 더 잘 드러납니다(예: 이메일 아이디는 모두 아스키
문자라 `CHAR_LENGTH`와 `LENGTH`가 항상 같습니다).

### 문제 3. IFNULL + 산술 연산

```sql
SELECT EMP_NAME, SALARY, (SALARY + SALARY * IFNULL(BONUS, 0)) * 12 AS 연봉
FROM EMP
WHERE DEPT_ID = 'D5'
ORDER BY 연봉 DESC;
```

**출력 결과**
```
박지민 3500000 48300000
윤정주 3760000 45120000
유제영 2500000 30000000
염성원 2200000 29040000
최주호 1800000 21600000
```

**설명**: `BONUS`가 `NULL`인 사원(유제영, 윤정주, 최주호)은 `SALARY * NULL`이 `NULL`이 되어
전체 연산 결과가 `NULL`로 오염됩니다. `IFNULL(BONUS, 0)`으로 먼저 `NULL`을 0으로 바꿔줘야
"보너스가 없으면 급여 12개월치만 받는다"는 의도대로 계산됩니다. 급여가 더 높아도 보너스가
없으면(윤정주 376만) 급여가 낮아도 보너스가 있는 사람(박지민 350만, 15%)에게 연봉이 역전당할
수 있다는 점도 확인할 수 있습니다.

### 문제 4. CASE + GROUP BY

```sql
SELECT
    CASE
        WHEN SALARY >= 5000000 THEN '고액'
        WHEN SALARY >= 2500000 THEN '중액'
        ELSE '소액'
    END AS 등급,
    COUNT(*) AS 인원수
FROM EMP
GROUP BY 등급;
```

**출력 결과**
```
고액 2
중액 11
소액 8
```
(등급이 나오는 순서는 보장되지 않으므로, 특정 순서가 필요하면 `ORDER BY`를 추가로 붙여야
합니다)

**설명**: `GROUP BY`에는 컬럼뿐 아니라 `CASE` 표현식(또는 그 별칭)도 그룹 기준으로 쓸 수
있습니다. MySQL은 `SELECT`에 쓴 별칭(`등급`)을 `GROUP BY`에서 그대로 재사용할 수 있어
`CASE` 식을 두 번 쓰지 않아도 됩니다. 고액 2명(곽상혁 800만, 권진우 600만), 소액 8명
(염성원·최주호·이광렬·오미자·한재헌·심재호·엄용민·조정원), 나머지 11명이 중액입니다.

### 문제 5. GROUP BY + HAVING

```sql
SELECT DEPT_ID, ROUND(AVG(SALARY)) AS 평균급여
FROM EMP
GROUP BY DEPT_ID
HAVING AVG(SALARY) >= 3000000;
```

**출력 결과**
```
D9 5900000
D6 3650000
```

**설명**: `WHERE`는 그룹으로 묶기 **전** 개별 행을 거르고, `HAVING`은 `GROUP BY`로 집계된
**그룹 결과**를 거릅니다. 부서별 평균은 총무부(D9) 590만, 해외영업2부(D6) 365만이 300만을
넘고, 나머지 부서(D5 275.2만, D1 260.7만, 부서 미배정 260.5만, D8 232.9만, D2 228만)는
모두 300만 미만이라 결과에서 빠집니다. `HAVING`에는 `AVG(SALARY)`처럼 집계 함수를 직접 써야
하며, `SELECT`의 별칭(`평균급여`)을 `HAVING`에 쓰면 반올림된 값 기준으로 비교되어 결과가
달라질 수 있으므로 원본 집계식을 쓰는 것이 안전합니다.

### 문제 6. 종합 - CASE로 성별 구분 후 집계

```sql
SELECT
    CASE
        WHEN SUBSTRING(EMP_NO, 8, 1) IN ('1', '3') THEN '남'
        WHEN SUBSTRING(EMP_NO, 8, 1) IN ('2', '4') THEN '여'
    END AS 성별,
    COUNT(*) AS 인원수,
    ROUND(AVG(SALARY)) AS 평균급여
FROM EMP
GROUP BY 성별;
```

**출력 결과**
```
남 14 3106429
여 7  3160891
```

**설명**: 주민등록번호 뒷자리 첫 글자(`EMP_NO`의 8번째 문자)는 `1`(남, 1900년대),
`2`(여, 1900년대), `3`(남, 2000년대), `4`(여, 2000년대)로 출생연도와 성별을 함께
나타냅니다. `SUBSTRING(EMP_NO, 8, 1)`로 이 한 글자를 뽑아 `IN`으로 묶으면 연도와
무관하게 성별만 분리할 수 있습니다. 남 14명의 급여 합은 43,490,000원, 여 7명의 급여
합은 22,126,240원이며 두 값을 더하면 `1_함수.md`에서 확인한 전체 급여 합계
65,616,240원과 정확히 일치합니다.

### 문제 7. 종합 - TIMESTAMPDIFF + WHERE

```sql
SELECT EMP_NAME, HIRE_DATE,
       TIMESTAMPDIFF(MONTH, HIRE_DATE, '2026-08-19') AS 재직개월
FROM EMP
WHERE ENT_YN = 'N'
  AND TIMESTAMPDIFF(MONTH, HIRE_DATE, '2026-08-19') >= 120
ORDER BY 재직개월 DESC;
```

**출력 결과**
```
곽상혁 2013-03-02 161
권진우 2013-09-15 155
김민혜 2014-02-10 150
김은민 2014-07-01 145
김태일 2014-11-11 141
박지민 2015-05-20 134
박홍주 2015-11-09 129
```

**설명**: `TIMESTAMPDIFF(MONTH, 시작일, 종료일)`은 두 날짜 사이의 **완전히 채워진** 개월
수를 계산합니다(예: `2020-01-15`~`2020-02-14`는 아직 1개월이 안 채워져 0을 반환하고,
`2020-02-15`부터 1이 됩니다). `ENT_YN = 'N'` 조건이 없으면 퇴사자인 오미자(212, 입사일
2021-11-28)도 오늘까지 계속 재직 중인 것처럼 계산되어 버리므로, 실제로 존재하지 않는
재직 기간이 나옵니다. 날짜 함수로 "현재까지의 기간"을 구할 때는 항상 재직 여부처럼
그 계산이 의미를 가지는 대상인지부터 `WHERE`로 걸러야 합니다.
