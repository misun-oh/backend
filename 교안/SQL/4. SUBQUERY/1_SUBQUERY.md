# Day 8~9. SUBQUERY

| 선수학습 | 이번 챕터 | 권장 진행 |
|---|---|---|
| DQL(SELECT), 함수(FUNCTION), JOIN | 단일행/다중행/다중컬럼/상관 서브쿼리, 인라인 뷰, WITH, LIMIT | 2일 (Day 8~9) |

## 학습목표
- SQL문 안에 또 다른 SELECT문(서브쿼리)을 넣어서 문제를 단계적으로 풀 수 있다.
- 서브쿼리가 반환하는 값의 개수(단일행/다중행/다중컬럼)에 따라 다른 연산자를 골라 쓸 수 있다.
- 바깥 쿼리의 값을 참조하는 상관 서브쿼리와 `EXISTS`를 이해한다.
- `FROM`절 서브쿼리(인라인 뷰)와 `WITH`(CTE)로 복잡한 쿼리를 읽기 쉽게 나눌 수 있다.
- `LIMIT`으로 상위 N개(Top-N) 데이터를 조회할 수 있다.

---

## 1. 서브쿼리란

**서브쿼리(subquery)**는 다른 SQL문 안에 포함된 `SELECT`문입니다. "평균 급여보다 많이
받는 사람"처럼 **비교 기준 자체를 미리 알 수 없고, 쿼리 결과로만 구할 수 있는 값**을
다룰 때 사용합니다.

```sql
SELECT EMP_NAME, SALARY
FROM EMP
WHERE SALARY > (SELECT AVG(SALARY) FROM EMP);   -- 괄호 안이 서브쿼리
```

서브쿼리는 반환하는 결과의 모양에 따라 쓸 수 있는 연산자가 달라지므로, 항상 "이 서브쿼리는
값을 몇 개(몇 행, 몇 열) 반환하는가?"부터 확인해야 합니다.

| 종류 | 반환하는 값 | 쓸 수 있는 연산자 |
|---|---|---|
| 단일행 서브쿼리 | 1행 1열(값 하나) | `=`, `>`, `<`, `>=`, `<=`, `!=` |
| 다중행 서브쿼리 | 여러 행, 1열 | `IN`, `ANY`, `ALL`, `EXISTS` |
| 다중 컬럼 서브쿼리 | 1행(또는 여러 행), 여러 열 | `= (col1, col2)`, `IN` |

---

## 2. 단일행 서브쿼리

서브쿼리가 정확히 값 1개만 반환한다면 일반 비교 연산자(`=`, `>` 등)를 그대로 쓸 수
있습니다.

```sql
SELECT EMP_NAME, SALARY
FROM EMP
WHERE SALARY > (SELECT AVG(SALARY) FROM EMP);
```

**출력 결과**
```
곽상혁 8000000
권진우 6000000
김태일 3900000
윤정주 3760000
김민혜 3700000
전태성 3660000
박지민 3500000
김은민 3400000
```

전체 평균 급여는 `65,616,240 / 21 ≈ 3,124,582.86`원입니다. 이 값보다 급여가 많은
8명만 조회됩니다.

> **주의**: 서브쿼리가 실제로는 값을 2개 이상 반환하는데 `=`나 `>`처럼 단일행 전용
> 연산자를 쓰면 `Subquery returns more than 1 row` 오류가 납니다. 반드시 서브쿼리가
> "값이 딱 하나만 나오는 상황"인지 먼저 확인하세요.

## 3. 다중행 서브쿼리 - IN

서브쿼리가 여러 행을 반환하면 `=` 대신 `IN`을 씁니다.

```sql
SELECT EMP_ID, EMP_NAME, DEPT_ID
FROM EMP
WHERE DEPT_ID IN (
    SELECT DEPT_ID FROM EMP WHERE JOB_CODE = 'J6'
)
ORDER BY EMP_ID;
```

**출력 결과**
```
210 이광렬 D8
211 이금빈 D8
212 오미자 D8
213 이다현 D1
214 전태성 D1
215 한재헌 D1
```

**설명**: 안쪽 서브쿼리는 대리(`'J6'`)인 사원들의 부서코드를 반환합니다
(`D8, D8, D1, D1, NULL` - 조정원(219)은 부서가 없어 `NULL`이 함께 나오지만, `IN`
목록에 `NULL`이 섞여 있어도 나머지 값(`D8`, `D1`)과의 비교에는 영향을 주지 않습니다).
결과적으로 "대리가 한 명이라도 있는 부서(D8, D1) 전체 사원"이 조회됩니다.

## 4. 다중행 서브쿼리 - ANY / ALL

`ANY`(또는 `SOME`)는 "목록 중 **하나라도** 만족하면 참", `ALL`은 "목록 **전부**를
만족해야 참"입니다.

### ALL - 기준 그룹의 모든 값보다 커야 함

```sql
SELECT EMP_NAME, SALARY
FROM EMP
WHERE SALARY > ALL (
    SELECT SALARY FROM EMP WHERE DEPT_ID = 'D1'
)
ORDER BY SALARY DESC;
```

**출력 결과**
```
곽상혁 8000000
권진우 6000000
김태일 3900000
윤정주 3760000
김민혜 3700000
```

인사관리부(D1) 사원 급여는 `2,780,000 / 3,660,000 / 1,380,000`이며, 그중 최댓값은
3,660,000입니다. `> ALL(목록)`은 "목록의 최댓값보다 커야 한다"는 뜻과 같으므로,
급여가 3,660,000을 **초과**하는 5명만 조회됩니다. (급여가 정확히 3,660,000인 전태성
본인은 "본인보다 큰가"의 문제이므로 포함되지 않습니다.)

### ANY - 기준 그룹의 어느 값보다 작아도 됨

```sql
SELECT EMP_NAME, SALARY
FROM EMP
WHERE SALARY < ANY (
    SELECT SALARY FROM EMP WHERE DEPT_ID = 'D8'
)
ORDER BY SALARY ASC;
```

**출력 결과**
```
한재헌 1380000
심재호 1550000
최주호 1800000
이광렬 2000000
염성원 2200000
조정원 2320000
오미자 2436240
엄용민 2490000
유제영 2500000
```

기술지원부(D8) 사원 급여는 `2,000,000 / 2,550,000 / 2,436,240`이며 그중 최댓값은
2,550,000입니다. `< ANY(목록)`은 "목록의 최댓값보다 작으면 된다"는 뜻과 같으므로,
급여가 2,550,000 **미만**인 9명이 조회됩니다.

> `ALL`은 "최댓값/최솟값과 비교"로, `ANY`는 "최솟값/최댓값과 비교"로 바꿔 생각하면
> 헷갈리지 않습니다. `> ALL(목록)` = `> MAX(목록)`, `< ANY(목록)` = `< MAX(목록)`,
> `> ANY(목록)` = `> MIN(목록)`, `< ALL(목록)` = `< MIN(목록)`.

## 5. 다중 컬럼 서브쿼리

컬럼 여러 개를 한 번에 서브쿼리 결과와 비교할 수도 있습니다.

```sql
SELECT EMP_NAME, DEPT_ID, JOB_CODE
FROM EMP
WHERE (DEPT_ID, JOB_CODE) = (
    SELECT DEPT_ID, JOB_CODE FROM EMP WHERE EMP_NAME = '이광렬'
)
AND EMP_NAME != '이광렬';
```

**출력 결과**
```
이금빈 D8 J6
```

**설명**: `(DEPT_ID, JOB_CODE) = (서브쿼리)`는 두 컬럼을 각각 비교하는 것이 아니라
**한 쌍으로 묶어서** 비교합니다. 이광렬은 (D8, J6)이고, 같은 부서·같은 직급인 사원은
이금빈뿐입니다(같은 D8 소속인 오미자는 직급이 J7이라 제외됩니다). 자기 자신이 결과에
다시 나오지 않도록 `EMP_NAME != '이광렬'` 조건을 추가했습니다.

## 6. 상관 서브쿼리 (Correlated Subquery) + EXISTS

지금까지의 서브쿼리는 바깥 쿼리와 무관하게 **한 번만** 실행됩니다. 반면 **상관
서브쿼리**는 바깥 쿼리의 각 행마다 안쪽 서브쿼리가 그 행의 값을 참조하며 반복 실행됩니다.

```sql
SELECT E.EMP_NAME
FROM EMP E
WHERE EXISTS (
    SELECT 1 FROM EMP M WHERE M.MANAGER_ID = E.EMP_ID
)
ORDER BY E.EMP_ID;
```

**출력 결과**
```
곽상혁
권진우
김은민
박지민
염성원
이광렬
이다현
```

**설명**: 안쪽 서브쿼리의 `M.MANAGER_ID = E.EMP_ID`는 바깥 쿼리(`E`)의 사원 한 명 한
명을 가리키며 "이 사람을 관리자로 둔 부하 직원이 있는가?"를 매번 다시 검사합니다.
`EXISTS`는 서브쿼리가 **행을 1개 이상 반환하기만 하면** 참이 되고(값 자체는 보지
않음), 한 건도 없으면 거짓이 됩니다. 그래서 실제로 부하 직원이 있는 7명(대표 포함
관리 직급자)만 조회됩니다.

> `EXISTS`는 `IN`과 결과가 비슷해 보일 때가 많지만, `IN`은 서브쿼리 결과값 **자체**를
> 비교하고 `EXISTS`는 "행이 존재하는지"만 확인합니다. 서브쿼리 결과에 `NULL`이 섞여
> 있을 가능성이 있다면 `NOT IN`보다 `NOT EXISTS`가 더 안전합니다(`NOT IN`은 목록에
> `NULL`이 하나라도 있으면 예상과 다르게 전체 결과가 빈 값이 되어버릴 수 있습니다).

## 7. FROM절 서브쿼리 (인라인 뷰)

`FROM`절에도 서브쿼리를 쓸 수 있습니다. 이렇게 쓰인 서브쿼리를 **인라인 뷰(inline
view)**라고 부르며, 서브쿼리의 결과를 마치 임시 테이블처럼 다룰 수 있습니다.

```sql
SELECT D.DEPT_TITLE, T.평균급여
FROM (
    SELECT DEPT_ID, ROUND(AVG(SALARY)) AS 평균급여
    FROM EMP
    GROUP BY DEPT_ID
) T
JOIN DEPT D ON T.DEPT_ID = D.DEPT_ID
WHERE T.평균급여 >= 3000000;
```

**출력 결과**
```
총무부      5900000
해외영업2부 3650000
```

**설명**: 안쪽 서브쿼리(`T`)가 먼저 "부서별 평균 급여"라는 임시 결과를 만들고, 바깥
쿼리는 그 결과를 `DEPT`와 조인한 뒤 `WHERE`로 걸러냅니다. 함수 챕터에서 `GROUP BY` +
`HAVING`으로 풀었던 것과 **똑같은 결과**를, 여기서는 "먼저 집계 → 그 결과를 다시
조회"하는 두 단계로 나눠서 풀었습니다. 인라인 뷰는 이렇게 집계 결과에 또 다른 테이블을
조인해야 할 때(`HAVING`만으로는 부족할 때) 특히 유용합니다.

---

## 8. WITH (공통 테이블 표현식, CTE)

인라인 뷰가 중첩되면 괄호가 겹겹이 쌓여 읽기 어려워집니다. `WITH`를 쓰면 서브쿼리에
미리 이름을 붙여두고 본문에서는 그 이름으로 참조할 수 있습니다.

```sql
WITH DEPT_AVG AS (
    SELECT DEPT_ID, ROUND(AVG(SALARY)) AS 평균급여
    FROM EMP
    GROUP BY DEPT_ID
)
SELECT D.DEPT_TITLE, DA.평균급여
FROM DEPT_AVG DA
JOIN DEPT D ON DA.DEPT_ID = D.DEPT_ID
WHERE DA.평균급여 >= 3000000;
```

바로 위 인라인 뷰 예제와 결과가 완전히 같습니다. `WITH DEPT_AVG AS (...)`로 서브쿼리에
`DEPT_AVG`라는 이름을 붙여두면, 본문에서는 그냥 테이블처럼 `FROM DEPT_AVG`라고 쓸 수
있어 쿼리가 훨씬 읽기 편해집니다.

## 9. LIMIT을 이용한 Top-N 분석

"상위 N개만 보고 싶다"는 요구는 실무에서 아주 자주 나옵니다. MySQL은 `ORDER BY` 뒤에
`LIMIT`을 붙여서 처리합니다.

```sql
SELECT EMP_NAME, SALARY
FROM EMP
ORDER BY SALARY DESC
LIMIT 3;
```

**출력 결과**
```
곽상혁 8000000
권진우 6000000
김태일 3900000
```

중간 구간(예: 4등~6등)을 보고 싶다면 `LIMIT`에 시작 위치를 함께 지정합니다.

```sql
SELECT EMP_NAME, SALARY
FROM EMP
ORDER BY SALARY DESC
LIMIT 3, 3;   -- 4번째 행부터 3개 (= LIMIT 3 OFFSET 3)
```

**출력 결과**
```
윤정주 3760000
김민혜 3700000
전태성 3660000
```

**설명**: `LIMIT 시작위치, 개수` 형식에서 시작 위치는 0부터 셉니다. `LIMIT 3, 3`은
"0,1,2번째(=1~3등) 행을 건너뛰고, 그다음 3개(=4~6등)를 가져오라"는 뜻이며, `LIMIT 3
OFFSET 3`이라고 써도 완전히 같은 결과입니다.

> Oracle에는 `ROWNUM`이라는 가상 컬럼으로 Top-N을 구현했지만(`WHERE ROWNUM <= 3`),
> MySQL에는 `ROWNUM`이 없습니다. `ORDER BY ... LIMIT n`으로 정렬 후 상위 n개를 자르는
> 것이 MySQL의 표준적인 방식입니다.

---

## 자주 하는 실수

- **다중행을 반환하는 서브쿼리에 `=`, `>` 같은 단일행 연산자 사용** → `Subquery
  returns more than 1 row` 오류. 결과가 여러 행이면 `IN`/`ANY`/`ALL`을 씁니다.
- **`ANY`와 `ALL`을 반대로 이해** → `> ALL`은 목록의 **최댓값**보다 커야 하고(까다로운
  조건), `> ANY`는 목록의 **최솟값**보다 크면 됩니다(느슨한 조건). "ALL은 전부
  이겨야 하니 더 어렵다"고 기억하면 헷갈리지 않습니다.
- **`NOT IN` 서브쿼리 결과에 `NULL`이 섞여 있는 경우** → `NOT IN (1, 2, NULL)`은
  비교 대상이 무엇이든 결과가 전부 `NULL`(즉, 조건을 만족하는 행이 하나도 없음)이
  되어버립니다. 서브쿼리 결과에 `NULL`이 나올 수 있다면 `NOT IN` 대신 `NOT EXISTS`나
  `WHERE ... IS NOT NULL`을 서브쿼리 안에 추가해서 `NULL`을 미리 걸러내야 합니다.
- **상관 서브쿼리에서 바깥/안쪽 별칭을 혼동** → `EXISTS` 안의 서브쿼리가 바깥 쿼리의
  어느 별칭을 참조하는지 명확히 구분해야 합니다(예제의 `E`와 `M`처럼).
- **인라인 뷰에 별칭을 안 붙임** → MySQL은 `FROM (SELECT ...)` 뒤에 반드시 별칭
  (`T`, `DA` 등)을 붙여야 하며, 붙이지 않으면 문법 오류가 납니다.
- **`LIMIT` 앞에 `ORDER BY`를 빼먹음** → 정렬 순서가 보장되지 않은 상태에서 `LIMIT`만
  쓰면 "상위 N개"가 매번 다른 결과를 줄 수 있습니다. Top-N은 항상 `ORDER BY` +
  `LIMIT`을 함께 씁니다.

## 핵심 요약

| 구분 | 특징 | 이 교재의 예시 |
|---|---|---|
| 단일행 서브쿼리 | 값 1개, `=`/`>` 등 사용 | 전체 평균 급여보다 높은 사원 |
| 다중행 서브쿼리 | 여러 값, `IN` 사용 | 대리가 있는 부서 전체 사원 |
| ANY / ALL | 다중행 값 중 하나/전부와 비교 | D1 급여 전부보다 높은 사원(`ALL`) |
| 다중 컬럼 서브쿼리 | 여러 컬럼을 한 쌍으로 비교 | 이광렬과 부서·직급이 같은 사원 |
| 상관 서브쿼리 + EXISTS | 바깥 쿼리 값을 참조하며 반복 실행 | 부하 직원이 있는 사원 |
| 인라인 뷰 (FROM절 서브쿼리) | 서브쿼리 결과를 임시 테이블처럼 사용 | 부서별 평균 급여 집계 후 조인 |
| WITH (CTE) | 서브쿼리에 이름을 붙여 재사용 | 인라인 뷰를 더 읽기 쉽게 표현 |
| LIMIT | 정렬 후 상위 N개만 추출 (ROWNUM 대체) | 급여 상위 3명 조회 |
