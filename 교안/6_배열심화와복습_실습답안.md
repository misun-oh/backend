## 기본

### 문제 1. 2차원 배열 합계

```java
public class Practice1 {
    public static void main(String[] args) {
        int[][] 표 = {{1,2,3}, {4,5,6}, {7,8,9}};
        int 합계 = 0;

        for (int i = 0; i < 표.length; i++) {
            for (int j = 0; j < 표[i].length; j++) {
                합계 += 표[i][j];
            }
        }

        System.out.println("합계: " + 합계);
    }
}
```

**설명**: 바깥 반복문은 행(`i`)을, 안쪽 반복문은 그 행 안의 열(`j`)을 순회하며 `표[i][j]`의 값을 하나씩 `합계`에 누적합니다.

**틀리기 쉬운 포인트**: 안쪽 반복문의 조건을 `j < 표.length`로 잘못 쓰면, 행과 열의 개수가 다를 때 오류가 날 수 있습니다. 항상 `표[i].length`로 그 행의 실제 열 개수를 확인해야 합니다.

### 문제 2. 값 교환 (swap)

```java
public class Practice2 {
    public static void main(String[] args) {
        int[] 숫자들 = {100, 200};
        System.out.println("교환 전: " + 숫자들[0] + ", " + 숫자들[1]);

        int temp = 숫자들[0];
        숫자들[0] = 숫자들[1];
        숫자들[1] = temp;

        System.out.println("교환 후: " + 숫자들[0] + ", " + 숫자들[1]);
    }
}
```

**설명**: `temp`에 `숫자들[0]`의 원래 값(100)을 먼저 저장해두었기 때문에, `숫자들[0]`을 200으로 덮어써도 `temp`를 통해 100이라는 값을 잃지 않고 `숫자들[1]`에 대입할 수 있습니다.

**틀리기 쉬운 포인트**: `temp` 없이 바로 `숫자들[0] = 숫자들[1]; 숫자들[1] = 숫자들[0];`처럼 작성하면, 두 번째 줄이 실행될 때 이미 `숫자들[0]`이 200으로 바뀐 뒤라 결과가 `200, 200`이 되어버립니다.

### 문제 3. 2차원 배열로 학생 점수 출력

```java
public class Practice3 {
    public static void main(String[] args) {
        int[][] 성적표 = {{90,85}, {78,92}, {88,76}};

        for (int i = 0; i < 성적표.length; i++) {
            System.out.println((i + 1) + "번 학생: 국어 " + 성적표[i][0] + ", 영어 " + 성적표[i][1]);
        }
    }
}
```

**설명**: 각 행(`성적표[i]`)이 한 학생의 점수 배열이므로, `성적표[i][0]`은 국어, `성적표[i][1]`은 영어 점수입니다. 학생 번호는 인덱스가 0부터 시작하므로 `i + 1`로 사람이 읽기 좋은 번호로 바꿔 출력합니다.

**틀리기 쉬운 포인트**: `i`를 그대로 출력하면 "0번 학생"부터 시작해 사람 눈에는 어색합니다. 배열의 인덱스(0부터)와 화면에 보여줄 번호(1부터)를 구분해서 `i + 1`로 변환하는 습관이 필요합니다.

### 문제 4. 버블 정렬로 오름차순 정렬

```java
public class Practice4 {
    public static void main(String[] args) {
        int[] 숫자들 = {8, 3, 6, 1, 9};

        for (int i = 0; i < 숫자들.length - 1; i++) {
            for (int j = 0; j < 숫자들.length - 1 - i; j++) {
                if (숫자들[j] > 숫자들[j + 1]) {
                    int temp = 숫자들[j];
                    숫자들[j] = 숫자들[j + 1];
                    숫자들[j + 1] = temp;
                }
            }
        }

        for (int 값 : 숫자들) {
            System.out.print(값 + " ");
        }
    }
}
```

**설명**: 교안에서 설명한 버블 정렬 로직을 그대로 적용했습니다. 인접한 두 값을 비교해서 앞이 더 크면 교환하는 과정을 반복하면, 매 바깥 반복(`i`)마다 가장 큰 값이 뒤쪽으로 하나씩 확정되어 갑니다.

**틀리기 쉬운 포인트**: 안쪽 반복문의 조건을 `j < 숫자들.length - i`(-1을 빠뜨림)로 쓰면, `숫자들[j+1]`에 접근할 때 배열 범위를 벗어나는 인덱스가 나와 `ArrayIndexOutOfBoundsException`이 발생합니다.

### 문제 5. 학생 이메일에서 아이디 목록 추출

```java
public class Practice5 {
    public static void main(String[] args) {
        String[] 이메일들 = {"kim@test.com", "lee@test.com", "park@test.com"};

        int 번호 = 1;
        for (String 이메일 : 이메일들) {
            int 위치 = 이메일.indexOf("@");
            String 아이디 = 이메일.substring(0, 위치);
            System.out.println(번호 + ". " + 아이디);
            번호++;
        }
    }
}
```

**설명**: Day5에서 배운 `indexOf`와 `substring`을 배열 순회(Day5의 향상된 for문)와 결합했습니다. 각 이메일 문자열마다 `@`의 위치를 찾아 그 앞부분만 잘라내는 과정을 배열의 모든 요소에 반복 적용합니다.

**틀리기 쉬운 포인트**: 이메일마다 `@`의 위치가 다르므로(`kim@`은 3번째, `park@`는 4번째), `substring(0, 3)`처럼 위치를 고정값으로 쓰면 안 되고, 매번 `indexOf`로 새로 계산해야 합니다.

### 문제 6. 성적 처리 종합 프로그램

```java
public class Practice6 {
    public static void main(String[] args) {
        int[] 점수들 = {85, 92, 78, 90, 88};

        int 합계 = 0;
        int 최댓값 = 점수들[0];

        for (int i = 0; i < 점수들.length; i++) {
            합계 += 점수들[i];
            if (점수들[i] > 최댓값) {
                최댓값 = 점수들[i];
            }
        }

        double 평균 = (double) 합계 / 점수들.length;
        String 학급평가 = (평균 >= 85) ? "우수 학급" : "보통 학급";

        System.out.println("합계: " + 합계);
        System.out.printf("평균: %.2f%n", 평균);
        System.out.println("최댓값: " + 최댓값);
        System.out.println("학급 평가: " + 학급평가);
    }
}
```

**설명**: 이 문제는 Day1(형변환), Day2(연산자·삼항), Day3(반복문), Day5(배열)에서 배운 개념을 한 번에 사용합니다. 반복문 하나로 합계 누적과 최댓값 비교를 동시에 처리해서 효율적으로 계산했습니다.

**틀리기 쉬운 포인트**: 합계 계산과 최댓값 비교를 별도의 반복문 두 개로 나눠 작성해도 결과는 같지만, 하나의 반복문 안에서 동시에 처리하면 배열을 한 번만 순회해도 되므로 더 효율적입니다. 이런 습관은 배열이 커질수록 성능 차이로 이어집니다.
