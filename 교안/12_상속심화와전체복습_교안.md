## 1. protected 접근제한자

Day10에서 배운 `private`(같은 클래스만), `public`(어디서든) 외에, 상속 관계에서 유용한 `protected`가 있습니다.

| 접근제한자 | 같은 클래스 | 자식 클래스 | 그 외 |
|---|---|---|---|
| `private` | O | X | X |
| `protected` | O | O | X |
| `public` | O | O | O |

```java
public class 사람 {
    protected String 이름; // 자식 클래스에서는 직접 접근 가능, 그 외에는 불가

    public 사람(String 이름) {
        this.이름 = 이름;
    }
}

public class 학생 extends 사람 {
    public 학생(String 이름) {
        super(이름);
    }

    public void 이름출력() {
        System.out.println(이름); // protected이므로 자식 클래스에서 직접 접근 가능 (private이면 불가)
    }
}
```

**설명**: `private`는 자식 클래스에게도 숨겨지지만, `protected`는 상속 관계에 있는 자식 클래스에게는 접근을 허용합니다. 완전히 공개하고 싶지는 않지만, 상속받은 클래스에서는 자유롭게 쓰게 하고 싶을 때 사용합니다.

## 2. 타입 변환과 다형성

Day11의 문제 5에서 이미 다형성을 살짝 경험했습니다. 여기서는 이를 조금 더 명확히 정리합니다.

**업캐스팅(자동)**: 자식 타입 객체를 부모 타입 변수에 담는 것. 자동으로 이루어집니다.
```java
사람 사람1 = new 학생("홍길동", "S001"); // 학생 객체를 사람 타입 변수에 담음 (업캐스팅)
```

**다형성**: 같은 메서드 호출(`사람1.소개하기()`)이라도, 실제 객체(학생, 교수 등)에 따라 다른 동작을 하는 것.
```java
public class 다형성예제 {
    public static void main(String[] args) {
        사람[] 사람들 = {
            new 학생("홍길동", "S001"),
            new 교수("김교수", "P001")
        };

        for (사람 사람 : 사람들) {
            사람.소개하기(); // 선언 타입은 모두 "사람"이지만, 실제 객체에 따라 다른 메서드가 실행됨
        }
    }
}
```

**다운캐스팅(강제)**: 부모 타입 변수에 담긴 객체를, 원래의 자식 타입으로 다시 되돌리는 것. `(자식타입)`으로 명시적 캐스팅이 필요합니다.
```java
사람 사람1 = new 학생("홍길동", "S001"); // 업캐스팅
학생 학생1 = (학생) 사람1;                // 다운캐스팅: 사람 타입을 다시 학생 타입으로

System.out.println(학생1.get학번()); // 다운캐스팅해야 학생만의 메서드(get학번)를 호출할 수 있음
// System.out.println(사람1.get학번()); // 컴파일 에러! 사람 타입에는 get학번()이 없음
```

**설명**: `사람1`이라는 변수는 선언 타입이 `사람`이므로, `사람` 클래스에 있는 메서드(`get이름()`, `소개하기()`)만 바로 호출할 수 있습니다. `학생`만의 메서드(`get학번()`)를 사용하려면 `(학생) 사람1`처럼 다운캐스팅해서 원래 타입으로 되돌려야 합니다.

## 3. 추상 클래스 (Abstract Class)

**추상 클래스**는 그 자체로는 객체를 만들 수 없고, 자식 클래스가 상속받아 완성해야 하는 미완성 설계도입니다. 특히 **추상 메서드**(구현 내용이 없는 메서드)를 포함할 수 있으며, 자식 클래스는 이 추상 메서드를 반드시 오버라이딩해야 합니다.

```java
public abstract class 사람 { // abstract: 이 클래스는 직접 객체를 만들 수 없음
    protected String 이름;

    public 사람(String 이름) {
        this.이름 = 이름;
    }

    public String get이름() {
        return 이름;
    }

    public abstract void 소개하기(); // 추상 메서드: 구현 내용이 없고, 자식이 반드시 재정의해야 함
}
```

```java
public class 학생 extends 사람 {
    private String 학번;

    public 학생(String 이름, String 학번) {
        super(이름);
        this.학번 = 학번;
    }

    @Override
    public void 소개하기() { // 추상 메서드를 반드시 구현해야 함 (안 하면 컴파일 에러)
        System.out.println("저는 학번 " + 학번 + "인 " + get이름() + "입니다.");
    }
}
```

```java
public class 추상클래스예제 {
    public static void main(String[] args) {
        // 사람 사람1 = new 사람("홍길동"); // 컴파일 에러! 추상 클래스는 직접 객체를 만들 수 없음
        사람 학생1 = new 학생("홍길동", "S001"); // 자식 클래스(학생)는 객체 생성 가능
        학생1.소개하기();
    }
}
```

**설명**: `abstract class 사람`처럼 클래스 앞에 `abstract`를 붙이면, `new 사람(...)`으로 직접 객체를 만들 수 없게 됩니다. 대신 `사람`을 상속받는 `학생`, `교수` 같은 구체적인 자식 클래스만 객체로 만들 수 있습니다. 추상 클래스는 "이 부모를 상속받는 자식은 반드시 이 메서드를 자기 방식대로 구현해야 한다"는 규칙을 강제할 때 유용합니다.

## 자주 하는 실수

1. **추상 클래스를 직접 객체로 생성하려 시도**
   ```java
   사람 사람1 = new 사람("홍길동"); // 컴파일 에러: abstract 클래스는 new 불가
   ```

2. **추상 메서드를 자식 클래스에서 구현하지 않음**
   ```java
   public class 학생 extends 사람 {
       // 소개하기()를 구현하지 않으면 컴파일 에러 발생
   }
   ```

3. **다운캐스팅 없이 자식 타입 전용 메서드 호출 시도**
   ```java
   사람 사람1 = new 학생("홍길동", "S001");
   사람1.get학번(); // 컴파일 에러! 사람 타입에는 get학번()이 없음
   ((학생) 사람1).get학번(); // 올바른 방법: 다운캐스팅 후 호출
   ```

## 핵심 요약

| 항목 | 핵심 내용 |
|---|---|
| protected | 같은 클래스 + 자식 클래스에서 접근 가능, 그 외에는 불가 |
| 업캐스팅 | 자식 객체를 부모 타입 변수에 담는 것 (자동) |
| 다운캐스팅 | 부모 타입 변수를 다시 자식 타입으로 되돌리는 것 (`(자식타입)` 명시 필요) |
| 다형성 | 같은 메서드 호출이 실제 객체 타입에 따라 다르게 동작 |
| 추상 클래스 | `abstract class`, 직접 객체 생성 불가, 자식이 상속받아 완성 |
| 추상 메서드 | `abstract` 메서드, 자식 클래스가 반드시 오버라이딩해야 함 |
