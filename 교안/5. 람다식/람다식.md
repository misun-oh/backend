# 부록 4. 람다식 (Lambda Expression)

| 항목 | 내용 |
|---|---|
| 선수 학습 | 인터페이스 (Day 13) |
| 이번 챕터 | 익명 클래스의 번거로움을 해결하는 람다식, 함수형 인터페이스, 컬렉션과의 활용 |

## 학습목표
- 익명 클래스의 번거로움을 통해 람다식이 왜 필요한지 설명할 수 있다
- 함수형 인터페이스(추상 메서드가 하나뿐인 인터페이스)의 개념을 이해할 수 있다
- 람다식 문법으로 함수형 인터페이스를 간결하게 구현할 수 있다
- 자바가 미리 제공하는 대표적인 함수형 인터페이스(`Runnable`, `Comparator`)를 활용할 수 있다
- 매개변수를 그대로 넘기기만 하는 람다식을 메서드 참조(`::`)로 더 줄일 수 있다
- 객체 생성만 하는 람다식을 생성자 참조(`클래스::new`)로 표현할 수 있다
- 람다식을 컬렉션(Day16 복습)과 함께 활용할 수 있다

## 1. 문제 상황: 익명 클래스로 인터페이스 구현하기

Day13에서 배운 인터페이스를 구현하려면, 지금까지는 별도의 클래스를 만들어서 `implements`하는 방식을 썼습니다. 그런데 그 구현체를 **딱 한 번만 쓰고 버릴 것**이라면, 클래스를 따로 만드는 것 자체가 번거롭습니다. 이럴 때 자바는 **익명 클래스(anonymous class)** 라는 문법을 제공합니다.

```java
public interface Greeter {
    void greet(String name);
}
```

```java
public class AnonymousClassExample {
    public static void main(String[] args) {
        // 이름 없는 클래스를 그 자리에서 즉석으로 만들어 Greeter를 구현
        Greeter greeter = new Greeter() {
            @Override
            public void greet(String name) {
                System.out.println("안녕하세요, " + name + "님!");
            }
        };

        greeter.greet("홍길동");
    }
}
```

**설명**: `new Greeter() { ... }`는 "이름 없는 클래스를 그 자리에서 만들어 즉시 객체까지 생성한다"는 뜻입니다. 클래스 파일을 따로 만들지 않아도 되는 점은 편리하지만, `greet(String name)` 메서드 하나를 구현하기 위해 `new Greeter() { @Override public void greet(String name) { ... } }`라는 상당히 긴 코드를 매번 반복해야 합니다. 람다식은 바로 이 번거로움을 줄이기 위한 문법입니다.

---

## 2. 함수형 인터페이스란?

**함수형 인터페이스(functional interface)** 는 **추상 메서드가 정확히 하나뿐인** 인터페이스입니다. `Greeter`처럼 메서드가 `greet()` 하나만 있는 인터페이스가 바로 함수형 인터페이스입니다. 람다식은 오직 함수형 인터페이스를 구현할 때만 사용할 수 있습니다.

```java
@FunctionalInterface // 이 인터페이스가 함수형 인터페이스임을 명시 (필수는 아니지만 실수 방지에 유용)
public interface Greeter {
    void greet(String name); // 추상 메서드가 정확히 1개
}
```

**설명**: `@FunctionalInterface`는 Day13(애노테이션 부록)에서 배운 것과 같은 애노테이션입니다. 이 표시를 붙여두면, 나중에 실수로 추상 메서드를 하나 더 추가했을 때 컴파일러가 "함수형 인터페이스 규칙 위반"이라는 에러로 바로 알려줍니다.

```java
@FunctionalInterface
public interface Broken {
    void methodA();
    void methodB(); // 컴파일 에러! 추상 메서드가 2개라 함수형 인터페이스가 될 수 없음
}
```

## 3. 람다식 문법

람다식은 `(매개변수) -> { 실행문 }` 형태로, 익명 클래스보다 훨씬 짧게 함수형 인터페이스를 구현하는 문법입니다.

```java
public class LambdaExample {
    public static void main(String[] args) {
        // 1번의 익명 클래스 버전과 완전히 같은 동작을 하는 람다식
        Greeter greeter = (String name) -> {
            System.out.println("안녕하세요, " + name + "님!");
        };

        greeter.greet("홍길동");
    }
}
```

**익명 클래스와 비교**

| 익명 클래스 | 람다식 |
|---|---|
| `new Greeter() { @Override public void greet(String name) { ... } }` | `(String name) -> { ... }` |
| 인터페이스 이름, `@Override`, 메서드 이름을 모두 반복 작성 | 매개변수와 실행문만 작성 |

**설명**: 람다식은 "어떤 인터페이스를, 어떤 메서드로 구현하는지"를 굳이 적지 않습니다. 람다식이 대입되는 변수의 타입(`Greeter greeter = ...`)을 보고, 컴파일러가 자동으로 "이건 `Greeter`의 `greet()`를 구현하는 코드구나"라고 판단하기 때문입니다.

**람다식 문법 축약 규칙**

| 규칙 | 예시 |
|---|---|
| 매개변수 타입 생략 가능 (추론됨) | `(name) -> { ... }` |
| 매개변수가 1개면 괄호 생략 가능 | `name -> { ... }` |
| 실행문이 1줄이면 중괄호와 세미콜론 생략 가능 | `name -> System.out.println("안녕, " + name)` |
| 반환값이 있는 한 줄짜리 식은 `return` 생략 가능 | `(a, b) -> a + b` |

```java
Greeter greeter1 = (String name) -> { System.out.println("안녕, " + name); }; // 원래 형태
Greeter greeter2 = name -> System.out.println("안녕, " + name);              // 축약 형태 (완전히 동일하게 동작)
```

## 4. 커스텀 함수형 인터페이스 + 람다 활용 (학사관리 도메인)

학사관리 도메인에 맞는 함수형 인터페이스를 직접 만들어 람다로 구현해봅니다.

```java
@FunctionalInterface
public interface StudentFilter {
    boolean test(Student student); // 학생 한 명을 검사해서 조건에 맞으면 true
}
```

```java
public class Student {
    private String name;
    private int score;

    public Student(String name, int score) {
        this.name = name;
        this.score = score;
    }

    public String getName() {
        return name;
    }

    public int getScore() {
        return score;
    }
}
```

```java
public class StudentFilterExample {
    public static void main(String[] args) {
        Student student1 = new Student("홍길동", 92);

        // 점수가 90 이상인지 검사하는 규칙을 람다식으로 즉석에서 정의
        StudentFilter highScoreFilter = student -> student.getScore() >= 90;

        System.out.println(highScoreFilter.test(student1)); // true
    }
}
```

**설명**: `StudentFilter`는 우리가 직접 만든, "학생 한 명을 조건에 맞는지 검사한다"는 규칙만 정의한 함수형 인터페이스입니다. `highScoreFilter`라는 람다식은 그 규칙을 "점수가 90 이상이면 true"라는 구체적인 동작으로 채워 넣은 것입니다. 이런 필터 인터페이스는 다음 섹션에서 컬렉션과 결합할 때 진가를 발휘합니다.

## 5. 자바가 미리 제공하는 함수형 인터페이스

매번 함수형 인터페이스를 직접 만들 필요 없이, 자바는 자주 쓰이는 형태를 미리 정의해서 제공합니다. 그중 대표적인 두 가지를 소개합니다.

| 인터페이스 | 추상 메서드 | 용도 |
|---|---|---|
| `Runnable` | `void run()` | 매개변수와 반환값이 없는 작업 하나를 표현 |
| `Comparator<T>` | `int compare(T a, T b)` | 두 객체를 비교해서 정렬 순서를 정하는 규칙을 표현 |

```java
public class BuiltInFunctionalInterfaceExample {
    public static void main(String[] args) {
        Runnable task = () -> System.out.println("작업을 실행합니다."); // 매개변수 없으면 빈 괄호
        task.run();

        Comparator<Student> byScore = (a, b) -> a.getScore() - b.getScore(); // 오름차순 비교 규칙
        System.out.println(byScore.compare(new Student("홍길동", 90), new Student("김철수", 85))); // 양수(90-85=5)
    }
}
```

**설명**: `Comparator<T>`의 `compare(a, b)`는 관례적으로 `a`가 `b`보다 작으면 음수, 크면 양수, 같으면 0을 반환하도록 구현합니다. `a.getScore() - b.getScore()`는 이 관례를 그대로 따르는 흔한 구현 방식입니다. `Runnable`과 `Comparator` 외에도 `java.util.function` 패키지에 `Function`, `Predicate`, `Consumer` 같은 범용 함수형 인터페이스가 더 있지만, 이번 과정에서는 컬렉션과 자주 함께 쓰이는 이 두 가지만 다룹니다.

## 6. 메서드 참조 (Method Reference)

람다식 중에는 "매개변수를 받아서 그대로, 다른 로직 없이 어떤 메서드 하나에 넘기기만 하는" 경우가 많습니다. 이런 람다식은 메서드 참조(`::`) 문법으로 한 번 더 줄일 수 있습니다.

| 종류 | 문법 | 예시 | 같은 의미의 람다식 |
|---|---|---|---|
| static 메서드 참조 | `클래스::static메서드` | `Integer::parseInt` | `s -> Integer.parseInt(s)` |
| 특정 객체의 인스턴스 메서드 참조 | `참조변수::인스턴스메서드` | `System.out::println` | `x -> System.out.println(x)` |
| 임의 객체의 인스턴스 메서드 참조 | `클래스::인스턴스메서드` | `Student::getScore` | `student -> student.getScore()` |

```java
public class MethodReferenceExample {
    public static void main(String[] args) {
        // static 메서드 참조: Integer.parseInt(s)를 그대로 넘김
        Function<String, Integer> toNumber = Integer::parseInt;
        System.out.println(toNumber.apply("100")); // 100

        List<String> names = List.of("홍길동", "김철수", "이영희");

        // 특정 객체의 인스턴스 메서드 참조: System.out이라는 정해진 객체의 println을 그대로 넘김
        names.forEach(System.out::println); // name -> System.out.println(name)과 동일

        List<Student> students = new ArrayList<>();
        students.add(new Student("홍길동", 92));
        students.add(new Student("김철수", 78));

        // 임의 객체의 인스턴스 메서드 참조: 매개변수로 들어오는 객체의 getScore()를 호출
        students.sort(Comparator.comparing(Student::getScore)); // (a, b) -> a.getScore() - b.getScore()와 사실상 같은 정렬
    }
}
```

**설명**: `Integer::parseInt`는 "문자열 하나를 받아서 `Integer.parseInt(그 문자열)`을 그대로 호출하고 결과를 반환한다"는 뜻이므로 `s -> Integer.parseInt(s)`와 완전히 같습니다. `System.out::println`도 "받은 값을 그대로 `System.out.println(...)`에 넘긴다"는 람다식(`x -> System.out.println(x)`)의 축약형입니다. 반면 `Student::getScore`는 "누구의 `getScore()`를 부를지"가 미리 정해져 있지 않고 **람다식의 매개변수로 들어온 객체 자신**의 `getScore()`를 호출하므로 `student -> student.getScore()`와 같습니다. `Comparator.comparing(...)`은 이런 "비교 기준을 추출하는 함수"를 받아 `Comparator`를 만들어주는 표준 라이브러리 메서드입니다.

**메서드 참조를 쓸 수 있는 조건**: 람다식의 본문이 **매개변수를 그대로, 순서 그대로, 다른 로직 없이** 어떤 메서드 하나에 전달하는 형태여야 합니다. `student -> student.getScore() + 10`처럼 추가 연산이 붙으면 메서드 참조로 줄일 수 없고 람다식을 그대로 써야 합니다.

## 7. 생성자 참조 (Constructor Reference)

메서드 참조와 같은 `::` 문법으로, 생성자를 그대로 참조할 수도 있습니다. "객체를 새로 만들기만 하는" 람다식을 `클래스::new`로 줄일 수 있습니다.

```java
@FunctionalInterface
public interface StudentFactory {
    Student create(String name, int score); // Student(String, int) 생성자와 매개변수 구성이 같음
}
```

```java
public class ConstructorReferenceExample {
    public static void main(String[] args) {
        // 생성자 참조: new Student(name, score)를 그대로 넘김
        StudentFactory factory = Student::new; // (name, score) -> new Student(name, score)와 동일

        Student student = factory.create("박민수", 77);
        System.out.println(student.getName() + ": " + student.getScore());
    }
}
```

**설명**: `StudentFactory`의 추상 메서드 `create(String name, int score)`는 매개변수 구성이 `Student`의 생성자 `Student(String name, int score)`와 정확히 일치합니다. 이렇게 시그니처가 맞아떨어지면 `(name, score) -> new Student(name, score)`라는 람다식을 `Student::new`로 줄여 쓸 수 있습니다.

## 8. 컬렉션과 함께 쓰기 (Day16 복습)

Day16에서 배운 `List`와 람다식을 결합하면, 반복문을 직접 쓰지 않고도 간결하게 순회하거나 정렬할 수 있습니다.

```java
import java.util.List;
import java.util.ArrayList;

public class LambdaWithListExample {
    public static void main(String[] args) {
        List<Student> students = new ArrayList<>();
        students.add(new Student("홍길동", 92));
        students.add(new Student("김철수", 78));
        students.add(new Student("이영희", 85));

        // forEach: 반복문 대신 람다식으로 각 요소에 대해 동작 수행
        students.forEach(student -> System.out.println(student.getName() + ": " + student.getScore()));

        // sort: Comparator 람다로 정렬 기준을 즉석에서 정의 (점수 오름차순)
        students.sort((a, b) -> a.getScore() - b.getScore());

        System.out.println("정렬 후:");
        students.forEach(student -> System.out.println(student.getName() + ": " + student.getScore()));
    }
}
```

**설명**: `students.forEach(...)`는 Day3~6에서 배운 향상된 for문과 같은 일을 하지만, 반복문 틀(`for (Student student : students) { }`) 없이 "각 요소로 무엇을 할지"만 람다식으로 전달하면 됩니다. `students.sort(...)`는 `Comparator` 람다를 넘겨받아, 그 비교 규칙대로 리스트 내용을 직접 정렬합니다. `(a, b) -> a.getScore() - b.getScore()`를 `(a, b) -> b.getScore() - a.getScore()`로 바꾸면 내림차순으로 정렬 기준을 손쉽게 바꿀 수 있습니다.

## 자주 하는 실수

1. **추상 메서드가 2개 이상인 인터페이스에 람다식을 쓰려는 시도**
   ```java
   public interface NotFunctional {
       void methodA();
       void methodB();
   }
   NotFunctional obj = () -> { ... }; // 컴파일 에러! 어떤 메서드를 구현하는지 알 수 없음
   ```

2. **람다식의 매개변수 개수를 인터페이스와 다르게 작성**
   ```java
   // Comparator<T>의 compare(T a, T b)는 매개변수가 2개
   Comparator<Student> wrong = (a) -> 0; // 컴파일 에러! 매개변수 개수 불일치
   ```

3. **Comparator의 반환값 규칙(음수/0/양수)을 반대로 착각**
   ```java
   students.sort((a, b) -> b.getScore() - a.getScore()); // 내림차순
   students.sort((a, b) -> a.getScore() - b.getScore()); // 오름차순
   // 순서를 헷갈리면 정렬 결과가 의도와 반대로 나옴
   ```

4. **람다식 안에서 바깥의 지역변수를 수정하려는 시도**
   ```java
   int count = 0;
   students.forEach(student -> count++); // 컴파일 에러! 람다식은 바깥의 지역변수를 읽을 수만 있고 수정할 수 없음(사실상 final)
   ```

5. **메서드 참조로 줄일 수 없는 람다식을 억지로 `::`로 쓰려는 시도**
   ```java
   // 매개변수를 그대로 넘기는 게 아니라 추가 연산(+ 10)이 붙으면 메서드 참조로 표현할 수 없음
   Function<Student, Integer> plusTen = student -> student.getScore() + 10; // 이 경우엔 람다식을 그대로 써야 함
   ```
