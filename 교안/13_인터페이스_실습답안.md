## 기본

### 문제 1. 인터페이스 정의와 구현

```java
// 소리내기가능.java
public interface Soundable {
    void makeSound();
}
```

```java
// Dog.java
public class Dog implements Soundable {
    @Override
    public void makeSound() {
        System.out.println("멍멍!");
    }
}
```

```java
// Practice1.java
public class Practice1 {
    public static void main(String[] args) {
        Dog dog1 = new Dog();
        dog1.makeSound();
    }
}
```

**설명**: `interface Soundable`은 `makeSound()`라는 구현 없는 메서드 하나만 선언합니다. `Dog`는 `implements Soundable`으로 이 인터페이스를 구현하고, `@Override`로 실제 동작을 채워 넣었습니다.

**틀리기 쉬운 포인트**: `Dog`에서 `makeSound()`를 구현하지 않으면 "인터페이스의 추상 메서드를 구현하지 않았다"는 컴파일 에러가 발생합니다. 인터페이스를 구현하는 클래스는 그 안의 모든 메서드를 반드시 오버라이딩해야 합니다.

### 문제 2. 서로 관계없는 두 클래스가 같은 인터페이스 구현

```java
// Cat.java
public class Cat implements Soundable {
    @Override
    public void makeSound() {
        System.out.println("야옹");
    }
}
```

```java
// Practice2.java
public class Practice2 {
    public static void main(String[] args) {
        Dog dog1 = new Dog();
        Cat cat1 = new Cat();

        dog1.makeSound();
        cat1.makeSound();
    }
}
```

**설명**: `Dog`와 `Cat`는 서로 다른 클래스이고 상속 관계도 없지만, 똑같이 `Soundable` 인터페이스를 구현했습니다. 인터페이스는 상속 계층과 무관하게 "이 기능을 할 수 있다"는 공통점만으로 클래스들을 묶을 수 있습니다.

**틀리기 쉬운 포인트**: 이 두 클래스를 하나의 부모로 묶으려면 원래 상속(`extends`)을 써야 했겠지만, "동물"이라는 억지 부모 클래스를 만들 필요 없이 인터페이스만으로 공통 기능을 강제할 수 있다는 것이 이번 문제의 핵심입니다.

## 응용

### 문제 3. 인터페이스 배열로 다형성 활용

```java
public class Practice3 {
    public static void main(String[] args) {
        Soundable[] items = {
            new Dog(),
            new Cat()
        };

        for (Soundable item : items) {
            item.makeSound();
        }
    }
}
```

**설명**: `Soundable[]` 배열에 서로 관계없는 `Dog`와 `Cat` 객체를 함께 담았습니다. 반복문에서 `item.makeSound()`를 호출하면, 실제 객체 타입(강아지인지 고양이인지)에 맞는 오버라이딩된 메서드가 실행됩니다.

**틀리기 쉬운 포인트**: 배열의 선언 타입을 `Dog[]`나 `Cat[]`처럼 하나로 고정하면 다른 하나를 같이 담을 수 없습니다. 공통 인터페이스(`Soundable`) 타입으로 배열을 선언해야 서로 다른 클래스들을 함께 관리할 수 있습니다.

### 문제 4. 상속 + 인터페이스 함께 사용

```java
// 정보출력가능.java
public interface Printable {
    void printInfo();
}
```

```java
// Professor.java
public class Professor extends Person implements Printable {
    private String professorId;

    public Professor(String name, String professorId) {
        super(name);
        this.professorId = professorId;
    }

    @Override
    public void printInfo() {
        System.out.println("[교수] 이름: " + getName() + ", 교수번호: " + professorId);
    }
}
```

```java
// Practice4.java
public class Practice4 {
    public static void main(String[] args) {
        Professor professor1 = new Professor("김교수", "P001");
        professor1.printInfo();
    }
}
```

**설명**: `Professor`는 `extends Person`(상속)과 `implements Printable`(인터페이스 구현)을 동시에 합니다. `Person`으로부터 `getName()`을 물려받고, `Printable`으로부터 `printInfo()`을 구현 의무로 받아, 둘을 조합해서 출력합니다.

**틀리기 쉬운 포인트**: `extends Person implements Printable`처럼 순서를 반드시 `extends`가 먼저, `implements`가 나중이어야 합니다. 순서를 바꾸면 컴파일 에러가 납니다.

### 문제 5. 상속 관계가 다른 여러 클래스를 인터페이스로 묶기

```java
// Student.java
public class Student extends Person implements Printable {
    private String studentId;

    public Student(String name, String studentId) {
        super(name);
        this.studentId = studentId;
    }

    @Override
    public void printInfo() {
        System.out.println("[학생] 이름: " + getName() + ", 학번: " + studentId);
    }
}
```

```java
// Course.java
public class Course implements Printable {
    private String courseName;
    private int capacity;

    public Course(String courseName, int capacity) {
        this.courseName = courseName;
        this.capacity = capacity;
    }

    @Override
    public void printInfo() {
        System.out.println("[강좌] 강좌명: " + courseName + ", 정원: " + capacity);
    }
}
```

```java
// Practice5.java
public class Practice5 {
    public static void main(String[] args) {
        Printable[] items = {
            new Student("홍길동", "S001"),
            new Professor("김교수", "P001"),
            new Course("자바프로그래밍", 30)
        };

        for (Printable item : items) {
            item.printInfo();
        }
    }
}
```

**설명**: `Student`은 `Person`을 상속받고, `Professor`도 `Person`을 상속받지만, `Course`는 `Person`과 전혀 관계가 없습니다. 그런데도 셋 다 `Printable`을 구현했기 때문에, 하나의 `Printable[]` 배열로 관리하고 동일한 방식(`item.printInfo()`)으로 처리할 수 있습니다. 이것이 상속만으로는 불가능했던, 인터페이스이기에 가능한 다형성입니다.

**틀리기 쉬운 포인트**: `Person[]` 배열에는 `Course`를 담을 수 없습니다(`Course`는 `Person`이 아니므로). 하지만 `Printable[]` 배열에는 담을 수 있는데, 이는 `Course`가 "사람이다(is-a)"는 아니지만 "정보를 출력할 수 있다(can-do)"는 공통점은 있기 때문입니다.

### 문제 6. 종합 - 인터페이스 2개 동시 구현

```java
// 저장가능.java
public interface Savable {
    void save();
}
```

```java
// Student.java
public class Student extends Person implements Printable, Savable {
    private String studentId;

    public Student(String name, String studentId) {
        super(name);
        this.studentId = studentId;
    }

    @Override
    public void printInfo() {
        System.out.println("[학생] 이름: " + getName() + ", 학번: " + studentId);
    }

    @Override
    public void save() {
        System.out.println(getName() + " 학생 정보를 저장했습니다.");
    }
}
```

```java
// Practice6.java
public class Practice6 {
    public static void main(String[] args) {
        Student student1 = new Student("홍길동", "S001");

        student1.printInfo();
        student1.save();
    }
}
```

**설명**: `implements Printable, Savable`처럼 콤마로 나열해서 두 인터페이스를 동시에 구현했습니다. `Student`은 두 인터페이스가 요구하는 메서드(`printInfo()`, `save()`)를 모두 오버라이딩해야 하며, 둘 다 구현했으므로 정상적으로 컴파일됩니다.

**틀리기 쉬운 포인트**: 클래스 상속(`extends`)은 `Person` 하나만 가능하지만, 인터페이스 구현(`implements`)은 이렇게 개수 제한 없이 얼마든지 나열할 수 있습니다. 이것이 상속과 인터페이스의 가장 뚜렷한 차이점입니다.
