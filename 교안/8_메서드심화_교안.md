## 1. 메서드 오버로딩 (Overloading)

**같은 이름**의 메서드를 매개변수의 **개수나 자료형을 다르게** 해서 여러 개 정의하는 것을 오버로딩이라고 합니다.

```java
public class 오버로딩예제 {
    // 매개변수 개수가 다름
    public static int 더하기(int a, int b) {
        return a + b;
    }

    public static int 더하기(int a, int b, int c) {
        return a + b + c;
    }

    // 매개변수 자료형이 다름
    public static double 더하기(double a, double b) {
        return a + b;
    }

    public static void main(String[] args) {
        System.out.println(더하기(1, 2));       // int 버전 호출 → 3
        System.out.println(더하기(1, 2, 3));     // 매개변수 3개 버전 호출 → 6
        System.out.println(더하기(1.5, 2.5));    // double 버전 호출 → 4.0
    }
}
```

**설명**: 자바 컴파일러는 메서드를 호출할 때 넘긴 값의 **개수와 자료형**을 보고 어떤 버전의 메서드를 실행할지 자동으로 판단합니다. 이렇게 하면 "정수 더하기", "실수 더하기"처럼 이름을 억지로 다르게 짓지 않아도, 같은 의미의 기능을 하나의 이름(`더하기`)으로 통일해서 사용할 수 있습니다.

**주의**: 매개변수의 **개수/자료형/순서**가 달라야 오버로딩이 성립합니다. 반환형만 다르고 매개변수가 완전히 같으면 오버로딩이 아니라 컴파일 에러입니다.
```java
public static int 계산(int a, int b) { return a + b; }
public static double 계산(int a, int b) { return a + b; } // 컴파일 에러! 매개변수가 같아 구분 불가
```

## 2. 재귀 메서드 (Recursion)

메서드가 자기 자신을 다시 호출하는 것을 재귀라고 합니다. 반복문으로 풀 수 있는 문제 중 일부는 재귀로도 표현할 수 있습니다.

```java
public class 재귀예제 {
    // n의 팩토리얼(n!) = n * (n-1) * (n-2) * ... * 1
    public static int 팩토리얼(int n) {
        if (n <= 1) {
            return 1; // 종료 조건 (base case): 더 이상 자신을 호출하지 않고 값을 바로 반환
        }
        return n * 팩토리얼(n - 1); // 자기 자신을 더 작은 값으로 다시 호출
    }

    public static void main(String[] args) {
        System.out.println(팩토리얼(5)); // 5 * 4 * 3 * 2 * 1 = 120
    }
}
```

**동작 과정 이해하기**: `팩토리얼(5)`는 `5 * 팩토리얼(4)`를 계산해야 하고, `팩토리얼(4)`는 `4 * 팩토리얼(3)`을 계산해야 하는 식으로 계속 더 작은 문제로 쪼개집니다. `n <= 1`이 되면 더는 자신을 호출하지 않고 `1`을 반환하며, 그때부터 거꾸로 값을 곱하며 돌아옵니다.

```
팩토리얼(5) = 5 * 팩토리얼(4)
            = 5 * (4 * 팩토리얼(3))
            = 5 * (4 * (3 * 팩토리얼(2)))
            = 5 * (4 * (3 * (2 * 팩토리얼(1))))
            = 5 * (4 * (3 * (2 * 1)))
            = 120
```

**중요**: 재귀 메서드는 반드시 **종료 조건(base case)** 이 있어야 합니다. 종료 조건이 없거나 잘못되면 메서드가 자기 자신을 무한히 호출하다가 `StackOverflowError`가 발생합니다.

## 3. 배열을 매개변수로 전달하기

Day7에서 배열을 매개변수로 넘기는 것을 다뤘습니다. 이번에는 **메서드 내부에서 배열의 값을 바꾸면 원본도 바뀐다**는 점을 자세히 살펴봅니다. 이는 Day4에서 배운 참조형 개념과 직접 연결됩니다.

```java
public class 배열매개변수예제 {
    // 배열의 모든 값을 2배로 만드는 메서드
    public static void 두배로만들기(int[] 배열) {
        for (int i = 0; i < 배열.length; i++) {
            배열[i] = 배열[i] * 2;
        }
    }

    public static void main(String[] args) {
        int[] 숫자들 = {1, 2, 3};
        두배로만들기(숫자들);

        // 메서드 안에서 바뀐 내용이 원본 배열에도 그대로 반영됨
        for (int 값 : 숫자들) {
            System.out.print(값 + " "); // 2 4 6
        }
    }
}
```

**설명**: Day4에서 배웠듯이 배열은 참조형이므로, 매개변수로 전달될 때 배열의 "주소"가 전달됩니다. 즉 메서드 안의 `배열`과 `main`의 `숫자들`은 서로 다른 변수 이름이지만, **같은 배열 객체(같은 힙 메모리 위치)** 를 가리킵니다. 그래서 메서드 안에서 배열 요소를 수정하면 원본 배열도 함께 바뀝니다. 이는 `int`, `double` 같은 기본형을 매개변수로 넘길 때(값만 복사되어 원본이 바뀌지 않는 것)와 다른 점입니다.

## 자주 하는 실수

1. **오버로딩 조건을 반환형만 다르게 착각**
   ```java
   public static int 더하기(int a, int b) { return a + b; }
   public static double 더하기(int a, int b) { return a + b; } // 컴파일 에러
   ```

2. **재귀 메서드에 종료 조건을 빠뜨려 무한 재귀**
   ```java
   public static int 팩토리얼(int n) {
       return n * 팩토리얼(n - 1); // n <= 1 조건이 없어 계속 호출되다 StackOverflowError
   }
   ```

3. **배열이 참조형이라는 것을 잊고 원본이 안 바뀔 거라 착각**
   ```java
   int[] 배열 = {1,2,3};
   두배로만들기(배열);
   // 배열 값이 변경되지 않았을 거라 착각하기 쉽지만, 실제로는 원본이 바뀜
   ```

## 핵심 요약

| 항목 | 핵심 내용 |
|---|---|
| 오버로딩 | 같은 이름, 다른 매개변수(개수/자료형)로 여러 메서드 정의 |
| 오버로딩 판단 기준 | 매개변수의 개수·자료형·순서 (반환형만 다르면 오버로딩 아님) |
| 재귀 | 메서드가 자기 자신을 호출, 반드시 종료 조건(base case) 필요 |
| 배열 매개변수 | 배열은 참조형이라 메서드 안에서 값을 바꾸면 원본도 바뀜 |
